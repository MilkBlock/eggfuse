# What is actually inside one GPU token?

The current token is one `float32[279]` row per Cell instance. It is a structured
soft state, not the previous opaque 128-float embedding. It stores probabilities
produced by learned heads alongside a protected copy of initial structure.

| Half-open float range | Shape | Meaning |
| --- | --- | --- |
| `[0,64)` | 8 x 8 | Equality scores E between stable old-member roles |
| `[64,136)` | 8 x 9 | Pointer scores P from each old role to a destination slot |
| `[136,275)` | 139 | Protected initial structure, requests and annotation |
| `[275,278)` | 3 | Source Run phase one-hot |
| `[278,279)` | 1 | Learned completion/transfer activation score |

That is 1,116 bytes, versus the old 512 bytes. No RSS or compression benefit is
claimed. Intermediate reference keys, neural activations, logits and saved audit
checkpoints are additional storage, not included in this payload count.

## Protected fields, exactly

| Float range | Encoding | Content |
| --- | --- | --- |
| `[136,144)` | 4 x 2 | Four constructor opcodes, F or H |
| `[144,224)` | 4 x 2 x 10 | Each constructor's ordered argument-role references |
| `[224,240)` | 2 x 8 | The two endpoints of the source union request |
| `[240,241)` | 1 | Whether that request exists |
| `[241,257)` | 2 x 8 | LHS query endpoint bindings |
| `[257,271)` | 2 x 7 | Two adjacent-swap requests |
| `[271,275)` | 4 | Opaque annotation bits |

The one-hot argument references include a missing/unary-argument sentinel. The
initial requests are inputs, not computed answers. For example, retaining a union
request does not authorize equality visibility during Run 1. Phase gating still
prevents that request from becoming a relation feature until Run 2.

The source structure is copied by fixed GPU tensor operations into every generated
token. This deliberately removes its lossy reconstruction from the learning
problem. It does not show that an unconstrained latent has learned lossless graph
compression. Nothing rereads the original seed between advances.

## Stable role versus physical slot

E is indexed by stable logical member roles. P is indexed by an old role and a
new physical slot. Equality and ownership transfer are therefore different state
changes:

```text
role 4 = F(role 0)
role 5 = F(role 1)
role 6 = H(role 4, role 4)
role 7 = H(role 5, role 5)

union(0,1) -> generated E[0,1], E[4,5], E[6,7] become true
```

The constructor arguments stay intact. Equal members still have distinct roles.
A later transfer can generate:

```text
new physical slots: 0 1 2 3 4 5 6 7 8
members:            0 3 1 2 8 4 5 6 7

old role -> new slot:
0->0, 1->2, 2->3, 3->1, 4->5, 5->6, 6->7, 7->8
```

P's row 4 then points to column 5. E[4,5] still talks about the same logical roles,
not about whichever members now occupy physical slots 4 and 5. This preserves
references during the one A-to-B transfer supported by the prototype.

The new member 8 is implicit in the fixed completion template `G(query-left)`
and activation flag; it occupies slot 4 under this experiment's insertion policy.
There is no arbitrary new-instruction stream. E does not grow to include arbitrary
future unions involving member 8. That requires an expanded/generalized ABI.

## Shared heads do not mean fewer output entries

The 64 E entries are generated by repeated use of one 8->32->1 MLP. The pointer
scores are generated by one other 8->32->1 MLP, applied to relative source/target
features. There are no learned weights dedicated to `(role 1, role 3)` or to a
particular whole mapping. The activation head is 1->8->1. Total trainable
parameters: 667.

A relation update gathers prior argument relations and two-hop evidence on GPU,
then the learned scorer votes on new equality. Max with the prior state retains
existing votes; it does not certify new votes. Eight sweeps are unrolled per
Run 1/2. Run 3 directly reads the previously generated relation at the query pair.

For transfer, two learned single-swap matrices and one learned insertion matrix
compose with the prior P. The target mapping is not supplied at inference. The
final layout is decoded from P's columns plus the new/empty-member indicator.
The proof is a fixed macro instantiated with protected bindings and generated
choices; its semantics were not discovered by the network.

## Rotation, side metadata and masking

Only the first 64 lanes are rotated by the Cell coordinate. They must be inverse
rotated before interpreting E as relation probabilities. The other lanes are
carried unchanged by this Cell rotation. Port rotation lives in transient
128-float reference keys, using separate Cell and port subspaces. It is not a
large rotary vector permanently attached to every argument slot.

`advance(token, current_position, Run_phase, available_positions)` consumes the
actual generated previous token. The remaining arguments are schedule/address
metadata. Absolute position is not encoded as an additional integer field in the
token, and is not reconstructed by the CPU from a hidden answer.

After a generated ownership transfer, the old bank entry is masked with `where`
before arithmetic. NaN poisoning of the old payload must not affect reads. CPU
verification later decodes saved token bytes and checks the complete source
contract. It never fills a missing relation or patches a bad pointer.
