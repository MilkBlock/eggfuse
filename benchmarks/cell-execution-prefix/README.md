# Continue Cell queries to their first dependency boundary

Control: `4ba83913`, annotated tag `cell-execution-refactor-base`. This is the
first executable stage of [the ownership refactor](../../docs/CELL_EXECUTION_REFACTOR.md),
on the **standalone Cell CPU runtime**. It is not a complete resumable worker
executor and does not establish a throughput or utilization improvement.

The previous RHS draft queued a second pool pass after winner selection. This
change instead continues successful point/expansion queries on their existing
worker. A typed plan divides the authoritative source operations at constructor,
mutable read/write, union, visibility, failure and unsupported primitive
boundaries. The current runtime consumes only the initial local segment; later
segments are compiled cuts for the subsequent boundary-resumption work.

Ordinary opcodes stay in their existing immutable allocation, now shared with
Arc. The plan contains source positions and slot projections, not copied
instructions or a second fact graph. Artifact loading rederives and checks the
plan. Old artifacts without the optional plan are still reconstructed from
their original source. Eq-sensitive primitives and writes to input slots cannot
enter the speculative local segment.

Query completion allocates the instance's input and initial result capacity
together, using the compiled output slots. Pure results stay in that original
Slots array. The winning instance passes its prepared position into the normal
single-write/general RHS, which omits those operations. No operation log, result
binding copy or second pool dispatch is introduced. A source failure stops
preparation; the original executor reports it at its original RHS position.
Preparation is not a committed rule application.

Winner comparison, legacy origin lookup and input audit serialization use the
original rule inputs. Newly prepared slots cannot change identity. The original
query snapshot, effect order, current-value mutable merge, constructor lookup,
union submission, completion and publication remain authoritative. This stage
does not move Cursor ownership, shared graph writes or post-boundary execution
onto workers, and it does not remove the source Run query barrier.

## Complete work comparison

[results.json](results.json) is generated by [check.py](check.py) from complete
saved executions. Every existing graph counter and checked query/maintenance
counter agrees with the tag. Exact final states and all source Run records
match. The native sum-bits semantic acceptance is `pass / exit 0`; Raytrace is
an exact relative regression, not a new independent native contract.

| Slot-array growth during preparation | 0 | 0 |
| Compiled dependency-plan payload bytes | 386,216 | 2,313,240 |

Each sparse execution instance also carries one `usize` prepared position
(8 bytes on this machine), including instances that prepare no instructions.
Existing transport/capacity counters charge the enlarged instance headers.
The result-slot reservation is cumulative capacity, not peak residency or an
allocation count. Plan payload includes segment and slot-vector capacities,
excluding allocator metadata and the existing shared opcodes. Prepared work
includes candidates subsequently discarded or otherwise not consumed; only the
consumed counter denotes omitted RHS operations. Inline preparation remains
coordinator computation. No graph lookups, merges or committed mutations are
counted as saved by this scalar prefix change.

The layout reserves space once with the query input allocation. The earlier
uncommitted allocation trial grew the input array while preparing results; it
is retained only in ignored raw artifacts and is not the shipped layout.

## Validation and reproduction

111 runtime unit tests and 28 selected integration tests pass. Coverage includes
source-snapshot inputs after earlier RHS updates, actual constructor results,
deferred arithmetic failure, forged boundary plans, input-slot protection,
mutable-read cuts, original winner identity, late inputs, union and deletion.
A separate test runs with `audit=false` and compares the actual graph after
each of ten Runs through foreign constructor reuse, union, deletion/recreation
and real Entry publication. This avoids relying only on an audit path that may
disable compiled publication. Forced hash/Sieve collision tests also pass.

use fresh outputs; bench repeat 1 is a smoke check, not a speed experiment.
