# 读到整数端口回复以后，网络能否选对下一项实际消费？

对每个真实 SubTuple 发布事件，策略面对三个由源码提取的消费者。规则 137 检查长度 b 等于 1；规则 138 检查 b 大于 1；规则 145 额外需要起点 a 等于 0，并与另一个表中的长度吻合。一次动作最多选择一个主消费者（137 或 138）和一个附加消费者（145），也可以不发行。目标是预测这次**具体发布票据**在后续源 Run 中实际供给了谁。

单独核对整数分支相对容易。sum-bits 的 252 个等于 1 的发布中，85 个此后未被记录的 Spine 消费，139 个仅供规则 137，28 个还供规则 145。完整长度分支已经确定时，未来消费者集合在 sum-bits、dot-product、GEMM-bias-ReLU、stable-argmax 上分别仍有 1.339、1.435、1.302、1.358 bit 的经验条件熵。这里按每个程序的冻结轨迹计数。

## 拿什么训练和验收

整数值从已提交生产者自己的 RHS 槽和前序效果中重建。网络发行阶段使用生产规则、效果位置、当前源 Run、可静态推出的字面量以及同地址此前的发布次数和间距。后续真正的消费者从精确发布序号回溯，单独用于监督和事后评分。训练只用四个真实家族。双种子在两个锚点、两个独立留出家族上评估，每个发布事件重新计算一次局部上下文。所有臂共享同一个有冻结权重的两步网络。

第一步形成待决策端口的隐向量，第二步在这个隐向量上读回复、预测是否发行、选哪个主消费者以及是否另发 145。训练时每个样本随机提供四种可见性。测试分别给动态字段遮盖、只给 Rust 对 b 的比较、给精确 b、给精确 b 和 a。编译期已知值在所有条件下可见。每种输入的地址请求策略固定；本实验学习的是回复之后的动作。另保留冻结遮盖与编译器延迟分派对照。

| 对照 | 问题 |
|---|---|
| blind | 只靠生产者上下文与静态字段，模型能选多少实际消费者？ |
| guard | 现在立即询问动态长度与阈值的关系，改变了哪些动作？ |
| value | 增加完整 i64 长度后，下一步选择是否继续改善？ |
| both-values | 再让模型读取另一 i64 端口 a 的值，能否选对额外的 145？ |
| deferred | 模型只按 blind 的隐向量决定是否签发主动作和 145。最终由 Rust 在归档票据的原 epoch 上解析主动作的确切分支。 |
| native-deferred | 将同样的盲发行动作交给 Rust。它按实际源顺序推进发布账本，到下一个可激活的 Run 才取该物理地址的当前版本并解析。若票据已被替换则撤销。此外，对附加动作检查源码要求的 a 等于 0。 |
| native-deferred-all | 每项都留给同一个原生版本和字面量检查，量出确定性规则本身的效果。 |

比较主 guard 使用 verifier-placement 的真实 Rust ABI，精确值读取接受地址、epoch 与发布序号。过期回复无权提供该值。输入和数值投影在运行前整理好，计时包括原网络设备上的两步前向、按源时代批量工作的 Rust 交互、回复写回设备和最终可读的提案。额外测量原生延迟段读取源 Run 和发布日志、更新局部账本及处理发行动作的耗时。提供 CPU 网络＋Rust 和 MPS 网络＋Rust；两种放置必须得到完全相同的离散动作。纯编译器条件、训练监督和时钟边界互相独立。

## 结果

| 程序 | 有实际后继的发布数 | blind 预测完整 | 立即 guard ／ 延迟符号分派 | 同时读取 b、a（种子 1703／1709） |
|---|---:|---:|---:|---:|
| sum-bits | 260 | 203 | 205／205 | 213／210 |
| dot-product | 160 | 126 | 126／126 | 130／129 |
| GEMM-bias-ReLU | 527 | 403 | 406／406 | 425／429 |
| stable-argmax | 260 | 204 | 205／205 | 220／221 |

这里按一个票据所需的全部不同消费者是否恰好选中计数。立即取得长度比较的结果，在这四个程序两个种子上都与延迟符号分派达到相同的非空完整数。两个整数一起返回，结果经常提高。反事实冻结发现，sum-bits 种子 1703 由此改变了 2 个主发行门和 14 个附加发行门，选中候选由 283 增至 304。dot-product 种子 1709 虽然多完成 3 个本来有消费的票据，连同空票据计算，精确票据数从 218 降为 217。

为检验增加发行数的影响，另以同一源 Run 中 blind 可行主动作和可行附加动作的数量设定配额。所有臂在共同的整数可行集合上用各自冻结的学习分数排序。在两类动作各自配额相同时，额外提供两个值对八组非空完整数均无改善。若允许两类互相调剂、仅固定总数，sum-bits 种子 1703 在同样的 283 个候选中从 205 升至 207，其余七组相同。[固定工作量排序](budget_check.py) · [配额对照](matched.json)

在当前**实际神经来源**子集中，两个种子四个程序的长度均可静态取得。即使把动态起点 a 返回给同一网络，也未改变任何一次后继选择。sum-bits 两个种子实际请求了 35／33 次 a。基于真实源发布全集的结论需要与这一点一起读。原生延迟账本在下一个可激活 Run 前，分别发现 9、0、50、12 张票据的原物理地址已经被新发布占用，所涉旧票据都没有后续源消费。

以 sum-bits 种子 1703 为例，CPU 网络＋Rust 的 blind、立即 guard、两个值、延迟符号分派分别耗时 1.74、2.29、3.03、1.79 ms；MPS 网络＋Rust 分别为 17.90、34.59、52.25、18.55 ms。立即 guard 读取 226 个动态长度，延迟分派只需为真正发行的符号主动作读取 97 个。计时限于 446 个源发布的决策重放，均含最终可读结果。Rust 原生段先后读取 1,428 个真实 Run 边界并更新原物理地址的版本。该段没有驱动 Pass 3 的图维护。[原始计数与配对时间](results.json)

## 归因的范围

真实发布全集包括精确引擎与神经路径完成的 RHS。神经来源子集另取当时实际写入 RHS bank 的唯一序号，并核对物理起点。两种子与四个验收程序中，这个子集的 b 全都是静态字面量，a 则全是动态值。子集单独运行神经策略，其历史特征只来自子集此前的发布。原生版本服务仍看到真的其他写者，这些写者可以使旧票据过期。

结果来自完整 Pass 3 的源事件、以读写边界驱动的独立 Rust 事务段和网络决策重放。选择中一个随后被消费的票据和规则仅算一个不同目标，同一组合的多次源 RHS 另报。未在冻结轨迹中被该票据供给的消费者可能仍有合法独立来源。Rust 回答一个整数 guard 也无法单独证明未来调度一定会消费它。该策略没有驱动整张图或向真机 Pass 3 的 RHS bank 提交，计时只覆盖这里的决策与核验片段。

从生产者完整绑定重新执行源码投影，也能获得这批实验中的两个整数值。请求收益取决于网络输入边界：模型如果已经保存了准确的整数操作数，可以在本地执行同一判断。归档票据与延迟到原 Run 的可变地址是两种不同的版本契约。原生局部账本处理同一物理位置被再次发布；跨地址转发、union 后同类与额外的 tuple-length 条件仍需完整引擎核验。
