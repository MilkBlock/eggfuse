# 完整唯一键上的神经父引用提案

在 M3 Max 上的两份实际 eggcc Pass 3 中，模型从设备常驻的 Cell 端口选出父行，按真实端口引用验证，再对未解决的锚点做精确点查。sum-bits 的整轮推理为 112.15 ms，dot-product 为 123.24 ms。同一组入口直接查 CPU 索引为 25.39／22.16 ms，使用现有批量 Metal 搜索为 91.61／83.52 ms。实验在独立的 Rust Cell 运行时执行，默认策略保持原状。[原始样本、后端标识和有序事件摘要](results.json)

## 准入与来源

复用编译产物的 `multi_stage.stage_entries`。编译器以一个关系原子为 pivot，要求另一原子的完整输入键全部可由已绑定槽或类型化字面量得到，扩展预算为零。程序加载时从类型化规则重导并校验证书。本实验限定为两个关系原子，目标键至少一列取自锚点，两边都能作 pivot 时按证书顺序选第一个。两份计划各有 64 条合格规则，sum-bits／dot-product 实际进入该路径的分别为 30／23 条。其余规则沿用原引擎。规则 61 从 `Add-Gets(orig,something,n)` 的第二列取得 `Not-Just-Concat(something)` 的完整键；规则 139 从 `DoWhile` 的结果端口取得 `tuple-length(lhs)` 的完整键。[编译器准入](../../../engine/cell-runtime/src/stage_spine.rs) · [实验计划与验证](../../../engine/cell-runtime/src/unique_parent.rs)

一次 Run 内冻结读视图，CPU 调度锚点。设备的每张相关表首次读取时建立端口 bank，存有可见位及每个端口的值经散列后的编号。后续仅上传已发布变化的见证，退役位置置为不可见；本次推理中位置不复用。模型为每个锚点输出一个目标 bank 的位置或弃权。CPU 将位置解析回稳定的构造器事实引用或函数行，直接读真实行、检查表、可见性和完整键。验证通过就可凭键唯一性关闭本次父行查找。弃权或验证失败都会调用原图的精确键索引。两条路径随后执行相同的增量水位与其余 LHS 条件，保留源槽位顺序。旧锚点仍可与新版本目标行匹配。

网络使用共享的 128×8 桶 embedding 和一个可学习的弃权分数。对锚点所给出的每个键槽，以向量点积比较目标行的相应端口，按各槽的平均分选出最高的可见行。PyTorch 在合成键集上用交叉熵训练 800 步，种子 1703，训练标签来自完整键，训练没有读取这两个 Pass 的图或轨迹。实际前向在进程内 Metal 执行。桶碰撞和相似向量允许错指，精确验证使用原始类型值。这里仍需给 bank 中的候选打分；这不具备哈希索引的直接寻址成本。[训练](train.py) · [冻结权重](weights.json) · [设备前向](../../../engine/cell-runtime/src/parent_pointer.metal)

沿用原混合版的整规则 Spine 排除条件时，每例只剩 2 个有效绑定。正式三臂允许在活跃规则上运行：从已验证的两条见证行取回原调度的增量入口和已发布 cursor，沿现有深度与见证顺序选择接续来源，使用同一份已验证输入执行 RHS。三个实验臂均经过这段路径。sum-bits／dot-product 有 549／393 次携带已发布 cursor 的入口路由；全程序实际接续为 2,098／1,835 次。

## 父行质量与验证成本

| 实际计数 | sum-bits | dot-product |
| --- | ---: | ---: |
| 完整键锚点义务 | 27,411 | 25,063 |
| 提出父引用 | 17,741 | 18,147 |
| 经精确检查为正确父行 | 11,232 | 9,971 |
| 错父引用 | 6,509 | 8,176 |
| 模型弃权 | 9,670 | 6,916 |
| 补查次数（弃权加错指） | 16,179 | 15,092 |
| 本组最终产生的 RHS 绑定 | 889 | 952 |
| 由正确提案直接提供 | 680 | 563 |
| 因错指而由补查找回 | 209 | 389 |
| 因弃权而由补查找回 | 0 | 0 |

每个锚点都会选父或弃权，其中很多锚点在本次水位下没有有效 RHS。按全部提案计，错父比例为 36.7%／45.1%；按实际需要的 RHS 计，模型独立提供了 76.5%／59.1%。弃权次数本身不能衡量漏掉了多少个有效绑定。独立审计构建对全部 17,741／18,147 个提案额外读取精确索引，逐项核对物理见证身份，审计行不用于执行。强制模型对所有锚点弃权时，补查找回 889／952 个绑定，所有有序轨迹与终图仍一致。

| 完整 Pass 3，中位数 ms | sum-bits 推理 | 新进程 CLI | dot-product 推理 | 新进程 CLI |
| --- | ---: | ---: | ---: | ---: |
| 原 Cell CPU | 22.36 | 132.98 | 19.18 | 134.79 |
| CPU 直接点查同一组完整键 | 25.39 | 135.28 | 22.16 | 135.50 |
| 常驻端口模型，验证并补查 | 112.15 | 258.44 | 123.24 | 274.43 |
| 现有 Metal 搜索，同一组规则 | 91.61 | 243.69 | 83.52 | 232.35 |

每臂一次预热、八个轮换的新进程。整轮推理计入端口首次建立、增量上传、模型调用、CPU 验证、补查和正常引擎的其余工作。CLI 另包含进程启动、加载计划、建立 Metal 管线、最终导出和退出。直接点查臂也在相同的源 Run 下枚举锚点并重接原 cursor。原 CPU 对照保留共享入口和原有增量规划，两者衡量的整轮工作不同。

| 五次独立细粒度运行，中位数 ms | sum-bits | dot-product |
| --- | ---: | ---: |
| 直接点查臂，全部目标索引读取 | 1.31 | 1.11 |
| 模型臂，端口维护与准备 | 1.33 | 1.08 |
| 模型臂，设备前向、命令提交、等待及取回 | 85.93 | 84.26 |
| 其中 command buffer 的设备执行区间 | 37.90 | 39.25 |
| CPU 提案解析与父行完整键验证 | 1.94 | 1.84 |
| CPU 失败或弃权后的精确补查 | 0.54 | 0.55 |

逐查计时仅在独立诊断运行开启。验证列含每个锚点的提案解析；输出槽绑定、增量合法性检查、Spine 来源选择和有序提交计在整轮时间中。端口 bank 首次上传 259／393 行，随后增量更新 2,153／1,970 行。网络仍覆盖约 276 万／363 万个锚点与目标位置组合（包含退役槽，内核会跳过不可见行）。已验证的父引用节省了 41.0%／39.8% 的索引读取；本机上全部这些读取原本也仅耗时约一毫秒。两个负载都应保留直接索引和原 CPU 调度。

## 复验

sum-bits 的 1,428 次 Run 与 dot-product 的 1,535 次 Run 逐项核对规则集、路径、迭代、变化标志、RHS 数及有序输入摘要、有效写入和 Spine 接续。所有实验臂最终导出与独立 CPU 对照逐字节相同。两份原生源程序的既有语义验收也均通过。[逐项结果](results.json)

```sh
verified=/Volumes/EggFuseWorkspace/experiments/pass3-atlas-integration-20261120
~/.local/bin/eggfuse-job submit --kind compute -- /Volumes/EggFuseWorkspace/bin/run-eggfuse python benchmarks/pass3-cell-gpu/unique-parent/bench.py "$verified" /Volumes/EggFuseWorkspace/experiments/NEW-unique-parent
```

单跑推理可使用 Cargo，替换模式为 `point` 或 `metal` 时省去权重参数。

```sh
cargo run --release --locked -p eggfuse-cell-runtime --features gpu-bindings -- --program "$verified/sum-bits/program.json" --output /tmp/eggfuse-parent-trial --unique-parent model --parent-weights benchmarks/pass3-cell-gpu/unique-parent/weights.json
```
