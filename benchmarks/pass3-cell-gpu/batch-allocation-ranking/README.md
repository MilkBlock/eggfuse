# Predict private Cell placement for a whole proposal wave

A frozen model first issues typed proposals. A learned count policy reserves physical headers per (Run, rule). An additional PyTorch-trained head then sees *all* issued lanes in each contested group and assigns the same fixed number of headers to specific proposals. Every choice finishes before the first exact validation of that wave. The learned action changes which private physical object the eventual winner can publish. The original schedule determines writes, merges and the order in which Cells become visible. No labels or hindsight enter the online allocation.

**Training.** Three separate source programs (sum-bits, dot-product, jacobi-1d) yielded 114,021 proposed lanes and 43,618 actual primary Cell births, including outcomes of unstaged lanes. 2,220 groups had a positive grant below their lane count. Twelve quantized inputs describe the issued page, relative lane position, parent ages, repetitions, frequencies and query width. Labels and count budgets are extracted with capture.py. The native feature and top-K definitions are in the sibling lane-rank-issuer directory. CPU inference consumes exported weights directly.

We compare per-lane weighted binary cross entropy with expected fresh physical births under each actual quota. For the latter, a group-specific threshold makes the sum of inclusion probabilities equal to K, with repeated inputs counted at their observed frequency. The loss uses the derivative of that constrained group return, including the effect of shifting the threshold. check_gradient.py compares it with independent finite differences. This is a one-decision reward surrogate. Deployment uses deterministic top-K with source-order ties. The auxiliary head has 13 parameters (linear) or 113 (one hidden layer of eight tanh units). Both seeds train from scratch for 140 steps. Complete issuer and verifier costs are included.

Of 97,293 and 232,796 physical grants on CG and 3mm respectively, 72,960 and 172,547 could be attached to distinct issued lanes. A rule can receive more grants than it ultimately issues proposals. Actual fresh primary demand totaled 96,535 and 228,095. With the same physical budgets, exact hindsight *within each rule* gives 59,752 and 137,864 hits. The earlier group-authorization executor reached these counts online by letting the first authenticated winners share the grant. The selection head performs 235,993 and 872,592 individual score evaluations at the contested quotas. More exact placements do not pay for this extra scoring on these two programs.

On CG with seed 1709, first K yielded 36,608 hits, eight hidden units with BCE 41,307, and the quota-trained head 36,703. Inference took 618.79, 676.46 and 657.27 ms respectively. Both donor-trained heads can use structure available before validation, but the additional gains from the quota objective at seed 1703 do not transfer consistently across seeds. No 3mm timing is reported for 1709.

**Independent bounds.** ceilings.py consumes a separately captured held-out stream after freezing the policy. It calculates the lower and upper hit counts consistent with all equal-score ties, and an expectation for random tie order. It also pools the observed grant of each rule with issued lanes within the same epoch to measure additional headroom from changing the allocation unit. Aggregating only rule groups that issued at least one lane gives 81,603 grants on CG and 193,729 on 3mm. If their storage were fungible within each Run, the respective ceilings would increase from 59,752 to 68,637 and from 137,864 to 158,785. These counts exclude grants to groups with no issued lanes. They assume compatible header/payload layouts and do not authorize cross-rule publication. This hindsight diagnostic cannot choose actions online. The uncompressed grouped input can be regenerated by capture.py from the same native emitter. The digest identifies its exact capture. verify.py checks that all native top-K outcomes lie inside the corresponding interval and audits exact semantics across every timed arm.

Reproduction uses the external experiment root EXP, the native session built by ../lane-rank-issuer/build.py, and Python with PyTorch for training. All output directories must be fresh. The tracked donor histograms suffice to retrain the frozen models.

```sh
python train.py donors /tmp/rank-policy.json
python check_gradient.py
python study.py "$EXP" "$NATIVE" /tmp/rank-policy.json "$EXP/new-rank-test"
python study.py "$EXP" "$NATIVE" /tmp/rank-policy.json "$EXP/new-rank-seed1709" --seed 1709 --cases conjugate-gradient --arms bce-0 quota-0 bce-8 quota-8
python capture.py "$EXP" "$NATIVE" "$EXP/new-held-out-groups" --cases conjugate-gradient 3mm
python ceilings.py "$EXP/new-held-out-groups" /tmp/rank-policy.json /tmp/ceilings.json
python verify.py
```
