# 哪些样本能让模型认出 union 后仍须通知的外部读者？

真实训练轨迹显著减少了模型原始提案中的边界漏报。训练预算内加入成对反例，更常使模型在外部读者发生变化时翻转动作。两种真实数据训练出的策略在原负载上实际省掉的 repair 几乎相同；确定性的结果端口检查也拿到了这些收益。

## 同一幅 CPU 图上的实际工作

源前端在 CPU 上用冻结的 PyTorch forest 生成器发射证书。Rust Cell 执行器消费这批真实 token，由精确余项搜索完成其他绑定。在真正的 union 通知阶段，以被位移等价类的反向读者集合为候选。每个已缓存的标量构造器事实对应一个 Cell 和一个操作位置。两层网络在 Rust 内选择是否提议“只替换结果端口”，以及外部义务是否仍需保留。这里的外部依赖指其他 Cell 的事实或函数记录。

Rust 从排好序的反向依赖集端点核对外部边界。若网络声称无外部依赖却发现其他读者，这项提案退回普通路径。结果端口验证还检查实际 losing class、所有等价类型的输入键列、已有待办，以及唯一 hash 桶中的准确源身份。仅在通过后才原地更新结果、epoch、版本与变更通知，省去该事实的普通 dirty 入队与后续按序修复。其余读者按原序接收通知。普通路径仍负责同键冲突、函数和容器。在固定的合成、真实和配对训练轨迹上，原始模型输出与 native Rust MLP 的逐事件离散选择一致。[原生选择与验证](trial.rs)

常驻计时先就绪同一程序的全新初图，再执行 CPU 神经 forest 前向、传送密封字、native Rust 验证、完整源调度、在线 repair 模型和最终同步回复。每臂 18 个样本轮换顺序，编译、初图重建和最终图导出另计。六个程序还包括两个独立开发家族。每次计时核对全部源 forest 归因及最终图 SHA，每个审计臂另对照独立原版的逐 Run RHS、有效写入、Spine 接续、完整 union 顺序和导出图。跨臂比对了所有反向读者的源地址和分发顺序，区分走本地更新与进入普通队列。捕获和审计只读取运行过程，在线路径不读取未来标签。

额外的反事实固定计算设备和整个源 forest，只把“结果等于 losing class”编译成廉价前置检查。四个程序中，这条检查与总是尝试验证的路径得到完全相同的通过数，分别为 878、461、1,710、948。独立配对的整轮计时在不同程序上有升有降；模型没有稳定的净速度优势。[二次配对与全部样本](result-gate.json)

## 训练集与反例

先固定四个训练、两个开发、两个留出程序家族，另加 sum-bits 和 dot-product 两个锚点。用 typed LHS 和 effect 序列的 SHA-256 确定整个模板族，预留约五分之一的结构族。先从训练来源移除预留族，再根据同一 losing class 上的完整生产者结果和读者键列做 co-repair Bake。58 个候选三元组至少在两个训练家族中出现，保留八个描述符供模型识别其所涉表。此处使用 native Cell 实例和真实反向依赖。先前 Metal 订阅组实验与这里的性能样本分别计量。

合成语料从构造器字段、来源类、owner、开放读者与待办状态生成标签。真实语料使用四个训练程序的原始 union 观察。配对语料在完全相同的 2,400 行预算内用 600 对“原始、单项修改”替换半数普通观测，外部读者、额外同 hash 桶成员和已有 dirty 义务各 200 对。额外 hash 桶成员只表示需保留精确碰撞检查；是否真的同键需由图决定。所有模型使用相同的 12→12→2 结构、400 次更新、64 个样本每批、相同初始种子与推理阈值。[训练定义](train.py) · [家族划分和预算](training.json) · [源轨迹捕获](capture.json)

完整结果另按未见模板族、训练集第 90 百分位以上的高工作量候选、单层或多层历史 union 链分列。高工作量切点来自事实宽度乘以 union 的反向集合大小。链长指从真实 losing→kept 链构造的等价合并历史树高度，与物理 Cell 的 parent 链分开。该版本在这批候选上物理 parent 深度均为零。GEMM 种子 1703 的 755 个留出模板族候选中，可免字段权重 709，三个策略分别取得 697、709、709。

另外实际编译了三份小程序。第一份只合并两个 Atom。第二份只多创建一个外部 Single 读取 losing Atom；第一个候选保持 Cell 4、操作 2、模板 3，外部义务由 0 变为 1。故意声称没有外部的策略在第一份通过，但在第二份被拒绝。两个真实训练策略在这个冷例上也漏报了外部读者，Rust 仍交付两个应通知地址。第三份在 kept Atom 上多建一个同键 peer，原样发生一次实际冲突退役和随后的第二次 union。源序、通知和终图在各臂均一致。在真实 Pass 3 另复用前一条实际 union 的票据，旧 union 序号或端口不匹配的证书均不能发布。[源反例和诊断](counterexamples.json)

## 复现

构建脚本从固定 Git 修订提取两个本地 crate，只在独立实验目录的副本中挂接图的通知入口。PyTorch 用于离线训练 repair 策略。每个在线 repair 策略由 Rust 在原生 Cell 实例上执行。CPU forest 使用同一冻结的 1703 权重贯穿全部实验。

~~~sh
d=benchmarks/pass3-cell-gpu/repair-training
e="$EGGFUSE_ARTIFACT_ROOT"
out="$e/NEW-repair-study"
families="$e/repair-bake-families-20261120"
ref="$e/pass3-atlas-integration-20261120"
forest="$e/whole-pass-generation-20261120/policy-1703.pt"
python "$d/build.py" "$out/native"
python "$d/harness.py" "$families" "$ref" "$forest" "$out/native/session" "$out/capture"
python "$d/train.py" "$out/capture" "$out/weights"
python "$d/evaluate.py" "$families" "$ref" "$forest" "$out/capture" "$out/weights" "$out/native/session" "$out/paired"
python "$d/evaluate.py" "$families" "$ref" "$forest" "$out/capture" "$out/weights" "$out/native/session" "$out/gate" --gate --cases sum-bits dot-product gemm-bias-relu stable-argmax
python "$d/boundaries.py" "$CARGO_TARGET_DIR/release/eggfuse-cell-compiler" "$e/native-forest-20261120/runtime" "$out/native/session" "$out/weights" "$out/boundaries"
~~~
