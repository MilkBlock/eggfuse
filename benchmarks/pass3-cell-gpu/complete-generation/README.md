# Visible generation limits and complete multi-parent pages

Deriche exposed a completeness error in the standalone research Cell CPU: a per-rule pointer expansion budget could leave a branch unexplored while the no-residual executor continued with its current list. The old bounded one-view path lost 3,120 source bindings on Run 819. The exact same source program, the old three-view weights and the narrower frozen two-view route can avoid that loss under different exploration costs. Hitting a numerical counter is not sufficient evidence of omission; source comparison and an attempted further branch are separate observations.

The joint session now distinguishes bounded and complete multi-parent generation. Preserving a finite limit with no residual returns an incomplete-execution error if another branch was left unexplored. Its status identifies source Run, rule, limit and number of attempts. An older request with no generation-mode field uses its existing finite limit and receives the same protection. A certified newly prepared request explicitly asks for complete enumeration and does not use the diagnostic pointer budget to discard branches. This removes quota-related truncation; other policy or semantic errors must still pass independent source conformance.

The paged research variant can also close a reference buffer every N complete tuples while the graph and learned decisions remain frozen. All the resulting pages are issued in the original order before the first exact check. The limit applies to the size of one page; it does not bound the sum of all live pages. No independent parent is generated by a verifier and an incomplete run cannot export a successful final graph.

Deriche issued 35,780,746 raw single-view tuples in 6,993 pages; the largest contained 7,192,696 tuples. Segmentation at 8,192 tuples produced 10,943 pages with identical raw and physical identities. The two-view forward filters reduced issuance to 574,416 tuples and all three correct neural arms recovered 635,818/635,818 RHS and 450,414/452,913 direct fresh Cells. The full checks include every ordered RHS, effective write, Spine resume, union, schedule and final graph against the independent unmodified Rust executor. The tiny source fixture makes the distinction explicit. With one Left and one matching Right, budget one is reached and the original one RHS is complete. Adding a second Right leaves a real pending branch at the same budget; the bounded path reports it, while complete generation returns both joins. The one-shot compiled-bundle check also verifies hot-path accounting without historical JSON. The old reporting code showed 4,588 learned RHS when winner archiving was off and 7,265 when it was enabled, with identical final graphs.
