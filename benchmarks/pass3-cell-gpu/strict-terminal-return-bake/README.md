# Select static consumers by the typed nodes that survive internal execution

Each donor sample is a real verified invocation of a consumer whose static parent template was signed before the actual constructor output existed. It receives exactly that output at the original Run. Dot-product and Jacobi supply all selection data. No post-hoc graph relation can introduce another parent. Three alternatives rank consumer schemas by removed child packets, by directly typed final-visible constructor origins produced inside the child, or by those typed origins plus runtime dynamic ones. A nested constructor whose merge has a separate selected child is excluded from both node rewards. The compiler relinks the selected consumer types to statically checked concrete producer instructions in each held-out program. Top-one and top-two limit the number of consumer schemas; the number of linked producer edges can differ substantially. All activations, signed costs and source physical parents are rechecked in native execution.

On 3mm under strict partial coverage with scalar guards, top-one packet reward selected 12 producer edges, saved 4,058 packets and brought **two** typed final-visible nodes into internal instructions. Top-one terminal reward selected 943 eligible edges, saved 1,555 packets and brought **1,611** such nodes inside. Top-two packet reward saved 8,195 packets for 7 typed visible nodes; top-two terminal reward saved 2,050 for **2,663**. Their global FEPTs were 0.168506 and 0.166644 with identical final graph and 92,658 eligible origins. The learned static rule selector improves which nodes are actually produced within a single root's template. Its terminal-reward ranking does not maximize the overall ratio at fixed source semantics. It also has more potential producer ports to maintain. There is no evidence for a large whole-graph FEPT gain here.

The plain whole-bank control illustrates the role of coverage. Its productive donor favorite failed to activate on sum-bits and 3mm; their numbers stayed at leaf. Held-out Deriche had nine credited typed origins under top-one terminal reward, compared to two under top-one packet reward. Partial disjoint release enables productive consumers previously masked by this completeness restriction. This is data-directed offline Bake; root neural weights were fixed. No root/child instance selection used held-out state or future rows.

whole-policy/partial-policy/guards-policy contain the actual frozen donor labels and schema ranks. Whole / transfer / partial / guards archives contain paired executions on the correspondingly named configurations. Identical native configurations are run once and marked in the table. To reproduce use bake.py EXP NATIVE OUT (optional --partial or --partial --guards), then study.py EXP NATIVE OUT/policy.json NEW_OUT. Whole uses the filtered-explicit-parent links build, partial the strict-partial-named-ports build and guards the strict-guarded-return build.
