# 已执行 Cell 的 Token Embedding 审计

以 157c323f 的 CellKV-C 为现有表示。**GNN 结构码确实进入了已执行 Cell 的 Key 和 Value。** 在原生 Higher 的末端端口上反传一枚下游 Primitive 的完整 CE，已经退出当前模板菜单的生产者 Higher 仍收到梯度。不过，在严格相同的输入和输出契约下，四种 embedding 都没有学会随入口数据可靠切换 Higher 的内部 guard。本报告给出这两个结论各自的证据。[逐张量记录](trace.json) · [成对模板概率](prob.json)

## 从原生具名回执到下一枚 Token

1. Recipe 读入 structural 模式的 OpaqueParentActor。静态语义因子通过共享的 61×32 embedding 求和进入节点。两轮信息传递在边上旋转消息以标记角色，再按入度归约。可学习更新为 `h' = tanh(h + W_update(mean(R_role W_msg h_src)) + b)`。CellKV 调用这个 Actor 的图编码，随后走自己的 KV 路径。[静态节点](../../semantic_catalog.py) · [两轮 GNN](../../actor.py) · [KV 入口](../../cell_kv_model.py)
2. GraphBank 为每个步骤编码根规则、局部参数共享和阶段位置，为每根连线编码生产操作、输出槽和消费角色。对步骤 j，`h_j = tanh(W_step s_j + b_step + Σ tanh(W_edge e + b_edge + W_msg h_parent) / sqrt(max(1,fan_j)))`；空的外部父状态为零，边仍保留外部角色。模板码 `c = Σ h_j / sqrt(length)`。Primitive 是一个步骤，Higher 是多个步骤。两者为了减少内存 padding 而分批，使用完全相同的矩阵，拼成同一个模板张量，没有模板 ID 查表。sum/sqrt(length) 仍是有损读出。权重冻结后按程序缓存静态张量，训练时每次更新重建可导图。[具名图与读出](../../ripsat_policy.py)
3. 根请求接受后登记逻辑 owner、模板及本次选择的真实父引用。只有原生发布后，端口才进入可寻址 Memory。Higher 将根和末步公开端口归给同一 owner，中间步骤使用实际具名接线、版本钉住和原生回执继续执行。端口快照保留物理 (uid,op,version)、逻辑 owner、生产模板、表、字段哈希、forwarded、原入口引用。地址用于提取指定数据与最终签发，无数值地址 embedding。[实例与可见性](../../cell_kv_runtime.py)
4. 对公开端口 p，令 `v_p = tanh(type_p + W_dynamic φ(fields_p) + W_age [log1p(epoch-version)/8, forwarded])`。φ 的第 i 个分量读取第 j 字段哈希的第 (i+7j) mod 64 位，转为 ±1，除以 (1+j) 并跨字段求和，共 32 个分量。实际输入进来的是运行时公开字段哈希。对已生成 owner，`u = tanh(c_producer + mean(v_public) + mean(v_visible_inputs))`。实现对每个公开端口计算入口引用的均值再跨端口平均；一个 owner 各端口携带同一份入口引用。只读取仍可按精确版本解析的父引用；零命中贡献零。初始事实用表类型码代替生产模板码。最后 `K=W_input_content u`，`V=W_latent u`。当前 C 还向同一注意力暴露各端口的 `W_input_content v_p` 及端口值。[端口特征、整体 KV 和公共端口读出](../../cell_kv_model.py)
5. 最近回执的接受、更新、退役数量及 Run、epoch 进入全局 Query。原实现不在 owner Key 中显式编码 Draft、在途请求、完成标志、阻塞原因或已不可见父端口的历史值。解码器通过全域 owner 注意力、owner 内端口及后续具名引用生成完整 Token。训练累加所选模板及各父引用的负 log 概率。整数索引、地址抽样、CPU 接受、发布和实际运算都在反传范围之外。[state、address、token_loss、generate](../../cell_kv_model.py)

## 当前整体 Key 丢失了什么

- 在一次自由运行中捕获了真正发布的双父 Primitive，然后离线改变其输入。在原有表示中交换两个不同且均可读的父引用，K、V 的 L2 变化都严格为零。去掉一个父引用时分别改变 1.406、0.754。修改公开输出哈希的低位使 K 改变 0.673，切换 forwarded 使 K 改变 0.343。保持行内容不动仅改公开 op 编号，原有 K 和端口 Key 均不变。角色化接口版本交换父顺序时 K 改变 0.125；改变 op 标签时整体 K 仍不变，但可独立读取的端口 Key 改变 0.839。这些是信息流干预，修改后的记录不算作原生合法轨迹。[实例与干预](interventions.json)
- 对同一快照内同模板不同实例的配对，现有表示的平均 Key 距离是 0.915，只保留结构时严格为零。能区分实例的主要来源是实际可见行和已选父引用的内容。仅替换真实物理地址、同步重命名所有具名引用并倒转端口存储顺序，四组概率最大绝对变化低于 2×10⁻⁷。[实例配对](instances.json) · [重命名](prob.json)
- 32 维字段压缩确有碰撞。单字段 21 和 21+2⁴⁵ 得到完全相同的 φ。**这并不能解释本次单输出 Seed 上的 guard 失败。** 对这批三字段 Seed，已知正确 owner、类型、版本后，在双精度下逆解现有 Key 投影、tanh 与动态投影，再从每个分量的八个可能带符号和中读出前两字段重叠的 25 位。18 个原生入口 × 两个权重共 36 次，原始哈希、φ、由最终 K 恢复的位关系均与原生 guard 方向相符。最大行向量重建误差 0.0189。25 个重叠位对更广输入不构成精确相等证明。该诊断使用已知正确行及静态上下文，从未用于生成、选择、过滤或计时。[离线实现](../../token_embedding_guard_probe.py) · [全部观察](guard-probe.json)

## 只训练 embedding

四组都从同一份历史 C-joint-71-360 权重开始。共同运行 C 的 dense owner/port Attention 和结构化 Decoder，训练时冻结 K、V、Query、GRU、模板投影、lane 及其他既有模块。可训练部分仅有 Recipe GNN 4,032、布局 GNN 3,136、动态投影 1,024、年龄投影 64，共 8,256 个。结构组的动态参数在该前向中无有效路径。共享的静态 GNN 会同时改变目录侧及已执行实例侧的结构码；另有仅干预 owner、不动目录的读出实验。所有训练前后冻结参数逐字节 SHA-256 相同。[表示实现](../../token_embedding.py) · [权重清单及曝光](manifest.json)

| 组别 | owner 表示 | 同一 Attention 能读到的端口表示 |
|---|---|---|
| 现有 | 生产模板、公开输出均值、可见父输入均值 | 各端口原有动态向量 |
| 仅 GNN 结构 | 生产模板码，初始事实为表类型码 | 复制该 owner 的结构码 |
| 结构加动态实例 | 与现有相同的整体表示 | 复制该 owner 的整体表示 |
| 保留外部接口 | 用 Recipe 输入角色和位置旋转编码每个可见父引用，再与结构、公开行合成 | 每个真实公开端口独立保留其行、生产模板、入口上下文和具名输出操作的 GNN 节点 |

各组公开端口、地址域、张量宽度与解码器完全相同。复制整体向量的两组仍可见有几个公开槽，但没有各槽独立的内容。现有组在真实快照上与改动前读出的 K、V、上下文、模板概率及端口 Key 逐元素相同。没有新投影或辅助分类器。现有表示在两次训练中，Recipe GNN、布局 GNN、动态投影、年龄投影的平均裁剪前梯度 L2 分别为 1.087、0.404、3.114、0.0298，参数位移分别为 1.490、1.474、0.735、0.492。所有冻结模块位移为零。[梯度、参数量和位移](gradients.csv)

语料来自 18 个完整小型程序，原生重放得到 144 条状态记录、126 个不同程序内状态、336 个不同状态与目标配对。每个配置 360 次 AdamW 更新、2,160 枚完整 Token 曝光；两种训练采样种子，配平样本顺序；先用 1/2 个任务，再混合 1/2/4 个任务。监督是经原生核验的完整 Token CE。两种 Higher 的入口均为 Seed，公开根均为 Mid，末端均发布同一张 Common 表、相同 op 和类型；一个分支需要 x=y 且执行加法，另一个需要 x≠y 且执行减法。后续同一个 Primitive 读取 Common 和 Permit。之前对照的左右末端表名不同，本次移除了这条线索。

训练冻结后对八个程序 Bake 7 或 9 步 Higher，包括留出的内部汇合和反转入口条件的成对程序。规范化 Higher 签名均与本轮和直接初始化检查点所用 CellKV 训练目录不相交；两侧本体属于同一个规则家族，未独立审计最早期通用 Actor 的全部历史语料。正式生成面向当前原生调度窗口的目录与全部公开 Memory，每窗口六槽，固定退出，内部请求逐步提交、按实际版本确认并原价计费。Teacher、guard 探针和正确模板提示均在独立分叉运行。CPU 不按值或 guard 选候选。训练和在线神经推理用单线程 PyTorch CPU。[训练与原生评估](../../token_embedding_study.py) · [布局契约及签名](layouts.json)

| 仅 GNN 结构 | 49.74% | 0.1286 | 358.5 | 106 → 44 → 22 | 16 |

每组 8 程序 × 2 训练种子 × 2 地址/生成种子，32 条轨迹；每条正反序两次计时，核对事实集合、图摘要、请求计数和有效操作数相同。表中 Coverage、EPT、EPS 为轨迹等权平均；事件计数只取一次。Coverage 为参考非初始事实的不同事实召回，EPT 为原生有效原子操作/实际付费请求，EPS 含程序静态编码、神经生成、内部接续、通信、执行及发布。相同终图比较中，结构化接口与现有组有 9/32 对完全相同，平均 EPT 差为零，墙钟比中位数 1.049。其余轨迹终图不同。原有表示同分布训练前为 45.42% Coverage、0.1081 EPT；追加训练后两个种子的 Coverage 分别为 50.63%、60.94%。这是小型原生 CCP 工作负载，未测开放 EggCC 的性能。[逐轨迹事实与回执](native.json) · [训练前对照](before-native.json) · [配对离散度](summary.csv) · [同终图子集](matched.csv)

在只有一个合法入口的成对程序上，给定正确 Higher 后的绑定概率，四组分别为 **96.36%、99.29%、95.24%、96.88%**。允许完整目录后，正确 Higher 加正确引用的概率降至 **20.83%、24.52%、19.29%、21.82%**；只在正确与错误 Higher 之间归一化，每组给正确分支的平均概率均在 **49.97%–50.01%** 内。各组都是 8 次比较中 4 次把正确分支排在前面。现有表示的两个结构码平均 L2 距离 0.379，单实例正确分支概率仅在 49.30%–50.61% 间。两种结构得到不同向量，生成器对哪一个应当在此刻执行仍缺少有效区分。[原始模板、条件绑定及完整 Token 概率](prob.json)

在已执行 Higher 的真实下游状态，保持值、接口、菜单和解码器不动，仅替换该实例的生产者结构码。原有表示中下一枚正确完整 Token 的平均概率从 0.28438 变为 0.23905（替换为根 Primitive），或 0.28400（替换为另一个同接口 Higher）。相同接口也意味着两侧发布 Common 后，正确下游操作相同。这个结果显示下游读取对抽象粒度敏感，却不能充当两个分支在入口处可区分的证据。[生产者干预](owner.json)

**结论。** 在这批入口，已训练的整体 Key 仍能携带区分两个 Higher 所需的数据，选定模板后的绑定也可靠。主要可观察的缺口是从当前实例和两个候选程序共同读出适用的内部语义。原有均值同时有可复现的输入角色和输出槽身份损失；修复这些身份没有带来更好的独立前沿。本次证据不足以启动稀疏化，也无法在冻结的读出和现有 CE 语料之间进一步分摊原因。

## 复现和校验

在 instruction_pointer 目录使用已有 cell-kv-fullread 检查点和 partner_index_reproduce.sh 所需的 ARTIFACT_ROOT、CELL_DATA、CELL_COMPILER、CELL_REPLAY、PYTHON 环境变量。把 PARTNER_INDEX_OUT 指向新目录，然后执行：

```sh
sh token_embedding_reproduce.sh
"$PYTHON" -m unittest test_cell_kv test_token_embedding
```

实验盘 token-embedding 目录保存原生程序、语料、八个权重和 Cargo 校验日志。Git 保存实验源、原始测量与哈希。旧实验保持原默认接口。八个局部回归测试通过；仓库规定的 sum-bits Cargo compile/run/bench 成功，基于已有导出的 choice_diagnosis 原生语义合同返回 pass。该合同检验与上述小程序的逐轨迹原生验收分别运行。
