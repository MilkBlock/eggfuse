# 接口角色、字段存储顺序与自主 Cell 生成

把字段的声明身份与物理位置一起移动后，模型在两个未见排列中保留了完整 Token 分布。在相同入口上改写 Recipe 接线，模型也能改变选择。换成新接口声明，软读取仍会找错字段。进入多个 owner 的原生环境，单入口训练的 C 只有 9.85% Coverage；同预算使用混合入口轨迹训练后达到 31.06%。

## 模型与计算边界

基线为 46b72e6d 的 Operand Attention D。三个组冻结同一 GNN、Token Embedding 和整体 Cell KV，复用同一 actor 的 8,576 个可训练参数、完整 Token CE 和固定退出策略。种子 71、113。A 复用已训练检查点；B 和 C 使用相同随机布局流、2,048 个已有原生程序和原训练预算。每个种子 1,680 次更新，前 420 次为单 Recipe 课程，每次 34 枚目标，合计 57,120 次曝光。

| 组别 | 字段如何进入操作数读取 |
|---|---|
| A | 上轮 D 的局部 GNN 操作数 Query，字段 Key 使用存储位置 |
| B | 与 A 相同，训练时置换字段，同一端口保留所有值 |
| C | 与 B 相同的字段和值，Query 额外读取 Recipe 声明的入口表与列身份；Key 随字段携带该表与列角色 |
| C-hard | 离线单入口对照，直接读取静态操作数列，复用 C 的 Value、关系算子及解码器 |

物理置换发生在公开端口的神经字段张量上。各组读取同一原生回执和同一套整体 KV。Rust 存储格式不属于本实验变量。新五列声明中移动实际被使用的列是另一项更难的测试。角色在本轮以表及其声明列标识；跨声明复用仍有待解决。

C 沿已有 Recipe 单表输入、确定的拷贝/构造和已接线的具名 effect 输出，追踪第一个可定位的二元条件操作数。不能追溯时使用未知列角色。它给出要读哪些列的静态提示。所有候选 owner、端口、模板继续由网络读取、选择并向 CCP v0.1 签发。线上没有字段值比较、guard 求值、合法 Higher 掩码或伙伴搜索。Higher 内部的实际计算由原生执行器逐步核验。测试覆盖具名 op 与 effect 指令编号不相同及来源未知的情况。

每个操作数的 32 维 Query 由原操作数 GNN 表示、上下文、共享投影和静态角色残差组成。每个字段的 Key 是表限定列角色加可训练投影，64 维 Value 是该字段位表示加可训练残差。两个读出的 Value 做逐通道乘积、折叠及共享可训练投影，送回现有读出与完整 Token 解码器。字段权重形状为 [端口, 模板, 操作数, 字段]。固定宽度下每端口每模板成本为 O(mF)，此次 m=2。新增 Recipe 只需处理自己的静态契约。[实现](../../interface_role_model.py)

## 分开检验物理不变性和语义敏感性

原有 64 对接线冲突样本固定入口，交换 x=y 与 x=z 两种计算。只有两边都将各自正确的 Higher 排在前面才计为一次成功。表中使用同一个完全留出的物理反序，每格依次列出两个种子。另一留出排列及规范顺序均有独立记录。

| 排序翻转 | A | B | C |
|---|---:|---:|---:|
| 原 64 对，规范顺序 | 64、64 | 18、32 | 64、64 |
| 原 64 对，留出反序 | 8、28 | 0、0 | 64、64 |
| 新接线 y=z，48 对未见输入 | 0、0 | 2、0 | 48、48 |

冻结后重新 Bake 的六步 Higher，以及增加无关列但保留操作数声明列的接口，C 均为 48/48、48/48。将操作数移到新五列声明的其他位置，C 降到 18/48、24/48；正确列的平均注意力降至 70.2%。同一批状态使用 C-hard 后恢复到 48/48、48/48，正确完整 Token 平均概率从 53.7% 升至 78.8%。该差值把可恢复的一部分损失定位在字段读取。固定策略在未见输入值和新接线上表现不同，不能用单个平均准确率替代。[全布局概率与翻转](layout.csv)

对同一状态比较所有完整 Token 的联合概率，C 在两个留出物理排列上的最大总变差低于 0.000001。该性质来自带身份的集合读取。正确分支排序还需要训练与正确的静态信息：C 初始化时是 8/64，单 Recipe 阶段结束为 0/64，完整训练后为 64/64。冻结后删去静态列提示，两个种子均退到 0/64；互换两种接线的列提示，两边全部选反。GNN 操作数节点在干预中保留。[训练检查点](checkpoints.csv) · [读取干预](controls.csv)

## 原生固定退出与混合入口迁移

实际从完整 Memory 自由生成模板和具名引用。四个公开 owner 来自两种不同入口关系；各有两个 Higher 和一个根 Primitive，另有一个独立算术 Primitive。第一窗口有 7 个模板、10 枚经核验的不同有效具名 Token。参考终图包含 22 条目标关系行。每窗口 6 槽；两个生成与地址种子 193、827，以正反序配对计时，保存逐次事实和终图。Coverage 计参考行，EPT/EPS 的分子沿用 Runtime 签名的有效操作，分母分别是实际付费请求和包含神经生成与原生执行的墙钟。以下均为两训练种子均值。

| 训练和执行条件 | Coverage | EPT | EPS |
|---|---:|---:|---:|
| 熟悉接线，A | 84.38% | .1078 | 227.7 |
| 熟悉接线，B | 49.61% | .0627 | 137.5 |
| 熟悉接线，C | 100% | .1250 | 261.9 |
| 单入口训练 → 混合入口，A | 11.93% | .0676 | 130.4 |
| 单入口训练 → 混合入口，B | 18.75% | .1054 | 206.7 |
| 单入口训练 → 混合入口，C | 9.85% | .0584 | 106.4 |

熟悉接线时，C 与 A 终图相同的子集上，C 的墙钟中位比分别为 1.033、1.039。混合盲测 C 与 A 仅 2/24 对达到相同事实集合及终图。物理排列检验使用相同随机数，C 的 48/48 次混合配对均保留事实集合、终图、请求分类计数和有效操作数；A、B 保留相同终图各为 19/48、21/48。分类计数一致不保证每条请求轨迹一致。[原生指标与同终图配对](native.csv) · [物理重排独立执行](rollout-pairs.csv)

混合盲测中，C 首窗口对全部有效具名 Token 的概率质量约 35%；已经选择 Higher 时绑定有效引用的条件概率约 32%。每次执行平均 36.5 个付费请求，23.83 次类型拒绝。每个首窗口平均只生成 1 枚不同有效 Token。对概率域的穷举仅用于冻结状态诊断，匹配 Teacher 原生结果在策略执行之后进行。[首窗口概率分解](mixed.csv)

另做配平分叉以检验混合入口经验。两组从各自相同的 C 第 420 步检查点重建相同 AdamW，各继续 1,260 次更新，每次采样 17 枚根窗口目标及 17 枚后续窗口目标。每组 32 个原生程序。replay 来源为原单入口语料；mixed 使用 16 组新输入、两种接线和浅层混合 Higher。评估使用另外 3 组输入及冻结后 Bake 的较深混合 Higher，结构签名与混合训练 Higher 分离。两组均从完整初态独立执行。

| 训练分布 → 冻结后混合盲测 | Coverage，71 / 113 | EPT 均值 | EPS 均值 |
|---|---:|---:|---:|
| 单入口 replay | 10.23% / 9.47% | .0584 | 105.6 |
| 混合入口 mixed | 30.30% / 31.82% | .1755 | 304.2 |

每次执行完成的 Higher 从平均 .167 增至 .583，仍有约 21 次类型拒绝。在同一熟悉接线保留集上，Coverage 从两个种子的 100% 降为 89.84%、90.63%。这个对照识别的是训练分布的整体作用，入口数量、模板竞争和样本值一起变化。EPS 包含实际开销，两个不同 Coverage 的运行点不能用来宣称同终图加速。[迁移实验逐种子指标](transfer.csv)

## 复现

在 instruction_pointer 工作目录下复用上一轮 rich 原生语料、GNN/actor 初态及 operand-read 的 D 检查点。单线程 PyTorch CPU 推理，执行器为实际 CCP v0.1 Native Runtime。本轮结果适用于上述受控原生程序；真实 EggCC 开放负载和 Metal 性能有待检验。各组的静态角色先验、训练预算和核验口径如上。

```sh
# 设置 ARTIFACT_ROOT、CELL_DATA、CELL_COMPILER、CELL_REPLAY 和 PYTHON，详见上轮复现脚本
export PARTNER_INDEX_OUT="$ARTIFACT_ROOT/conditional-value"
sh interface_role_reproduce.sh
"$PYTHON" -m unittest test_interface_role test_operand_read test_value_read test_compatibility test_cell_kv test_token_embedding
```

逐状态概率、逐次原生执行、事实集合、终图、训练轨迹和权重位于 PARTNER_INDEX_OUT/interface-role。manifest 同时记录复用的 A 权重。一次只使用列而尚未限定表身份的开发试验保存在该目录的 column-only-pilot 子目录，未纳入正式结果。[原始数据与权重 SHA-256](manifest.json)
