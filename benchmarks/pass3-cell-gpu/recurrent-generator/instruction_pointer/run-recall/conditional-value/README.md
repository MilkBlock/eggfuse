# Recipe 与入口实例的条件计算选择

在原生 CCP v0.1 的小型完整程序上，同一 Recipe 的 Higher 选择可以随着未见输入可靠翻转。两个训练种子在追加的 128 对盲测中均翻对 128 对。最能说明局限的是另一组输入：当两种已训练的接线要求相反的选择时，结构化读取组给正确 Higher 的平均概率只有 0.501。当前证据支持固定接线上的关系学习，跨 Recipe 选择字段的能力仍有缺口。

## 读出、参数和梯度

每个菜单项都有一个冻结的 32 维 Recipe GNN 编码 c。真实发布的 owner 与外部端口分别有 32 维 Key 和 Value。对 T 个菜单项、O 个 owner、P 个公开端口，模板 Query 为 [T,32]，owner 权重为 [T,O]，端口打分为 [T,P]。先在 owner 内归一化端口权重，再在全部 owner 上归一化。单 owner 单端口时，无论 Query 如何变化，这两个权重都精确等于 1。全局上下文仍通过 Value 和原有 GRU 依赖实际实例。

| 组 | 相同打分出口之前的计算 |
|---|---|
| A | 原始模板分数为 Q(ctx + read) 与 R(c) 的内积除以 √32。单入口的 read 等于 owner Value 加 port Value。不同 Recipe 的最终内积仍可能不同。 |
| B | 将 read 替换为 read + GRU(read, tanh(R(c)))，复用现有 next_read、Q 和 R。候选 Recipe 现在可以非线性地调制实例 Value。 |
| C | 在 B 的 GRU 之前，用模板 Query 读取每个公开端口内部的字段关系，沿原有 owner 和 port 注意力权重汇总。打分出口与 B 相同。 |

C 的算子取每个端口已发布的 64 位字段哈希，包括原生关系见证。将各字段表示成带符号位向量，对同端口每个字段位置对逐位相乘，将上下两半平均成 32 维，以 Query 的 32 维 softmax 加权，再乘固定的字段位置对余弦编码并累加。因此相同哈希天然给出全正的位积，网络获得了很强的相似性先验。计算涵盖端口内的所有字段对，神经推理中没有跨 Cell 的字段配对。当前实现临时保留 [T,P,32] 接口读出和每个端口最多 F(F−1)/2 个字段对，收缩开销随 T、P 和字段对数增长。此实验没有测量大 Memory 或宽接口的规模性能。[实现](../../value_read_model.py) · [原有注意力与完整 Token 打分](../../cell_kv_model.py)

三组分别训练相同的 8,576 个既有参数，均从 token-embedding/current-71.pt 开始。GNN、实例 Embedding、Key/Value 权重冻结，冻结参数 SHA-256 在训练前后相同。最终打分、内部读取和下一次引用寻址复用投影，故共享参数会受到多个路径的梯度。以下是一个真实原生单入口状态上完整 Token CE 的梯度 L2 范数，种子 71，第 1,680 次更新。Value 的张量灵敏度通过离线开启 autograd 测量，训练中冻结的权重没有更新。[不同阶段及多 owner 梯度](gradients.json)

| 组 | 模板 Query | owner Key | owner Value | 端口 Key | 最终 Q 输出 | 共享 Q 权重 | R 权重 | GRU 输入权重 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|
| A | 0 | 0 | .1791 | 0 | .9023 | .6229 | .5510 | .1111 |
| B | 0 | 0 | .5013 | 0 | 1.1543 | .8247 | .7068 | .8441 |
| C | .0584 | 0 | .1366 | 0 | .4580 | .8050 | 5.1928 | .4180 |

三组中，单 owner 地址权重对模板 Query 的偏导均为零。C 的非零梯度来自端口内部读取。它说明完整 Token CE 能训练这条路径。下文的干预单独检验预测是否依赖该路径的候选特异性。

## 反事实、训练与执行

一个三字段 Seed 同时允许启动根 Primitive 和两种具有相同输入、相同最终输出接口的三步 Higher。Higher 内部分别处理相等与不等条件，并执行加法或减法。训练覆盖两种字段接线、两种 guard 极性和两种算术分配的全部八个组合。每个 Recipe 均使用相同的填充值池，每个池取两个互异整数的全部八种三字段排列。每个单字段值在两种目标分支等频出现。每对反事实只改变一个相关字段，核对其余原生状态、地址、epoch、端口版本和菜单一致。真值由原生执行和具名接线回放确定。训练与盲测具体整数交集为空。覆盖的数值关系只包括这类二值池构成的相等与不等，没有测试一般算术条件推理。[原生程序](../../value_read_world.py) · [配对核验](../../value_read_eval.py)

- 小语料每个 Recipe 有 6 个填充值池，共 384 个原生程序。主实验每个 Recipe 有 32 个池，共 2,048 个程序，两档使用相同的盲测池。每步 24 个 Higher 完整目标、8 个合法 Primitive 完整目标和 2 个来自后续原生状态的目标。
- 前 420 次更新训练同一个 Recipe，之后交替训练八个 Recipe，到第 1,680 次更新结束。每个模型累计 57,120 次完整目标曝光。训练种子为 71 和 113。单入口的批量训练与常规完整 Token CE 的数值和梯度有回归检验。各组使用同一损失、优化器、曝光预算和起点。[训练代码](../../value_read_train.py) · [每 60 步 CE 与冻结参数摘要](training.csv)
- 单 Recipe 主盲测有八个新池，32 对反事实。门槛要求两个种子各自双侧翻转率及正确 Higher 平均相对概率均达到 90%。过门后才 Bake 留出接线和更深结构。随后冻结全部模型，再用另外 32 个新池做 128 对数值盲测。该追加组只测预测，不用作训练、筛选或计时。[门槛结果](gate.json) · [Recipe 与规范化签名](layouts.json)
- 保留了早期探索批次 pilot 的失败及原始结果。该批次只在两个角点监督 Primitive。表中主结果使用八个角点等频的 rich 批次；small 与 rich 可配平比较。
- 正式执行从完整公开 Memory 和 Recipe 菜单自由生成，固定每窗口 6 个槽，使用相同退出策略，每次实际内部原子请求均计费。教师和字段真值只出现在离线标签与事后诊断中。原生 Runtime 负责执行、核验、发布和版本检查。测试中改变物理地址种子。PyTorch 在 CPU 单线程运行，未测试 Metal。

## 正确 Higher 随输入翻转了吗

只有成对两个状态都把各自正确的 Higher 排在另一 Higher 前面，才计一个正确翻转。表中两个训练种子使用相同的测试对。相对概率在两种 Higher 间归一化。完整 Token 概率的分母包含 Primitive 干扰，并乘以具名引用概率。单入口处正确绑定的条件概率为 1。[全部分种子结果](conditional.csv)

| 单 Recipe，第 420 步 | 主盲测正确对数，71 / 113 | 追加盲测正确对数，71 / 113 | 追加盲测相对概率 | 追加盲测完整 Token 概率 |
|---|---:|---:|---:|---:|
| A | 2 / 2，各 32 对 | 19 / 18，各 128 对 | .500 | .372 |
| B | 2 / 2 | 19 / 10 | .500 | .368 |
| C | 32 / 32 | 128 / 128 | .992 | .728 |

未经本轮训练的 C 在主盲测为 0/32，正确 Higher 平均相对概率 .497。仅用 6 个均衡训练池时 C 为 23/32 和 22/32。数值多样性对这个读出有实际影响。训练扩大到八个 Recipe 后，同一原始 Recipe 主盲测退至 18/32 和 20/32。

在新取的单 Recipe 干预状态上，第 420 步 C 的正确 Higher 平均相对概率约 .994。去掉字段读取变为 .500，交换相关字段和干扰字段的位置变为 .500，把字段对的位置编码取均值变为 .619，去掉新增 GRU 路径为 .697。将各 Higher 的字段读取 Query 改为同一个均值，或直接令各位权重均匀，仍约 .994。故固定关系表征及位置访问对本任务有作用，单 Recipe 成绩本身无法证明每个 Recipe 学会了自己的读取指令。[逐项干预](intervention.csv)

八个已见 Recipe 在未见数值上，C 两个种子均翻对 64/128 对。进一步固定输入，对比两条已训练的接线。若 x=y 与 x=z 对实际输入给出相同判断，C 在两个种子各 128 个状态全对，正确 Higher 平均概率 .995。若两种判断冲突，各 64/128，概率 .501。两种合法 Recipe 的静态签名均随接线改变；冻结 GNN 的第一条带 guard 的 Primitive 根向量距离却为零，整体 Higher 向量 L2 差为 .0125 至 .0263。固定入口时 owner Key 完全相同，两个 Higher 的相对 logit 随接线替换最多变化 .196。这将失败定位到所测 GNN 表示和模板读出之间；尚未分离二者各自的因果责任。[冲突分组](wiring-conditions.csv) · [同实例替换 Recipe](wiring-audit.json)

冻结后 Bake 五步 Higher，保留熟悉接线，C 在 16 对中两个种子各对 12 对，A、B 各为零。改用新接线 y=z 时，C 只有 4/16 和 0/16。加入 Noise 和其 Primitive 也破坏了 C 的可靠翻转。留出结构针对本轮训练目录去重，未审计所有历史预训练数据的结构重合。

## 原生独立执行

事实 Coverage 为实际产生的参考关系行比例。EPT 为原生有效操作除以付费请求数。EPS 使用同一有效操作分子以及原生 harness 的执行墙钟，包含在线推理、通信、原子请求和发布。每个计时状态使用两个生成种子 193、827，每次按正反次序配对重复，验证两个计时块的实际事实、终图、有效操作及请求计数均一致。表内为按运行取均值，再对训练种子等权平均。首个 Recipe 使用第 420 步模型，其余使用第 1,680 步。未对不同终图宣称等价加速。[分种子计时、同终图比例与离散度](execution.csv) · [原生计量代码](../../cell_kv_runtime.py)

| 场景 | A Coverage / EPT / EPS | B Coverage / EPT / EPS | C Coverage / EPT / EPS |
|---|---|---|---|
| 单 Recipe | 100% / .127 / 309.2 | 100% / .127 / 309.7 | 100% / .125 / 296.5 |
| 八个已见 Recipe，未见值 | 93.6% / .119 / 292.4 | 94.1% / .119 / 295.0 | 100% / .126 / 301.9 |
| 未见字段接线 | 96.1% / .122 / 261.7 | 94.7% / .120 / 258.8 | 81.2% / .103 / 211.0 |
| 已见接线，新增内部计算深度 | 88.5% / .119 / 298.6 | 87.1% / .117 / 289.6 | 97.7% / .133 / 310.3 |

单 Recipe 的首个窗口，自由生成正确完整 Higher 的实测槽命中率从 A 的 37.5% 提高到 C 的 75.5%。每个种子的 16 次运行中，C 均有 16 个 Higher 完成并收到最终发布回执，A 为 8 个。Primitive 也可以到达相同终图。在八个已见 Recipe 的 256 次配对执行中，C 与 A 有 234 次同时满足事实集合和终图哈希完全相同；仅看这些配对，C/A 墙钟比中位数为 1.0305，EPT 平均差为 −.00090。当前实验支持特定入口条件下更可靠的选择，尚未证明同终图的效率收益，也没有真实 EggCC 开放工作负载的结果。
