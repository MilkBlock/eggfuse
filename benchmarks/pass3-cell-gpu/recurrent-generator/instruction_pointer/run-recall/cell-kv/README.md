# Cell-level KV Memory 与完整 Cell 生成

**在这些留出程序上，完整 Token CE 训练改善了入口绑定。模型也能主动签发、完成并消费新 Bake 的 Higher。它尚未学会根据上下文可靠地区分两个外部接口相同、内部执行条件相反的 Higher。** 给定正确 Higher 与自主发现适用 Higher 得出了不同结论。

## 原生任务与语料

一个 Primitive 从 Seed(x,y) 发布 Mid(x,y)。两个 Higher 共用这个 Primitive、同一个入口引用及相同端口类型。其中一条后缀要求 x=y 并执行加法，另一条要求 x≠y 并执行减法。后续 Primitive 读取一条分支的具名结果及 Permit(x)。Noise 是无关的可见输入。正式执行可以自由选择单步及整个 Higher，开放区域仍可生成 Primitive。每个合法调度窗口固定六槽，按原 CCP v0.1 边界提交和 Seal。所有内部请求实际签发、付费，并等待原生具名版本。只有末步指定的输出真正发布才计作 Higher 完成。

18 个训练程序交叉组合三种后缀深度、1/2/4 个任务及两种输入模式。每个程序以 Primitive 和 Higher 两套逻辑粒度重放原生请求。Higher 重标记要求链上每一个实际消费引用匹配生产者、端口、版本和顺序；两种重放均核对参考终图。自由运行使用独立的实际 Higher 接续器。共 126 条有监督状态记录、108 个不同的程序内决策状态、294 个不同的状态与完整目标配对。每个配置 360 次 AdamW 更新、2,160 枚完整目标曝光、两个训练种子。前 120 次从 1/2 个任务开始，随后混合全部规模。训练使用单一完整 Token CE，按一个目标的全部条件选择累加负对数概率。样本来自受控 Teacher，未穷尽其他合法证明。

正式评估的四个新程序在冻结后 Bake，包含更深的链和训练 Higher 内部从未见过的两路汇合。训练及留出的规范化 Higher 签名集合和显式 Seed 输入整数集合均不相交。每个模型在每个程序上使用两组真实随机地址与生成种子，每个结果正反序计时两次并逐一核对事实集合与图摘要。配对计时只增加时钟样本。离线已知入口、参考终图和未来轨迹只用于训练、诊断或运行结束后的核验。[数据、签名、权重清单](manifest.json) · [原生结果、事实及回执](native.json)

## Memory 和梯度

Cell 具有逻辑 owner、模板结构、已绑定的具名输入、实际公开端口及版本。Higher 的根和末步公开端口仍解析到其各自真实原生引用；索引把这些端口归到同一个逻辑 Cell。内部接线只读取请求中指定的生产者。私有中间步骤留在 Runtime 接续状态，完整 Memory 的神经寻址只看到公开边界。当前动态状态含已发布字段、版本年龄、forwarded 和最近回执计数。该原型在每个决策页重算动态 KV；静态结构在冻结后缓存。未发布的未来值不进入 KV。

复用 InstructionActor 的 Recipe 消息传递、CellScorer 对具名接线的 GNN、动态投影、Query、Key、Value 投影及 GRU。生成的完整概率分解为模板、具名 owner、owner 内端口及后续引用。模板选择前已经对整个可见 Cell Memory 做 Attention。B 读整体 Cell。C 进一步读各 owner 的公开端口。D 也可读取端口内独立字段。C/D 在模板和引用两个阶段均开放这些读取。另有只在地址阶段开放细粒度读取的独立训练对照。没有模板 ID embedding、辅助目标或 RL。完整 CE 的训练前向每次更新都重建可导图，冻结后按程序对象缓存；已加载新权重时丢弃旧缓存。

## 原生自由生成

Coverage 分母是参考原生终图中不同的非初始关系事实。逐个核对关系名及所有显式标量，另报告原生图摘要。EPT 是原生签名的有效原子操作除以实际付费请求，EPS 分母覆盖静态编码、动态 Memory、生成、内部接续、通信、原生核验与执行。预先编译程序及事后比较参考不计入在线时间。下表按留出程序、训练和生成种子等权汇总，各行终图不同。

| 模型 | Coverage | EPT | EPS |
|---|---:|---:|---:|
| 既有 Recipe 专用联合 posting，原寻址器 | 57.68% | .3101 | 202.2 |
| 既有共享 posting，原共享寻址器及反向探测 | 82.42% | .3330 | 203.9 |
| B 整体 Cell，训练前 → 联合训练 | 33.59% → 36.98% | .1179 → .1279 | 307.1 → 317.2 |
| C 整体及端口，训练前 → 联合训练 | 22.14% → 40.10% | .0839 → .1366 | 179.7 → 307.3 |
| D 再加独立字段，训练前 → 联合训练 | 20.31% → 37.89% | .0730 → .1223 | 147.4 → 249.4 |

密集模型及其训练使用单线程 PyTorch CPU，适合这个小环境。前两行运行既有 Metal 地址实现，模板选择使用同一训练过的混合目录读出；跨设备 EPS 包含分派差异。既有稀疏实现读取静态类型域；B/C/D 的模板和父引用生成均面对完整公开 Memory。独立的同域诊断使用相同 CPU CE 解码器，固定联合索引与类型域取得 78.12% Coverage，向相同索引开放全部行取得 40.23%；缺失字段在这一诊断中用零补位。候选域和固定表示的作用不能归给学习。C 的 40.10% 没有超过该开放域对照。

冻结 GNN、只训练读取及生成的 B/C/D 分别取得 36.33%、27.86%、27.21% Coverage。C 联合训练在 16 条不同设置的自由轨迹中自主签发 Higher 49 次，根被接受 18 次，确认末端输出 12 次；后续 Primitive 有 7 次实际接受并读取了 Higher 的具名结果。D 对应为 50、16、10、5 次。先前只在地址阶段读取字段/端口的对照也在相同留出程序上独立运行；开放细粒度模板读取并未稳定提高 Coverage。各组均保留未完成实例和失败请求。[原生汇总和计时离散度](summary.csv) · [直接复用两条旧地址路径的原生对照](legacy.csv)

## 是否学会识别计算结构

六对单任务环境切换同一输入的相等关系。每一对保持程序结构、外部接口、环境规模和可选 Higher 数一致。用原生重放标出在该状态能完整执行的 Higher。计算两个 Higher 的相对概率时把两者的概率重新归一；概率分母排除了同样合法的 Primitive。指标因而直接回答哪一个 Higher 适用。

| 联合训练 | 给定正确 Higher 的正确绑定概率 | 适用 Higher 在两个 Higher 中的概率 | 给定同一入口后的相对完整 Token 概率 |
|---|---:|---:|---:|
| B | 98.62% | 49.99% | 49.99% |
| C | 95.55% | 49.95% | 49.96% |
| D | 92.54% | 49.98% | 49.95% |

在原生单次签发对照中，C 给定正确 Higher 完成 24/24。相同的 24 个窗口从完整 Memory 自主生成一次后完成 6/24。两者的后续内部执行机制相同。D 分别为 24/24 和 4/24。一次自由选择 Primitive 本身合法，模板间归一概率另行控制这一因素。已知正确模板的数字都排除在正式成绩之外。[单次执行](oneshot.csv) · [成对反事实及根表示消融](counter.csv)

对 C，两个 Higher 结构码的平均余弦相似度为 .9989。其训练内的单任务状态对正确 Higher 的平均相对概率也只有 .5076。正确绑定已经能拟合，分支区分在训练状态中也很弱。只在消费端把 Higher owner 的结构码替换为根 Primitive 码、保留所有实际端口和地址，C 对正确下游完整 Token 的平均概率从 .0821 变为 .0828。这些测量没有建立结构理解的因果收益。高余弦相似度本身也不能证明区分在数学上不可能。合法的物理地址重命名和行重排在 C 的配对诊断中引起的最大概率差约 2.4×10⁻⁷。[训练内诊断](fit.csv) · [下游 owner 消融](owner.csv)

## 抽象尺度与边界

固定 1 个外部输入、6 个可见 owner、3 个入口模板，在冻结后 Bake 4、16、64、128、256 步的计算主体。各档原生完整 Teacher 重放核对了终图及末端的实际发布。单个 Higher 缓存向量固定为 32 个 float32，即 128 字节。4→256 步时整个目录的静态 GNN 冷编码约 2.44→62.03 ms，命中缓存后取结构码约 2–4 µs，生成一页 32 枚完整 Token 约 1 ms。目录中的其他 Primitive 表示、编译和内部原生执行仍有成本。这个规模对照测量入口寻址，未将给定模板或 Teacher 的大规模执行记作模型自主完成 256 步。[原始规模测量](size.csv)

硬件为 Apple M3 Max。运行目录为 instruction_pointer，沿用前一份 shared-sparse 报告中的 ARTIFACT_ROOT、CELL_DATA、CELL_REPLAY、CELL_COMPILER、PYTHON 环境变量。执行 `sh cell_kv_reproduce.sh` 重建语料、训练权重、原生对照、诊断和导出。完整语料、生成的 .egg、Recipe、原生 Teacher 和检查点保存在实验盘 cell-kv-fullread 目录。16 个回归测试通过；sum-bits 按仓库 Cargo compile、run、bench 执行，既有语义合同返回 pass。这里报告的小程序衡量的是原生 CCP Cell Runtime，不能外推为真实开放 EggCC 工作负载的前沿。
