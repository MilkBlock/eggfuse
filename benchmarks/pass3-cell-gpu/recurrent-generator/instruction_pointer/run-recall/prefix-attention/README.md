# 已绑定父引用如何改变下一枚具名引用的概率

在三个真实 EggCC 程序逐一留出的实验中，完整 Cell CE 能训练统一 KV 的跨 Cell 关联读取。二父给定正确首父时，原生 binding 拒绝从 144/368 降至 53/368 和 56/368，历史联合寻址为 1/368。从空前缀开始，两个训练种子都发现了 51 次有新增贡献的请求，原 KV 为 37，历史寻址为 55。三父仍有明显差距，完整自主执行也没有建立跨程序一致的 Coverage–EPT–EPS 优势。

## 前缀表示审计

原实现保存了正在生成的模板和已选择的**有序具名引用**。每次地址预测从 `tanh(ctx + template_code)` 开始，把前缀中每个命名端口的 32 维实例向量依次送入 `next_read` GRU。随后加入下一父角色的 GNN 节点，送入 `actor.query`。首父的具体字段哈希、类型、版本年龄和转发状态经过原编码器影响 GRU。owner 的结构、其公开端口和仍可见的上游引用也影响整体 KV。此前的静态字段读取服务于 Higher 变体选择；它的操作数值没有被直接携带到下一次地址预测。原有地址解码能够看到绑定进度，但无法从该 32 维隐藏态按名字重新读取之前绑定的某个操作数。[实例编码与地址读出](../../cell_kv_model.py) · [模板变体选择与完整 CE](../../selected_cell_model.py)

新读取保留原分数，并通过已生成前缀直接访问选中 Cell 的外部端口。给定下一父角色 j，复用 Catalog 已有的静态跨角色字段连线及 GNN 查询操作数节点。每条连线给出已绑定父角色、源列、当前候选列和操作数表示。某条候选引用的所有比较都在同一候选行上完成，支持多个已选父角色同时约束这一行。不同 Recipe 读取同一份状态内字段张量；Higher 只使用真实入口的外部接口。本轮的训练标签为 Primitive，正式自主运行保留原 Higher 目录。结果尚不能回答未见 Higher 的组合泛化。[关联读取](../../prefix_attention.py)

设 P 为公开端口数、F 为最大外部字段宽度、L 为当前绑定步骤的静态连线数。每个已发布的 64 位字段哈希沿用现有位编码，得到两个 32 维向量。对源和候选分别应用共享的 `v = tanh(actor.latent(bits))`。源读出为 `q = v + 0.25 tanh(actor.query(v + role))`，候选读出为 `k = v + 0.25 tanh(actor.input_content(v + role))`。把 L 条连线上的点积之和除以 √(64L)，与原具名引用的 log 概率相加，再在同一静态域归一化。此处 `role` 是 GNN 对应的操作数节点。首父和没有跨角色接线的步骤走原寻址。全域读取的瞬时字段存储为 P×F×64，候选交互为 P×L×64，每次只处理一个实际前缀。CPU 不判断字段相等、不建立按字段值分组的域、不检查 guard。具名引用、回执、版本检查与付费沿用 CCP v0.1。本次保持原 owner/port 读出，既有扁平读出的独立计时和实现保留在[前一轮对照](../variable-completion/README.md)。

## 原生状态、训练、干预

从历史自主轨迹逐请求重放，核对原生 ID 和回执。每个程序使用已知有贡献的活跃窗口，验证各模型的可见具名引用集合一致。fact 有 9 个决策状态、18 个「状态 × Recipe」、60 个经核验的完整目标；loopfact 为 14、21、40；sum-divisors 为 11、24、128。训练每折只读取另外两个程序的样本。同一运行状态可以支持多个 Recipe。三个程序间没有完全相同的序列化决策状态，仍共享 EggCC 的规则和静态接线。[语料统计](cohorts.json) · [重放与目标生产](../../prefix_corpus.py)

所有模型从 e03aab79 的同一个 both-71 检查点出发。匹配训练的 A 与 C 使用完全相同的状态顺序、目标、已有参数和预算。两个采样种子各训练 192 次更新，每次从一个「状态 × Recipe」取最多三个不同的已核验目标，只计算完整 Cell Token CE。GNN 与 GRU 冻结。更新已有的 Query、Key、Value 和 input_role 投影，共 4,160 个参数。静态接线是归纳偏置；冻结新读取、训练原 KV 和在训练后的 C 上撤掉关联项分别估计其来源。未核验引用不作为有证据的失败标签，CE 归一化仍可能压低未标注的合法目标。[训练和梯度](training.json)

**逐字段干预。** 保持活跃 Recipe、已选首父的具名地址和其他端口不动。在离线神经输入中，仅把该父的一列改成另一个同类型候选在相应列上的真实值，重新编码整个状态。要求原候选先胜，换值后另一候选胜，才算一次翻转。在可构造的 50 个有连线干预中，A 初始为 18/50，同曝光训练 A 为 10/50，冻结 C 为 47/50，训练 C 为 50/50 和 48/50。种子 71 的 C 在 45 个无接线列干预中为 0 次翻转。这些是神经输入敏感性测量；改写的视图不提交给 CPU，也不假定候选交换后就能通过其他运行时条件。[逐字段原始分数](field-swaps.json)

**梯度。** 在 32 个多父窗口各取第一个经核验目标，从完整 CE 反传至最后一个有接线的父步骤。种子 71 对关联 Query、Key、源 Value、候选 Value 的平均梯度范数分别为 0.134、0.258、0.136、0.260。训练日志另列每个实际参数的梯度范数及 CE 曲线。固定结构本身已有明显收益；训练进一步改变了端口选择。[逐窗口梯度](gradients.csv)

## 正确活跃 Recipe 的离线干预

每个窗口、每组签发 16 枚完整请求。从空前缀自主选父以及给定已核验正确首父两种干预分别从同一原生前缀重放。给定首父时轮转不同的已核验首父引用，只由模型生成后续引用。起点的空分叉充当事实对照，各分叉在相同 Run 导出事实。以下每格依次为「原生 binding 拒绝 / 有有效操作归属的请求」。用户评估的正式自主路径不接收正确 Recipe 或首父。

| 寻址 | 二父空前缀，368 | 二父给首父，368 | 三父空前缀，144 | 三父给首父，144 |
|---|---:|---:|---:|---:|
| A 冻结 KV | 247 / 37 | 144 / 38 | 126 / 3 | 99 / 4 |
| B 历史联合寻址及其原回退 | 26 / 55 | 1 / 57 | 53 / 24 | 0 / 32 |
| C 接入关联、冻结原权重 | 183 / 47 | 73 / 44 | 121 / 8 | 89 / 11 |
| A 同曝光训练，71 | 250 / 38 | 154 / 35 | 121 / 5 | 98 / 5 |
| C 完整 CE，71 | 159 / 51 | 53 / 49 | 114 / 12 | 75 / 18 |
| C 完整 CE，113 | 163 / 51 | 56 / 48 | 112 / 13 | 69 / 17 |

在二父空前缀，C-71 产生 157 次原生重复（A 为 83，B 为 286）；分窗口新覆盖参考事实数为 52（A 为 35，B 为 56）。同一事实跨窗口可以出现，表中的 productive 是按请求 ID 归属有效原子操作的次数；每个分叉的新、失去的具体参考事实均另存。撤掉 C-71 的关联项、保留其全部更新权重，binding 拒绝变为 251，有贡献请求回到 37。拒绝减少不必然带来同等数量的新计算。[回执、重复与新增事实汇总](summary.csv)

**三父归因。** 48 次可用历史联合索引的签发中，A / B / C-71 分别有 3 / 4 / 3 次新增贡献。另 96 次（三个程序中的 532、534）在 B 中使用历史条件网络回退，A / B / C-71 分别为 0 / 20 / 9。新 C 在这两类窗口均使用同一个可训练的跨父读取，没有调用历史回退。给定首父的所有三父签发中，B 的绑定拒绝为零，C-71 仍有 75 次；同一算子对真实多父关系的恢复仍不充分。

**完整概率。** 对所有经核验见证，在重放诊断的 Primitive 目录中按模板、变体和有序父引用的条件概率相乘。自主执行另使用 Primitive/Higher 混合目录。二父见证的完整 Token 平均概率，A / B / C-71 为 1.71% / 4.50% / 2.46%，给定正确首父后的次父平均概率为 23.4% / 44.2% / 34.4%。三父见证的第二、第三父概率在 C-71 达到 55.8%、56.6%，但含模板选择的完整概率只有 0.46%，低于 A 的 0.82% 和 B 的 5.27%。这能解释为什么只观察局部绑定会高估整枚 Token 的收益。统计对全部见证等权，前一轮只抽至多四个见证的均值不能直接与之比较。B 的条件概率包括原索引的量化 posting 质量、二级选取与探索项；该计算只用于离线诊断。[逐见证概率与各原生分叉](interventions.jsonl)

## 复现

使用研究提交 e03aab79 的资产和同版原生运行器，在 benchmarks/pass3-cell-gpu/recurrent-generator/instruction_pointer 下执行。目录 ARTIFACT_ROOT/conditional-value/prefix-attention 保存经过核验的决策状态、训练权重、原生自由执行与离线分叉原始记录。A/B 既有原始结果用于逐窗口交叉核验，不进入在线模型。脚本不更改变长结束策略、控制器、CCP、GNN 或目录。[文件摘要](manifest.json)

```sh
export ARTIFACT_ROOT='/Volumes/Extreme SSD/eggfuse-experiments'
export CELL_DATA=/tmp/dfm-local/data
export CELL_COMPILER=/tmp/cost-audit-build/release/eggfuse-cell-compiler
export CELL_REPLAY=/tmp/cost-audit-build/release/examples/cell_token_replay
export PYTHON=/tmp/prefix-ml/bin/python
sh prefix_reproduce.sh
"$PYTHON" -m unittest test_prefix_attention test_variable_completion test_rule_publication test_constructible test_competition test_selected_cell test_head_joint_index test_partner_index
```

本轮 53 项相关测试通过，包含同一候选承接两个已绑定父的关系、归一化支持域与梯度的回归。运行本地 Cargo compile、run、五次 bench 及既有 sum-bits 原生合同验收，语义状态为 pass。EggCC 各组的覆盖率以实际原生导出计量。
