# Discrete Cell Token editing on the native CCP runtime

A four-step Edit Flow issued accepted proofs from an empty draft in three held EggCC programs. Its coverage was 31/1,120 on fact, 48/1,112 on loopfact and 113/8,018 on sum-divisors. It covered 0/233 facts on the held grammar. Ordinary supervised editing removed more verified duplicate requests. In this implementation sparse addressing buys inexpensive draws at a substantial cost in proof discovery.

Coverage counts reference facts, and EPS and EPT use the existing effective-op counter. EPS includes per-program static setup, native initialization, Memory updates, model calls, edits, address reads, packing, transport, verification and publication. There is no permanent K-sized shortlist or ceiling on the length of a draft.

### Historical reference and responsibility boundary

The historical prefix weights were reused. The historical guarded decoder selects a bucket using joint prefix freshness in `stream_guard.py`; `CellStream.path_batches` also intersects the final expansion with freshness accumulated across roles. The old fast-path performance is excluded from formal Neural Execution results. The replacement uses an explicit individual source delta and otherwise visible typed rows. It charges the scan for each source, scores prospective bindings with the frozen network and submits duplicates to native verification. On sum-divisors moving that anchor to the front hit a native assertion at Run 154; those two aborted runs are retained as diagnostics. Keeping it at its original slot finished Run 777 with 3,137 facts, 3,396,005 paid requests and 368,722,521 traversed positions in each of two runs (257.7 and 273.4 s, identical terminal SHA). A separate 150 s cap stopped at 2,679 facts. Completed runs and censored runs have separate identifiers. Source order affects native execution. [Reference code](../../discrete_reference.py)

The edit arms use the native published rule schedule, the type and actual publication of named ports, and the frozen GNN. Neither semantics-based partner lookups nor cross-role watermarks guide online addressing. The mark decoder follows a learned binary choice over two physical pivot entries per level, first for the template and then for each external reference. It can copy a named event/draft reference and can select a typed output of an earlier draft item. Reading a retired leaf can fail. The tree order comes from the physical table or the static schedule; its pivots have no semantic ordering guarantee. Active draft local ports are inspected and charged. The schedule's static vocabulary is cached on first use. The live system performs no exhaustive template × parent scoring.

For E4 on sum-divisors the timed instrumentation run used 10,718 template probes, 6,889 parent probes, 180 draft-local ports inspected, 2,336 edit-network calls and 7,141 address-network calls. It issued 291 CCP requests, reached 544 synchronization boundaries, and 265 requests received native `untriggered_rule`. In Rust this verdict means the native dirty check failed; the online model received the verdict after issue. The 0.236 s draft-sampling interval includes mark calls. Subtimers on this run measured 0.068 s in template addressing and 0.053 s in completed parent addressing. They overlap the sampling timer and omit the partial time of abandoned parent attempts. All attempts remain in elapsed time. The full legal baseline and E4 have very different coverage, so their difference in visits cannot be credited as eliminated equivalent work.

## Training, probabilities and addressing

All examples refer to a common native pre-state for source and target. The previous 99 fork points supply 47 training contexts (32 sum-bits teacher, 12 sum-bits rollout, 3 training grammar), 12 dot-product validation contexts, and 40 held cases across three EggCC programs and a second grammar. The 329 examples include 47 duplicate, 47 keep, 46 repair, 46 empty→one, 44 partial, 44 empty→two, 44 keep-two, five primitive→Higher, five empty→Higher and one failed-Higher→primitive. Each positive addition requires observed native publication. Known duplicate labels have a complete suffix check on each corpus, including subsequent versions, publications, repair, effects and final state; the duplicated replays produced exactly 99 additional duplicate verdicts. A rejected guarded Higher was separately compared with its surviving root; both had one effective op, the Higher cost an extra paid request. Uncertified cases carry no negative label. These are short plans; they do not establish long-horizon credit for arbitrary omissions. [Training composition](fit.json) · [Suffix audit](suffix-audit.json) · [Guard certificate](guard-certificate.json)

We froze the previous Recipe GNN and reused its generated rule/port nodes, integer-parameter structure, `producer_op → consumer_slot` wiring and stage-group encoding. The native receipt contract supplies output ports and the actual Runtime checks guards, versions, publishing and retirement. The learned structural readout is lossy; it has no guarantee of distinguishing every guarded or absent output. The new placement network and stochastic address network are shared in size across controls; no learned template-ID table is installed. The address network learned 3,826 supervised branch choices shared across the three fitted editors. An ordinal tree with weakly informative pivots and a single event-conditioned state is a restrictive decoder. Its mark distribution uses context and the substitution hint, with no separate learned time-dependent address decoder. Response feedback is available online; the original fork frames do not reproduce the entire distribution of model reject histories.

**B.** Supervised gap counts and keep/delete/substitute decisions train on endpoints, with one parallel update and shared stochastic mark sampling.

**C.** A supervised count decoder first chooses an insertion window. Independent absorbing masks reveal slots with probability `dt/(1−t)`; the mark sampler supplies a token at a revealed insertion/substitution. Source-position decisions are trained on conditional masked endpoints. The window length can differ between pages but stays fixed during a page's mask dynamics. This is a hybrid mask control.

**D/E.** Choose a valid ordered edit script of length m connecting the draft to the native target. Its m jump times are sorted independent uniform samples. Conditional on the endpoints, the number of jumps by t is Binomial(m,t). After k jumps the only forward jump has intensity `(m−k)/(1−t)` at the next site/type. Training samples k uniformly from 0…m and then t from Beta(k+1,m−k+1). For `mu=(1−t)u` the location/type loss sums `mu−n log(mu)` over enabled sites. Here n is m−k at the next site/type and zero elsewhere. The shared mark model uses conditional target pointers weighted by remaining jumps. D and E share a checkpoint. D starts with up to two addressable sparse draws; E starts empty. All samplers run on unpublished plans. A finite-step leap uses Poisson gap insertions and competing substitution/deletion hazards; conflicts are resolved on stable local IDs in reverse position order. Substitutions preserve identity; incompatible or dangling edges block the edit. Every finalized request has a CCP verdict or a recorded outstanding local dependency. There is no runtime synchronization inside a leap. This is an ordered-bridge adaptation of discrete edit-rate matching; it uses a chosen bridge and approximate finite-step sampling. [Edit Flows](https://arxiv.org/abs/2506.09018)

## Causal checks and Higher Cells

Across 40 held duplicate drafts ordinary editing gave the exact one-copy target 40 times, four-step D gave 23 and C gave 10. On the first three held contexts per program we reran each actual edit through the entire native suffix. B removed one paid copy and preserved every compared downstream effect 12/12 times; D did this 7/12 times and C 3/12 times. D preserved the suffix in all 12 but kept two requests in the other five. Exact empty→one proof recovery was 1/39 for both B and D; partial→complete was 0/37 for both. In the 12 native empty-draft tests no method recovered the whole reference suffix. Same-run signature repeats, within-draft excess, native duplicate verdicts, and unscheduled/unresolved requests are logged separately. No delayed or abandoned request earns a duplicate-elimination credit. [Frozen snapshot evaluation](frozen.json) · [Edited suffix replays](native-evaluation.json)

On 39 productive held snapshots, 312 sampled marks yielded 191 fully addressable tokens, 79 correct root templates and only three exact proofs. Even supplying the target template offline gave only 9/312 exact parent bindings. Alternative proofs can also be useful; this diagnostic tests a known reference and uses no oracle at deployment. Sparse partner selection and the high frequency of requests returned as untriggered both constrain independent coverage. [Address diagnosis](address-diagnosis.json)

After freezing the four checkpoints, held layouts were baked from native recipe structure. Normalized donor and held signatures are disjoint. Four fresh controlled layouts (three- and five-step chains, fork/join, shared input) all had an autonomous selection, successful root binding and completed Higher suffix with E4. Small menus expose one Higher option per applicable root. The frozen GNN had historical experience with other Higher Cells. The held layouts were unseen by this editor's supervised training; results do not establish that the system selects useful unseen layouts at library scale. The true/false guard pair both attracted two Higher selections and one accepted root; only the true branch completed. ### Primitive-only supervision

A second fit used the same 47 contexts with all Higher demonstrations removed (318 examples, 3,804 branch labels). After both fits were frozen, we compiled an additional six-step shared-input fork/join whose normalized signature is absent from both donor catalogs, the eight earlier held fixtures and the historical 10,000 structural keys. At seed 536 both fits independently selected, bound and completed the new macro. With/without it the primitive-trained model spent 17/13 requests at the exact same terminal graph; the mixed model spent 17/15. This control removes Higher examples from new training. The reused, frozen Recipe GNN still has its historical pretraining.

Across 12 additional paired seeds on this six-step program, the primitive-trained editor using the actual Higher graph completed the macro in 11/12 runs and reached all six facts in 12/12. Replacing only its Higher graph vector with the primitive root vector yielded 6/12 completions and 9/12 full-coverage runs. The full representation cost 215 requests across the seeds; the collapsed representation cost 176. This intervention gives evidence that structure affects selection on this particular layout. The number of seeds measures stochastic variability on one layout, not transfer across 12 independent programs. [Native executions, ablation and weight digests](transfer.json)

## Reproduction

Run from the instruction_pointer directory in the project PyTorch environment. Use the pinned 38125ba0 runtime, teacher states, actor, GNN and primitive weights. The upstream input digests and commands for rebuilding the 99 forks are in the [previous experiment](../latent-computation-flow/README.md). ROOT is its RUNTIME_DATA with the native replay binary, grammar programs, `multi.pt`, and writable recursive-agent directory. FORKS contains the eight named JSONL files. ROLLOUT contains the original sum-issued.json and sum-native-memory.jsonl. COMPILER is the native eggfuse-cell-compiler executable. OUT is a writable experiment directory. Use these same arguments for train, frozen and native audits.

```sh
mkdir -p "$OUT"
python edit_native_pairs.py "$ROOT" "$FORKS" "$ROLLOUT" "$OUT"
python discrete_study.py train "$ROOT" "$FORKS" "$ROLLOUT" "$ACTOR" "$COMPILER" "$OUT"
python discrete_study.py frozen "$ROOT" "$FORKS" "$ROLLOUT" "$ACTOR" "$COMPILER" "$OUT"
python discrete_native_eval.py eval "$ROOT" "$FORKS" "$ROLLOUT" "$ACTOR" "$COMPILER" "$OUT"
python discrete_diagnosis.py eval "$ROOT" "$FORKS" "$ROLLOUT" "$ACTOR" "$COMPILER" "$OUT"
python discrete_holdout.py "$ROOT" "$OUT" "$ACTOR" "$COMPILER"
python discrete_late.py "$ROOT" "$OUT" "$ACTOR" "$COMPILER"
python discrete_rollout.py "$ROOT" "$OUT" "$ACTOR" fact editor:1 mask:4 flow:4 empty:4 --block 0
python discrete_rollout.py "$ROOT" "$OUT" "$ACTOR" fact empty:4 flow:4 mask:4 editor:1 --block 1
mkdir -p "$OUT/primitive-fit"
cp "$OUT/suffix-audit.json" "$OUT/primitive-fit/"
python discrete_study.py train "$ROOT" "$FORKS" "$ROLLOUT" "$ACTOR" "$COMPILER" "$OUT/primitive-fit" --primitives-only
python discrete_transfer.py "$ROOT" "$OUT" "$ACTOR" "$COMPILER"
python discrete_reference.py "$ROOT" "$OUT" fact
python discrete_reference.py "$ROOT" "$OUT" sum-divisors --original-order --seconds 600
```

Repeat the rollout commands for loopfact, sum-divisors and grammar-benefit-left-17119, using the desired arm names/steps in paired and reversed order. Add `--primitive-only` for the matched Higher control, `--milestones` for semantic-set checkpoints, or `--waves 0 --seconds 60` for the uncapped-page diagnostic. Rows in independent.jsonl include seed, waves, step count and measured costs. Run the reviewed sum-bits validator on its saved exports, writing OUT/semantic.json. Then run `python discrete_report.py "$OUT" run-recall/discrete-computation-flow`. Four checkpoint files were byte-identical on a second training run. The Cargo sum-bits compile/run/five-repeat benchmark, the reviewed [semantic acceptance](semantic.json), and the instruction-pointer unit suite were checked locally.
