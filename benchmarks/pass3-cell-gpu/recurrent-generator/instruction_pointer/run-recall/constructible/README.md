# 完整 Cell Token 的静态类型域与抽象尺度

轨道为 Neural Execution，模式为 exclusive。EggCC 使用真实 CCP v0.1 Cell Native Runtime、冻结的 Response KV 权重、原 Recipe 调度和固定退出。受控的小程序也编译后交给同一个原生执行器。离线同快照打分和训练标签另计。

**按完整 Token 的类型域归一化消除了通往空父域的抽样，增加了相同生成槽数能发现的事实。完整调度下，额外完整 Token 大多收到了未触发回执，付费效率下降。** 在小型抽象尺度实验中，减少神经决策最明显的是中等 Higher。该比较使用自建留出程序，不能外推成真实 EggCC 的 Higher 收益。

## 结构边界与实现

审阅了工程的 AGENT-RULES.md。B2 允许使用静态类型掩码以及公开可见域，禁止候选间按值、可达性、新鲜度组合等条件裁剪。B3 禁止另训一个有限真值表。这里直接使用现有父引用解码器的表标签。对已经给出的调度菜单中的入口族 r，其每个父槽 j 在当前公开快照中有地址域 D(r,j)。仅当每个域均非空时，该族能够填写全部引用。零父族满足空合取；同类型的多个槽可选同一端口。表存在即可，无需检查有多少行、是否不同、是否共享变量或能否通过 guard。公开可见域的变化会改变结构支持集。Receipt KV 行不属于可选父端口。

当前目录里的 Primitive 和同族 Higher 共用入口的声明父类型。实现先求原有神经入口质量，再在支持集上做一次 log-softmax。给定入口的原有变体和父地址分布继续由网络评分。支持集全空时记录没有可构造 Token；有支持但规则未唤醒、字段不匹配、请求重复等情况均可被模型实际签发并付费。只有一个可构造 Token 时，其条件概率为 1，这部分归功于构造算法。整个流程没有重抽失败模板、按水位找伙伴或由 CPU 判定规则有效性。当前 CPU 实验每页遍历一次公开端口表标签，并检查各菜单入口的声明父槽，额外复杂度为 O(公开端口数 + 菜单父槽总数)，无父引用笛卡尔积。上游整份 KV 和菜单神经打分的开销仍然存在。[支持集和 CE](../../selected_cell_model.py) · [页内抽样](../../competition_draw.py)

A 为原入口抽样加类型约束父解码。B 只加上述归一化，继续独立抽样。C 使用 B 的相同权重，增加既有的页内完整具名 Token 不放回。TB/TC 在与 B/C 相同的支持集上重新训练再执行。每窗口两页、每页三槽，下一页可重新签发；没有跨页、跨状态语义去重。Response Memory、GNN、Embedding、Attention、原生核验和付费口径沿用 9336011a。参考事实由执行结束后的原有构造子对齐合同核对。正式执行不接收 Teacher 证据或诊断答案。

## 首次停滞与后续窗口

重跑历史单页、六槽、权重 71、抽样种子 193 的真实轨迹，逐窗口核对已提交的原动作和既有单请求原生分叉的概率。在三个程序的 Run 2，菜单均有十个入口，只有零父 574() 能构成完整 Token。历史模型对它的原概率分别为 0.02260%、0.02263%、0.02512%，历史轨迹三者都漏签。换成当前回执可见的冻结权重 71，在同一个历史前缀上原概率分别为 23.22%、23.13%、22.28%。B 在两个版本的权重上都得到 100%。

本轮两页的自由执行也核对到了真实请求。三个程序中，A 的权重 71 均签两次、接受一次，权重 113 均漏签。B 的两个种子都签六次、接受一次；C 均签两次、接受一次。C 在第一页已经发过的 Token，第二页仍然允许发。历史与当前模型的原概率、冻结快照干预与真实生成不能混用。[逐请求](windows.csv) · [同快照原生核验目标概率](forks.csv)

Run 3 中，当前可见权重在已核验有新增贡献的绑定上分配的概率质量，fact 从 0.916% 升到 5.237%，loopfact 从 1.572% 升到 8.994%，sum-divisors 从 0.0353% 升到 0.0909%。这些都是抽查所得的下界。最后一次新增之后的首窗口分别为 Run 53、4、27；当时仍有 6、6、15 个类型可构造入口，在既有抽查的具名请求中，没有发现新增事实的请求。未穷举的部分保留未知。B 只重分配支持集内的总质量，无法改善两个可构造入口之间的相对排序。
