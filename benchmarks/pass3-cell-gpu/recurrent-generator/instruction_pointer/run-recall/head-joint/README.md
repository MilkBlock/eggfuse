# 在同一伙伴行上联合四个 Head

**每角色 32,768 行时，正确首父平均概率从 13.23% 升至 99.61%。** 原困难组的 4 组留出值、两种字段互换和 3 套冻结权重共 24 个观测，乘积核全部将正确首父排第一。每角色 131,072 行的一组留出值和两种互换也得到 99.61%。真实 EggCC 的三个独立程序均未增加覆盖事实数量。

## 首父为什么会错

设单头的软坐标内积为 kₕ(a,b)，原非线性为 g(x)=s Σₕ[log(xₕ+10⁻⁵)−log(1+xₕ)]，s 沿用冻结的正强度。以下读出使用相同的神经投影、首父先验和公开候选域。离线比较在两个父角色上进行，叶伙伴权重为一。

| 读出 | 每个首父的关系权重 | 32,768 行正确首父平均概率 |
|---|---|---:|
| A 原读出 | exp g(Σᵦ k(a,b)) | 13.23% |
| B 同行非线性 | Σᵦ exp g(k(a,b)) | 约 100% |
| C 同行乘积 | Σᵦ ∏ₕ kₕ(a,b)，加 10⁻¹² 底值 | >99.99% |
| D 离线最佳单伙伴 | maxᵦ exp g(k(a,b)) | 约 100% |

B 只交换聚合和非线性的次序，已恢复首父。D 是对完整伙伴域取最佳同行关系的乐观诊断，不是所有解码器的理论最优值。离线按有共同**神经特征坐标**的行对精确求和、求最大值，其余行对按 g(0) 的重数计入。对真实首父及 D 的最强竞争者逐行稠密复核数值。全程没有分配首父域 × 次父域的矩阵。正式执行只使用 A 或 C 的设备索引。[诊断实现](../../head_joint_audit.py)

| 每角色行数 | 单伙伴困难组的 A | C 含探索 | 1024 次自由抽样的完整 Token 命中 | 四头各有支持、无同行支持的首父数 |
|---:|---:|---:|---:|---:|
| 1,024 | 100.00% | 99.61% | 99.04% | 0 |
| 8,192 | 98.26% | 99.61% | 99.19% | 2 |
| 32,768 | 13.23% | 99.61% | 99.13% | 292–340 |
| 131,072 | 0.061% | 99.61% | 99.14% | 47,670–47,671 |

除 32,768 行外，主规模曲线每点使用同一组留出值的两种互换和 3 套冻结权重。跨规模复用值以隔离规模效应。这些观测共享程序结构。78 个冻结观测覆盖 1 或 8 个合法伙伴、近似干扰行比例 0/50/100% 及额外的 32,768 行 filler。离线原生重放对正确具名绑定提供标签。

另做了一项可控诱饵实验。保持 32,768 个真实首父和唯一有效结果，离线选定四头由不同伙伴支持的困难首父，改变其独立输出列以形成不同物理行。诱饵占 0/25/75% 时，实测分散支持的首父数为 0/8,200/24,592，原正确首父概率为 100%/0.0609%/0.0205%，联合索引始终为 99.61%。这一压力测试针对冻结映射选样，单列于自然留出组之外。全部环境重新编译并原生核验。[冻结观测](frozen.csv) · [受控诱饵](lures.csv)

## 联合索引、采样律与精度

四头各有两个非负软特征。在同一行对四个分量做外积，得到至多 16 个非零坐标。设 t=(c₁,c₂,c₃,c₄)，Qₜ(a)=∏ₕqₕcₕ(a)，Vₜ(b)=∏ₕvₕcₕ(b)。展开分配律可得 ΣₜQₜ(a)Vₜ(b)=∏ₕkₕ(a,b)。原读出 A 继续使用上轮权重、首父非线性和 8 个稀疏提案重打分。新读出 C 沿用已经训练的坐标映射、GNN、首父先验和 Recipe 接线；组合运算为固定乘积。本轮训练更新次数为零。两个首父分布与两种条件采样器均单独记录。

对一版发布内的伙伴权重 wᵦ，索引在 GPU 把 wᵦVₜ(b) 转成 2⁻³² 单位的整数 Uₜᵦ 并建立 int64 区间累加。第一级以 Qₜ(a)ΣᵦUₜᵦ 为质量抽样，第二级在同一坐标区间以 Uₜᵦ 为质量抽样。在实数均匀随机数模型下消去 t，伙伴概率正比于 ΣₜQₜ(a)Uₜᵦ。实际实现另有浮点乘法、有限精度均匀随机数和整数舍入。冻结世界中，与离线逐对实数乘积相比，全部首父聚合质量的最大绝对误差为 1.33×10⁻⁷。CPU/MPS 同分布测试包含一个坐标对应多个伙伴、非均匀权重、零质量、地址重排、高位差异和分散支持。首父、条件伙伴分别混入 1/256 的类型域均匀探索；无支持时条件伙伴在整个公开类型域抽样。两级都保留后续抽到任意行的机会。[联合索引](../../head_joint_index.py) · [回归测试](../../test_head_joint_index.py)

**码宽。** 每头容纳 0 至 262,145 的坐标，逻辑空间上界为 262,146⁴，即 4,722,510,599,706,996,899,856 个坐标。整体编号至少需 73 位，逐头定宽拼接需 76 位。实现以两个 38 位整数分别编码头 1–2 和 3–4，在本次发布上分别排序、核对完整半码并转成秩。缺失半码使用保留秩。最后以 4N+1 为基数组合两个秩并检查 int64 上界。N=131,072 时整个秩码小于 2³⁹。CPU 不参与码匹配。

**碰撞。** 主困难组 131,072 个伙伴的 2,097,152 个分配位置中，2,097,136 项有正质量，正 posting 的重复码数为零。8 个合法伙伴的组有 112 项重复码，即 7×16：这些伙伴共享参与绑定的两个字段，各自仍有具名引用和独立输出。重复码占正 posting 约 0.00534%。针对已核验首父，各规模的正乘积错误伙伴实测为零。该结果只约束测过的值；前端仍使用 64 位字段哈希及四个有损投影。

## 成本和原生验收

每个索引 posting 保存本版物理类型域中的行偏移，经公开表解析到 (owner, op, version)。正式路径读取完整公开域的特征，为每个首父查询 16 个联合坐标，缓存区间和质量。32 槽页读取 32 个选定 posting 的行号；原 A 为每槽 8 个提案、全页 256 次同行打分。二分探测和整域建索引、首父归一化及公开行装包均有成本。发布或退役后重新构建；本轮没有增量维护的性能主张。

| 每角色行数 | 联合索引 / 首父缓存 MiB | 完整 GPU 页，A / C ms | 缓存首父分布后的解码，A / C ms |
|---:|---:|---:|---:|
| 1,024 | 0.375 / 0.313 | 2.77 / 2.18 | 0.68 / 0.40 |
| 8,192 | 3 / 2.5 | 5.07 / 4.62 | 0.76 / 0.43 |
| 32,768 | 12 / 10 | 13.05 / 14.31 | 0.63 / 0.40 |
| 131,072 | 48 / 40 | 58.80 / 63.42 | 0.70 / 0.44 |

在 Apple M3 Max 上预热后取三次 GPU 同步墙钟的中位数，完整页含重新编码、构建、根打分和采样，装包上传另测。131,072 行时，联合索引的完整准备成本 61.78 ms，装包上传 206.44 ms，整页 PyTorch dispatch 可见的张量峰值增量 686 MiB（不含驱动私有工作区）。只复用缓存时，给原 A 同样缓存首父概率后，其解码从 37.48 ms 降至 0.70 ms，且在同一随机数下输出逐项相同。两者都缓存后可归于寻址路径的差距为 0.70 对 0.44 ms。不可把 37.48 对 0.44 ms 全算成跨头联合的收益。[设备计时](cost.csv)

**原生合成独立执行。** 实际签发 CCP v0.1，固定退出；每个大小使用两种互换、真实置换的 owner、关闭最近端口复制，正反序各执行一次，同一组内固定抽样流。每行以新增参考操作计 Coverage，以真正付费请求数计 EPT，以含程序载入、公开 Memory、GPU、通信及原生执行的墙钟计 EPS。参考终图另行取得；逐次断言达到完整 Coverage 当且仅当原生图摘要等于参考。两次计时重复不增加统计独立样本数。

## EggCC 多规则、动态发布和多父

从空的自主执行历史启动 fact、loopfact、sum-divisors，使用原 Native Runtime 和固定退出。原冻结神经模板采样器从每个 Run 的 Recipe 规则域抽 8 个槽，公开 dirty 状态作为神经特征。两组都对树状共享变量接线使用对应的索引，零父直接生成；单父、有多个前驱角色或没有静态共享变量的接线回到原冻结父引用网络。两组都关闭显式最近端口复制。网络抽模板、选首父、选具名伙伴；CPU 读取当前公开类型域、解析已选引用、核验并执行。未使用 Teacher、合法伙伴掩码、CPU 字段比较或水位预筛。每次索引调用都使用当前发布视图。状态和模板变化时的重建、空域尝试、未触发和重复请求全部计入原生墙钟。[执行入口](../../head_joint_egg.py)

| 程序 | 覆盖事实 A / C | Coverage | 有效原子操作 A / C | 付费请求 A / C | EPT A / C | EPS 中位数 A / C |
|---|---:|---:|---:|---:|---:|---:|
| fact | 49 / 49 | 4.375% | 94 / 94 | 541 / 541 | 0.17375 / 0.17375 | 23.08 / 23.28 |
| loopfact | 61 / 61 | 5.486% | 79 / 79 | 742 / 745 | 0.10647 / 0.10604 | 17.28 / 17.03 |
| sum-divisors | 119 / 119 | 1.484% | 223 / 223 | 742 / 742 | 0.30054 / 0.30054 | 54.51 / 54.06 |

一个冻结策略和生成种子，四组交替正反序配对。fact 的原生墙钟范围 A 4.05–4.37 s、C 4.00–4.64 s；loopfact 为 4.43–4.95 s、4.51–4.72 s；sum-divisors 为 4.05–4.13 s、4.12–4.15 s。各组内四次终图一致。fact 和 loopfact 的两种机制各覆盖了对方遗漏的一个参考事实，两个程序的终图也有差异；sum-divisors 的参考事实集合与终图完全相同。该组提供了同图比较，联合索引没有改善前沿。[逐次计时和终图](egg.csv) · [事实集合和回执](egg-outcomes.json)

这项迁移实际走到了多父路径。联合索引在三个程序上分别用于 305、514、575 个槽，其中三父及以上占 55、85、72 个槽。对应的索引页仅平均读取约 7.2、5.1、10.6 个伙伴行（多条边合计）。sum-divisors 的 2,312 次模板尝试中，1,570 次遇到空父域；742 枚实际签发的请求中，660 枚被原生判为 untriggered_rule。fact 和 loopfact 各有 485 和 646 枚未触发。联合索引解决的是已有候选中的伙伴身份问题；这一页预算下大量尝试发生在其他阶段。运行记录不足以判断提高模板选择能力之后的收益，也不足以代表高召回 Cell Stream 的上限。
