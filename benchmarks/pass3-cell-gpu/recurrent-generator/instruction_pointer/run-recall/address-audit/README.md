# Cell Token 的模板与父引用寻址审计

基于 10da23c4。结论有两层。物理地址树确实会在到达叶子之前漏掉关键证据。换成逐地址神经打分后，等预算下找回的不同原生绑定从重训树的 261 个升到 312 个。但在 5,397 个预算内可取的已知绑定中，两种方法都只能找到很小一部分。给对模板和此前的父引用后，单个父地址的识别仍然很弱。更换树对终图和吞吐的影响随程序、预算及打分实现而变化。

## 现有树究竟读了什么

| 步骤 | 实际行为 |
|---|---|
| 模板域 | 按原生 Run 提供的 opcode 顺序展开。每个规则先放 Primitive，有已编译 Higher 时紧随其后。相同调度列表复用词表。 |
| 父端口域 | 按输入角色的静态表类型取一条物理数组。首次见到的 `(table, owner, op)` 追加到尾部。同地址新版本更新向量。退役清除可见值，旧物理位置可以留在树里。 |
| 二分节点 | 对半开区间 `[lo,hi)` 取 `mid=(lo+hi)//2`，只读左半区位置 `(lo+mid-1)//2` 和右半区位置 `(mid+hi-1)//2` 的两个真实叶子。将 Query、两个 Key、分支种类输入冻结的 99→512→512→1 MLP，再按 sigmoid 概率选择左右。 |
| 更新 | 原树没有缓存子树表示。追加一个地址后，下次按新的长度重算二分位置，未移动的旧叶子也可能换路径。Metal 在发布时更新地址、版本、Key、类型成员及按 owner/op 投影的缓冲区。 |
| 模板 Query | 来自确认 Memory 聚合、最新发布变化、已接受请求/最近实际回执、开放依赖和当前事件。这一级还没有选定 Recipe。比较用的模板 Key 来自共享 GNN 和 Bake 接线。 |
| 父 Query | 模板选定后融合模板向量和当前 Recipe 输入角色节点。消费一个指定父端口后，冻结的 GRU 读取该端口向量和槽节点再生成下一次 Query。端口 Key 包含表、字段哈希表示、版本和转发状态。Query 不单独包含该规则的数值水位或原生 dirty 位，也没有无损保存完整绑定环境。 |
| 旁路 | 神经门可以复制最近地址，或选定首父 owner 的静态具名投影。这些路径可以与树命中同一个地址。首父投影开关会关联多个后续槽。 |

因此，对包含 1,024 个叶子的域，根节点只读取位置 255 和 767。固定 Query 时，只修改其他 1,022 个叶子中的任意一个，根分支得分都不变。在更深层仍有机会读到它，前提是先走进正确子树。这里没有“池化后保留了唯一关键 Cell”的保证。[物理地址域及 CPU 决策](../../discrete_cells.py) · [Metal 解码](../../draft_page.metal) · [发布与索引更新](../../resident_page.py) · [状态与回执](../../response_plan.py) · [端口编码](../../latent_cell_flow.py)

**实际路径。** sum-divisors 的 Run 147、规则 57，有三个正确父端口。模板在 241 个选项中排名 10，概率 0.01397。给对模板后，首父在 24 个地址中排名 9，概率 0.03935；给对首父后，第二父在 104 个中排名 8，概率 0.02480。即便前三项全给对，第三父在 1,202 个中仍排 629，概率 0.000331。这枚完整 Token 的单次概率是 4.51×10⁻⁹。逐层记录给出区间、左右真实 pivot、选择方向和条件概率。[这个实例](worked-example.json) · [所有 6,423 个绑定的概率、排名与原树逐层概率，gzip JSONL](paths-original.jsonl.gz)

## 109 个冻结状态

离线使用同一 teacher 快照的完整可见域，按程序和 Run 对齐。109 个状态含 6,423 个不同的已核验模板与版本化引用组合，含 6,423 个首父和 6,172 个后续父槽。**这些目标都在相应寻址域内。** 排名按目标发生次数统计，采用竞争排名，同时保留并列数。每个后续父的概率与排名都以已有前缀正确为条件。完整概率对复制和 owner 投影的多条生成路径求和；对后续共享投影开关使用给定正确前缀的条件概率。没有枚举父地址的笛卡尔积。

| 原模型 | 目标概率中位数 | 排名中位数 | 排第一 | 排前八 |
|---|---:|---:|---:|---:|
| 正确模板 | 0.603% | 49 | 7.24% | 16.91% |
| 给对模板后的首父 | 0.359% | 60 | 3.52% | 17.62% |
| 给对前缀后的后续父 | 0.627% | 31 | 6.27% | 24.81% |

正确完整 Token 的单次概率中位数约 9.17×10⁻⁸。首父所需分支在第 1、2、4、8、10 层的平均选择概率分别约 0.59、0.56、0.52、0.52、0.51；每层的分母是实际到达该深度的目标。在状态等权的口径下，一次独立抽样落在见证模板的概率质量为 25.5%，保留正确模板与首父后为 5.8%，延长至第二父后为 2.5%，命中完整见证的质量为 2.1%。[各阶段](stages.csv) · [各深度](layers.csv) · [各状态和干预](witnesses.csv)

**159 与 5,397 的距离。** 按历史 CPU 随机数消费顺序逐次运行，原始抽样文件逐字节一致。在 27,904 次抽样中精确找回 159 个不同绑定，12,209 次未形成完整 Token，2,838 次重复了同状态已有的完整输出。每状态最多 256 次且允许离线直接点名不同见证，合计上限为 5,397。在实际分布下，用完整概率算出的不同原地址绑定期望为 178.96。以下是逐状态计算后相加的离线诊断，均按原地址计。

| 对照 | 256 次抽样的期望不同命中 |
|---|---:|
| 有放回、只在已知绑定中均匀抽 | 4,587.6 |
| 保持模型落在已知绑定上的总概率质量，把这部分质量均匀分配 | 282.5 |
| 原模型 | 179.0 |
| 按见证数量提供正确模板，父寻址仍用原模型 | 606.0 |
| 同时按见证数量提供正确模板和首父，其余父仍用原模型 | 1,408.4 |

在这组有放回的反事实中，落在已知集合以外造成的损失大于已知集合内部概率不均造成的损失。集合以外还有合法替代证明。原生重放历史同一批样本后，允许替代端口的 Primitive 命中从 **159 增至 198**；另有 15 个仅由 Higher 的入口证明命中，单列且没有记为完成 Higher。[复现流水](reproduced-draws.csv) · [原生替代证明](original-native-recall.csv)

**相同 Key 的含义。** 正确首父中有 3,560/6,423 与另一可见地址具有逐位相同的 FP32 Key，最大并列组有 1,104 个地址。后续父槽有 1,588/6,172 个这类目标。对这 5,148 个出现位置分别换入一个均匀抽取的同 Key 地址，保持其他父引用不变。5,148 次替换的编码输入签名都一致，并且 **5,148 次均通过原生核验，指向原来的同一个签名绑定**。这项结果支持按实际证明语义评估召回。每个位置只抽一次，不能据此将所有相近向量或所有并列地址在运行时合并。[Key 碰撞](alias.csv) · [逐次原生替换结果](substitutions.csv)

## 同数据寻址对照

训练使用原有 sum、dot、训练 fork grammar 的 teacher/模型轨迹，共 108 个状态和 4,557 个已核验目标。四个评估程序均未用于本轮寻址训练。原 GNN、状态、GRU、复制门、owner 投影门、Recipe、Higher 与 CCP 均冻结。原树和直接 MLP 使用同样的 314,369 个可训练参数、初始权重、抽中的状态/目标及 1,600 步 AdamW；每步 32 个该域的已见证选择。树优化目标叶子路径的二元负对数似然，直接寻址用完整单角色域的 softmax 负对数似然。没有对未知绑定赋予原生非法标签。

直接 MLP 将同一个两 Key 打分器读成标量分数 `[f(q,0,k)−f(q,k,0)]/2`。训练前先用冻结权重比较，原树期望命中 179.0，直接 MLP 为 205.1。用同一未训练点积打分，两种读法分别为 198.6 和 200.7。另做每种角色类型使用一个 32×32 矩阵的小型双线性对照，单独训练后树为 126.0，逐叶为 173.7。改变归一化、打分函数和物理分组会有不同结果。

C 使用同一份冻结 Key 做固定投影，再按投影排序、二分。每个子区间以其真实平均向量为代表，用相同 MLP 和数据单独训练。Metal 在线为受发布、退役或静态模板列表变化影响的域重新排序并重建均值；全域的物理地址都保留，主机不读取排序结果选择伙伴。这个分区只是一个可复现的语义布局实验。[训练与分区](../../address_scores.py) · [设备缓存](../../address_centroids.py)

GPU 用设备内随机流，冻结原树的 174 与 CPU 的历史 159 是两批抽样。原生等价列要求同 Run、相同 teacher 签名绑定；所有 Higher 入口的额外匹配另存。实抽从每状态 4、16、64 增至 256 次，A 依次找回 8、29、86、229 个原地址绑定，B 为 8、28、95、272，C 为 8、31、87、263。B 相对 A 的 43 个新增净命中中，sum-divisors 多 45，loopfact 少 5。不能将单次采样差距外推为所有程序上的优势。[累计抽样与原生核验](samples.csv)

**Query 消融。** 保持目标前缀、类型域、真实端口、复制/owner 接线不变，只在诊断中移除 Query 的已绑定父 GRU 更新，原树期望从 178.96 变为 176.47，直接 MLP 从 265.28 变为 265.37。保留最后事件和确认 Memory，单独移除近期发布与接受结果对 Query 的显式贡献，两者分别为 177.22 与 262.10。这个实验只辨识这两条输入通道的边际作用。它不能说明动态信息毫无价值，也没有证明某个未提供字段单独解释了召回损失。当前证据不支持“单引用预测已经准确，剩下的主要是联合绑定”。

## 原生回执与端到端成本

上轮 sum-divisors，256 槽、1 步 DFM、block 0 的 3,917 个请求均是状态码 2，`untriggered_rule`。其中 3,558 个普通证明、359 个 Higher 入口，覆盖 250 个 Run 和 91 条规则。最多的三条是 279（382 次）、281（358 次）、289（281 次）。CCP 已收到请求且已计费；Runtime 在 `check_dirty && !dirty[rid]` 处返回，尚未调用针对父引用、版本、水位及 guard 的 `admit`。原生调度词表中出现规则，仅表示其 opcode 可请求。原生图变更的 Wake 可以置位 reader 的 dirty，调度消费可清位。这 3,917 次不能判断相同绑定在另一 Run 是否有效。没有把 dirty 传给模型，也没有用它在寻址前过滤。[逐请求明细](untriggered.csv) · [CCP 验证分支](../../../../../../engine/cell-runtime/src/token_transaction.rs) · [原生 Wake 与调度](../../../../../../engine/cell-runtime/src/runtime.rs)

B/C 只替换每个 Token 中当前角色的地址读取，零父、Primitive 与 Higher、命名投影、原生签发与验证沿用实际生成路径。A/B/C 在空草稿上独立生成完整 Token，每 Run 两页，考察每页 4、16 次，不进行 DFM 编辑。共 72 次独立 Rust Cell Runtime 执行，包括双线性对照及每配置两次正反序计时。所有外部绑定、通信、GNN、索引更新和原生执行计入墙钟。Coverage 用终图不同参考派生事实；EPT/EPS 的分子为署名有效原子操作，EPT 的分母含所有付费请求。这些是实际独立执行器结果，不是上游 egglog 的墙钟基准。

## 复现与边界

离线完整域概率、排名、置换、正确前缀、原生替代证书及 Oracle 仅用于测量。在线 CPU 提供真实物理地址、静态类型与命名投影，并在签发后执行原生核验。B 在 GPU 上打分单角色域，C 在 GPU 上给同域全部 Key 排序；均未使用字段相等、跨角色 freshness、dirty 或参考证明提前过滤。没有更改 DFM、Higher 结构、协议、参数规模或训练集规模。
