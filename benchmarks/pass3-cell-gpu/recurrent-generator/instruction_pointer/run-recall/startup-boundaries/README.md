# sum-divisors 规则 56 的 Higher 启动边界

**边界位置解释了一部分启动损失。将生产者移入 Higher 有时会同时引入晚到的证据；继续向前扩张可以获得合法入口，却仍会在后续绑定失败。** 在同一条自主轨迹上也有已入目录且可以完整执行的 Higher 被网络遗漏。本实验分别从实际回执、原生前缀反事实及冻结策略的路由和签发记录得到这三项结果。

实验基线为 `664019f8` 的 E 组、种子 536、每 Run 32 页。诊断覆盖留出 sum-divisors 的十个完整八步见证，起点均为 teacher Run 123，以及模型自己的所有对应调度前缀。被考察轨迹曾覆盖 172/8,018 个参考事实，付费 6,489 次。加入只读计数后重新独立执行，逐字段核对已接受请求、repair 记录、终图哈希、付费数、有效操作和各类原生判决，均与基线一致。本轮的边界来自测试轨迹，仅用于诊断；没有训练、上线这些布局或据此计入神经性能成绩。

十例的上述引用版本均为 119。左侧分别来自规则 51 对 If 行的投影（九例）以及规则 50 对 DoWhile 行的投影（一例）。左侧具名祖先均只有两个提交：初始化请求 1 和直接生产者。右侧均由规则 49 生成。它要绑定 `TupleT(tl)` 的结果、同类型的 `HasType(expr, type)` 以及同一个 `tl` 的 `TypeList-length`。每例左右两侧已签名生产者的交集都只有初始化请求 1。这个请求的一次原生执行计入 199 个有效操作；多个端口来自它不意味着一个端口就能充当其他端口。十例合并去重后，原八步主体及具名祖先共 291 个请求，涉及 28 条规则和 9 个初始化边界 owner。步数是已记录证明的提交数，其他合法证明可能更短。生命周期变化另作版本检查；端口首次产生与该端口后来变得可用是不同事件。[全部父引用、共享祖先、规则和逐节点信用](dependency.json)

以 1007 为例，764 只读取初始化请求的 `1.130@1`。740 需要 `610.0@1`、`584.3@53`、`12.3@9`。在自主轨迹中，规则 49 的 12 个调度 Run 都能看到三类表。按不同字段元组计数，可见 TupleT、HasType 和 TypeList-length 分别为 6、4、3。前两表之间有一个类型匹配，TupleT 和长度表之间有两个键匹配，三者同时满足的组合为零。字段交集仅作离线解释；每个前缀同时用原生精确枚举确认规则 49 的合法绑定数为零。自主轨迹没有签发成功的 49、50、51。规则 50/51 在自主 Run 17 分别有 1 和 4 个合法绑定，只读路由记录显示网络在该 Run 没有选到这两条 Primitive。因此两侧缺失有不同的直接原因。[逐前缀原生机会](exact.json) · [冻结网络的实际路由与原生签发](generator.json)

## 同一八步主体，更换入口后的结果

每行包含十个实际见证。外部槽按互不相同的具名 `(owner, op, version)` 计数。它衡量现有接口需要提供多少引用，未证明这是所有等价程序的最小独立输入数。当前 Rust 图证书可以在入口接收完整边界，也可以在同一 Run 验证首组中的多条规则；冻结 B 的 Higher 解码器每步接续一个请求，外部引用来自根绑定。此处使用原生图证书测试边界能力，给它比冻结解码器更宽的表达范围。

分母按**见证 × 首组规则共同调度的 Run**计算，同一轨迹的这些机会相关。例如 0/120 表示十个边界实例各经历十二个相关 Run。自主正例都经过真实图证书接管，必须校验全部有序外部端口及版本，且首组每个请求都实际执行。负例依据必要的端口类型缺失或首组原生合法绑定不足。未能构造具名见证但也不能证明不可能时，代码保留 unknown，本次表中该数为零。完整执行率衡量具体被试实例，不穷举替代接线和其他证明。自主的两个有入口组也分别实得 248–327 和 49–128 个有效操作，但最终均未完成八步目标。

**左右任取一侧向前移动，反而切断了入口。** 两个生产者同处 teacher Run 119，结果要在发布后才能消费。只吸收左侧，右侧的 `tuple-length` 在新入口仍未发布；只吸收右侧也会等不到左侧的 `leading-Expr`。把两侧同时移入，teacher 十例全部完成。另做完整 teacher 执行中的实际替代，原八步和十步各 10/10 通过终图、调度、写入、RHS、恢复与事件检查。十步入口的四个外部槽仍需满足规则 49 自身的两组共享变量约束，以及随后规则 56 对表达式的对应关系。自主状态的零个规则 49 绑定足以阻止它启动。

**两侧追到初始化，能启动的区域也可能执行不完。** 以 1007 的 59 步图为例，首次执行后冻结输出版本的策略遇到 13 个不同消费位置的版本落差。请求 149 的 op 3 在 Run 18 首次可见，版本为 17；Run 20 推进到 19，teacher 请求 326 在 Run 26 读取版本 19。十个实例有 13–59 个这样的消费位置。还观察到实际调度差异：59 步隔离执行在 Run 18 已尝试原见证 Run 26 才执行的 531 和 539，三个内部请求收到 binding 拒绝。现有“下一次被调度就接续”的语义无法重现这条特定轨迹。版本落差和实际首个拒绝分别记录，不能把所有失败归给同一个 guard。初始化贡献的 199 个操作已在表中计入一次；不能把这些已有工作算成扩大边界的净收益。[版本时间线及失败位置](versions.json)

## 四种瓶颈各有什么证据

| 情况 | 观察结果 |
|---|---|
| A．有可封装区域，现有目录没有 | 1007 右侧祖先包含一条七步规则 575 的 TypeList-length 递推。自主 Run 3 已有入口。用七条已命名的 TCons 引用和一个已接受的基础长度引用签发离线图证书，7/7 步完成，得到 7 个有效操作。当前部署的 trace 目录没有规则 575。它证明可封装性；七条 TCons 引用来自同一个初始化 owner 的不同 op，这个案例的接线从留出见证提取，未验证跨程序复用或自动发现成本。 |
| B．目录已有、自主入口合法、生成器没用上 | 在 1007 右侧谱系中找到了现有根 279 的三步 Higher 和根 544 的两步 Higher。在自主 Run 6，对 279 的三个原生合法根分别接管，3/3 完成，每次 7 个有效操作。冻结网络实际选了两次，签发两次，均为 binding 拒绝。自主 Run 8 的 544 有五个合法根，5/5 完成，每次 3 个有效操作，网络一次也没路由到这个 Higher。这些是各自独立的反事实，不可相加为终局收益。 |
| C．当前静态接线不足 | 完整具名祖先没有包含所有促成后续版本、绑定和调度的环境变化。图证书能编译且首组能执行；固定首次版本、按下一调度接续的执行器仍在十个实例中全部停在目标之前。实验确认当前表达和执行策略的限制，无法据此断言任一等价程序都必须动态搜索。 |
| D．扩大区域引入额外独立绑定 | 同时吸收两个直接生产者把入口从 2 槽增至 4 槽。若把已完成的初始化留在外部，完整祖先要绑定 47–172 个具名端口，分属 6–10 个 owner。把初始化移入区域可缩回 5–9 槽，但会重新执行程序特定的初始化。单侧扩张甚至在槽数不变时也可能因晚发布而失去合法入口。 |

575 还给出了可定位的生成偏离。Run 3 有两种合法的长度后继。模型签发成功的 TCons 与 teacher 所需 TCons 有相同的尾部，却属于不同的行。模型沿另一条后继产生了长度事实，没有生成 1007 所需的那条七步链。即使把七步链补齐，也只恢复了长度侧的一段计算；本轮没有据此声称其余 HasType 证据都会出现或 Coverage 必然上升。

直接生产者的目录普查单独进行。部署的 trace 目录没有包含 49 或 50；51 仅出现在根 346 的一个后缀，其已见证前缀没有产出这十例所用的 51 实例。原 wide 拓扑目录也不含 49，虽有包含 50/51 的布局，所查前缀同样没有命中目标生产者。Primitive 动作仍然存在。上表 B 的正例出现在更早的祖先，不能把规则名出现在目录中就解释为已覆盖两个入口。[两个目录逐布局普查](catalog.json) · [七步切片与已有 Higher 的逐根反事实](upstream.json)

## 执行与复现

本研究使用实际 Rust Runtime。原生隔离执行从 teacher 或模型的已接受前缀开始，只额外签发指定图证书并继续原生调度；不会用未来 teacher 请求保持图运行。完整替代对照则保留区域外 teacher 请求，并比较终态和事件。无效证书退回普通根时，普通根的有效操作单列，未归给 Higher。计数按原有原生 EPT ledger，包括存活的新增事实、写入、有效 union 和可见性变化。本轮没有将离线精确枚举、图证书强制选择或观察钩子的时间计为 Neural Execution 的 EPT/EPS，也未调整冻结策略。

在 instruction_pointer 目录执行。ROOT、冻结 actor、Rust 二进制和数据身份与上一轮一致。OUT 指向可写的临时目录，ACCEPTANCE 指向保存的 sum-bits 导出。输出中保留了完整调度负例、原生失败和未完成的部分工作。

```sh
export ROOT=/path/to/runtime-data OUT=/path/to/scratch PYTHON=/path/to/pytorch/bin/python
export ACTOR=run-recall/higher-scaling/weights/actor.pt
export ACCEPTANCE=/path/to/saved/sum-bits/exports
"$PYTHON" boundary_study.py "$ROOT" "$OUT"
"$PYTHON" boundary_generator.py "$ROOT" "$OUT" "$ACTOR"
"$PYTHON" boundary_upstream.py "$ROOT" "$OUT"
"$PYTHON" boundary_versions.py "$ROOT" "$OUT"
"$PYTHON" -m unittest discover -p 'test_*.py' > "$OUT/tests.log" 2>&1
"$PYTHON" ../../../../benchmarks/marker-handoff/choice_diagnosis.py "$ACCEPTANCE" "$OUT/semantic.json"
"$PYTHON" boundary_report.py "$OUT" "$OUT/report"
```

105 项单元测试通过，保存的 sum-bits 语义验收为 pass，minimal CPU 的 Cargo compile、run 和五次 bench 也已完成。它们用于回归验收，未用于估计扩大边界的速度收益。[测试记录](tests.log) · [语义验收](semantic.json) · [基线输入指纹与原生见证](../region-ownership/transfer.json) · [冻结模型权重指纹](../higher-scaling/weights.json)
