# 增量 Cell KV 与端到端完整 Cell 预训练

基于研究分支的 `6bfba4a9`。测试在 Apple M3 Max 上运行，使用 PyTorch 2.15.0、单线程 CPU 算子和本地 Rust CCP v0.1 执行器。三个程序从原生初态自主运行。Coverage 为命中的参考事实数除以参考事实总数，EPT 为原生有效原子操作数除以实际付费请求数，EPS 使用端到端墙钟。所有组沿用固定生成、固定退出、每页 6 个槽及每 Run 两页的策略。

**本轮有两个独立结果。** 冻结权重时，增量缓存将完整调度加速 1.74–1.85 倍，保留逐请求回执和终图。开放全部生成路径训练后，训练集上的完整 Token CE 最低，但三个留出程序在相同 256 枚付费预算下均未由端到端组获得最高 Coverage。

## 哪些 KV 能复用

| 数据 | 原路径 | 实施后的复用边界 |
|---|---|---|
| Recipe GNN、操作数节点、模板和类型表示 | 冻结时已经按 World 缓存 | 推理继续复用。会话限制 World 和权重版本。端到端训练按优化步重新构图 |
| 已发布端口的字段载荷 | 每次状态编码重新构造字段特征并线性投影 | 完整具名引用和载荷不变时复用投影。退役时从缓存移除 |
| 端口及 owner KV | 按当前年龄、类型、转发位、owner 的输出及可见父引用重算 | 同一发布视图整体复用。改变视图时按版本、epoch、载荷及具名父依赖更新端口与 owner |
| Response | 每次对整个回执前缀重新编码、投影 | 新回执的头、状态及具名父引用的静态部分只追加一次。同一发布视图只追加动态 KV。epoch 或可见父引用变化时，重新计算年龄和依赖可见性的动态部分 |
| dirty、watermark、近期 Response、当前 Query | 随决策状态输入评分器 | 始终从当前状态取得。旧 Query 或旧 Attention 权重跨 Submit 复用会改变模型概率 |
| 父前缀及字段关联 | 针对实际采样到的具名前缀评分 | 复用原页内分布缓存。批处理在当前上下文中按模板和有序前缀缓存 GRU 状态及按需读取的字段投影。前缀随决策上下文失效 |

`fact` 的冻结轨迹有 1,744 枚付费请求、375 次 Seal。旧路径累计处理 **660,216 个回执行**，其中同一条回执会随计算进度出现多次。在正序那一次，旧回执编码耗时 **5.102 秒**，新回执更新耗时 **0.893 秒**。新路径只编码 1,744 个静态头，仍为年龄及父可见性更新 330,544 个动态行，Attention 仍可读取全部历史。公开 Memory 累计访问 267,420 行，实际字段载荷投影 385 行，年龄感知端口编码 133,710 行，owner 重建 62,476 次，完整公开视图命中 374 次。该模型的年龄在非线性激活之前进入 KV，跨 epoch 永久保留整行会产生错误读数。[实现](../../incremental_kv.py) · [路径挂接点](../../cell_kv_model.py) · [成本与计数](cache.csv)

缓存仍有成本。校验追加历史时会比较已有前缀，改变视图后还要访问公开端口、建立分组并拼接张量。新 Query 对历史行的 Attention 也仍然随可见域增长。模板读出在 rich 路径中先计算一次基础读出，有可读 owner 时再覆盖该结果，本轮保留了该计算。[缓存测试](../../test_incremental_kv.py) · [状态及模板读出](../../cell_kv_model.py)

基准为带 owner 基数修正的扁平寻址核。基准和增量组都使用历史 `sweep-71` 冻结权重。在完整调度上以同一种子 193 先做基准→缓存，再做缓存→基准，逐次检查完整具名请求与回执摘要、Higher 来源和步骤、原生计数、参考事实集合及实际终图。下表墙钟列列出两次原值，EPS 为两次均值。[逐次配对](paired-timing.csv)

## CPU 与 Metal 批处理

每个原生会话独立推进。共享服务合并不同会话已经发出的同类神经请求，按各自域长度做 padding。单个会话的下一父槽仍由真实已生成前缀决定。容量 1 和 4 均从头到尾完成同样四个种子，每个种子上限 128 个付费请求。每格为两轮正反序运行的总有效操作数/整组墙钟的均值。下表包括上下文 KV 读取、owner 值归约、模板 GRU 及条件父寻址的批处理；原生通信、CPU 上的实例编码、张量准备和宿主采样均计时。另一项消融只批量处理模板和父寻址。两个设备、两种容量、两种读出范围的 **192 条轨迹**与各自的独立 CPU 参考一致。[逐次吞吐](batch.csv) · [计数和阶段时间](batch-costs.json)

| 程序 | CPU 容量 1 EPS | CPU 容量 4 EPS | Metal 容量 1 EPS | Metal 容量 4 EPS |
|---|---:|---:|---:|---:|
| fact | 70.38 | 68.76 | 36.04 | 48.07 |
| loopfact | 60.34 | 58.51 | 31.91 | 35.26 |
| sum-divisors | 158.75 | 149.90 | 86.72 | 106.32 |

`fact` 的 Metal 容量 4 反序运行中，836 个真实父查询组成 382 个批次，实际平均 **2.19** 个查询，访问 **206,178** 个候选行。四类调用合计 836 次回读，逻辑上传 323,149,837 字节，回读 1,918,316 字节；统一内存下这些数字表示设备 API 提交的数据量。父投影能在同一视图驻留，owner 和 Response 的上下文张量仍按批填充与传递。准备及关系核派发合计 2.51 秒，上下文/owner/父/模板计算与收集合计分别为 0.598/0.104/0.583/0.172 秒。CPU 三个实测 fact 页的独占算子时间中，60 次 mm 用 0.531 ms，53 次 addmm 用 0.174 ms，318 次 cat 用 0.915 ms，476 次 index 用 0.976 ms。设备 Event 另存每类前 16 个分组的区间计时，包括冷启动和其中的归一化等算子；这些计时与派发墙钟有重叠。实测 CPU 在这些批量下更快。[三程序 CPU 算子明细](operators.json) · [Metal Event 原始计时](metal-events.json) · [真实批处理路径](../../incremental_batch.py)

## 完整 Cell CE 的训练与留出

**模型注册 32,874 个参数。** 在这批真实输入及目标上，以模块调用和直接张量读取跟踪到 18,880 个参数元素所属张量进入前向。A/B/C 的反向连通张量分别包含 4,160、10,624、18,880 个元素。C 中至少一次非零梯度的标量为 18,560–18,688 个，最终可测得权重变化的为 18,490–18,612 个。冻结权重推理使用相同的静态图缓存；C 的训练每步重建可微 Recipe 图。参数级列表记录了连通性、非零梯度和实际变化。[参数与语料清单](parameters.json)

每个工作负载留出整份程序，用另外两个 EggCC 程序的 Teacher、自主状态、原生核验分叉，以及基础绑定和 Higher 反事实样本训练。同一来源最多抽取 32 个独立状态，按状态合并核验过的完整目标，每个状态一次 CE 反向。保留上游初始化，从相同起点、相同状态和相同目标比较各组，训练种子 71/113 控制状态顺序。AdamW，学习率 0.001，权重衰减 0，梯度裁剪 2，3 轮曝光。每折有 92 个 Higher 目标，语料包含零父到六父，loopfact 留出折另有一个七父目标。留出验证分别记录 Teacher 和自主状态；训练来源共享基础结构，仅能声称该折训练排除该 EggCC 程序，不能据此声称所有历史权重从未见过其结构。[训练程序](../../incremental_fit.py) · [留出集状态数、目标数和 CE](heldout.csv)

## 活跃与失活窗口

在生成与签发完成后，根据当时的公开静态类型域及原生入口检查状态做归因。活跃表示至少一个可构造入口通过触发状态这一项检查。失活表示所有可构造入口均失活。没有静态可构造入口单独统计。分类结果从未传回策略。时间为相邻原生发布事件间的墙钟，包括推理、通信和 Seal。下表采用冻结 sweep 权重、种子 193、完整调度；这些轨迹没有产生内部 Higher 有效步骤。

| 程序 | 活跃窗口，付费 / 有效操作 | 活跃 EPT / EPS | 全部入口失活窗口，付费 / 有效操作 | 失活墙钟 |
|---|---|---|---|---:|
| fact | 37，214 / 135 | .631 / 174.2 | 255，1,530 / 0 | 7.03 s |
| loopfact | 36，208 / 125 | .601 / 161.5 | 211，1,266 / 0 | 6.10 s |
| sum-divisors | 32，180 / 276 | 1.533 / 349.3 | 257，1,522 / 0 | 8.18 s |

三个程序的失活组 EPT、EPS 均为 0。固定退出与固定生成保留了这个真实成本。结果也包含 A/B/C 各自完整调度的分层，不能将时机和计算发现方面的损失归入缓存加速。Teacher 和核验目标仅用于离线训练及留出评估；运行时父选择仍由网络按公开类型域、具名版本及实际前缀评分，未引入语义候选过滤。[全部窗口](activity.csv) · [归因代码](../../incremental_windows.py)

## 复现

在本目录上两级的 `instruction_pointer` 下执行。需要同一原生执行器、编译器、已采集的 EggCC 检查点与语料，以及支持 MPS 的 PyTorch 环境。本机原始逐次 JSON 和权重位于 `/Volumes/Extreme SSD/eggfuse-experiments/conditional-value/incremental-foundation`。完整运行可指定新的结果目录，已有原始文件的实验步骤会复用已完成记录。

```sh
export ARTIFACT_ROOT='/Volumes/Extreme SSD/eggfuse-experiments'
export PARTNER_INDEX_OUT="$ARTIFACT_ROOT/conditional-value"
export CELL_DATA=/tmp/dfm-local/data
export CELL_REPLAY=/tmp/cost-audit-build/release/examples/cell_token_replay
export CELL_COMPILER=/tmp/cost-audit-build/release/eggfuse-cell-compiler
export PYTHON=/tmp/prefix-ml/bin/python
sh incremental_reproduce.sh
"$PYTHON" -m unittest test_incremental_kv test_cell_kv test_prefix_attention test_continuous_stream test_value_read test_selected_cell test_joint_cell test_structure_runtime
```

关联基础语料的生产步骤沿用上一轮的 joint_cell_reproduce.sh，具名采样与历史基线沿用 continuous_reproduce.sh。结果生成器拒绝汇总请求、回执、事实集合、原生计数或图签名不一致的配对。仓库最小 CPU 分支的 Cargo compile/run/bench 和已保存 sum-bits 输入的 choice_diagnosis 也已通过，后者为既有语义合约回归；本报告的 EggCC 验收来自实际 CCP 原生运行。
