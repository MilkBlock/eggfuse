# Latent computation flow on native Cell transactions

Two questions guided this experiment. Does a pending token change the predicted marginal effect of the next token? Can a policy use a newly compiled program based on its wiring? On held programs both behaviors occur. Neither reliably increases end-to-end throughput at preserved coverage.

## Execution and supervision boundary

The research base is 665fc8fa. The Rust CPU executes and validates named references through CCP v0.1. Exact forks, factual reference exports, certificate replay, and terminal coverage alignment are offline. We did not invoke CostBake, its freshness proof, a cross-role maximum watermark, semantic equality retrieval, or future teacher state in a live decision.

The shared actor in actor.py encodes Recipe declaration, operand and instruction nodes. GraphBank and CellScorer in ripsat_policy.py connect a producer operation and owner step to a specific consumer slot, distinguish boundary slots, and encode publication group. Query/effect operands and ordinary merge sites enter the catalog. Conditional receipt existence, retirement and custom repair are not guaranteed by the static vector. The native contract, actual publications and pinned versions resolve named outputs. A shared variable edge in a graph does not make a pooled graph embedding lossless.

The existing CCP client knows which requests await responses. Its pointer decoder did not consume that state. The experiment keeps confirmed named ports separate from a provisional transaction state. The frozen 32-dimensional port encoder reads native field hashes, type, version and forwarding status. A publication removes obsolete vectors and adds the affected rows. The sum is a projection of the current visible store. It does not represent every e-class, an unpublished scalar value, or an arbitrary explored region exactly. Physical search history is recorded in an independent audit and is not a learned component of z. Pending handling here spans at most two proposals. Receipt collection ends that provisional window; only publication changes confirmed rows. There can be accepted work that is still unpublished across that boundary.

A common reference uses the existing B binary template decoder with GNN-derived tree codes and a greedy learned pointer over **every** visible row of a chosen static type at non-source slots. We charge the entire matrix multiplication. The source event obeys its own scheduled watermark. Static role ordering uses the Recipe. The existing field index is maintained in all arms, but its semantic buckets never filter the pointer domain here. This narrow reference sacrifices alternative bindings. Its coverage cannot be compared as an improvement over the historical high-recall Cell Stream. All timed rollout operators used CPU PyTorch and native Rust.

## Actual prediction training

99 same-start contexts contributed seven complete native forks each. We retained only contexts with a verified common before-frame and an observable after-frame. The alternatives were empty, A, A+A, B, A+B, B+A, and a wrong-version A. The native verifier confirmed the repeated proof and the version rejection in every retained context. A fixed common background request was used in short grammar schedules when needed. Native sum-bits teacher, a separate sum-bits model rollout and a grammar supplied 47 training contexts. Dot-product supplied 12 validation contexts. The three EggCC tests and a separate grammar supplied 40 test contexts. A missing comparison was never labeled negative.

One Flow MLP predicts a vector. A mode input distinguishes absolute publication change, marginal change at fixed background, and unconditional horizon. Single-step, four-frame and sixteen-frame targets came from the actual consecutive frames of each individual trajectory. Training used MSE in the common projected space, divided per sample by one plus the mean squared target component; the reported MSE is untransformed. See the training code for exact weighting. Three state-conditioned and three token-only fits use identical splits and validation selection. Seed 137 was fixed for deployment. A second collection of the same encoder outputs and a retraining reproduced prediction.json byte for byte.

For pairs in which one candidate contributed and a repeat contributed zero in the observed projection, the deployed state model ranked them correctly 34/38 times. Token-only scored 15/38. By program the state model scored 10/12, 10/10, 10/12 and 4/4. State seeds 293 and 431 each scored 35/38. These comparisons identify a repeated named proof and a selected productive alternative. They do not establish general semantic equivalence detection. On sum-divisors the one-, four- and sixteen-frame errors were all within 0.2% of always predicting zero. Multi-step forecasting has little support on that workload.

An independent two-rule fixture gives a stronger negative control. Each proof establishes the same source relation Outcome(42). After the first proof, issuing the other is accepted under a distinct rule and leaves the visible export byte-for-byte equivalent after sorting rows. The model still predicts a displacement norm of 5.84, compared with 6.43 for the second proof issued alone. Native proof duplicates, identical reference lists and duplicate semantic outcomes have distinct meanings. The native admission key is the rule plus checked input values. Physical constructor IDs can also differ between two independently materialized instances of the same source relation. See overlap.json.

## Independent EggCC and grammar runs

There are four alternating-order timing blocks per program. Coverage counts different reference-derived facts. EPT is native signed effective operations per actual CCP request. EPS below is effective operations divided by measured driver/runtime time including setup of the frozen encoder and policy. Native reference construction, post-run replay/coverage comparison and offline training are excluded. Timings were collected on a shared workstation. Some paired blocks overlapped other local experiment processes. Small grammar timings are especially variable. The recorded native endpoint digest and the set of covered reference indices are separate comparisons.

## Higher Cell generalization

Training donors were eight native instances of a single two-step chain, verified by native certificate replay against the primitive tape for endpoint digest, schedule, writes, RHS, resumes and events. Composition training matches the measured endpoint displacement, each observed primitive displacement, the **predicted** sum of state-conditioned primitive steps and the horizon target. There is no Higher ID embedding. The shared GNN previously saw other Higher structures during its historical pretraining; the primitive-only control refers to the Flow fit. Held fixture Bake followed the weight freeze. Normalized signatures were checked against the donor and the historical 10,000-template catalog. Training and held graphs have distinct normalized signatures. For the EggCC experiment we additionally excluded all 10,000 historical catalog signatures and the donor signatures.

The controlled fixtures place one primitive and one statically addressed Higher at the entry. Native independent runs separate effect prediction, choice, root acceptance and completed execution. Five arms include a forced diagnostic. On fresh chain3, chain5, diamond and shared-input graphs, composition training reduced MSE from 2.64 → 1.60, 7.63 → 4.74, 2.72 → 2.44 and 4.77 → 2.85. Selecting the larger predicted displacement chose and completed all four; primitive-supervised Flow also chose all four. Matching the predicted horizon chose none. Each arm reached the reference endpoint and paid respectively 4, 6, 5 and 5 CCP requests.

The same three-step guard layout was offered with the guard true and false. The composed policy chose both and completed only the true instance. With all output facts preexisting, effective operations were zero, yet the policy still selected the macro and paid six requests against four for primitives. New physical receipts and version changes can have latent displacement with zero effective operations. This is a concrete mismatch between the supervised target and useful computation.

For held programs we baked one statically wired two- or three-step option per eligible unary entry directly from the native Recipe receipt contract, without a teacher/rollout profitability filter. This gave 31 options per EggCC program and none on the grammar. The current B decoder routes to the primitive entry; only its single optional Higher and its primitive are scored, with the same GNN and learned displacement. An accepted root only unlocks explicitly wired suffixes. The runtime still pays each primitive CCP request, verifies the pinned named receipts and respects scheduled publication. It performs no partner lookup. Even after activating a macro the EggCC primitive search remains live. Macro completion alone earns no skipped-search credit.

Primitive-supervised Flow completed 14 too, with 23 selections and 37 lowered suffix requests versus 29 after composition training. On fact the composition-only group completed 6/6 chosen; on loopfact it completed 3/3. For the full stacked horizon arm on sum-divisors, 3,157 requests yielded EPT .1156 versus baseline .1122, but cold EPS fell from 275 to 169. The four paid timing repetitions use the same programs and initial facts. They are not new independent template instances.

Live EggCC records include the cost of reading ports, pointer positions, evidence encoding, selection, actual CCP, open instances, paid suffixes, and setup. The standalone controlled fixture runs precompute static codes once, time the independent driver separately, and have no directory-scale retrieval. This is a bounded two-way decoder experiment. We have not demonstrated open-ended inverse decoding, general unseen-layout addressing, or an encoder with no lifetime exposure to Higher structures. The experiment does not establish a Coverage–EPT–EPS improvement over the high-recall generator.

## Reproduction

Use the instruction_pointer directory, the project PyTorch environment, the frozen checkpoints in run-recall, and native compiler/runtime binaries from the pinned research branch. Supply DATA in the existing recursive_train.folder layout, GRAMMARS containing the two grammar directories, ROLLOUT containing sum-issued.json and sum-native-memory.jsonl, and the opaque parent ACTOR checkpoint. In RUNTIME_DATA expose the same programs, the two grammar directories under recursive-agent, multi.pt and unified-scale/build/release/examples/cell_token_replay. Use a writable scratch directory for OUT and for compiling the small fixture programs under RUNTIME_DATA/recursive-agent.

1. Run latent_forks.py RUNTIME PROGRAM_DIR TAPE MEMORY OUT/NAME.jsonl --contexts N. Use 32 for sum, 12 for each other source including the grammars. Sum-roll uses the sum program and the model-issued tape and memory. Short schedules can yield fewer complete contexts.
2. Run latent_cell_flow.py DATA GRAMMARS OUT ROLLOUT ACTOR. This fits all six models and freezes the deployed weights before program Bake.
3. Run latent_live.py RUNTIME_DATA OUT ACTOR CASE A B C serial Cdecode --ratio 0.7101457715034485 --block 0. Repeat for blocks 1–3, reversing arm order on odd blocks. Run A C once more with --search-audit --block 0 for the separate instrumentation.
4. Run latent_composition.py RUNTIME_DATA COMPILER ACTOR OUT, then latent_egg_higher.py RUNTIME_DATA OUT ACTOR. Each script performs four alternating-order blocks internally. The forced fixture is diagnostic only. The oracle receives the teacher tape exclusively in the offline relabeling function.
5. Run latent_overlap.py COMPILER RUNTIME ACTOR OUT and latent_results.py OUT RESULT_DIR. inputs.json pins raw fork JSONL and model digests. prediction.json, higher.json, egg-higher.json, independent.json, overlap.json and the model checkpoints accompany this report.

The project semantic acceptance returned pass on the saved sum-bits exports. The README Cargo compile, run and five-repeat bench ran locally. The runtime ABI and the B2/B3 rules were unchanged.
