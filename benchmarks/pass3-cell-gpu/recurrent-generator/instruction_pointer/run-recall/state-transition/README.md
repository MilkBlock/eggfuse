# 执行前后，完整 Cell Token 的概率去了哪里？

在真正发布入口证据以后，连续状态训练将核验有效的 Higher 完整 Token 的平均概率从冻结基线的 12.51% 提高到 45.41%。更严格的双分支测试发现，它提高了整个 Higher 家族的概率，同时削弱了根据入口值选择正确分支的可靠性。模型也可能在自主执行中错过生产入口的机会。三个真实 EggCC 程序仍未获得一致的 Coverage、EPT、EPS 收益。

## 基准和证据边界

使用与 3b1197ac 相同的结构化 KV、GNN、模板和引用解码器。每个状态来自真实 CCP v0.1 进程。保存实际生成前缀、具名引用及版本、响应和发布记录；从相同程序、地址种子和动作前缀启动新的 Runtime，逐窗口比较快照、请求和回执后再干预。从 S 分出空提交和仅签发一枚核验 Token 的路径，两边照常 Seal。在下一发布窗口分别得到空对照和 S′。单请求核验在该分支上继续跑完调度，只保留已签发 Higher 的具名内部接续。完整效果按相对于相同前缀静默分支的新增行计；原有行必须保留，Higher 还必须由本次签发的 owner 完成。没有直接证明新增贡献的候选不参与 CE。此判据覆盖这些关系型程序中的实际效果，不能推断所有长程必要性。

混合程序有两个 Seed、生产 Ready 的 Primitive、多个竞争 Primitive、零父和二父规则，以及两个同接口、不同内部 guard 的 Higher。根 ruleset 连续运行三次，生产 Ready 和消费 Ready 用同一目录。评估包含六个新程序，训练与留出的数值、地址种子分离，本轮训练与评估 Higher 的规范化结构签名无交集。Mutable Best 的单独版本探针使用可变函数及原生 max 合并。所有枚举、诊断复放和等效贡献分组均离线；自主生成只使用当前发布 Memory、调度菜单、既有静态类型约束和网络概率。不放回只扣除本页已经选出的完全相同的模板及有序具名引用，下一页重新开始。

## 数据审计和实际训练

上轮 60 个训练程序的 180 个 Teacher 决策窗口包含 1,056 个有贡献的具名目标。首个监督窗口以后有效 Higher 目标数为 **0**，使用正向运行中产生的父引用的 Higher 目标数也是 **0**。此前已经有多个程序阶段的状态，但它们没有覆盖本次要学的 Primitive 发布入口再激活 Higher。

新训练集来自 12 个程序。两个冻结策略权重交替生成三槽页，沿其真实执行路径审计每一窗口，并在前两个窗口对可产生贡献的模板做单请求和空提交分叉。共 90 个自主前缀，加入分叉后有 164 个受审前缀，公开快照按程序去重后为 154 个。858 个单候选干预给出 145 个前缀内正目标，其中 19 个是使用新父引用的 Higher。38 个前缀有正例，其中 26 个来自自主路径。其余前缀保留于审计数据。评估另有 54 个自主前缀、总计 94 个受审前缀、91 个不同公开快照及 30 个单请求配对。这里没有把不同前缀自动等同于独立的神经输入。[语料明细](corpus.csv)

比较冻结的 B、同起点的 Teacher 续训、同起点的连续自主状态及分叉续训。两种续训都在上述 12 个训练程序上运行，使用完整 Token CE，先均匀抽本状态中核验不同的新增效果，再抽一种具名实现。Teacher 对照访问完整 Teacher 前缀中有正例的 48 个状态、204 个正目标。每个训练种子 420 次更新、6,720 次完整 Token 曝光；连续组两个种子分别有 4,208、4,232 次来自自主前缀，其余来自原生分叉。CE 逐状态训练，前后状态的关联用于构造和审计样本，不提供未来输入、时序损失或新预测头。两组的状态和正例组成不同，差值包含这种分布差异。[训练曲线](training.csv)

## 同权重、同快照的概率变化

下表对类别非空的干预取均值。完成类有 30 个实际干预，新出现类有 6 个；每个干预对两个权重种子重复评分。

| 经核验的具名集合 | 冻结 B，S → S′ | Teacher 续训，S → S′ | 连续状态续训，S → S′ |
|---|---:|---:|---:|
| 原有效且其效果已全部实现，重签无新增 | 12.84% → 12.46% | 19.54% → 13.65% | 17.66% → 11.25% |
| 原有效、效果未全部实现、签发窗口关闭 | 34.63% → 32.25% | 45.60% → 33.50% | 47.32% → 20.06% |
| 新出现的全部有效 Token | 0 → 41.52% | 0 → 28.76% | 0 → 69.81% |
| 其中新出现的有效 Higher | 0 → 12.51% | 0 → 9.55% | 0 → 45.41% |

上述新出现的 Token 在 S 中都缺少实际具名引用，空提交后概率也仍为 0。零到正包含引用进入可生成域的结构性效果。发布后对新证据如何分配概率才能反映权重差异。完成类与其他失效类重签都遇到原生触发或水位检查，不能将二者共同下降全部归功于学会去重。例中 Seed 的具名引用为 (-3,0,0)，Primitive 请求 1 被接受，实际发布的新 Ready 引用为 (1,0,1)。在案例 0、权重种子 71 上，Higher 14 绑定该引用的概率从 0 升到 23.21%，原生完成后增加五行。[同一状态与实际回执](example.json) · [逐干预概率及空对照](transitions.csv)

**条件选择。** 从同一个起点只改变生产 Ready 时网络指定的具名 Seed。两条分支的发布时刻、候选目录、端口地址、类型及版本相同，Ready 的值和父来源随实际请求改变。两个 Higher 的正确性在两条分支间翻转。要求两边都将正确 Higher 排在另一 Higher 之前。六对程序 × 两组权重，冻结 B 为 11/12、Teacher 为 12/12、连续组为 3/12。在这组双向配平状态中，连续组对整个 Higher 家族分配 61.88%，对正确完整 Token 分配 37.57%；冻结 B 分别是 16.34% 和 9.94%。家族质量提高可以与相对排序退化同时发生。样本量不足以推断通用结构遗忘。[配平分支的概率和排名](matched-higher.csv)

**Submit 与 Seal。** 在公开快照固定的同一个 Run 内先签发一枚 Primitive，再独立提交第二笔事务。六个测试程序中，重签相同具名 Token 收到六次 duplicate，均无新增行；另外 24 次重签前仍可做的不同计算全部被接受，各新增一行。两次 Submit 之间从活的 Memory 重新取快照并重新前向，当前解码器的输入完全相同。连续组给刚执行 Token 的平均概率保持在 10.86%。现有输入包含上次发布的 accepted/update/retired 数量、Run/epoch、具名版本、父引用、字段与实例归属；即时签发回执没有在 Seal 前进入该输入。发布后，连续组的上下文向量与空对照确实有差异；这个差异本身不能证明网络理解了贡献。主基准跨发布时没有保留同一具名有效绑定的实例，上述 24 次是同 Run 的持续有效证据，两种分母分别记录。[同窗口原生双提交](before-seal.csv)

**版本。** Best(3) 实际从 10 更新为 20，同一个 owner/op 的版本从 0 变为 1。旧版 Observe 请求被原生返回 version；新版两种具名证明都能产生 Observed(20)，两条证明只对应一种新增效果。旧具名 Token 的概率在发布后变为零来自当前版本域的变化。空提交分支保留旧版地址，尽管该窗口审计已无法取得新增 Observed，模型仍给旧请求正概率。[版本读取及旧请求强制重放](versions.csv)

## 自主执行、固定槽与固定付费预算

额外对三种策略自己的轨迹逐状态原生分叉审计。在混合环境、抽样种子 193、六槽独立抽样的 12 条轨迹里，冻结 B、Teacher、连续组在首窗实际产生 Ready 的次数分别为 8、11、2。次窗相应具备有效 Higher 的次数也是 8、11、2；实际生成至少一个核验有效 Higher 的为 5、5、1。换成页内不放回，三者都在 12/12 条轨迹中创造了入口，次窗生成有效 Higher 分别为 9、9、12 次。这是状态到达、计算生成与完整 Higher 完成之间的区分。这些频数来自共同随机流；逐状态的精确概率质量另外记录。[每条策略的真实状态与概率](on-policy.csv)

固定退出且完整跑完原生调度。以下受控结果覆盖六个程序、两个训练种子及两个生成种子；每种条件正反序各计时一次，重复的事实集合、终图、操作和请求计数必须相同。EPT 使用原生有效原子操作除以实际付费请求，EPS 使用同一分子除以含神经生成、缓存准备、通信及原生执行的墙钟。计时在离线终图对齐之前结束。均值按执行计算。单线程 CPU 推理；机器未做系统级隔离，细小时间差应结合原始配对离散度解读。

| 混合环境，连续组固定权重 | 独立抽样 Coverage / EPT / EPS | 页内不放回 Coverage / EPT / EPS |
|---|---|---|
| 总共提供 18 个生成槽，24 对全部达到 | 13.96% / .335 / 185 | 36.67% / .514 / 437 |
| 两种抽样都恰好支付 18 次的 10 对 | 21.50% / .239 / 246 | 36.50% / .406 / 382 |
| 每窗六槽，完整执行全部 24 对 | 23.75% / .316 / 228 | 50.21% / .543 / 436 |

同一完整六槽条件下，冻结 B 为 26.88% / 40.63% Coverage（独立 / 不放回），Teacher 为 26.25% / 59.17%。连续组在不放回时超过冻结权重，仍落后于 Teacher。全局槽预算包含预留后未填满的槽；另报实抽数。付费上限包括 Higher 接续，耗尽后保留 pending，照常发布并走完既定调度。部分策略无法用满上限；等实付子集有选择偏差，另提供全部配置。相同预算并不保证相同终图。[所有预算点](budget-curves.csv) · [实付配平](same-paid.csv) · [事实集合交差](draw-facts.csv)

## EggCC 迁移

在 fact、loopfact、sum-divisors 的真实 Recipe 上测试冻结 B 和连续组。沿用既有 Primitive 目录和构造子对齐，分母分别为 1,120、1,112、8,018 个参考事实。神经空提交控制在三个程序和受控混合程序的新增参考事实、有效操作和付费请求均为零。EggCC 每组两个训练权重、一个生成和地址种子 193、两次反序配对。受控 Higher 没有移植进 EggCC。

| 六槽每窗、独立抽样、完整调度 | 冻结 B：Coverage / EPT / EPS | 连续组：Coverage / EPT / EPS |
|---|---|---|
| fact | 2.90% / .430 / 15.18 | 2.95% / .366 / 14.81 |
| loopfact | 4.05% / .237 / 11.36 | 3.51% / .336 / 10.42 |
| sum-divisors | 1.46% / .518 / 33.99 | 1.28% / .748 / 36.31 |

连续组在三个程序独立抽样时，将全局槽预算从 96 提到 384，平均发现的事实分别从 32.5 到 33、38.5 到 39、100.5 到 103。进一步比较实付 64 次与完整无付费上限执行，三个程序的平均覆盖数量均持平。页内不放回在完整执行中对应 31、39.5、100.5 个事实。数据支持“训练可改变发布后的概率分配”；对于持续创造入口、维持条件分支辨识和改善 EggCC 前沿，还没有一致的正向证据。[逐次执行与终图](native.csv) · [空提交控制](idle.csv)
