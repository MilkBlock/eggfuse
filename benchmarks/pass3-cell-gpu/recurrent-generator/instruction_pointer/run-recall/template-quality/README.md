# 哪些深层模板能迁移

Neural Compilation 离线审计与 Neural Execution shadow 诊断。冻结 3a1e1c1d 的 10,000 项参数化目录、GNN 和父端口模型。使用原训练 tape（sum、dot）和三个既有评估 tape；这些评估程序已用于开发。没有用评估结果训练或改动执行器。目录和权重 SHA-256 随[审计结果](audit.json)记录。

## 入库门槛的实际效果

deep_ripsat 的目录选择先按就绪支持排序，再从被观察的深层布局中补足 size。一个布局即使在两个训练程序上都没有出现过可在入口绑定且按首次调度执行的实例，也可以入库。训练代码分开监督“在轨迹中出现”和“当时能够启动”。下表按实际训练时的 donor 映射、原挖掘器和不同 teacher 根提交计数。同一个根的多个匹配只算一次。

| 训练就绪根数 | 模板数 | 在至少一个评估程序就绪 | 比例 |
|---|---:|---:|---:|
| 0 | 5,210 | 5 | 0.10% |
| 1 | 3,473 | 918 | 26.43% |
| 2–4 | 1,007 | 576 | 57.20% |
| ≥5 | 310 | 258 | 83.23% |

在训练就绪为零的 5,210 项中，3,456 项的完整布局在评估 tape 的采样子图中重现，只有 5 项有就绪实例。五个例外的目录下标为 4812、4813、4814、6090、6091，均在 sum-divisors 出现。在有训练就绪样本的 4,790 项中，1,758 项重现，1,752 项至少有一次就绪。可据[逐模板数据](templates.csv)按深度、独立外部槽数、程序和根数复核。这是条件频率，不能从相关性推断多重复训练几遍就能提高迁移率。

各关累加约束；差值取决于检查顺序。观察范围是每次最多十步的祖先/消费者挖掘，绑定采用已录制的具名证明。因而缺失指这次没有找到，不能证明目标程序上没有替代证明。为检查遍历偏置，保留原消费者扩展，并轮换每个不同直接父亲作为祖先遍历起点。三组就绪模板数分别变为 325、450、1,694。所有评估在目标程序自身规则命名空间挖掘，再与结构链接目录比较；旧精确 donor 指纹可能漏掉某些生产者。

## 晚到的外部输入

FullTemplates.begin 在根获准时绑定后续所有外部槽位。按采样实例计数，在已经重现接线但未就绪的记录中，入口至少缺一份外部回执的比例分别为 1,634/1,653、2,117/2,125、21,945/22,415。一次失败可以同时遇到多种问题。比例不包括未重现的布局；也不代表把等待条件放宽就能成功执行。

一个例子是 loopfact 的目录下标 4790。该五步模板的接线在 16 个不同根提交处出现，全部没有就绪实例。其中一次根 token 1012 在 Run 185 提交，后继规则 287 在 Run 191 读取 Smaller。所需外部端口 (1028, 8) 由 Run 190 的提交产生。即使识别器预先知道应选该模板，Run 185 也无法绑定这份具名输入。每个程序按失败模板的重现根数取前三例，详见 audit.json 的 late_examples。

## GNN 与模板质量各自损失多少

给定正确根规则和 teacher 快照，只在对应根事件上打分。下表以事件与根提交的组合计数；一个根可对应多个事件。相同根上多种就绪模板中的任一个被选中均算正确。

| | 有就绪模板 | 选中就绪模板 | 放弃 | 选了其他模板 |
|---|---:|---:|---:|---:|
| fact | 350 | 36 | 150 | 164 |
| loopfact | 346 | 47 | 202 | 97 |
| sum-divisors | 3,158 | 564 | 1,687 | 907 |

当前识别器读一个 16 维事件向量和该根的模板菜单。按规则与逐位相同的事件向量归类，在评估标签上为每类事后挑一个最有利的模板，上限分别为 328、333、3,060 对。这个数字只检验完全相同输入导致的 top-1 冲突，允许记住每个不同向量，不是可部署模型的预期表现。

此前独立 Rust 执行的实际尝试、启动、完成分别为 94/71/25、68/65/19、250/242/74；三组在内部步骤遭拒的次数分别为 38、41、164。独立执行的状态分布不同于上面的 teacher 状态。这些实测及 Coverage、EPT、EPS、拒绝明细见[冻结执行](../parameterized-deep-ripsat/independent.json)与[逐次回执统计](../parameterized-deep-ripsat/raw)。

## 同权重的训练支持对照

仅用训练信息选取 4,790 个至少就绪一次的模板。在已采样就绪证明所覆盖的不同 teacher 步骤上，完整目录与该子集分别为 fact 982 → 982、loopfact 942 → 942、sum-divisors 8,847 → 8,841。这里计数的是去重的历史 token；没有把包装机会计作运行时节省。若再把入选门槛提高到五个不同根，只剩 310 项，机会覆盖降至 570、636、5,884。将模板当作永久不可用会丢掉有证据的低频推导。

在相同 teacher 事件上重新运行冻结的 GNN，只改变菜单，实际选中就绪模板所覆盖的不同步骤分别为 150 → 150、155 → 155、1,701 → 1,701。因此在这三条轨迹上，低支持模板增加菜单负担，却没有解释剩余模板识别率低的现象。本次没有重新运行独立计时。

从 instruction_pointer 运行以下命令。ROOT 包含 sum、dot、fact、loopfact、sum-divisors 的 program.json、tape.json 和 memory.jsonl。

```sh
python template_quality.py "$ROOT" run-recall/parameterized-deep-ripsat OUT
```
