# 跨 Submit 连续生成与预算内计算发现

冻结全目标 CE 权重后，连续采样在三个真实 EggCC 程序上都能运行。严格复用决策视图节省了编码，六条完整轨迹没有增加一个事实。降低近期具名请求的采样权重在完整调度中增加了一些发现，但三个程序在 256 请求时都比原模型少覆盖事实。可以稳定复现的效率收益来自保留原概率的扁平读出。现有证据支持保留固定生成生产基线，尚不足以启动策略后训练。

## Submit 到下一枚 Cell

原生成器在每次 generate 新建 Page；Page.state 重编码实例与 Response，Page.base 从空开始缓存已访问的根、首父、变体及后续父的条件分布，draws 使用局部字典扣除本页已发出的完整具名叶子。下一次 generate 丢弃这些权重与前缀缓存。采样 RNG 在 native 的整个调度中连续；静态 GNN 模板表示也已有缓存。原来就没有跨 Submit 的半成品 Token。两次 Submit 共用同一发布窗口，但每个非空 Submit 都把逐请求回执追加到模型输入中。[旧生成入口](../../variable_completion.py) · [原生窗口与回执](../../cell_kv_runtime.py) · [分解采样](../../competition_draw.py)

原代表样本取扩展语料模型、训练种子 71、生成种子 193。三个程序的 4,598 次入口签发有 2,517 次与以前的 Submit 完全同名，具名包含模板以及有序的 owner、op、version。每个重签 UID 都对到最后一次 Seal 之后的原生有效操作来源。2,517 次均被拒绝，新增有效操作均为零。拒绝分别为未触发 2,451、原生 duplicate 31、watermark 17、binding 13、guard 5。其中 2,273 次已跨 Run，另外 244 次仍在同一 Run。56 次重签的上一次同名签发曾产生贡献。另有 7 次沿相同物理地址重访时至少一个版本变化，均无新增；它们按完整版本名字单列检测。以上只为已观察到的执行提供证据，不能证明重新执行在任意未来窗口都无用。[逐程序核对](historical-repeats.json) · [全部 2,517 对执行记录](repeat-ledger.csv)

| 冻结策略 | 同一视图 | 新视图 |
|---|---|---|
| A 页内不放回 | 每次从原分布开始 | 重新编码 |
| B 精确续采 | 延用条件前缀及已抽叶子质量 | 从新神经分布重新开始 |
| C 可重探 | 同 B | 将紧邻上一页仍可表示的完整名字在新分布中的叶子质量乘以 0.25，其他名字保持原质量，再归一化 |

C 的 0.25 是预先选定的算法系数，本轮没有用数据拟合。新版本是新名字。无论收到哪种回执，只要进入新视图，原名字都有机会再次生成。算法按此前实际抽出的名字直接走它在新模型中的因子化路径，计算折扣也要付寻址成本。缓存有效期间仅由同一个发布回调序号和该窗口中只追加的回执数识别；新发布、退役、版本变化或新增回执都会使缓存失效。B 的硬性零质量只在同一生成分布内延续，边界依据为局部不放回采样，未将名字宣布为原生非法或已饱和。A/B/C 均由同一网络决定 Recipe 和所有实际父引用。宿主只维护抽样树，不查字段相等、dirty、guard、伙伴或未来效果。历史 Stream 单列，它有宿主顺序访问计划内规则和半朴素单源 anchor 的路径，没有纳入 A/B/C。[持续采样实现](../../continuous_stream.py) · [历史实现](../../discrete_reference.py)

## 覆盖与计算发现

从相同程序初态独立执行，固定退出，每 Run 两页共六个槽。生成种子 193、307 同时配对原生地址置换。从头分别运行所有预算；达到上限后仍走完原生发布调度，表中有实际付费量。原始 A 的六条完整调度重现上一轮 sweep 的终图和计数。B 在全部预算、程序与两个种子上得到与 A 相同的事实集合、原生回执汇总及终图；完整调度六次合计复用 461 次视图。跨 Submit 重签 A 和 B 都为 6,017 次，C 为 5,394 次。C 在 loopfact 两个种子都增加重签，说明局部抽样变化还会改变后续窗口与总付费量。

## 在线推理成本

每次独立运行从 GNN 静态准备开始计时，包含推理、无产出窗口、抽样、原生通信、回执处理、Seal 和 Runtime 执行。离线终图评分、结果写盘和分叉诊断在计时外。神经模型预加载，GNN 按世界冷启动；历史对照额外计入权重和 reader 的 setup。实测硬件为 Apple M3 Max，PyTorch 2.15.0。正式神经解码为单线程 CPU，设备同步次数为零。CCP 回执屏障另计。当前逐前缀采样会取出单个分布的 NumPy CDF，旧的设备驻留地址树与这个 Decoder 的归一化和前缀更新不同。

fact 完整调度的一次原始 A 运行中，静态 GNN 计算一次、耗时 0.09 秒；748 次状态编码耗时 10.88 秒，其中实例编码 1.94 秒、回执向量 5.08 秒。模板最终读出 0.08 秒、具体变体评分 0.05 秒。父寻址 7.68 秒，含基础分布 6.67 秒，前缀关联及其归一化另占约 1.01 秒，共打分 1,193,017 个候选行次。CCP 有 584 次响应收集屏障，打包及写入共 0.058 秒，等待回执 0.024 秒。计数按调用层级嵌套，不应相加还原墙钟。三个程序的逐组测量保留了通信字节、静态准备、重建 / 折扣、状态编码、网络调用和墙钟。[逐项计时](profiles.json)

在 256 请求下直接拿旧 flat 替换父寻址，三个程序终图均改变。原层级地址分布在同一 owner 的公开端口上包含平均归约；端口数不等时，直接把 owner 和端口 Key 相加再打分会漏掉这一项。修正后的端口 logit 为 `(owner_key + port_key) · q / √d − log(owner_public_port_count)`，静态类型归一化和已训练的前缀关联保持原顺序。另复用既有分组张量归约来计算模板的 owner 消息。两项作为一个实现优化测量，未分别给出加速归因。逐次断言同事实集、终图、付费量、完整入口回执、内部步骤和有效来源记录相同。256 请求做四轮正反序，完整调度做两轮正反序。

| 程序 | 完整调度 A 秒，两次 | 修正扁平秒，两次 | A → 修正扁平 EPS | 同种子随机页内不放回 EPS |
|---|---|---|---|---:|
| fact | 19.52 / 19.77 | 11.76 / 11.78 | 6.87 → 11.47 | 253.79 |
| loopfact | 17.81 / 17.84 | 9.74 / 9.51 | 7.01 → 12.99 | 237.42 |
| sum-divisors | 20.84 / 20.78 | 12.73 / 12.48 | 13.26 → 21.90 | 489.07 |

另在真实自主状态取相同 Query、相同 Key 和类型域，将扁平基础父寻址的矩阵、owner 归一项和类型张量放在 Metal 设备上。每轮连续执行 32 次，两端同步，五轮记录全部耗时。fact 的 234 行、4 个 Query 上 CPU/MPS 为 17.9/140.7 微秒，64 个 Query 为 77.1/169.6 微秒。这是基础打分核的设备诊断，未覆盖完整 Decoder、前缀关联和跨 Submit 索引更新。当前小批量未表现出迁移此核的效率优势；这些数字未计入原生 EPS。[设备驻留测量](device.json)

## 相同后续预算的原生分叉

每个程序从模型自己的执行前缀中取五个状态。从同一个冻结分布抽三枚不同具名 Token，分别选择其中一枚实际签发，再让同一模型自主使用恰好 24 个后续付费请求。每处以两套共同随机数继续；每个分支从相同程序初态重放到锚点，断言完整状态摘要、原生地址、已付费量、备选名字和 CE 完整 log 概率都一致。没有按合法性或收益预筛备选。预算后仍按固定策略 Seal。单独报告首枚原生贡献、后续 24 枚贡献和最终事实。结果只描述此冻结策略实际兑现的价值。[90 次分叉及原生结果](forks.json) · [配对差值](fork-rank.csv)

90 个成对排序比较中，76 对累计新增操作相同；其余 14 对，CE 高概率对应更高收益 6 次，更低收益 8 次。单独看后续 24 枚，88 对持平，2 对是低概率动作得到更高后续收益。例如 loopfact 一个早期状态中，三枚动作 log 概率分别为 −1.964、−2.226、−2.229，首枚贡献为 0、0、1，后续贡献都是 5。这证明有局部排序反例；同一状态的比较共享备选和随机数，不能当作 90 个独立样本。这里仅有 15 个决策状态，长程可区分的结果很少，尚不能据此确定策略梯度收益。当前决定是保留 CE 和固定退出，先保留这些有辨别力的原生分叉作为后续策略对照。

## 复现与验收

在 instruction_pointer 目录，按上一轮准备 ARTIFACT_ROOT、CELL_DATA、CELL_COMPILER、CELL_REPLAY、PYTHON 与三折 sweep-71 权重。历史对照需要 CELL_DATA/recursive-agent/multi.pt 和 CELL_DATA/structured-retrieval/field.pt，可从已提交的 run-recall/cell-stream/multi.pt 与 run-recall/higher-scaling/weights/field.pt 恢复。然后运行：

```sh
sh continuous_reproduce.sh
"$PYTHON" -m unittest test_continuous_stream test_competition test_joint_cell test_variable_completion test_prefix_attention
```

原生分叉、原生有效来源和参考事实匹配均只用于回放与评价。在线持续采样不读取 Teacher、Oracle、语义重复标签或有效来源。实验没有改变协议、调度或模型参数。21 项相关回归测试通过。Cargo 编译、原生 sum-bits 运行、五次基准和原约定 choice_diagnosis 语义验收通过；该验收仅覆盖其规定的 sum-bits 契约。EggCC 的独立验证依赖逐 UID 原生观察、有效操作对账、终图和实际事实集。原始日志路径和抽样脚本见[复现入口](../../continuous_reproduce.sh)。
