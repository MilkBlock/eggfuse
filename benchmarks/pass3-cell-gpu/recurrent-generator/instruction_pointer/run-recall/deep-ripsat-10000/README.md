# 一万个三级以上 RipSat 模板

Neural Execution，exclusive。训练在 Metal 上完成，独立执行使用 PyTorch CPU 和 standalone Rust Cell Runtime。冻结 CCP v0.1、B 的事件模板树、字段检索和父指针。新 GNN 在 B 生成根规则角色后、寻找根证明之前，从发布事件决定采用哪个 Bake 布局，或沿用 primitive。这个实现会对所选根规则的静态相容布局逐项打分，相关成本计入 higher_scores。

## 样本与覆盖口径

深度为实际 producer → consumer 最长路径上的原子 Cell 数，根计一级。挖掘从 sum-bits 和 dot-product 的提交轨迹出发，沿祖先和消费者两个方向取连通图，单布局最多十次规则执行。本次检验平展后的有向依赖深度。递归嵌套的 Bake 次数是另一个量。

排除按哈希保留的模板后，按启动时边界和版本就绪的记录数、观察数、布局结构排序。前 10,000 项各有不同的具名连线结构，都至少以一次观察正例参与了反传。深度 3/4/5/6/7/8/9/10 分别有 5059/3049/1096/549/178/52/13/4 项。72,434 个事件–模板训练样本，单种子、一个 epoch。4,790 项有就绪正例，其中前 4,096 项均有就绪正例。新增 5,904 项只增加了 694 项有就绪正例的模板。其余模板得到结构观察监督，启动正例欠缺。未观察配对的负标签属于弱监督。

下表统计 teacher 提交。将符合版本、根边界和源调度条件的已观察实例取并集，同一原子提交只计一次。重叠实例可以相互竞争。测量覆盖的单位是提交，独立终图事实另计。用正确根规则评估识别时，仅给 GNN 当前事件，允许它选择 primitive。固定优先级对照复用同一批获准事件，在同一静态菜单中选择训练就绪支持度最高项。

| 程序 | 参考提交 | 4,096 项就绪实例并集 | 10,000 项就绪实例并集 | 10,000 项事件 GNN 选中 | 相同获准事件固定优先级 |
|---|---:|---:|---:|---:|---:|
| fact | 1,668 | 837 | 858 | 168 | 219 |
| loopfact | 1,419 | 731 | 746 | 155 | 191 |

转移到另外 668 个训练时按哈希排除的就绪模板，GNN 在三个程序上分别选中覆盖 10、31、263 个原子提交的布局。这是已知根规则下的冻结快照实验。独立运行仍须自行找到根、实际绑定所有输入并获得逐步回执。三份开发程序都用于历史研究，旧 B 的模板树训练曾使用 loopfact。独立模板迁移结果保存在 [held.json](held.json)。

原生版本核验另取每个程序每种就绪模板的一次 teacher 实例。fact、loopfact、sum-divisors 分别完整核验 290、437、1,574 种模板。逐项篡改末步父版本的对照均被拒绝。[重放数据](replay.json)

## 独立执行

每个被激活的模板沿静态接线执行，在源 Run 调度点提交显式操作。在发布时锁存返回端口的版本。外部槽由 B 的字段桶与学习过的父指针打分，额外外部槽采用最高非负分的提案；绑定失败、回执失效和原生拒绝停止该实例。已提交的前缀仍按真实成本和效果计费。重复的 primitive 请求只在对应具名计算已通过原生核验时抑制。CPU 精确搜索补全次数为零。

[runs.csv](runs.csv) 的 arm 0 为 B，1 为仅使用根边界且每 Run 组单步的布局，2 为完整目录，3 为相同 GNN 权重仅开放前 4,096 项。arm 2 在三个程序各有 7,955、7,997、8,008 个规则签名可移植布局。每个获准事件选择一个布局，primitive 保留 B 的多结果生成。神经证明请求计外部根或 primitive 请求，每个实际内部步骤继续按 CCP 付费。高层选择的打分、启动、完整结束和实际替代数分别记录；省下的请求不计作省下的候选访问。

| 程序 | 参考派生事实 | B 命中 | 完整目录命中 | 完整结束的深层实例 | 已避免重复签发 | 完整目录打分 |
|---|---:|---:|---:|---:|---:|---:|
| fact | 1,120 | 764 | 768 | 20 | 99 | 617,296 |
| loopfact | 1,112 | 944 | 946 | 18 | 81 | 518,821 |
| sum-divisors | 8,018 | 3,085 | 3,089 | 73 | 284 | 2,163,720 |

三个程序上同权重的 4,096 项与完整目录终图 SHA 分别完全相同。完整目录相比 B 实际新增 4、2、4 个参考事实，未失去 B 命中的事实。相同事实数也可能来自不同终图，见表中 SHA。各组的完整签发、重复、拒绝原因、索引访问及核验成本见原始运行数据。事实覆盖与签名有效操作使用各自分母。[既有原生神谕对照](../generation-frontier/README.md)

## 复现

从 instruction_pointer 目录运行。ROOT 为 EggCC 训练盘路径，DATA 为 event_experiment 的数据根。WEIGHTS 为实验使用的冻结 opaque parent Actor，其哈希见 audit.json。模型、精简目录和构建身份保存在本目录。准备运行时和数据的方式见 [B 的复现说明](../cell-events/README.md)。

```sh
python deep_ripsat.py "$ROOT" "$WEIGHTS" "$OUT"
python deep_event_recognition.py "$ROOT" "$OUT"
python deep_event_transfer.py "$ROOT" "$WEIGHTS" "$OUT"
python deep_event_rollout.py "$DATA" "$OUT" fact loopfact sum-divisors --arms 0 1 3 2
python deep_ripsat.py "$ROOT" "$WEIGHTS" "$SMALL" --size 4096 --examples 72434
python deep_event_rollout.py "$DATA_SMALL" "$SMALL" fact loopfact sum-divisors --arms 2
```

## 配平训练与规模

另起同种子 GNN，独立训练 4,096 项。使用本组的 29,442 个事件–模板样本训练一遍，独立执行结果为 764、944、3,085 个参考事实。按 10,000 项组的 72,434 次训练曝光、283 次参数更新重训后，结果达到 768、946、3,089。逐个核对终图，两组在每个程序中命中的参考事实集合都完全相同，完整终图 SHA 均不同。训练事件多样性和正负样本比例仍会随目录变化。此对照每程序执行一次，用于语义与确定性计数。[事实身份核对](matched-facts.json) · [配平训练指标](matched-4096.json)

在相同 10,000 项权重上限制部署容量可以直接隔离菜单大小。由 4,096 项开放到 10,000 项，三个程序的终图 SHA、有效操作数和完整结束的深层实例数全部相同。付费请求分别增加 22、14、44 个，深层布局打分从 263,895、234,540、982,885 次升至 617,296、518,821、2,163,720 次。fact 和 loopfact 各做四对交替顺序计时，万项目录各有 0/4 对更快。中位秒数分别为 15.23 → 15.56、11.65 → 11.92。sum-divisors 没有四对隔离容量的计时。各系列存在同机并发，规模收益的判断以终图和操作计数为主。EPS 分母包含从原生启动到结束的在线执行；模型加载、静态目录导入和离线终图核对在计时区间外。

独立执行结果衡量 standalone Rust 的普通命名请求路径。每个实际提交的内部步骤继续付费，构成完整实例须所有步骤均通过验证。该实验不证明任意合法重写都已局部饱和，也不测原生单包融合的吞吐。最直接的容量结论是，在这套目录选择、训练和事件表示下，开放更多深层布局几乎没有扩大可发现的参考事实集合。冻结快照上，固定训练就绪频率顺序在相同获准事件中覆盖的 teacher 提交多于 GNN 选择。这一差距值得与扩大模板数量分别研究。
