# Seal 前的逐请求回执能否改变下一枚完整 Cell Token？

相同的公开快照下，网络现在可以读到两次 Submit 之间真实返回的不同回执；屏蔽回执会恢复原分布。两种子匹配训练表明，当前模型还不能可靠地把“哪枚请求被接受”转化为“下一次选另一枚仍有贡献的计算”。入口配对训练恢复了部分 Higher 条件选择能力。三个 EggCC 程序的第一个实际停滞都能定位到一个可签发的零父请求。

## 原生数据路径

1. CCP Rust 入口检查未发布端口、规则触发条件和具名父引用。对通过准入且有答案的 proof，原生执行器将请求放入当前 Run 和规则的 ready 队列并返回逐请求状态；原子效果和公开端口由后续执行和发布决定。Higher 根获接受也不能证明其后缀完成。[协议执行](../../../../../../engine/cell-runtime/src/token_transaction.rs) · [准入、去重及 ready 消费](../../../../../../engine/cell-runtime/src/cell_tokens.rs)
2. Python 的 Client.enqueue 保存请求及具名引用，_read 检查序号、Run、epoch 和响应大小。collect 调用 _record 按请求 ID 对齐、检查状态码。原有 submit 已经取回四列真实回执；客户端已有审计汇总。旧 Instances.begin 只为通过准入的实例建记录。解码器可读公开端口与最近发布帧的 accepted、updates、retired 数量，同一发布帧内的下一次 Submit 看不到是谁刚被接受或拒绝。[传输](../../ccp_v01.py) · [对齐检查](../../cell_transaction.py) · [提交适配](../../credit_scale_buffer.py)
3. 启用 receipt_memory 后，将签发的模板、有序输入引用及各自版本、Run、epoch 和四列实际回执追加到只读上下文。原样保留的四列是请求 ID、准入结果、操作位置 pc 及观测哈希。原生返回后即可进入下一页快照。Higher 内部签发也计入。失败不改写原请求；引用的当时版本和实际状态码可读，Runtime 未返回的预期版本不会被补入。[运行与快照](../../cell_kv_runtime.py)
4. 每条回执复用该模板的 32 维结构码、现有 dynamic/age 投影及带序的父引用编码。可见的精确版本可提供对应端口表示。经过已有 input_content 和 latent 投影后，回执行与公开 owner 共同供上下文及模板 Attention 读取。地址解码仍只在已发布端口上采样，发布/退役由原生帧驱动。所有模型均复用原有 GNN、Embedding、Operand Attention、解码、损失和可训练参数集合。[KV 读取](../../cell_kv_model.py) · [完整 Token 概率](../../selected_cell_model.py)
5. 本实验的生成器签发 proof 请求，使用 CCP 既有的默认观测模式；没有覆盖通用 VALUE 载荷生成任务。Submit 采用同步收取，再生成下一页。因此网络看到的是已返回回执；异步在途请求的预测没有在此实验中验证。原始日志逐行精确保留，32 维表示经过压缩，Attention 也不保证维持一一可辨。实现每页读取自本次执行开始的回执行，历史长度增加会产生额外开销。

## 训练与配对核验

在上一轮连续状态权重 71、113 上分别训练可见回执与屏蔽回执两组。每个权重做 420 次更新，每步四类来源各贡献四次完整 Token CE，合计 6,720 次目标曝光；两组采样种子和目标次序相同。12 个训练程序带来 38 个有核验目标的原连续前缀记录、72 个 Seal 前回执条件和 24 个发布后的反事实分支记录；加入原有基础关系样本。单程序、状态、目标和重复曝光的口径不同。六个留出程序使用独立数值、地址及本轮混合 Higher 结构。原生 Teacher、分叉、目标分组仅用于离线语料和诊断。[数据生产](../../feedback_data.py) · [训练](../../feedback_train.py) · [训练曲线](training.csv)

首次签发五枚有独立贡献的具名 Token 中的一枚，每个分支另起原生进程测试全部五种下一枚 Token。对六个留出程序，共 30 次原样重签返回 duplicate，另外 120 次签发有新增效果。另有六个首请求故意使用错误版本，后续 30 个目标仍有贡献。逐分支检查第二次签发前公开快照完全相等、第一条真实回执对齐，并以相同首请求后停止签发的原生终图为参照比对新增行。观察仅适用于这些已经核验的计算。

| 模型 | 原 Token 在签发前 | 收到自身接受回执 | 收到另一枚有效 Token 的接受回执 | 其余仍有效 Token 总质量，前 → 后 |
|---|---:|---:|---:|---:|
| 旧连续状态模型 | 12.97% | 12.97% | 12.97% | 51.86% → 51.86% |
| 同语料续训，屏蔽回执 | 14.04% | 14.04% | 14.04% | 56.14% → 56.14% |
| 同语料续训，读取回执 | 13.59% | 13.10% | 12.67% | 54.35% → 50.67% |
| 上一行权重，推理屏蔽回执 | 13.59% | 13.59% | 13.59% | 54.35% → 54.35% |

进一步固定模板、仅替换已签发的父引用，原 Token 在“刚签发自己”的条件下比“刚签发同模板另一引用”概率更低的样本，两种子分别为 10/24、12/24。错误版本首请求之后，正确版本目标平均概率 11.17%，接受正确版本后为 11.01%，提交前为 11.02%。这些测量支持状态可观测，尚不足以证明可靠的选择性去重或失败恢复。[逐 Token 对照](pre-seal.csv) · [版本对照](failed.csv)

## 新入口与 Higher 条件选择

同一布局的两次原生分叉各发布一个 Ready 入口，父引用相同，入口值要求相反 Higher。发布前该具名目标不可寻址；发布后分别统计两个 Higher 的总概率、正确分支占该总量的比重和正确完整 Token 的无条件概率。三列分别对实例取均值。翻转要求两个状态都排对。分母为六个布局乘两个权重种子，共 12 对。

| 权重和输入 | Higher 总概率 | 正确分支条件概率 | 正确完整 Token | 双向翻转 |
|---|---:|---:|---:|---:|
| 旧连续模型 | 61.88% | 63.05% | 37.57% | 3/12 |
| 续训，屏蔽回执 | 75.52% | 78.36% | 57.18% | 10/12 |
| 续训，读取回执 | 62.98% | 74.61% | 42.87% | 8/12 |
| 可见组权重，推理屏蔽回执 | 71.49% | 74.73% | 50.27% | 9/12 |

在另外八个基础单入口环境的首个决策窗口，用离线逐请求核验得到的正确 Higher 完整 Token 平均概率为旧组 24.86%、屏蔽组 53.40%、可见组 56.43%。这里给的是自由分布中的概率；独立执行另外测量。配对训练有助于恢复基础关系和动态分支辨识，可见回执组仍落后于同语料屏蔽组的动态分支结果。[双分支](higher.csv) · [基础关系](basic.csv)

## EggCC 第一次停滞

沿上轮连续状态策略独立执行，固定权重 71、抽样种子 193、每个窗口一个六槽页。以已有新增参考事实后的首个零新增窗口定义第一次停滞。对真实前缀重启原生进程，按原操作重放后静默运行至固定退出；用有无干预的事实集合差检验当时可执行性。三个程序都在 Run 2，Run 1 均为一枚接受、五枚重复；Run 2 的六个槽没有生成可签发请求。菜单有十个模板，其中九个至少缺一个所需类型的公开端口，完整静态类型域中只有零父的 574()。

| 程序 | Run 1 新事实 / 原子操作 | Run 2 的 574() 概率 | 此时单请求核验 | 原轨迹下次菜单出现时重试 | 注入后恢复原策略，最终覆盖事实数 |
|---|---:|---:|---|---|---:|
| fact | 31 / 72 | 0.02260% | 接受，新增 1 行 | Run 5，未触发 | 34 → 33 |
| loopfact | 38 / 52 | 0.02263% | 接受，新增 1 行 | Run 6，未触发 | 39 → 40 |
| sum-divisors | 100 / 199 | 0.02512% | 接受，新增 1 行 | Run 5，未触发 | 105 → 102 |

这里能排除父寻址失败、重复签发和证据尚未发布对 574 本身的解释。模型把极少概率分给唯一可签发模板，固定 Seal 后首个后续调度机会已经失活。单次注入均在下一发布帧观测到两个具名端口。以相同随机种子继续自主生成，三个最终事实集合都发生变化；当时能找回一行无法保证最终得到更多行。Run 3 各有 94、74、422 个类型相容具名绑定，分别抽查最多 16 个，发现 4、4、1 个有新增贡献，未查部分保留未知。原始轨迹的最后一次新增分别在 Run 52、3、26，此处的首次停滞不等于整段执行终止。[fact](stall-fact.json) · [loopfact](stall-loopfact.json) · [sum-divisors](stall-sum-divisors.json) · [注入和错窗复核](../../feedback_intervention.py)

## 独立执行

所有正式组沿原 Recipe 与固定退出执行，每窗口合计六个生成槽，分成两页各三个，使第二页可以实际观察第一笔 Submit 的回执。每页结束后收回实际响应，窗口末尾一次 Seal。独立抽样和页内不放回分别运行；不放回仅移除本页选过的完全相同模板及有序具名引用，下一页可再次抽取。相较上一轮单页六槽，抽样范围和 Submit 分批发生变化，故以本轮同配置重新执行的旧权重作基线。离线列举和 574 干预不参与下列得分。

每格为平均 Coverage / EPT / EPS。EggCC 工作负载使用原生 CCP v0.1 Runtime 和 EggCC 程序，神经推理为单线程 CPU，独立执行包含推理、回执编码、传输和执行墙钟。模型静态缓存每次运行前清空。每种权重和抽样方式交替计时两遍，两遍均核对事实身份、终图摘要、原子操作、请求数和未完成后缀。训练种子两个，每个 EggCC 程序使用一个生成种子；混合环境六个留出程序、两个生成种子。EPT 沿用原生有效操作/实际付费请求，EPS 沿用有效操作/执行墙钟；起止点见 native。EggCC 使用现有 Primitive 目录，Higher 自主执行由混合程序直接检验。

| 程序 | 原连续模型 IID | 原连续模型不放回 | 同语料屏蔽回执 IID | 同语料屏蔽回执不放回 | 可见回执 IID | 可见回执不放回 |
|---|---|---|---|---|---|---|
| 混合 | 23.75% / .316 / 173 | 28.75% / .535 / 208 | 28.75% / .342 / 215 | 54.38% / .376 / 353 | 26.88% / .242 / 166 | 40.21% / .317 / 244 |
| fact | 2.95% / .366 / 11.81 | 2.86% / .486 / 13.57 | 3.21% / .329 / 11.97 | 3.48% / .348 / 12.40 | 4.38% / .233 / 11.31 | 4.02% / .253 / 11.16 |
| loopfact | 3.51% / .336 / 7.98 | 3.46% / .329 / 8.08 | 4.63% / .242 / 9.41 | 3.60% / .313 / 7.96 | 4.68% / .177 / 8.23 | 5.04% / .195 / 8.78 |

在同一个可见模型上，混合程序的页内不放回提高了实际 Higher 完成数（平均 .25 → .54）和覆盖率；EggCC 上只有 loopfact 的 Coverage 跟着上升。训练收益以同一抽样方式下的新旧权重比较，抽样算法收益以同一权重的两种模式比较。对不同事实集合，这些点只描述资源与产出的权衡。逐次事实、终图、付费和计时离散程度另存。[指标](scores.csv) · [每次执行](native.csv) · [事实集合差](paired-facts.csv) · [同终图计时配对](paired-timings.csv)

在完全相同的六槽窗口再加全局 96 次付费请求上限，各 EggCC 组均实际签发 96 次。下表采用独立抽样；每格为平均参考事实数 / EPT / EPS，全部不放回组另见 scores.csv。三个程序的参考事实分母分别为 1,120、1,112、8,018。

| 程序 | 旧连续模型 | 同语料屏蔽回执 | 同语料读取回执 |
|---|---|---|---|
| fact | 33 / .776 / 24.8 | 36 / .812 / 30.6 | 49 / .964 / 45.8 |
| loopfact | 39 / .562 / 13.2 | 51.5 / .714 / 33.4 | 52 / .740 / 36.7 |
| sum-divisors | 103 / 2.104 / 74.4 | 107 / 2.161 / 100.9 | 114 / 2.240 / 125.7 |

等付费、独立抽样时可见组在三个程序都获得更多有效操作，较早用完预算之后仍完成固定原生调度，但省去了后续神经生成，故不能外推成持续生成时的吞吐提升。页内不放回时，屏蔽组和可见组在 sum-divisors 分别得到 108.5 和 106 个事实。混合程序的另一个上限为 12 次，部分组在退出前实际付费少于 12；应读作同上限。未设付费上限时，三个 EggCC 程序均无“同种子、同抽样、可见组与屏蔽组同时得到相同事实和终图”的计时配对。混合程序有八条这样的计时记录（包含正反序），可见组墙钟比值中位数为 1.217。没有数据支持在同终图下宣称普遍加速。全表覆盖 456 对重复计时，共 912 次原生独立执行。
