# Conditional Computational Compatibility

本实验从上一轮保留的 `token-embedding/current-71.pt` 初始化。四组使用相同的 CellKV-C、共享 Recipe GNN、32 维稠密 Cell KV、完整 Token CE 和固定退出策略。正式请求由模型从完整公开 Memory 自由生成。结果来自 CCP v0.1 原生 Runtime 上的小型程序。本轮没有测量开放 EggCC。

## 结果

**网络会读取具体入口，也能记住一对输入对应的两个 Higher。对未见数值和新 Bake 的 Higher，本次完整 Token CE 训练未建立可靠的条件选择。** 以下两个表分别回答整条原生执行是否改善，以及只改一个入口字段是否足以让模型正确切换计算结构。

|---|---:|---:|---:|---:|---:|
| A 全冻结 | 43.56% | .1120 | 241.2 | 5.19 | 10.07% |
| B 训练 GNN 与 embedding | 50.08% | .1458 | 317.1 | 7.23 | 22.22% |
| C 训练 Attention 与 Decoder | **51.01%** | **.1486** | 315.0 | **7.41** | 16.67% |
| D 端到端 | 45.59% | .1332 | 292.8 | 6.69 | **24.48%** |

### 哪一段具有条件信号

- **静态结构有可测差异。** 在一个已见程序和一个新程序中，分别只交换两侧 guard、只交换算术操作，重新编译并用原生回放确认适用分支。D 的对应 Higher 结构码平均 L2 变化分别为 1.807 和 0.480。单换 guard 时，D 在 8 个方向判断中正确 4 次。这个检验确认对语义改写敏感，不能仅凭向量不同推断模型学会了 guard 的适用条件。[结构干预](controls.json)
- **入口确实进入模板读出。** 新目录的额外单入口组，改变入口使 D 的 Key 平均移动 0.563。固定全局摘要，只更换真实逐实例 KV，两 Higher 的 log 概率差平均绝对改变 0.695，正确翻转 4/32。固定 KV、只换全局摘要，对应变化 0.058、正确翻转 0/32。这里的干预幅度不是可相加的因果贡献。
- **找到入口很容易，两个候选却几乎读到同一份信息。** D 两个 Higher 对该入口 owner 的平均注意力为 99.997%。实际输入翻转后，原始 Query–Key 分数差有变化，但方向正确地跨越零为 0/32。让两者共用一个读取 Query，同时保留各自最终模板投影，最终两模板 log 概率差平均仅改变约 0.00003，仍正确翻转 4/32。离线直接给出正确 owner 也只有 4/32。注意力可以成功定位证据，同时缺少根据候选 Recipe 不同而读取不同语义的能力。
- **保留归一化前的强度也没有解开这一区分。** 在同一冻结 D 上，对每个候选取全体 owner 的原始 QK 分数 log-mean-exp，只用该值排序时新目录正确概率 50.12%、翻转 0/32；把它加回原 logits 后为 52.63%、4/32，原始读出为 52.50%、4/32。未调整系数、未增加参数、未在线运行该变式。[离线分数干预](score-probe.json)
- **能拟合具体配对。** 以相同 CE 和总曝光只重复训练一对完整原生环境，两个种子在该对上的正确 Higher 平均概率为 98.79%，均能随字段翻转。换成同 Recipe 的未见数值后为 49.25%、0/32。架构能表达至少一组有条件的决策，本轮证据不足以判断当前训练分布和读出方式各自限制了多少泛化。[训练内及未见数值诊断](generalization.json)

### 动态发布与地址

在额外的多 Run 任务中，warm 窗口为随后 root 窗口创造新的 Seed。当 warm 要从 Noise 正确寻址才能产生 Seed 时，A/B/C/D 的 112 条自由轨迹均未发布新 Seed，存在离线 Teacher 见证。换成合法零父生产者后，112 条自由轨迹全部出现新 Seed；A、B、C、D 首个 root 页上实际生成了 8、10、16、32 枚使用新 Seed、符合原生见证的完整 Higher Token。各组分母分别为 16、32、32、32 条轨迹，每页六槽；重复抽样单独保留。这些命中表明模型有时会消费刚刚创造的实例。它们不证明对成对改变的入口能选择正确分支；D 在两种发布条件下的离线两侧正确排序翻转均为 0/8。[动态自由执行](publish.json) · [动态窗口配对](publish-probes.json)

原生地址种子在每个表内重新分配具名地址，单行表没有可置换的第二行。336 份首窗口概率核对中，154 份的目标物理引用与 Teacher 地址不同；重新在实际随机地址状态上计算，两种 Higher 的完整 Token 概率最大绝对偏差为 1.79×10⁻⁷。比较按原生字段匹配仅在执行结束后进行。[地址原始记录](address.json)

**研究判断。** 保留当前 Cell Embedding 和 KV。这里值得继续检验的是同一份已找到的证据，能否依照候选 Recipe 的 guard 和操作产生不同的读取结果。本轮排除了纯粹找不到入口、GNN 对两种结构完全同码，以及简单丢失 QK 总量这三种充分解释；没有证明扩大模型是必要条件。

## 反事实的控制条件

每对程序只改一条 Seed(x,y) 的 y，使第一种输入为 x=y，第二种为 x≠y。Noise 使用单独采样的数值。每对检查编译后的完整 Recipe、Bake 布局、模型目录码逐元素相同；在同一原生入口窗口，逐一比较所有具名地址、版本、类型、父引用、forwarded、Run、epoch、Response 和目录。仅一条 Seed 的第二个字段哈希有变化，该行隐含见证字段也相同。两次原生重放分别确认从相同引用启动的不同 Higher 到达指定末端并获得参考终图。两者的输入都是 Seed，公开根为 Mid，具名末端表和 op 均为 Common 的同一输出。两条分支的内部 guard、算术及接线由 Recipe 提供。[配对构造](../../compatibility_world.py) · [逐对契约、编码签名与公开字段](pairs.json)

课程从一个入口、两个 Higher 和合法的根 Primitive 开始，逐步加入多个 Seed、同窗口的独立 Primitive 及第三个同接口 Higher。三分支环境另有 x=0 的路径。后续 Run 发布、条件后缀失败、不同完成程度及最终 Primitive 都在原生回放或自由执行中产生。在多入口环境，另一个 Higher 可能适用于另一条 Seed；判断指定计算是否被发现时使用完整的模板与具名引用。两个反事实均应选择正确分支才算一次正确排序翻转。任一方向的翻转、限定两者的正确概率、全目录的正确模板概率、给定该模板的绑定概率、完整 Token 概率各自单列。[条件统计口径](../../compatibility_results.py)

## 四组训练

48 个原生训练环境组成 24 对，384 条有目标的快照记录，1,552 次完整目标记录（含两种重放粒度，非独立计数）。每次更新对同一输入对的两侧各训练三个经过核验的完整 Token，其中一个是改变入口对应的 Higher，另两个从完整执行轨迹抽样，包含 Primitive 和动态执行状态。B/C/D 各用两种采样种子、720 次 AdamW、4,320 次完整目标曝光；各臂的课程、采样序列、学习率和预算相同。A 不更新。正例未穷尽所有可行证明。没有 guard 标签损失或绑定辅助头。[训练实现](../../compatibility_study.py) · [各组曝光、损失和权重哈希](manifest.json)

| 组 | 更新的参数 | 可训练数 |
|---|---|---:|
| A | 全冻结 | 0 |
| B | Recipe GNN、布局 GNN、动态与年龄投影、写入 Memory 的 K/V 投影 | 10,304 |
| C | Query、lane、GRU、模板读出投影。写入的 K/V 及图编码冻结 | 8,576 |
| D | B 与 C 的全部参数 | 18,880 |

这里将用于存储的 Key/Value 投影归到 embedding 侧。C 不能通过更新这两块参数变相重写 Memory。逐配置比对冻结参数训练前后的字节哈希。未参与当前 CE 的旧分类器及控制头均冻结。

## 如何检验具体实例与 Recipe 的交互

对候选 i 和公开 owner j，原实现先计算 `q_i=Wq(ctx+c_i)+b`、点积 `q_i·K_j/√32`，再由该候选读取 owner 内的公开端口。端口消息加入 owner 分数，同时加入被读取的 Value。最终模板 logits 来自 `Q(ctx+read_i)·W_role(c_i)/√32`。训练用线上原实现；诊断重算这一路径并逐值核对最终模板 log-prob。在每对快照上记录两个 Higher 各自的原始点积、实际 owner 权重、全目录概率、条件父引用概率和完整 Token 概率。[逐步读出与断言](../../compatibility_eval.py) · [原始配对读数](probes.json)

另外交换全局摘要 ctx 和逐实例 K/V，一次只允许其中一路接收输入变化；让两候选共用同一个读 Memory 的 Query，但保留各自的最终模板投影；以及给定正确 owner 强制两候选读取它。这些都是离线干预。正式生成既没有入口提示，也没有预先比较字段或 guard。每次成对反事实只检查当下实际可区分的方向。即使原始 QK 差值方向不正确，后续端口消息与模板读出仍有可能纠正它。[成对干预原始值](generalization.json)

## 原生执行与复现

正式评估有 12 个输入对、24 个程序实例；半数复用训练 Recipe 但用未见数值，半数在所有正式权重冻结后 Bake，含 7 个不同的留出 Higher 结构签名。与本轮和两个直接前序 CellKV 训练目录核对；此前通用 Actor 的所有历史训练结构未穷尽审计。离线扩大数值样本时，在同一已见及同一新 Recipe 各增加 16 个单入口输入对，单列统计，未把这些概率诊断计作独立执行。诊断的单输入对过拟合模型单独训练，未作为上线策略。

每个正式程序用两个原生地址/抽样种子，每种设置反序计时重复一次。A 共 48 条不同自由轨迹，B/C/D 各 96 条；重复计时不增加样本数。检查同设置两次生成、事实集合、图摘要、操作数及请求计数相同。端到端墙钟从空静态缓存计入图编码、Memory、神经生成、提交、原生核验、接续与发布。Coverage 为参考非初始关系事实的召回；EPT 是原生有效原子操作数除以全部付费请求；EPS 使用全部在线时间。另报同事实集合且同图摘要的配对。CPU 只按静态阶段目录提供模板，读取网络指定的真实引用，执行明确的 Higher 内部接线；离线核验只在完成自由执行后对比样本。[原生事实、成本及回执](native.json) · [同终图成本](matched.csv) · [地址复核](address.json)

复用研究分支已有 ARTIFACT_ROOT、CELL_DATA、CELL_COMPILER、CELL_REPLAY 和 PYTHON 环境变量，在 instruction_pointer 目录运行以下命令。使用新的 PARTNER_INDEX_OUT 可以复核先训练、再 Bake 的顺序。训练语料、程序、原生回放和权重位于实验盘 conditional-compatibility-final。先行对照使用上一轮追加 embedding 训练以前的 C-joint-71-360 起点，另存独立执行结果和原始运行目录 conditional-compatibility；复现该起点可将 COMPAT_INITIAL 指向 cell-kv-fullread/weights/C-joint-71-360.pt 并使用独立输出目录；下文主结果统一使用追加训练后的 current-71。[先行对照](earlier-initialization.csv)

```sh
sh compatibility_reproduce.sh
"$PYTHON" -m unittest test_compatibility test_cell_kv test_token_embedding
```
