# Recipe 操作数如何读取同一 Cell

在固定实例、只换接线的 64 对冲突状态上，使用冻结 GNN 操作数节点的 D 在两个训练种子上都翻对 64 对。将两套接线的操作数节点向量互换后，两个种子都在全部 64 对上选中了相反的分支。这项收益依赖静态操作数信息及跨接线训练；位置迁移和端到端效率仍有明显限制。

## 读取算子和实验边界

共同输入为已发布 owner、其具名外部端口、字段值和版本。每个字段沿用原有 64 位哈希展开，位置角色使用固定余弦码。共享 Recipe GNN 输出 32 维 Higher 表示；所有组使用原有 owner/port 注意力和同一 GRU 模板读出。所有 Attention 均在单个端口内部完成，外层 owner 和端口仍由模型选择。受控入口实际只有一个 Seed，故该实验的难点是模板选择。

| 组 | 实际算子 |
|---|---|
| A | 复用上一轮 rich C 的两个完成训练的检查点，Query 对 32 个哈希特征维度归一化，作用于每个字段对。 |
| B | Query 与端口内每个字段对的位置角色做内积，在全部字段对上归一化。按权重汇合各对的逐位乘积。 |
| C | 复用共享投影和两个现有 lane 偏移，从整体 Recipe 和上下文产生两个操作数 Query。各自在同一公开端口的全部字段上归一化，读出两个 64 维向量，再逐位相乘并折叠至 32 维。 |
| D | 在 C 对应的 Query 输入上加上冻结 GNN 的两个操作数节点向量。其余步骤和 C 一致。 |

D 从静态目录收集节点 ID 并缓存。在本实验覆盖的 guard 中，Recipe IR 把相等编译为一条表查询内的重复槽，不等保留为二元 primitive。前者取同一个 GNN 槽节点两次，后者按两条操作数边取节点。实现选用主体内首个支持的相关计算步骤，无此结构的模板回退到入口节点。该静态选择给了 D 明确的语义先验，尚未覆盖任意计算或任意操作数个数。D 的 Query 得到节点向量，端口内所有实际字段仍参与神经打分。读取器既不接收正确字段编号，也不读取本次 guard 真值。动态路径不展开 Higher 内部，不执行字段 Join。[实现](../../operand_read_model.py)

训练复用 rich 语料、相同初始权重、相同随机 minibatch 及完整 Cell Token CE。B/C/D 各实际训练两个种子。共八种 Recipe、2,048 个原生程序，420 次单 Recipe 更新后训练全部接线至第 1,680 次更新，每个检查点累计 57,120 次完整目标曝光。所有组可训练参数均为原有的 8,576 个，训练前后冻结部分摘要一致。正式生成使用固定退出策略、每窗口六槽、CCP v0.1。Teacher 确定离线配对和核验目标，在线只执行指定请求，Higher 内部每步都按原口径计费。[共用训练循环](../../value_read_train.py) · [原生评估](../../operand_read_eval.py)

## 读到了什么

双方均正确排序才计一次成功。每个种子使用相同的 64 对原生状态。原始状态、实例数值、具名引用、版本和菜单在接线交换前后逐项相同。下表两列概率为种子均值。梯度是冲突组完整 CE 对实际读取 Query 张量的 L2 范数均值，C、D 包含两个 Query，不宜将其绝对值与单 Query 组当作同尺度指标。

| 组 | 双侧翻转数，71 / 113 | 正确 Higher 相对概率 | 正确完整 Token 概率 | Query 梯度，71 / 113 |
|---|---|---:|---:|---|
| A | 0 / 0 | .501 | .384 | .404 / .202 |
| B | 0 / 0 | .500 | .372 | .388 / .527 |
| C | 0 / 4 | .501 | .372 | 3.903 / 6.505 |
| D | 64 / 64 | .961 | .679 | 2.221 / 2.057 |

相同 D 算子在初始权重为 0/64，单 Recipe 阶段结束后两个种子也都是 0/64。冻结训练完成的 D，保留整体 Higher、入口和打分器不变，只交换两种接线的静态操作数节点，全部 64 对的两侧都错；将节点置零则每对只选对一侧。两个种子结果一致。[阶段检查](early.csv) · [交换试验](interventions.csv)

对于 C、D，正确无序字段组合的权重定义为两次操作数读取按两个顺序命中对应字段的概率之和。C 为 .485/.488，D 为 .206/.228。B 的单次字段对 Attention 给正确对 .349/.187。可见准确的分支选择与集中读取正确物理字段是不同的能力。例子取种子 71、入口 (a,a,b)，端口顺序为 x、y、z、见证。对 x=y 的正确 Higher，D 两个操作数的读取分布分别为 (.393,.303,.258,.046) 与 (.049,.069,.875,.007)；第二个操作数给干扰字段 z 最大权重，模型仍选对。这里的二值池及混合读取允许模型利用间接关系。[实际读取分布](weights.json) · [逐组概率和梯度](diagnostic.csv)

## 从完整 Memory 自主生成

计时切片对每组包含两种 guard 极性、两种算术分配、两个输入、两个物理地址及生成种子，各正反序执行两次。每次从原生初态自由生成到固定结束，保留实际事实集合与终图哈希，配对重复间核对事实、终图、原子操作和签发统计一致。Coverage 为参考关系行覆盖，EPT 为原生有效原子操作除以付费请求，EPS 包含 CPU 单线程神经推理、请求、执行和发布。这些受控程序可以通过 Primitive 到达与 Higher 相同的终图。

| 熟悉接线的独立执行 | Coverage | EPT | EPS | 首窗口正确完整 Higher 槽命中率 |
|---|---:|---:|---:|---:|
| A | 100% | .1270 | 286.1 | 40.6% |
| B | 90.6% | .1149 | 261.2 | 41.7% |
| C | 100% | .1270 | 288.0 | 42.7% |
| D | 100% | .1255 | 287.5 | 78.4% |

D 和 A 的终图在全部 64 次独立配对中相同。两种子各自的配对墙钟中位比为 .985、.993，配对重复的墙钟相对差中位数为 4%–7%。未建立稳健的同终图加速。六步 Higher 的独立执行中，D 的 Coverage/EPT/EPS 为 82.8%/.1163/288.8，A 为 87.1%/.1205/307.7。五字段重排组 D 的 Coverage 高于 A，但对应配对翻转率仍很低，仅从总体 Coverage 无法判定模型已经学会重排。[各接口分种子原生计时与同终图配对](execution.csv)

## 成本与复现

每个端口有 F 个公开字段（包括见证）。A/B 构造 F(F−1)/2 个字段对。C/D 对每个操作数读取 F 个权重，临时权重为 [端口,模板,m,F]。本轮只训练并测量 m=2 的二元操作，固定向量维度下读取开销为 O(mF)。在一个端口、三个模板的 CPU 微基准中，F 从 4 增至 128，B 从 62.5 增至 1,413 µs，D 从 58.0 增至 115 µs。128 字段时是 8,128 对和 256 个操作数字段位置。微基准包括字段位展开和神经读出，使用预编码的静态 GNN，跟踪的是单次内部读取。完整原生程序只测到五个数据字段加见证。这些结果不外推到 Metal、EggCC 或多元 guard。[4–128 字段逐档计时](cost.csv)
