# Continue、Submit、Seal 的原生成对经验

同一个程序给出了两个方向相反的时间决策。在动态程序 0 的 Run 2，两臂都支付 14 条请求，先 Continue 的终图多覆盖 9 个参考事实，没有丢失另一臂的事实。在 Run 13，两臂都支付 16 条请求，先 Seal 后执行下一页的终图多覆盖 2 个参考事实。两组事实身份、具名输入、发布前缀与两臂成本均可检查。[配对实例](allocation-examples.json)

固定退出仍是生产基线。扩大数据后，控制策略在留出程序上能学到部分局部选择，EggCC 的独立执行仍出现大量过早退出。本实验使用独立 Rust Cell Recipe 执行器和 CCP v0.1 的实际回执。全部 Teacher、重放和反事实评分都在训练或离线诊断中。正式在线动作仅由原冻结 Cell 生成器和现有 Rates 参数产生。

## 数据规模与归因对象

- 96 个动态 Recipe，各采集一条自主探索轨迹及一条带原生 Shuffle 前缀的轨迹。两条轨迹属于同一个程序分组。训练使用 72 个程序，留出 24 个，按结构签名检验隔离。一个训练程序内会经历多种发布、降低成本、repair、clear 和再次触发的 Stage。
- 共 4,332 个原生 Run 窗口、13,394 次控制决策、85,742 枚自主生成并付费签发的完整 Cell。基于当前控制状态和具名 Token 去重得到 69,512 个不同的「状态 × 具名 Cell」；不同合法绑定仍可能语义等价。13,394 个细粒度决策状态包括同一冻结快照内的 Draft 与在途历史变化。
- 对比上一轮的两个 16 程序队列，32 条轨迹的接受 tape、动作、具名 Token 及回执可逐项复现。扣除这些重复，本轮增加 **80 个程序、3,606 个 Run 窗口、11,131 次控制决策和 70,927 枚自主 Cell**。旧状态上的新分叉可以增加 Credit 证据，不重复计作新的自主 Token。
- 自主 Cell 的回执包括 7,021 次 accepted、7,880 次 duplicate、9,419 次 binding、9,043 次 guard、632 次 watermark 和 51,747 次 untriggered_rule。每条都复用 fine_credit.labels 的原生判定映射。Teacher 前缀和神谕分叉提出的请求另行记录。[数据清单](inventory.json)

统一读取接口按真实发生顺序给出控制动作和 Cell，并将每枚 Cell 的生成状态、签发状态、请求 ID、具名地址与回执对应。Continue 带实际生成页成本，Submit 带已签发批次和原生贡献；Seal 可带退出遗漏、发布依赖和配对比较。同一状态可以保留多个验证过的选择和冲突证据。未知维度省略，训练 mask 为零。状态更新和在线动作生成均不读取这些离线字段。[经验读取器](../../control_credit_experience.py) · [原生分叉实现](../../control_credit_pairs.py)

## 三种比较回答不同的问题

**从同一已排空草稿立即关闭，或多签发一个批次。** 保留同一原生前缀及后续具名请求，重放到本 Run 末端和各自终图；后续请求照常接受版本、水位、绑定和 guard 核验。5,979 个比较含 3,771 个已观察的神经批次和 2,208 个训练专用 Teacher 批次。每个试验同时记录当窗原子操作、终图事实增减、哈希、付费数、原生执行及进程墙钟。批次造成直接净增、其他已签发请求的原子贡献保持稳定、终图严格多覆盖参考事实时，才给出有收益的 Continue 标签。针对一个具体批次的成本偏好要求全部回执是重复或未触发，直接及最终状态相同。已有其他能产生贡献的分支会阻止把该偏好变成全局退出标签。其他情况可以保留 Unknown。全部 5,979 对重新执行并核对了具名请求的原生处置总数、目标、直接及终图差异。

**支付同样数量的完整请求，比较把一页放在哪个窗口。** 1,560 个比较均核对两臂的原生处置数。双方各支付 23,050 枚干预请求，另有相同的前缀与后缀。460 对的终图事实严格支持先 Continue，147 对严格支持先 Seal，953 对没有单向标签。这里使用轨迹上实际生成的两个具名页，固定共同请求数后分别在相应原生快照核验。其余计算使用同一后缀。每页原始生成时间和截取后的付费数分别保存。

另将已证实有净收益的原批次原样推迟到下一次其模板都进入词表的合法 Run。2,341 对有这样的后续窗口；在这个经过选择的子集中，延期批次的新增贡献均降为零，终图均失去至少一个参考事实。34,251 条延期请求收到未触发回执，其余包括 watermark、version、binding 和 retired。该分布只描述原先有贡献、又存在后续匹配规则窗口的批次，不能用于估计任意一次等待的失败概率。[等支出审计](allocation-inventory.json)

**实时 CCP 双分叉。** 在 96 个程序里，从 187 个实际主动 Seal 点恢复两份原生执行器，含 58 个本窗口已经签发部分计算的退出点。逐批验证恢复后的原始请求号、回执、epoch 和神经输入。两臂交换执行顺序，分别在发布前或发布后生成一页，再各用两页、相同随机数预算，根据自己的真实 Response 生成后继。最后走完 Recipe，重放核对终图。Continue 有 22 次严格多覆盖，Seal 有 28 次严格多覆盖，24 次各得到对方缺少的事实，113 次覆盖相同参考事实；其中 104 次终图也相同。两臂同为三页预算，实际支付分别为 5,691 与 5,537 枚请求。从决策点到原生终止的墙钟中位数分别约为 22.4 和 23.8 毫秒，包含生成、签发、反馈、后继和原生发布，不含恢复前缀与离线评分。单个分叉的时差只作成本记录。[逐对实时成本和终图](live.csv)

**必要发布。** 在真实轨迹中保留 203 个跨规则集的具名依赖见证。后继在下一窗口读取刚发布的实际 owner，删除该生产者后的同一具名消费者失去原子贡献。这里确证该引用的发布依赖，无法断言在此前多做任何其他合法计算都会有害。另用原生同规则集对照确认 Run 4 中生产者 accepted、消费者 pending_port，Run 5 发布后消费者才得到 accepted 和新增贡献。[端口与版本回执](port-controls.json)

## 训练与独立执行

训练固定 Cell 的结构及地址参数，只训练既有三个动作输出。每个模型使用相同的 160 次优化更新。小数据组使用前 12 个训练程序，所有扩量组使用相同的 72 个训练程序和 24 个留出程序。原 Credit 和配对 Credit 取自相同原始经验，但有效 mask 数随监督方法而变化。配对组有 3,210 条可训练的动作，其中 184 条直接针对实际过早 Seal；小数据配对组为 26 条。上一轮单队列为 17 条，加入 Shuffle 后为 33 条。这些标签可以来自训练专用的原生有效见证。187 对实时试验才直接测试冻结生成器是否能凭额外的一页找到有用计算。原生同支出匹配监督的留出动作为 896/1,011；加入实时比较的模型为 916/1,023。两个分母和目标不同。

表格内依次为 **Coverage 百分比 / EPT / EPS**。96 次完整独立执行覆盖四个工作负载、两个生成种子；第一种子正反序计时。同一种子重复计时校验终图、付费数和有效操作数。Coverage 与 EPT 不重复计入计时副本，EPS 为冷启动端到端中位数。原有计费规则保持一致，所有在线控制与读回时间计入 EPS。各训练数据分布上的离线偏好不参与正式运行。

## 复现与范围

运行目录为 recurrent-generator/instruction_pointer。完整原始经验、逐对原生重放结果、实时请求与回执、训练权重和独立执行终图在移动盘 eggfuse-experiments/control-credit-pairs。pairs 保存干预、具名页和参考事实差集；ledger 保存相同窗口下的 Fine-grained Cell 与控制 Credit；allocation 和 live 按程序、轨迹、Run 和决策状态关联。训练器只把在线可见的 x 和动作合法 mask 作为输入。跨规则集、晚到端口和遗漏核验只产生离线监督。训练程序来自现有动态 Recipe 家族，迁移到 EggCC 仍有分布差异。[复现脚本](reproduce.sh) · [权重摘要](weights.csv) · [历史高召回 Cell Stream 对照及预算](../neural-execution-control/README.md)
