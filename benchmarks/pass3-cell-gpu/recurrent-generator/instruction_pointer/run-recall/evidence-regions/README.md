# 首次证据发布能接管多少 EggCC 搜索

本实验在原生 egglog Runtime 上使用冻结 CCP v0.1。研究分支的上一版 B、GNN、父指针、递归 RipSat 和 RL 回报继续参与执行。新动作发生在一次证据发布之后、本 Run 的常规父端口搜索之前。程序可以在后续多个 Run 等待对应规则和真实回执。

## 真实轨迹中的机会

离线发现只在第一次实际发布的初始事实或生成 Cell 上启动。入口提供源实例的已发布具名端口，并能复用其仍可读、同版本的已匹配输入。发现器从所有消费这些证据的分支同时扩展。每个新步骤的所有角色必须来自入口、至多一个额外独立端口，或前一步实际发布的具名输出。步骤必须出现在证据就绪后的第一个合法调度 Run。独立证据不足的位置留给后续普通生成。未索引的 repair 事件继续由既有路径处理。每次发现最多 32 步，允许从发布起向后 32 Run。

只用 sum-bits 按累计有效操作 / 入口绑定选择 48 个结构。在其他程序中链接同签名的唯一 Recipe 规则，并校验其具名接线和表类型。下表的见证采用程序中与训练目录完全相同的区域形状，按 EAR 从高到低选择。每个源事件最多选一次，各区域不共享计入收益的步骤。EAR 的分子来自原生变更归属账本，分母计入源证据和任何新增独立端口。实际神经寻址次数另计。该算法可能漏掉更小的子图、不同的证明和其他打包方案，因此表中是已找到的机会。

| 程序 | 不重叠实例 | 有效操作 / 独立绑定 | EAR | EAR ≥8 / ≥16 的实例 | 额外直接消费分支 | 入口之后的 Run 执行的步骤 |
|---|---:|---:|---:|---:|---:|---:|
| sum-bits（训练目录来源） | 239 | 999 / 250 | 4.00 | 22 / 7 | 293 | 666 |
| dot-product | 182 | 769 / 182 | 4.23 | 15 / 4 | 167 | 518 |
| fact | 57 | 201 / 57 | 3.53 | 2 / 0 | 52 | 191 |
| loopfact | 53 | 226 / 53 | 4.26 | 6 / 0 | 48 | 161 |

sum-divisors 有 378 个单证据、17 个双证据实例，共占参考执行 11,905 个有效操作的 14.44%。它们对应原 B 在 teacher 快照上对新鲜角色的 949 次一元事件和 1,013 次末端候选访问。有效操作多的结构也可能只替代很短的父端口搜索。允许在 sum-divisors 自己的轨迹上发现结构时，这次贪心打包覆盖 2,503 个有效操作。评估程序中发现的结构只用于离线统计。[逐程序口径、分布、边际访问和原生见证](audit)

每个程序还选取冻结目录中 EAR 排序最靠前、兼有分叉和跨 Run 步骤的一个实例，强制接管并重放其余完整 teacher 轨迹。五个实例均通过原生终图、调度、写入、RHS、恢复、事件及请求接受数检查。例如 sum-divisors 的入口在 Run 132 已可用，三条直接分支参与最多 32 步的展开，实际步骤位于 Run 135–155，归属 25 个有效操作。此项原生布局检查从第一个可执行步骤接管。下面的神经策略在首次发布时自行决定是否激活。

## Neural Execution

在源类型链接的选项中，现有 B 打分头以一个已发布端口的向量、GNN 规则描述和具名接线选择一个区域或 Pass。每个首次发布事件做一次选择。可选的额外证据使用原有 B 字段桶和父指针，成功绑定后可供所有分支复用。每步在被调度的 Run 验证具名引用、版本和水位，经 CCP 实际付费提交。缺失条件回执、版本失效或原生拒绝只关闭依赖该步骤的区域分支。原生接受的具体绑定可跳过对应普通生成位置。对于二元规则，只有当前末角色候选桶中每个位置都已被真实回执覆盖时，才跳过整个根前缀，其余候选照常处理。已经执行的区域输出也进入旧的递归 RipSat 开放端口集合。

训练从 fe580c49 实验的 structure-rl.pt 续训。在 sum-bits 的前 320 Run 执行四组正负参数扰动，种子 431。完整原生 episode 的原有覆盖约束、有效操作、Token 成本和墙钟构成回报。EAR 仅用于描述和离线目录选择。三个独立执行程序都在历史研究中使用过。每次从初始状态运行到调度结束，训练和自主执行均未使用这些程序的反事实答案。[训练回报](training.json) · [冻结接线](evidence-book.json)

八条带探索的训练轨迹共激活 1,569 次，其中尝试寻址额外证据 9 次，区域输出累计归属 1,289 个有效操作。训练使用实测时间作为回报，保存的权重可复现自主决策，重新训练时主机负载会影响更新。

## 独立执行中的替代与额外搜索

旧策略从已完成的主体组合。加入首次发布动作后，冻结权重组和继续 RL 组使用同一动作空间。程序均完整运行两次，第二次反转三组顺序。覆盖率以派生参考事实为分母；各组每项原生有效操作只归属一次。下面的“区域操作”已包含在整次运行的有效操作内。区域的内部步骤全部按 CCP v0.1 各自付费。

| 程序 | RL 激活 / 有有效操作的激活 | 区域有效操作 / 入口绑定 | 区域签发 / 原生接受 | 额外直接分支 / 内部回执接续 | 完整跳过的二元根 | 完整候选打分净变化 | 总候选访问净变化 |
|---|---:|---:|---:|---:|---:|---:|---:|
| fact | 90 / 16 | 38 / 90 | 75 / 65 | 10 / 14 | 8 | −22 | +209 |
| loopfact | 94 / 22 | 65 / 94 | 97 / 80 | 19 / 23 | 21 | −57 | +824 |
| sum-divisors | 425 / 108 | 236 / 425 | 383 / 310 | 75 / 59 | 85 | −159 | +4,131 |

三个 RL 程序的区域动作都只绑定发布源，额外入口证据寻址次数为零。依赖其他独立证据的普通计算继续付费。每次激活的实际操作归属、额外绑定尝试、横向消费、纵向续接和签发数可由同目录的 activations.json 文件逐项检查。sum-divisors 的一次成功激活从 Run 311 的源证据出发，原生接受 5 步，其中两条直接分支、三条经内部回执接续，共归属 9 个有效操作。整个策略的平均 EAR 为 0.555，包括所有未产生有效操作的激活。

sum-divisors 为首次发布动作打了 1,984 个选项分数。85 个完整跳过的二元根总共只对应 85 个末角色候选。另有 299 次来自普通一元事件或末端解码的已接受位置被跳过。总访问量可核对为普通父候选 −159、既有边界指针 +20、开放伙伴指针 +4,270，合计 +4,131。原有递归策略能读取新区域的已发布输出，因此这些伙伴访问也计入端到端成本。同步比基线多 378 次。加入新动作本身，以及发布更多可被既有策略关注的回执，都有代价。

## 复现

在 instruction_pointer 下运行。DATA 使用之前结构组合实验的原生程序、teacher tape、冻结指针与索引模型。本次核对了移动盘原始 EggCC 档案，三个独立程序的 program.json、tape.json 均与本地输入逐字节一致，参考终图哈希一致。

```bash
mkdir -p "$OUT"
cp run-recall/entry-first/entry/catalog.json run-recall/multi-entry/entry-contracts.json "$OUT/"
cp run-recall/entry-wiring/{wired,graph}.pt run-recall/structure-compose/{structure-book.json,structure-rl.pt} "$OUT/"
python evidence_regions.py "$DATA" "$OUT" sum dot fact loopfact sum-divisors
python evidence_study.py "$DATA" "$OUT" sum train --limit 320 --seed 431
# 重现已报告的独立决策时可使用本目录保存的 evidence-rl.pt。
for rep in 0 1; do
  arms=(late early rl)
  if test "$rep" = 1; then arms=(rl early late); fi
  for case in fact loopfact sum-divisors; do
    python evidence_study.py "$DATA" "$OUT" "$case" "${arms[@]}" --rep "$rep"
  done
done
python evidence_results.py "$OUT" "$OUT/summary"
python -m unittest discover -p 'test_*.py'
```

86 项 Python 测试通过，其中新增的回归覆盖同一证据分叉后汇合、遇到独立证据停止、发布前等待、条件输出缺失时保留兄弟分支，以及只有整桶确认后才跳过前缀。README 的 Cargo compile、run 和五次 bench 通过，属于独立的最小 CPU 路径。既有 sum-bits 导出按项目审查合同得到 pass。[语义验收记录](semantic.json)
