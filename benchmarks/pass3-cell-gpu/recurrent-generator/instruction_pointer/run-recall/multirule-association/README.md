# EggCC 多规则发现与联合稀疏寻址

真实 EggCC 程序在项目 Rust Cell Runtime 上通过 CCP v0.1 完成固定调度。冻结联合索引后，完整 Token CE 提高了三个留出程序的自主 Coverage。三个抽样种子中，输入公开父域规模的模型每次发现的参考事实数都高于因子化随机。额外输入采样关系支持未稳定提高 Coverage，主种子在三个程序上均降低 EPS。当前直接生成器仍落后于高召回 Cell Stream。实验使用同一训练种子，泛化范围为留出程序，EggCC 程序之间共享规则结构。

## 完整 Token CE 和模板输入消融

三个 CE 组共享已有解码器参数规模、初始化、非负联合稀疏核、GPU 寻址、静态 Recipe 与训练样本。复用现有 gate，对调度集合内每个模板做两次相反方向的比较并求差，统一 softmax。保留冻结树及未经训练的平坦读出，分开观察读出变化。没有新增预测头。

- **CE-base** 仅使用原公开环境和图向量。
- **CE-count** 在原通道加入前四个角色的已发布类型域规模。所有调度内模板仍参与抽样。
- **CE-support** 另在第 17 个图通道加入关系支持。选取 Recipe 的第一对有连线的角色，每个类型域按与字段值无关的物理偏移至多抽八行；由冻结稀疏投影和 GPU PostingIndex 汇总同行跨头核的质量。零质量仍可选中。此实现每 Run 由宿主遍历公开行以构造物理抽样域，并在 GPU 重建探针索引；它仍有全模板打分和公开行读取开销。父绑定使用完整公开域。三个概念分别由类型域、原生 dirty 和实际执行归因观察，关系质量本身只能反映抽样字段支持。[关系取样与读出](../../multirule_support.py)

12 个动态训练程序、EggCC Teacher 和冻结策略自主状态合计 561 个规则×检查点组，2,334 枚有原生贡献归因的目标，285 个来源×Run。动态程序提供 342 组/1,764 枚，EggCC Teacher 提供 185 组/534 枚，自主状态提供 34 组/36 枚。93 组所在帧出现规则重新触发，101 组所在帧有版本更新，65 组有退役；采到的目标帧中没有即时 repair 事件。只有四组自主正例位于发生过原生重复请求的下一 Run。当前 Query 可见其后实际发布的状态；逐条 duplicate 回执未作为本轮新增特征。273/561 个正目标组的模板探针质量大于零。稀疏探针未命中、没有适用二角色连线和缺少值支持都可产生零值。未核验目标没有负标签。

分别留出整个 fact、loopfact、sum-divisors，包括各自的自主轨迹。每折按训练内活跃端口数分位数推进 Context Curriculum，前 64 次更新取最小 20%，到第 160 次取最小 60%，之后保留全部规模。每次抽四个正例组，每组至多六个经原生核验的绑定。400 次更新，三折每组分别曝光 7,107、7,278、6,896 枚完整目标。损失为模板 CE 加完整具名父引用条件 CE，包括联合索引的量化质量、探索分量与无命中回退概率。仅更新已有 gate 和地址 scorer，GNN 与联合投影冻结。逐组等权，未穷尽同状态有效计算。sum-divisors 留出集 CE-count 从 10.193 降至 8.696，CE-support 从 10.216 降至 8.690。这一微小差异未预测独立执行的排序。[语料分布](corpus.csv) · [学习曲线](curves.json) · [训练实现](../../multirule_ce.py)

## 独立执行与资源口径

每 Run 最多尝试八枚完整槽，遇空域照计生成尝试。固定 Seal/退出；实际推进的 Run 数随产生的事实变化。模板和父地址均使用真实地址置换，关闭最近端口复制。各策略取相同的抽样种子及地址种子，轨迹分叉后可见状态自然变化。主种子按正反序各跑一次，表中 EPS 为两次均值。Coverage 的分母只计初始化后应发现的参考事实。EPT/EPS 分别是原生归因的有效原子操作除以实际付费请求和在线墙钟。一个接受请求可以归因多个原子操作。直接模型计时含公开域准备、神经前向、通信、发布、原生执行和状态更新，预加载的模型权重及离线参考图比对在计时区间外。

|---|---|---|---|
| 因子化随机 | 4.02% / .239 / 83 | 4.77% / .187 / 67 | 1.48% / .321 / 167 |
| 冻结模板树 + 联合寻址 | 4.38% / .174 / 23 | 5.49% / .106 / 17 | 1.48% / .301 / 52 |
| 冻结权重，平坦模板读出 | 4.29% / .196 / 35 | 5.58% / .184 / 30 | 1.45% / .399 / 68 |
| CE-base | 5.18% / .124 / 30 | 6.12% / .110 / 28 | 1.67% / .270 / 57 |
| CE-count | 8.39% / .078 / 22 | 7.64% / .082 / 22 | 1.90% / .238 / 54 |
| CE-support | 7.68% / .075 / 18 | 7.55% / .087 / 18 | 1.73% / .233 / 41 |
| 历史 Cell Stream，每 Run 至多八枚付费请求 | 8.39% / .989 / 442 | 10.88% / .905 / 401 | 2.69% / 1.923 / 668 |

Cell Stream 使用历史权重和原始角色顺序、显式单来源 delta 锚点、可见的其余伙伴，以及原生重复核验；关闭跨角色 freshness 裁剪。它可以在八枚付费请求前进行更多前缀打分。该行对齐付费上限和程序调度，未对齐神经槽或搜索量；墙钟包含该实现的模型准备。完整历史预算的事实数另为 1,109、1,049、3,137。[本轮 Stream 原始结果](stream.json) · [历史完整预算](../fine-credit/historical-stream.csv)

三个抽样及地址种子的事实数范围，顺序为 fact、loopfact、sum-divisors。因子化随机为 42–55、49–54、112–124；CE-count 为 65–94、75–85、139–154；CE-support 为 71–86、64–84、139–144。九个配对中，CE-support 相对 CE-count 两次增加、七次减少。三个程序都缺少独立训练种子的误差估计。按冻结基线的程序总付费数再次截断至 541、745、742，主种子 CE-count 获得 91、85、152 项，CE-support 获得 84、84、139 项。该上限允许前面的 Run 消耗后面的预算。主种子 fact 上 CE-count 与 Stream 均覆盖 94 项，两者只有 71 项相同，各自另有 23 项。未建立同终图端到端加速。[全部付费、墙钟、索引工作及图摘要](native.csv) · [事实身份](facts.json)

## 动态索引

在 fact、sum-divisors 和动态程序的三张真实发布表上，按物理插入位置每 32 行分段。退役移除旧引用，更新替换端口版本和投影；固定字段归约顺序。对 130 次有变化的发布逐次独立重建全表，检查每个正 posting 的联合码、具名引用、版本及整数权重完全相等，再检查查询聚合在 1e-5 容差内一致。共 557 次退役、1,031 次版本变化跨码。sum-divisors 被测表增量重建 14,149 行，全量重建 245,945 行。测试范围为叶 posting 和实际版本变化，多父树的下游权重传播仍沿用原路径。正式独立执行使用原始建索引方式；上述行数节省仅归于维护诊断。[发布审计](maintenance.csv) · [增量实现](../../multirule_maintenance.py)
