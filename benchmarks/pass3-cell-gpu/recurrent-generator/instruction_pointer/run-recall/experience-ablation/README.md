# Teacher、自主轨迹与遗漏监督的配对消融

在 76 个留出自主状态上，每状态给 256 枚完整 Token 预算，将同状态原生核验的遗漏加入训练后，三个种子、两个抽样种子的不同有效计算总数均值从 264.0 升到 293.5（+11.2%）。六次配对中四次上升，两次下降。因子化随机为 352.0，加入遗漏的模型六次均低于随机。四个留出程序的独立执行也都由随机取得更高的平均 Coverage。由此保留遗漏监督作为下一项质量消融的对照，DFM 和 Higher 优化继续暂停。[消融计划](PLAN.md)

## 原生核账

对上一轮 64 份完整执行重新重放已签发并接受的证书，逐份复核终图哈希、参考事实集合、接受数、付费回执和有效操作。用每次发布的静态类型域容量重建每 Run 的完整 Token 配额。上一轮失败监督组的 12 个独立配置（去除反序计时复本）实际获配 65,559 个槽，填满 60,234 个，欠额 5,325 个。连同原生接续共付费 60,337 次，完成 1,766 个署名原子操作。原 Loss 组填满 71,265 个槽，付费 71,369 次，完成 2,091 个署名操作。各组走出的状态不同，因此可用配额也会变化。归档冻结数据的逐种子、逐预算和 Run 3 三张汇总表均按字节复现。三个 EggCC 程序在首次空档 Run 3 的高召回与精确分叉分别重放，均得到规则 575 的两个不同有效绑定。[历史核账](accounting.csv) · [原生空档重放](stalls.csv)

## 训练数据与有效性

训练程序为 sum、dot 和 fork grammar；留出 fact、loopfact、sum-divisors 和 left grammar。共用原有 Recipe、GNN、CCP v0.1、Metal 地址网络，以及预算内不同有效计算数的当前策略梯度。所有原生分叉和标签仅供离线使用。线上仍由模型选择模板和引用，随后由 CCP 原生执行核验。本实验沿用这些程序共享的规则及冻结布局，泛化检验的单位是程序和执行轨迹。

重新执行冻结 D 后获得 1,224 次页决策和 6,252 份原生回执。每个决策按 Run、epoch、页位置和此前已经付费的请求数索引，保留生成项、实际签发 ID、原生响应及独立接续。三条终图和付费数均与归档一致。统一索引另含 71 个 Teacher 决策。训练抽取每 Run 的首次决策；自主状态包括首次停产、重复靠前、产出和普通未产出 Run。还原自主模型的 context 后逐元素与在线实录严格比较。[逐状态标签和抽样层](training-states.csv)

| 来源 | 状态 | 在原轨迹中实际贡献的绑定 | 新确认的遗漏 | 遗漏贡献的原子操作 |
|---|---:|---:|---:|---:|
| Teacher | 71 | 1,688 | 0 | 0 |
| 自主 dot | 22 | 23 | 26 | 60 |
| 自主 sum | 24 | 15 | 96 | 138 |
| 自主 grammar | 2 | 1 | 0 | 0 |

对同一发布状态先原样执行，再追加精确引擎从该状态签出的缺失证书。只有追加请求在原生账本有新增有效操作，且原有每份证书的贡献数均保持一致，才给予遗漏监督。核对新增签名的贡献之和等于总署名操作增量。四次分叉改变了原有贡献分配，保留 Unknown；有贡献的遗漏集中在 11 个状态。标签反映本 Run 的边际署名贡献，对零即时贡献的长期价值保留未知。历史验证的 Teacher 地址别名归并为同一签名。新自主状态尚无同等密度的别名库。Teacher 样本在这次核验中没有获得新签名，故 Teacher 加遗漏与纯 Teacher 共用一套权重。[训练库存和原生状态分类](inventory.csv)

## 冻结快照

三个不同的训练配置，各以三个种子训练 256 次 AdamW 更新。T 只用 Teacher。TS 将一半 Teacher 位置换成自主经验。TSO 使用与 TS 完全相同的状态顺序和预算，并开放遗漏监督。三个组拥有相同的参数、初始化、训练目标和优化器步数。含已知贡献的更新次数及抽样实际命中标签的次数因数据不同而变化，逐权重记录。此次每组 256 次更新，历史 Coverage Loss 实验为 768 次，跨轮数值不用于拆分数据收益。[权重哈希与更新次数](weights.csv)

| 76 个自主状态 | 预算 4 | 预算 16 | 预算 64 | 预算 256 |
|---|---:|---:|---:|---:|
| 因子化随机 | 61.0 | 126.5 | 241.0 | 352.0 |
| T（亦为 Teacher 加遗漏） | 58.2 | 115.3 | 193.8 | 270.7 |
| TS | 58.8 | 112.5 | 189.0 | 264.0 |
| TSO | 60.8 | 121.2 | 204.8 | 293.5 |

每格先对各状态内原生核验的不同有效签名去重、跨状态求和，再对配对种子取均值。各状态上限取预算与物理域大小的较小值，比较组对齐实际交付的完整 Token。重复签发和未能构成完整 Token 的尝试均保留在原始记录。这里的自主快照来自归档策略 D，独立执行另测新权重自己的状态分布。在 109 个 Teacher 测试状态上，预算 256 时 TS、TSO、随机分别命中 252.7、280.5、419.0。自主状态的相同预算下，TSO 的物理重复生成率为 51.1%，随机为 42.1%。下一项应在同一批经验中分开打开重复反馈和原生拒绝反馈，检验节省的预算是否真的转移到了不同有效计算上。[各程序完整曲线](frozen.csv) · [原始配对汇总](frozen-pairs.csv)

## 完整独立执行

计时对象是仓库自有的独立 Rust Cell Runtime，实际通过 CCP v0.1 执行 EggCC 和 grammar 程序。四个程序、四种有效策略、三对训练与执行种子，首个种子再反序计时，共 64 次到达 schedule end。Coverage 使用最终可对齐参考派生事实；EPT 包含所有实际付费请求和接续；EPS 使用端到端冷启动墙钟。Coverage、EPT 对三对种子取均值，EPS 对首对种子的正反序运行取中位数。不同策略的终图与覆盖事实集合有差异。保留逐运行终图 SHA、各自独有事实数，以及配对耗时范围。[完整四组指标](native.csv) · [终图、付费、拒绝与耗时](native-runs.csv)

| 程序 | T Coverage | TS Coverage | TSO Coverage | 随机 Coverage | TSO / 随机 EPT | TSO / 随机 EPS |
|---|---:|---:|---:|---:|---:|---:|
| fact | 8.48% | 7.89% | 8.18% | 10.21% | 0.0218 / 0.0240 | 24.4 / 133.7 |
| loopfact | 10.46% | 9.65% | 9.98% | 11.15% | 0.0192 / 0.0220 | 22.6 / 118.3 |
| sum-divisors | 2.35% | 2.39% | 2.48% | 2.67% | 0.0405 / 0.0431 | 58.2 / 228.9 |
| 留出 grammar | 6.58% | 7.01% | 5.44% | 11.73% | 0.1979 / 0.4271 | 55.8 / 476.9 |

在共同的 2 秒冷启动墙钟上，按最后一个已确认的发布边界重放实际状态。三个 EggCC 程序的 TSO 平均覆盖 65.3、97.0、169.0 个参考事实；随机为 114.3、124.0、214.3 个。在这批计时中，随机已于 2 秒内完成。完整曲线记录 0.25–128 秒的事实数、付费和有效操作，保留已经提前结束的终图。[等墙钟原生曲线](clock.csv)
