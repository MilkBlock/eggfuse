# 神经控制能否保住原生执行窗口

**建议继续用 CCP v0.1。** 现有协议已经能测试两项不同的学习能力：在同一个冻结窗口内组织多次签发，以及决定何时关闭该窗口。本轮在独立 Rust Cell Recipe 执行器上完成 84 次原生独立执行。开放自主 Seal 后，初版策略在三个 EggCC 程序上都过早退出。加入合法 Teacher 前缀后的策略有所恢复，仍未稳定超过固定调度。这里测量的是项目的 CCP Native Runtime，未对上游 egglog 进程作性能测量。

## 调度审计

| 动作或状态 | 实际效果 |
|---|---|
| Continue | 策略展开下一页。无需向原生 Runtime 发消息。本实验用 Metal 生成具名 Cell，宿主读回完整页和控制选择，成本计入墙钟。 |
| Submit | CCP 校验序号、Run 和 epoch。非空批次逐请求返回带 ID 的回执。通过准入的 proof 进入当前 Run 的 ready 队列。确定性 computation 可以返回本批次的局部值。客户端可以据此继续签发。 |
| Seal | 客户端 flush 后发送带当前快照标识的结束帧。Rust 退出接收循环，执行当前源 Run。已接受的 proof 在此前仍可能没有可读输出。下一次发布或最终发布通过 committed_through_run 确认前一个窗口。 |
| dirty 与水位 | 来源规则被唤醒时置 dirty。半朴素路径在处理该次 occurrence 时消费唤醒。已调度的未触发规则也推进自身水位。一次生成、一页或一次普通 Submit 都不推进该水位。 |
| merge、repair、发布 | 执行已签发的 RHS，按原生次序完成源 Run、合并和修复，随后导出新增、更新和退役的可见端口。接受一条 proof 无法保证预期端口更新。 |
| Recipe 推进 | Sequence 固定子节点顺序。Repeat 有次数上限，首轮后可因无变化提前结束。Saturate 根据 last_change 继续或退出。Run 还可带源程序指定的 until/check。控制预测不能覆盖这些条件。 |

调用链可从 [Python 接收循环及自动 Seal](../../transaction_native.py)、[CCP 客户端](../../ccp_v01.py)、[Rust 接收及准入](../../../../../../engine/cell-runtime/src/token_transaction.rs)、[可见性发布](../../../../../../engine/cell-runtime/src/cell_tokens.rs) 和 [原生 Run 与 Recipe 解释器](../../../../../../engine/cell-runtime/src/runtime.rs) 核对。三个 EggCC Recipe 各含 208 个静态 Run 节点、171 个 Saturate 节点和 9 个 Repeat 节点。运行中可多次访问同一节点。四个被测 Recipe 都没有网络可自由选择的 Stage 分支，因此 D 没有独立处理组，主动 Advance 数为零。所有完整运行都走到 Recipe 终点。这个终点没有给出神经闭包完整性证明。[实际 Recipe 普查](schedules.json)

## 原生窗口能救回哪些计算

- **574。** 在 sum-divisors 的同一自主前缀上，Run 2 签发零父 574，原生新增 1 个有效操作。推迟到 Run 5，得到 untriggered_rule。在初版自主 Seal 策略的剩余空请求序列上只增加这条 Run 2 请求，运行至各自 Recipe 终点后净增参考事实 7838，未丢失其他参考事实。分叉走了 272 个 Run，原轨迹走了 208 个。
- **575。** 原生实时会话中，Run 3 的请求 3 返回 binding；同一 epoch 内再次 Submit，替换一个父引用，请求 4 返回 accepted。Run 4 才观察到新增的一个端口更新。重放核对修正请求净增 1 个有效操作。这次替换来自离线诊断。
- **网络实际恢复。** 从已有至少两次 Submit 的窗口中，按时间选第一个第二批含有已接受请求的窗口，比较“首批后关闭”与“执行网络实际生成的后续请求”。B 在 fact、loopfact、sum-divisors、grammar 四个局部分叉分别多完成 2、2、1、6 个有效操作。Shuffle 策略在 fact 的一个分叉恢复 9 个。这里的筛选产生存在性证据，不能将局部增量加总为策略的净收益。[原生回执与终图分叉](regressions.json) · [实际续算分叉](continuations.json)

## 实现与训练

复用既有 Rates 网络的三个动作输出，分别解释为 Continue 生成计算页、Submit 当前非空 Draft 和 Seal 已排空的窗口。Continue 的 Cell 内容由原冻结生成器与同一套 Metal 地址网络产生。控制粒度为一页。已有 Rates 参数针对控制动作重新训练，Cell 的权重固定。硬 mask 仅检查草稿是否为空和剩余资源。网络看到当前 Memory、事件、已生成页数、剩余预算、草稿大小、已签发数和上一批实际回执摘要。准入和发布仍由原生执行器确认。控制编辑选择需要一次 GPU 读回。

A 使用原来每 Run 两次生成和固定签发策略。B 允许自主累积和签发草稿，两个生成额度用完后关闭已排空的窗口。C 同时允许提前 Seal，每经过一个实际 Run 新增两个额度，可结转至多六个。首次 Run 同样只有两个额度。各组采用相同 16 个完整 Cell 的页目标、寻址域及原来的单页生成尝试上限。不同策略能改变后续 Recipe 迭代次数，因而整次执行的实际页数和请求数可不同。另做了关闭结转和去掉退出遗漏监督的独立对照。预算耗尽触发的关闭、策略主动关闭、源程序终止分别记录。没有通过重复 dirty、延后水位或由 CPU 搜索来延长窗口。

第一批来自 16 个独立生成的动态 Recipe 程序。用随机控制策略探索原生窗口，Cell 内容来自冻结神经生成器。采集 363 个窗口、1,123 个逻辑动作、6,729 枚完整签发 Cell。86 个退出点有经核验的直接遗漏。另一个训练队列从原生 Teacher 候选中乱序抽取合法前缀，改变非空批次边界并实际重放。31 个辅助窗口签发 3,080 个 Teacher 请求，后续自主轨迹签发 8,086 枚 Cell；其余均由原生反馈决定。相同程序的两条轨迹始终落在同一侧，按结构签名检查 12 个训练程序和 4 个留出程序互斥。EggCC 诊断和留出 grammar 均不供策略训练。

退出审计在离线分叉中相对实际已接受前缀补交具名请求。只有原先各请求的有效贡献稳定、附加贡献之和等于分叉净差时才给出局部归因。前一批有 9 个、Shuffle 队列有 16 个窗口的该检验未通过，保留 Unknown。仅有错误或重复回执的实际续算批次可以产生相对成本监督。零即时收益的 accepted 不自动产生负标签。退出时没找到遗漏也不提供饱和标签。对真实批次有贡献或输出被后续有贡献请求具名引用的情况，监督生成与签发决策，保留批次层级；不据此推断所有单枚 Cell 都有因果价值。每次 Seal 的实际发布量和后续使用单列，唯一解锁、最优 Seal 时刻和已完成状态下的全域无收益工作通常不可识别。

训练固定 160 次更新、同一初始化和抽样种子。第一批训练集提供 281 个有选择余地且有监督的动作，含 17 个直接针对过早 Seal 的标签。留出集正确 65/99。去掉这 17 个标签，留出为 64/99，EggCC 的三份终图完全相同。混入 Shuffle 前缀后，训练动作增至 633 个，含 33 个过早 Seal 标签，混合留出为 149/211。Shuffle 对照同时改变训练状态和样本量。[训练与留出](fit.json) · [遗漏监督消融](fit-no-exit-credit.json) · [Shuffle](fit-shuffle.json)

## 独立执行

表格各项依次为 **Coverage 百分数、EPT、EPS**。覆盖率和 EPT 合并两个生成种子，重复计时不重复计入事实和操作。EPS 为三次完整冷启动执行的中位数。第一种子同组正反序，第二种子复核事实集合。各组均保持原有付费请求口径；另计控制 Token 和前向时间。端到端包括生成、控制读回、原生通信、运行、Memory 更新和在线记录。精确重放、参考评分和生成事后报告在计时外。

sum-divisors 的 C 在两个种子都只支付了第一条请求，贡献 199 个有效原子操作、覆盖 100/8,018 个参考事实。余下 207 个窗口全部主动 Seal。关闭额度结转时行为相同。种子 536 下 A 实际有 578 个非空批次、371 次 Seal。B 有 484 个非空批次、371 次 Seal，另有 1,204 次控制前向，单计打分及动作读回约 0.98 秒。C 做了 210 次控制前向、一个非空批次和 208 次 Seal。高 EPT 与大幅丢失的 Coverage 同时出现。高召回 Cell Stream 的历史 Coverage 分别为 99.02%、94.33%、39.12%、100%；该参考采用自己的生成预算。[完整数据与计时范围](summary.csv) · [逐次控制、计费与终图哈希](runs.csv) · [实际事实集合](facts.json) · [历史 Cell Stream 原始指标](../fine-credit/historical-stream.csv)

对种子 536，按预先指定的 Run 2、Run 3、中点和末端抽取窗口，短程序去重。初版 C 抽到的 14 个窗口中，6 个存在可归因的直接遗漏，1 个绑定归因不稳定。sum-divisors 的 Run 2 和 Run 3 关闭时分别还可新增 1 和 28 个有效操作。后者是在该 Run 的真实状态单独分叉得到。这些窗口相关，不能把相邻 Run 的缺项相加，也不能从 14 个窗口推出全局 Coverage 中调度因素的百分比。不同预算与不同终图之间未建立等终图加速。[真实退出分叉](exit-forks.json) · [逐 Seal 发布、退役和被后续引用](publication.csv)

## 版本决策与复现

保留现有 CCP v0.1 请求、回执和快照语义。Continue、Submit、Seal 的逻辑选择已能在策略层区分。若需要“发布后继续消费同一源 Run 中的新证据”，则要先定义新快照身份、消费水位、merge/repair 的可见性与等待请求的处理。若需要自主 Stage 跳转，则要先在 Recipe 中定义可选后继和可跳过的工作。届时才有可测试的 v0.2 契约。本轮不支持让当前策略默认接管退出。

[复现脚本](reproduce.sh) 在 instruction_pointer 目录运行。原始训练轨迹、模型权重、每个请求的日志和终图在外置盘 eggfuse-experiments/execution-control-1127。verified-collection 包含带原始具名 Token 的重采经验，按程序比对接受 tape 和监督，并复训确认所有权重张量逐个完全相同。shuffle 包含 Teacher 辅助前缀与其后的自主经验。单个训练种子和两个生成种子不足以估计跨训练种子的不确定度。独立执行没有将 Teacher、离线遗漏或反事实替换提供给在线策略。
