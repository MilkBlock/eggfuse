# 真实发布回执、owner 绑定与离散计划编辑

基线为 `e89c929e`。在线实验使用单线程 CPU 推理及原生 Rust CCP v0.1，计费沿用现有协议。原生反事实、接口见证与留一重放属于离线诊断。本文的时间针对该项目的原生 Cell Runtime；独立的 standalone Cell CPU 回归另表记录。

在八页预算的 sum-divisors 上，D4 命中 122/8,018，花费 416 个请求，产生 225 个署名有效操作，EPT 0.541，冷启动 EPS 60.9。A 命中 3,137/8,018，产生 4,331 个署名有效操作。两者终图不同。8 页 C/D/E 都没有接受规则 576、531 或 56 的请求，没有自主复现 204 → 326 的链。眼下限制最明显的是从真实状态发出正确模板和完整父引用，回执可区分性尚未转化为开放计算覆盖。

A 使用 `multi.pt` 的递归 Compose 和 `structural-reach/prefix.pt` 的续接 MLP。它按原槽序分块遍历类型相容的可见端口，只对一个明确的 delta 源做版本检查。对伙伴的跨角色水位剪枝关闭，Prefix 的后续端口 lookahead 关闭。网络用字段向量点积、当前前缀和递归状态打分。它确实付出了稠密搜索成本。这个对照不向 C/D/E 输出候选或草稿。[基线](../../discrete_reference.py) · [前缀遍历](../../cell_stream.py)

B 在 A 搜索前每个原生 Run 有两次额外的冻结神经入口尝试。地址网络先定位模板和首个父端口，再选择该 owner 的静态投影契约。只有整个入口能由这次选择绑定时才可通过额外入口发出。原有一般入口继续处理其他合法绑定，同一请求再次出现也照常付费。P/O 是第二个对照，固定旧稀疏生成器、同权重同预算，关/开 owner 契约。A/B 与 P/O 各自在生成器内部配对。[高召回 A/B](../../response_reference.py) · [稀疏 P/O、C/D/E](../../response_study.py)

C 为普通单步监督 Editor，D 为条件 Edit Flow，E 在 D 的训练集上增加经原生核验的抽象替换。每个 Run 允许 2 个草稿页，另用 8 页复测 C1/D4/E4。页预算与 Flow 采样步数独立。第一个草稿为空，以后的页继续编辑未签发草稿。没有固定输出槽位。到原生调度末端仍 pending 的草稿、未完成接续和未服务事件保留为遗漏。达到 schedule end 不构成精确不动点证明。

Coverage 是相对原生参考新增的不同派生事实。EPT 使用原生署名有效原子操作除以全部付费请求。汇总表的 EPS 使用有效操作除以含模型载入、静态编码、Runtime 初始化、推理、通信、命名读取、执行与发布的墙钟。离线参考导出、整段重放及监督核验时间单列于评估路径。原始行还保留历史 warm EPS。每个定点使用相同随机种子正序/反序各执行一次；报告两个时间值的范围，不把它们当作两个独立训练种子。高召回第一份 A 来自本轮同配置独立复跑，后续 B、B、A 接续；部分早期墙钟与离线审计重叠，微小 EPS 差异解释力有限。全量事实集合、终图 SHA、原生状态、待办数量、计费、模板/端口探测、编辑和寻址前向调用都在逐次记录中。[原始运行](runs.jsonl) · [配对表](frontier.csv)

## Owner 接口究竟省了什么

规则 56 的十个 `after_init` 入口共含 1,153 个端口槽。如果固定见证给出的符号接线，按首次使用顺序抽取独立 owner 变量，则只需 85 次绑定，每例从 47–172 减为 6–10。本轮对每个入口交替四次逐槽和分组调用；两组每轮各提交 1,153 个真实付费 Observe，按相同顺序返回完全相同的类型化值和偏移。另有 1,153 次错版本读取全部被原生拒绝。可见版本取自已发布的指定端口，向执行器提交精确引用。端口有条件出现、已经隐藏或退役时不能靠其他值替代。

用于区域入口的符号分组来自离线已知的布局。实际选择 owner 时，使用同一冻结神经地址网络在物理类型域中选取，未提供正确 owner ID。初始化规则 375 的 owner 在该域只有一个，每次重复定位它本来就不需要神经二叉路由。两臂每轮实际地址前向同为 213、213、225、222 次。十个入口在四轮中 **0/40** 次完整选中 teacher 的全部外部地址，合法 Observe 仅证明选中的具名端口可读。单轮合计绑定加本地投影的中位数约 3.8 ms 降至 3.1 ms，所有原生观察仍需付费。原生批次 decode / execute / encode 单独留存；execute 包括地址解析、可见性、版本核验及取值，未将整个 execute 时间归给版本比较指令。[配对原始数据](owner.json) · [原生计数及错版本验证](owner-native.json)

正式生成路径另外编译可迁移的可选入口。根据已选消费规则的输入类型和已选生产者的原生输出契约，将有唯一静态角色的列映射到该程序的具体 PC。网络对整份契约选择一次，后续仅按指定 PC 投影。面对同表多个输出，不猜测 PC；一般入口仍然可用。没有根据实际值或其他角色的水位来确定 owner。区域 56 的见证专属 PC 列表不会进入评估策略。[绑定实现](../../discrete_cells.py) · [共享 Recipe 契约](../../response_plan.py)

## Higher 的开放边界与计划生命周期

Higher 使用原有 Recipe 的输入、确定性计算、原生 effect/custom merge、具名接线、可见性及寿命信息。规则的动态 guard 交给原生执行器。对已经签发的实例，只有对应输出的真实发布能固定内部引用的版本。接受但尚未物化的端口可以等待；固定版本退役或推进会释放该路径。已发布仍不足以满足消费规则的场合，保留环境条件，执行器没有寻找 writer 的入口。未穷举推断所有 guard 的充分外部生产者。阻塞和原生后缀回执可以通过已有结构嵌入影响下一页计划。[开放边界](../../response_plan.py) · [原生接续](../../region_owner.py)

跨页保留未签发的稳定局部 ID。只提交就绪的首项。生产者接受后，其尚未签发的消费者保留在可编辑草稿中，等待指定 owner/PC 的实际回执；回执发布时固定版本。生产者失败，消费者仍可被神经编辑。未解析引用永不提交，已签发副作用不可编辑。进入受托 Higher 的确定性后缀使用原有跨 Stage 续接机制。[回归测试](../../test_response_plan.py)

## 训练、采样及信息边界

训练来源是 sum-bits、它的模型 rollout 和训练 grammar。用同起点原生分叉构造空计划、修正错绑、保留、补全、重复和多结果目标。另从有原生有效操作署名的连续 Run 取得 35 个窗口目标和 25 个部分补全目标；各自的输入只读取此前状态和当前回执。46 对相同未签发草稿比较刚接受与版本拒绝。不同拒绝原因在最小模型中共享拒绝方向；实际状态仍按完整原生语义处理。公开行的动态值沿用冻结 Encoder 的字段指纹表示。E 另加入五个原生等效的两步折叠和五个直接激活例子。缺失收益证据不赋负标签。38 个 EggCC 更新和请求 204 全部留作评估。[训练清单](primitive/fit.json) · [组合监督](composition/fit.json) · [输入与权重 SHA](inputs.json)

两种方法共用冻结结构 GNN、二叉地址树和等规模的编辑速率/动作网络。训练 C 与 D 的合法端点和地址监督相同。C 学习原位置的插入计数以及保留、删除、替换分类。D 定义保持拓扑引用合法的有序编辑桥：对 n 个必要编辑，t 时刻已完成 K 服从 Binomial(n,t)；实现等价采样 K 在 0..n 均匀，再采 t | K 为 Beta(K+1,n-K+1)。路径下一跳速率为 (n−K)/(1−t)，通过时间加权 Poisson rate matching 拟合。推理使用冻结速率的 tau-leap，插入取 Poisson 计数，删除/替换取竞争风险，1/2/4/8 次神经更新后才与 CPU 通信。操作标记使用共同的神经地址模型。该模型沿用已有离散流，新增条件为真实发布的增量表示及已签发请求实际回执，不用 latent norm 判价值。[速率训练及采样](../../discrete_editor.py)

模板寻址每层读两个结构向量，父引用每层读两个物理类型域的代表端口。生成过程中没有构造完整证明笛卡尔积。建立静态目录编码、维护类型端口列表和读取当前草稿里声明的局部端口均有成本；原始记录中分别提供静态准备、索引维护、草稿访问和在线采样时间。模板、父端口、原生行、GNN 编码和确认状态之间没有精确 join。C/D/E 不读 teacher schedule 以外的未来执行、目标事实、因果表或参考证明。调度来自当前 native frame。离线评估使用的反向 ID 映射只用来对齐见证和报告。

## 回执敏感性与跨区域执行

留出程序共有 39 个起点。固定同一草稿、Memory 及采样随机数，仅提供两个真实分叉的即时回执。在成功后清空且在拒绝后保留正确草稿的双侧判据下，C 为 280/312，D4 为 137/312，E4 为 135/312。312 是 39 个起点各用八套随机数；确定性 Editor 的结果应按起点理解。网络在这一诊断能根据回执改变行为。不能把草稿缩短直接计作端到端省掉的重复。原生 duplicate 拒绝、同 Run 重签、零署名边际贡献和终点未付的草稿均单独报告。离线留一检查只为实际测试过的、移除后其余署名和终图仍一致的请求提供证据。[逐起点行为](feedback.json)

规则 56 的 38 个不重复命名版本更新分布于 17 个 Seal。完整前缀环境和省略该 Seal 写入的干预均由原生重放；完整环境在相应消费者的原 Run 上 38/38 组依赖都可见且规则进入调度。每组以 16 个种子从空草稿四步生成，指定完整消费者绑定 0/608；抽到消费者规则的样本为 14/608。省略写入后重放相同后续请求，只有 3/38 组还进入原消费调度，0/38 组具有原版本的全部输入。即刻下一 Run 没有一组调度该消费者，因而不使用即刻生成率判定绑定能力。[逐版本数据](revision-pairs.json)

在整段原始环境和隔离区域，204 的请求都被原生接受，149.op3 分别是 v19 和 v15，326 只在完整环境得到接受。固定各自真实 Memory、地址树、调度、草稿和随机数，交换两种实际发布回执的表示，在完整环境改变 7/16 份计划，在隔离环境改变 4/16 份计划。两臂交换的是整份实际发布，不能把差异唯一归于 149.op3 的版本字段。没有把已知的 204 或缺失生产者作为正式执行输入。[两种回执与生成计划](writer204.json) · [固定状态的通道干预](writer204-channel.json)

新 Bake 的六步分叉/汇合模板在 D4 中被主动选中两次，一次入口通过且完整走到终点。四步 Flow 的 Primitive-only、Higher、Higher 且所有神经请求重新原生核验三组，终图 SHA 与六个参考事实完全相同。

| 六步同终图控制 | 付费请求 | 有效原子操作 | EPT | 冷启动 EPS | 两次墙钟 |
|---|---:|---:|---:|---:|---:|
| 仅 Primitive | 12 | 6 | 0.500 | 147.8 | 37.3–43.9 ms |
| Higher + 已核验回执复用 | 9 | 6 | 0.667 | 153.8 | 37.6–40.4 ms |
| Higher + 每份神经签发均发往原生 | 15 | 6 | 0.400 | 143.6 | 41.2–42.3 ms |

历史接管器在同一快照可复用 Higher 已接受后缀的具名回执。D4 本例复用了 5 份；fresh_requests 消融把每份神经提案实际发送给 CCP。后续计划会受实际 duplicate 回执影响，付费差额不必恰好等于复用次数。因而 12 → 9 不能作为网络学会避免重复的证据。正式对照另覆盖每个 EggCC 的 fresh_requests 路径。对零署名边际贡献提案的离线抽样中，19 个留一反事实改变了后缀验收条件，另一个存在实际消费者而未删除。没有据此认证任何一份安全的端到端语义去重。

第二个冻结后编译的独立程序允许网络在两个写规则中选择，并提供两个 Ticket 作为入口干扰。起始没有 Permit。D1 在原生 Run 2 选择外部写规则生成 Permit，Run 3 的 Higher 根实际引用该 writer 的回执，随后完成四步分叉/汇合。打开 fresh_requests 后，同样完成 6/6 个参考事实，D1 付费 19 次。C 也完成 6/6 并使用了同一个 writer，但通过 Primitive 完成后续计算。这个正例证明网络可以产生外部证据并在下一阶段使用，不能证明它已学会为了未来的 Higher 才选择 writer。原生调度和小词表使这个留出程序比 EggCC 容易得多。

两个新模板的规范化签名都与本轮训练期间可见的 58 个结构及存档 GNN 的 10,000 项训练目录无交集。GNN 权重、Primitive 权重以及目录链接器来自既有项目，因此仅对具体签名和本轮留出程序主张零样本；几个历史 EggCC 程序已经用于此前的开发判断。[签名与身份](inputs.json) · [直接生成与回执接续](../../response_study.py)
