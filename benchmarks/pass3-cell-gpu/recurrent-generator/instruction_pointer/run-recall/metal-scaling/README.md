# 在 Metal 上实测 Response-conditioned D4 的容量与数据规模

在 Apple M3 Max（48 GB，macOS 27.0.1，PyTorch 2.15.0）上，50,043,836 个可训练参数能够完成 FP32 训练和原生独立执行。本轮共训练 13 组权重，完成 152 次原生 CCP v0.1 执行。扩大模型改善了部分监督指标，但最好的容量取决于训练数据和工作负载。在相同 fact 终图上，Metal 相对单线程 CPU 的整轮耗时到 50M 才占优。

## 实验口径

从 3a6425be 的 D4 出发，复用原来的地址树、响应特征、四步编辑采样、两页预算、参数共享、模板和 CCP。扩大的是原有 `Marks.choice` 和 `Rates.net` 的隐藏宽度和层数。这两部分原来合计 **15,732** 个可训练参数。另有冻结的 Actor 25,512 个参数和 CellScorer 7,362 个参数。它们是完整模块的参数总数，单次生成只调用其中相关的层。每档的隐藏宽度（地址 / 编辑）依次为 48/64、136/192、512/752、1216/1816、2760/4112。相应隐藏层数是 1、2、2、3、3。

| 容量 | 实际可训练参数 | 小数据地址损失 训练/留出 | 大数据地址损失 训练/留出 | 小数据编辑损失 训练/留出 | 大数据编辑损失 训练/留出 |
|---|---:|---:|---:|---:|---:|
| 原尺寸 | 15,732 | .304/.323 | .309/.319 | .493/.570 | .502/.494 |
| 100K | 102,068 | .296/.343 | .307/.324 | .399/.531 | .452/.449 |
| 1M | 1,008,468 | .302/.360 | .305/.320 | .354/.580 | .379/.404 |
| 10M | 9,990,628 | .300/.345 | .305/.319 | .333/.572 | .349/.383 |
| 50M | 50,043,836 | .293/.341 | .302/.323 | .340/.634 | .350/.408 |

小、大数据分别有 470、960 条计划，5,172、26,723 个监督地址决策。沿用 sum-bits、其模型 rollout 和训练 grammar 的原生核验分叉。扩充的是连续发布窗口，独立程序数量相同，训练样例中出现长窗口的比例也随之变化。dot-product 的 246 条计划、6,851 个地址决策作为历史验证程序，全程未参与拟合。四个独立执行工作负载与训练程序分开。这里检验相同程序提供更多监督的效果，跨程序数据多样性的作用仍未测量。

每档重新训练，固定随机种子，每个模块各进行 192 次 AdamW 更新，每次 128 行，学习率 0.0005。目标沿用有权重的地址二元交叉熵及带位置掩码的 Poisson 速率损失。原尺寸也在相同优化预算下重训。桥接时间按原有顺序编辑路径抽样，每条训练记录预取八次，拟合评估和留出评估各使用独立的四次抽样。训练损失按训练计划上的诊断抽样计算。learning.csv 还保留地址分支准确率、正跳转位置的原始操作 logit 第一名命中率（含端点未屏蔽的 logits）和样本数。

小数据有不同结果。按原尺寸、100K、1M、10M、50M 顺序，fact 命中 41、42、40、31、31，loopfact 命中 43、54、42、48、40，sum-divisors 命中 100、109、111、104、108，grammar 命中 0、0、0、3、0。完整 EPT、EPS、探测量及配对范围见 rollouts.csv。按事实身份取并集，所有扩大模型相对本轮原尺寸模型的并集，在四个工作负载上分别多发现 6、20、18、3 个事实；这些事实都已在上轮独立的高召回 Cell Stream 基线中出现。不同模型相同覆盖数也可能对应不同终图。

在大数据 sum-divisors 上，10M 和 50M 各签发 21 份付费请求，20 份原生返回规则未触发，1 份被接受。两者仍分别做了 11,902、11,329 次模板探测。留出编辑损失改善，并未保证采样得到适用规则及可执行绑定。原尺寸签发 139 份，6 份被接受。以上为实际运行的终点归因，尚不能单独判定模板选择、父绑定和训练分布各自的因果贡献。

### 四倍优化预算

大数据上另跑 768 次更新。50M 地址训练损失 .302 → .277，留出 .323 → .316；编辑训练损失 .350 → .302，留出 .408 → .451。10M 编辑损失也出现训练集继续改善、留出集变差。10M 与 50M 的 fact 覆盖均从 2 恢复至 31，sum-divisors 从 2 恢复至 100；同预算原尺寸分别为 35、104。长训的大模型每个工作负载只签发两份请求。fact 的两个大模型达成相同终图、EPT 均为 36，冷启动 EPS 分别为 14.75 和 12.23；sum-divisors 两者终图相同、EPT 均为 99.5，EPS 分别为 41.15 和 33.07。高 EPT 对应的覆盖依然很低。固定训练步数会影响容量判断，已有数据也不足以估计大模型最优学习率、所需标注量或整个架构的能力上限。

## Metal 成本和实现边界

每种规模在大数据 fact 上使用同一权重、随机种子和调度进行 CPU→Metal、Metal→CPU 配对。这里固定静态 GNN 在 CPU 预编码，只换热路径设备，包含权重装载、静态图编译编码、调度、Python、CCP 和原生执行。两种设备的事实集合、终图摘要、付费请求数及核验结果计数在五档中逐一相等。

| 容量 | CPU 冷启动秒 | Metal 冷启动秒 | 覆盖事实 |
|---|---:|---:|---:|
| 原尺寸 | 1.08 | 5.08 | 32 |
| 100K | 1.15 | 5.46 | 31 |
| 1M | 1.97 | 6.84 | 32 |
| 10M | 2.31 | 4.96 | 2 |
| 50M | 8.53 | 7.10 | 2 |

地址层的难点是因果依赖。每层只读两个枢轴，产生一个分支分数，Python 读取标量并采样，下一层才知道要读哪些地址。以原尺寸 fact 为例，5,001 次地址前向和 2,168 次编辑前向等同步模块调用合计 3.94 秒。50M 对应 5,010 次地址前向、2,168 次编辑前向。共享物理内存仍然存在命令提交、张量复制和同步开销。设备包装器让权重常驻 MPS，每次按原路径取回结果，计时覆盖实际消费者等待。每个结果文件保存按模块的时间、次数及逻辑输入输出字节数；该字节数并非硬件带宽计数器。

在相同留出特征上独立测试同步前向，50M 的地址网络单条 CPU/Metal 约 653/677 微秒，同批 128 条分别约 6.63/1.23 毫秒；50M 的编辑网络 128 条约 8.73/1.74 毫秒。原尺寸单条地址仅 CPU 7 微秒，Metal 468 微秒。每设备两组、每组 3 次预热 20 次测量，记录中位数和 P90，显式取回实际结果。在这些输入上，CPU/MPS 原始输出最大绝对差约 2.1e-5，地址阈值或速率 argmax 分歧为零。批量实验展示已经准备好的独立输入的成本，在线父地址树仍然逐层执行。

另用 `--device-gnn` 把冻结 Actor 的图消息传递、Primitive 与 Higher 的 CellScorer 编码也放在 MPS；静态向量一次读回用于原有目录和地址读出。五档在四个工作负载上的终图与 CPU 预编码一致。动态图的定长神经前向（dynamic、age、next_read）同样在设备上执行。具名端口表、FP64 增量汇总、树遍历、随机采样以及 Rust 核验在 CPU。全部 MPS 实验关闭 PyTorch 的 CPU 算子回退。在线决策接口、可见域和 B2/B3 边界沿用 D4。数据监督及终图对齐在计时外，在线执行未读取参考结果。

## 数据与复现

运行 `sh run-recall/metal-scaling/reproduce.sh`，从 instruction_pointer 目录指定 DATA、FORKS、ROLLOUT、OUT、PY。输入沿用 response-edit 的原生快照、模型 rollout 和核验分叉，可对照其 inputs.json。目录内的 models.csv 给出每个权重的 SHA-256 及含诊断的训练耗时，learning.csv 给出完整拟合曲线，rollouts.csv 给出配对明细，runs.jsonl 保存每次的终图摘要、事实身份、原生计费及设备调用明细。十三个实际训练的 FP32 权重位于实验输出各配置和 long 子目录的 weights.pt。机器上的输出位置为 `/Volumes/Extreme SSD/eggfuse-experiments/metal-scaling-1126`。

Coverage 沿用原生终图中可对齐的参考派生事实比例，EPT 使用 replay 的 signed effective operations / 付费 CCP 请求，cold EPS 使用同一分子除以含在线准备的墙钟；离线参考导出和审计重放单列。计时只有两次、模型和采样各使用一个种子，报告范围而无显著性推断。此前高召回生成器是另一条执行机制，其历史成绩仅用于核对发现的事实，未混入容量拟合或设备测速。部署和训练均未改动 CCP、Bake、原生计费或模型训练目标。

117 项 Python 回归通过，现有 sum-bits 语义验收 pass。另按仓库 README 完成 standalone Cell CPU 的 compile、run、bench，五次 bench 中位数 21.02 ms，终图摘要 95fa82263dfc6fc8b26e2faf23be62fdb1be6e4ca33f940224e59779dc63ed52。这项 CPU 回归与上面的神经独立执行分开计量。
