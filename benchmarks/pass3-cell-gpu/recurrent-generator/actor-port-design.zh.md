# 从 Base Actor 到多端口 Cell token 生成器（草案）

## 目标与依据

以 Base Actor 的递归前向、并行输出行、集合监督和 PyTorch/Metal 对照为骨架，替换固定的 leaf × rank 输出头。新 Actor 在一个冻结的 Run 快照上选择 Cell 模板，点名其外部事实来源，一次签发完整 token。Compound 提供对未来导出端口的引用与回执协议。规则 243 提供多行直接核验的实现参考。以下网络和通用核验接口是拟议设计。

已有 capture 在 sum-bits 的 7,265 个参考绑定中找到 7,263 个带新鲜表见证的绑定，另有两个空 LHS。固定窗口覆盖 742 个实际获胜锚点，现有目录加完整 delta 并允许替代锚点后覆盖 1,432 个。即使允许新入口，按当前表键和 primitive 做依赖闭包，仍有 5,163 个绑定需要额外独立输入。两槽条件下，现有目录的每 Run 单绑定提案上限合计为 213。这些结果来自同一条有精确执行辅助的轨迹。[统计及其边界](delta-coverage.json)

Compound 的父地址有实际作用。在 sum-bits、seed 1703 的既有实验中，两个 pending child 行分别贡献 15 和 10 个 RHS，屏蔽父地址后子 winner 归零。它证明父引用能够承载真实依赖，尚不足以证明通用多父生成或整程序加速。[Pending 实验与消融](pending/README.md)

## 1. 每个外部输入引用一个生产者实例的一条指令

建议的逻辑记录如下。物理实现可以用紧凑整数数组。

    CellToken   = (token_id, template_version, input_refs[])
    InputRef    = (producer_token_id, instruction_index)
    Receipt     = (InputRef, actual_result, observed_version, visibility)

`t7@5` 表示实例 t7 执行其模板中序号为 5 的指令所得的结果。序号从零开始，解释它的序列化指令表随模板版本冻结。同一模板可以有很多实例。若一条指令对外提供多个独立结果，引用再带上该指令声明的结果序号。token_id 在历史内唯一；复用物理槽时，句柄须包含世代。初始事实也用有结果位置的输入 token 表示。

Bake 将每条可引用指令的序号对应到模板图中的结果节点、类型，以及现有实例槽或回执投影。组合模板的静态内部连线继续由 Bake 处理。外部可读的结果才参加指针选择，纯控制指令没有可读结果。后继自己的输入和导出使用同一套表示。核验器沿引用读取实际返回值或见证；当构造子复用了其他实例的行，`t7@5` 仍表示 t7 这次执行第 5 号指令的返回值。

语义去重沿用原规则、绑定、阶段和赢家顺序。两条不同证明可以支撑同一绑定。union 或 ownership transfer 后，沿已验证的结果投影解析引用；退役、覆盖或世代失配产生相应回执。

在 Run r 开始时冻结可见的初始 token、历史 token 及其回执，得到 S_r。对半朴素规则，一个锚点须落在本规则 watermark 对应的可见增量中，其余输入可来自整个 S_r。空 LHS 和不受该 delta 条件约束的规则使用各自的入口。多 wave 可以交换提案及回执，RHS 在源程序规定的边界开放可见性。Stop 表示本轮 Actor 停发；宣告 ruleset 饱和还需要覆盖证据。

## 2. Actor 如何签发

例子中 C 需要 L(x) 和 R(x)。锚点 `t7@5` 给出 L(7)。t19 和 t23 实例化同一份模板，其第 2 号指令分别返回 R(7) 和 R(8)；t19 的另一条同类型指令也返回 R(8)。模型签发 `c31 = C(t7@5, t19@2)` 才能保住这个绑定。下一枚 token 可以直接把 `c31@4` 当作自己的输入，只要 C 的第 4 号结果已对它可见。整个例子中，选择父实例、选择指令以及读取结果都不会额外签发 token。

建议前向顺序：

1. **编译模板。** 用同一个 GNN 编码模板图，为序列化位置 k 取出对应结果节点的向量 g[T,k]。保留整模板摘要供选模板使用。把 `RoPE(k, W g[T,k])` 缓存在模板上。k 只在该模板内计数，同模板的所有实例共享这份矩阵。已有图编码器支持读取操作数节点；将读出与序列化指令结果逐项对齐是需要接入的一步。[现有 GNN 与读出](../../multi-row-generation/port_ablation/README.md)
2. **选择父 token。** Actor 选定消费者模板及其输入角色 j，由该角色、Run、已有输入与回执产生查询 q。对 S_r 中的 token 打分，token 的键包含模板摘要和实例已可见的动态结果信息。同模板的 t19 和 t23 因回执不同而可区分。类型、可见性和锚点的 delta 可做掩码；宿主不提供满足 x=7 的实例列表。
3. **选择父 token 内的指令。** 从选中实例 t 的模板取出共享矩阵。以 q 和 t 的状态生成位置查询向量，在模板局部坐标原点与各 k 的旋转键做点积，再加上该实例在 k 的可见结果内容分。掩掉没有相应类型结果的位置，将选中的整数 k 和实例句柄 t 一起写进 input_refs[j]。读出 t@k 后更新下一输入角色的查询。推理时不提供目标 t 或目标 k。已有旋转寻址实验可以复用打分算子；该实验给定了来源地址，新 Actor 必须从消费角色自己选出地址。[既有指针及其任务](../../multi-row-generation/address_ablation/README.md)
4. **成批执行。** 各 lane 的父选择在历史 token 上成批打分，指令选择按父模板复用旋转键。第一版可以完整读取冻结历史。旋转角只取模板局部指令序号；实例在内存中的物理行号不参与打分。离散引用和可重复的平局裁决使用稳定句柄。基线采用单线程 CPU 推理与 Rust 具名核验；同一前向可做 GPU 批量对照。
5. 先保留两行一 wave 作对照。随后允许多个固定宽度提案批次，用每行 abstain、整批停止和显式预算管理输出。区分主动停止与预算耗尽。已签发的完整绑定可用于后续批次去重；单独按锚点屏蔽会损失共享锚点但其他父亲不同的合法实例。

## 3. 核验与 Pending

通用验收路径依据模板布局，按具名引用读取行，逐项检查世代、版本、可见性、表类型、共享变量、标量条件与 delta 归属。成功后按源顺序提交，并绑定实际导出槽。缺父亲或签错一个父亲就拒绝。记录直接读取次数和独立搜索次数；后者必须为零。规则 243 验证页可以复用，但其发行端由 Rust 构造的专用连接不应给通用 Actor 预选父组合。[现有核验页](../counterfactual-issuance/overlay.py)

Pending 与已完成引用共用 t@k。子提案可以提前点名已签发实例的某条指令，回执到达后才能取得实际返回。只有所有父引用都可解析、consumer 被调度且所需事实在同一合法源快照可见，才核验并执行。父拒绝、端口失效、重复绑定分别记录。同一 wave 内允许提前签发依赖；这不提前开放同一 Run 的 RHS。复用 Compound 的回执与等待语义，按新核验契约替换普通 route 后缀。[Compound 实现](compound.metal)

## 4. 训练与信用

用随机生成的合法源程序和局部 Cell 交互训练，真实 EggCC workload 留作评估。网络输入为决策时可见的 token 历史、回执和静态模板。事后从完整验证过的证明得到监督，包括每个角色的父实例 t 及该实例的指令序号 k。两级指针共同为整份提案负责。存在多份合法证明时，在完整引用元组上分配信用，逐字段混搭仍须独立成立。加入两类配对反例，分别只改同模板的实例、只改同实例的同类型指令，并确保变更后的结果确实违反绑定。先用正确前缀训练，再让模型消费自己选的前缀和真实回执，测闭环误差。

RL 在生成器签发或停发的动作上实施。对同一合法快照分叉，比较选择大 Cell 与基础 Cell 后，后继是否保全、实际省掉多少独立付费提案。只有经验证的语义变化可以记入签名有效操作，重复或失败提案仍占分母。固定任务且语义完整时优化达到同一结果所需的付费 token；覆盖不足时同时报告缺失绑定和完整性，防止过早 Stop 抬高 EPT。验证器搜索补出的工作不能归功于模型。

## 5. 分阶段验收

| 阶段 | 改动 | 继续推进的证据 |
|---|---|---|
| A | 固定原目录、两 lane、预算及比较轨迹，改成完整 delta 上的单指针 | 区分 1,428 个实际获胜锚点和 1,432 个任意合法锚点的上限；报告实际命中、漏提和重复。只比较锚点选择，此阶段不声称多父核验 |
| B | 在已提交历史上为每个外部输入生成 t@k；孩子也可被下一枚 token 引用 | 在双父、跨 Run 例子中分别统计父实例命中、给定正确父时的指令命中、自由生成的整枚命中及后继消费成功率。换错实例或同实例内的指令均应检出，换物理存储顺序应得到同一引用。重复用同一结果的合法实例可通过。核验器独立搜索为零 |
| C | 扩大基础模板、空 LHS 和组合模板，增加多批输出及 Stop | 分别测目录与吞吐收益。在纯模型轨迹对照源 Run 边界、有效操作账本、遗漏、停止和 EPT；另列编码、推理、核验与整程序时间 |
| D | Pending 及跨阶段信用 | 父提交、复用已有行、拒绝、退役、晚调度和双父只到其一的分叉全部正确。比较是否真正少付后继提案，再评估 RL |

阶段 B 的配对消融固定模板、指令内容、历史、数据和发射预算，只开关指令位置的 RoPE，分别观察两类选错以及下一枚 token 对本次输出的实际引用。以同一条自由生成轨迹验收；单独给定地址的取值准确率只评价寻址算子。
