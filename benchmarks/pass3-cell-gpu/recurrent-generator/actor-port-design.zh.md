# 从 Base Actor 到多端口 Cell token 生成器（草案）

## 目标与依据

以 Base Actor 的递归前向、并行输出行、集合监督和 PyTorch/Metal 对照为骨架，替换固定的 leaf × rank 输出头。新 Actor 在一个冻结的 Run 快照上选择 Cell 模板，点名其外部事实来源，一次签发完整 token。Compound 提供对未来导出端口的引用与回执协议。规则 243 提供多行直接核验的实现参考。以下网络和通用核验接口是拟议设计。

已有 capture 在 sum-bits 的 7,265 个参考绑定中找到 7,263 个带新鲜表见证的绑定，另有两个空 LHS。固定窗口覆盖 742 个实际获胜锚点，现有目录加完整 delta 并允许替代锚点后覆盖 1,432 个。即使允许新入口，按当前表键和 primitive 做依赖闭包，仍有 5,163 个绑定需要额外独立输入。两槽条件下，现有目录的每 Run 单绑定提案上限合计为 213。这些结果来自同一条有精确执行辅助的轨迹。[统计及其边界](delta-coverage.json)

Compound 的父地址有实际作用。在 sum-bits、seed 1703 的既有实验中，两个 pending child 行分别贡献 15 和 10 个 RHS，屏蔽父地址后子 winner 归零。它证明父引用能够承载真实依赖，尚不足以证明通用多父生成或整程序加速。[Pending 实验与消融](pending/README.md)

## 1. 持久 token、导出端口与 Run 快照

建议的逻辑记录如下。物理实现可以用紧凑整数数组。

    CellToken   = (token_id, template_id, input_refs[])
    PortRef     = (producer_token_id, export_slot, generation)
    PortReceipt = (PortRef, actual_witness, observed_version, visibility)
    PendingRef  = (earlier_proposal_id, export_slot)

Bake 给每个模板编译有序外部角色、角色类型、静态内部连线、导出布局和允许启动的 Run。初始事实有可寻址的输入 token。一个外部表事实对应一个具名见证；同一个端口可以合法地占据两个角色。组合 Cell 的内部事实沿 Bake 连线取得。标量加法、比较等确定性指令直接从槽位算出，不伪造表见证。若要求某个外部事实成立，即使能按 key 查到，第一版也让 Actor 点名，便于严格验证“没有宿主补父亲”。

token_id 标识签发实例；语义去重另按原规则、绑定、阶段和既有赢家顺序处理。两条不同证明可以支撑同一绑定。回执记录构造子实际返回的见证，包括复用已有行的情况。union 后按合法的等价与版本证据解析引用，退役、覆盖或世代失配应产生明确结果。模型可读这些事件；latent 不承担身份解析。

在 Run r 开始时封存端口表 S_r。对半朴素规则，首个锚点从本规则 watermark 到 r 之前的可见增量中选；其他外部父亲可以来自整个 S_r。空 LHS 和不受该 delta 条件约束的规则使用各自的入口。多 wave 共享 S_r，可以交换提案及已取得的核验回执。本 Run 的新 RHS 要到源程序规定的边界才可见。Stop 表示本轮 Actor 停发，不能单凭 Stop 宣告 ruleset 饱和。

## 2. Actor 如何签发

例如模板 C 需要 L(x)、R(x)。Run 开始时，新发布的 t7.p 是 L(7)，较早的 t19.q 是 R(7)，另有 t23.q 是 R(8)。一行 Actor 先选 C 和 L 锚点角色，再从 delta 指向 t7.p。用这个端口的类型、字段和角色更新查询向量，在快照中的 R 端口上选 t19.q。最终签发 C(t7.p,t19.q)，两次指针读取只形成一枚付费 token。R 的类型可以由 Bake 掩码给出；本次读取中哪一个 R 满足共享变量，需要由模型选择，或由已声明的静态连线确定。宿主不提前按 x=7 列出正确配对。

建议前向顺序：

1. 由 Run/ruleset、上一轮 latent、已可见回执生成各 lane 的查询向量。移除旧 row 编号归一化和 rank embedding 对位置的依赖。端口键由模板角色、类型、动态字段与版本状态构成，精确 ID 通过整数侧带传递。共享或相等关系可提供精确比较特征。每个端口在同一快照内可复用编码。
2. 在该 ruleset 合法的模板和锚点角色上打分。首个指针应用 delta 和类型掩码。后续角色按共享模板规定的顺序读取，每个查询向量以先前选出的端口为条件。对两个独立输入都未知的情况，读完第一个再选第二个。最终 token 按模板角色顺序存放引用。
3. GPU 按兼容的角色数和端口类型成批计算。每层是矩阵打分、掩码及 gather；首版允许全表分块注意力。角色依赖形成少数固定层，层间不读回 CPU。训练与推理均避免把精确身份压成浮点数。端口存储换序后，在同一逻辑 ID、相同分数和显式平局规则下应选回相同引用。
4. 先保留两行一 wave 作对照。随后允许多个固定宽度提案批次，用每行 abstain、整批停止和显式预算管理输出。区分主动停止与预算耗尽。已签发的完整绑定可用于后续批次去重；单独按锚点屏蔽会损失共享锚点但其他父亲不同的合法实例。

## 3. 核验与 Pending

通用验收路径依据模板布局，按具名引用读取行，逐项检查世代、版本、可见性、表类型、共享变量、标量条件与 delta 归属。成功后按源顺序提交，并绑定实际导出槽。缺父亲或签错一个父亲就拒绝。记录直接读取次数和独立搜索次数；后者必须为零。规则 243 验证页可以复用，但其发行端由 Rust 构造的专用连接不应给通用 Actor 预选父组合。[现有核验页](../counterfactual-issuance/overlay.py)

Pending 放在已提交端口路径验证之后。子提案可以点名先前已签发的 producer 及其导出槽，形成无环依赖。运行时收到实际返回后绑定引用。只有所有父引用都可解析、consumer 被调度且所需事实在同一合法源快照可见，才核验并执行。父拒绝、端口失效、重复绑定分别记录。同一 wave 内允许提前签发依赖；这不提前开放同一 Run 的 RHS。复用 Compound 的回执与等待语义，按新核验契约替换普通 route 后缀。[Compound 实现](compound.metal)

## 4. 训练与信用

用随机生成的合法源程序和局部 Cell 交互训练，真实 EggCC workload 留作评估。按源 Run 构造样本：输入为当时可见的端口和回执，标签为事后确认的合法模板与整组端口。多证明只接受能在该快照完整核验的替代组合。集合损失对完整提案分配各 lane 的信用；逐角色指针损失可辅助训练。不能把多个可行证明的各个父亲分别合并成正例后任意拼接。训练中加入相同 delta、不同旧父亲，近似标量、重复类型、撤销、复用和 union 等成对反例。先用正确前缀训练，再让模型消费自己选的前缀和真实回执，测闭环误差。

RL 在生成器签发或停发的动作上实施。对同一合法快照分叉，比较选择大 Cell 与基础 Cell 后，后继是否保全、实际省掉多少独立付费提案。只有经验证的语义变化可以记入签名有效操作，重复或失败提案仍占分母。固定任务且语义完整时优化达到同一结果所需的付费 token；覆盖不足时同时报告缺失绑定和完整性，防止过早 Stop 抬高 EPT。验证器搜索补出的工作不能归功于模型。

## 5. 分阶段验收

| 阶段 | 改动 | 继续推进的证据 |
|---|---|---|
| A | 固定原目录、两 lane、预算及比较轨迹，改成完整 delta 上的单指针 | 区分 1,428 个实际获胜锚点和 1,432 个任意合法锚点的上限；报告实际命中、漏提和重复。只比较锚点选择，此阶段不声称多父核验 |
| B | 已提交端口的双指针和通用具名核验页 | 两个父亲来自不同 Run，互换第二个父亲后只拒绝对应提案；重复使用同一端口的合法实例仍可通过。零独立搜索，所有引用来自可见历史 |
| C | 扩大基础模板、空 LHS 和组合模板，增加多批输出及 Stop | 分别测目录与吞吐收益。在纯模型轨迹对照源 Run 边界、有效操作账本、遗漏、停止和 EPT；另列编码、推理、核验与整程序时间 |
| D | Pending 及跨阶段信用 | 父提交、复用已有行、拒绝、退役、晚调度和双父只到其一的分叉全部正确。比较是否真正少付后继提案，再评估 RL |

首个有判别力的原型是阶段 B。优先比较相同历史上的逐对打分与条件双指针，固定模板覆盖与发射预算。先证明网络能独立指对两个父亲，再决定是否扩大 hidden、增加层数或加大训练量。
