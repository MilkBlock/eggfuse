# 从 Base Actor 到多端口 Cell token 生成器（草案）

## 目标与依据

以 Base Actor 的递归前向、并行输出行、集合监督和 PyTorch/Metal 对照为骨架，替换固定的 leaf × rank 输出头。新 Actor 在一个冻结的 Run 快照上选择 Cell 模板，点名其外部事实来源，一次签发完整 token。Compound 提供对未来导出端口的引用与回执协议。规则 243 提供多行直接核验的实现参考。以下网络和通用核验接口是拟议设计。

已有 capture 在 sum-bits 的 7,265 个参考绑定中找到 7,263 个带新鲜表见证的绑定，另有两个空 LHS。固定窗口覆盖 742 个实际获胜锚点，现有目录加完整 delta 并允许替代锚点后覆盖 1,432 个。即使允许新入口，按当前表键和 primitive 做依赖闭包，仍有 5,163 个绑定需要额外独立输入。两槽条件下，现有目录的每 Run 单绑定提案上限合计为 213。这些结果来自同一条有精确执行辅助的轨迹。[统计及其边界](delta-coverage.json)

Compound 的父地址有实际作用。在 sum-bits、seed 1703 的既有实验中，两个 pending child 行分别贡献 15 和 10 个 RHS，屏蔽父地址后子 winner 归零。它证明父引用能够承载真实依赖，尚不足以证明通用多父生成或整程序加速。[Pending 实验与消融](pending/README.md)

## 1. 每个外部输入引用一个生产者实例的一条指令

建议的逻辑记录如下。物理实现可以用紧凑整数数组。

    CellToken   = (token_id, template_version, input_refs[])
    InputRef    = (producer_token_id, instruction_index)
    Receipt     = (InputRef, actual_result, observed_version, visibility)

`t7@5` 表示实例 t7 执行其模板中序号为 5 的指令所得的结果。序号从零开始，解释它的序列化指令表随模板版本冻结。同一模板可以有很多实例。若一条指令对外提供多个独立结果，引用再带上该指令声明的结果序号。token_id 在历史内唯一；复用物理槽时，句柄须包含世代。初始事实也用有结果位置的输入 token 表示。

Bake 将每条可引用指令的序号对应到模板图中的结果节点、类型，以及现有实例槽或回执投影。组合模板的静态内部连线继续由 Bake 处理。外部可读的结果才参加指针选择，纯控制指令没有可读结果。后继自己的输入和导出使用同一套表示。核验器沿引用读取实际返回值或见证；当构造子复用了其他实例的行，`t7@5` 仍表示 t7 这次执行第 5 号指令的返回值。

语义去重沿用原规则、绑定、阶段和赢家顺序。两条不同证明可以支撑同一绑定。union 或 ownership transfer 后，沿已验证的结果投影解析引用；退役、覆盖或世代失配产生相应回执。

在 Run r 开始时冻结可见的初始 token、历史 token 及其回执，得到 S_r。对半朴素规则，一个锚点须落在本规则 watermark 对应的可见增量中，其余输入可来自整个 S_r。空 LHS 和不受该 delta 条件约束的规则使用各自的入口。多 wave 可以交换提案及回执，RHS 在源程序规定的边界开放可见性。Stop 表示本轮 Actor 停发；宣告 ruleset 饱和还需要覆盖证据。

## 2. Actor 如何签发

例子中 C 需要 L(x) 和 R(x)。锚点 `t7@5` 给出 L(7)。t19 和 t23 实例化同一份模板，其第 2 号指令分别返回 R(7) 和 R(8)；t19 的另一条同类型指令也返回 R(8)。模型签发 `c31 = C(t7@5, t19@2)` 才能保住这个绑定。下一枚 token 可以直接把 `c31@4` 当作自己的输入，只要 C 的第 4 号结果已对它可见。整个例子中，选择父实例、选择指令以及读取结果都不会额外签发 token。

建议前向顺序：

1. **编译模板。** 用同一个 GNN 编码模板图，为序列化位置 k 取出对应结果节点的向量 g[T,k]。保留整模板摘要供选模板使用。把 `RoPE(k, W g[T,k])` 缓存在模板上。k 只在该模板内计数，同模板的所有实例共享这份矩阵。已有图编码器支持读取操作数节点；将读出与序列化指令结果逐项对齐是需要接入的一步。[现有 GNN 与读出](../../multi-row-generation/port_ablation/README.md)
2. **选择父 token。** Actor 选定消费者模板及其输入角色 j，由该角色、Run、已有输入与回执产生查询 q。对 S_r 中的 token 打分，token 的键包含模板摘要和实例已可见的动态结果信息。同模板的 t19 和 t23 因回执不同而可区分。类型、可见性和锚点的 delta 可做掩码；宿主不提供满足 x=7 的实例列表。
3. **选择父 token 内的指令。** 从选中实例 t 的模板取出共享矩阵。以 q 和 t 的状态生成位置查询向量，在模板局部坐标原点与各 k 的旋转键做点积，再加上该实例在 k 的可见结果内容分。掩掉没有相应类型结果的位置，将选中的整数 k 和实例句柄 t 一起写进 input_refs[j]。读出 t@k 后更新下一输入角色的查询。推理时不提供目标 t 或目标 k。已有旋转寻址实验可以复用打分算子；该实验给定了来源地址，新 Actor 必须从消费角色自己选出地址。[既有指针及其任务](../../multi-row-generation/address_ablation/README.md)
4. **成批执行。** 各 lane 的父选择在历史 token 上成批打分，指令选择按父模板复用旋转键。第一版可以完整读取冻结历史。旋转角只取模板局部指令序号；实例在内存中的物理行号不参与打分。离散引用和可重复的平局裁决使用稳定句柄。基线采用单线程 CPU 推理与 Rust 具名核验；同一前向可做 GPU 批量对照。
5. 先保留两行一 wave 作对照。随后允许多个固定宽度提案批次，用每行 abstain、整批停止和显式预算管理输出。区分主动停止与预算耗尽。已签发的完整绑定可用于后续批次去重；单独按锚点屏蔽会损失共享锚点但其他父亲不同的合法实例。

## 3. 核验与 Pending

通用验收路径依据模板布局，按具名引用读取行，逐项检查世代、版本、可见性、表类型、共享变量、标量条件与 delta 归属。成功后按源顺序提交，并绑定实际导出槽。缺父亲或签错一个父亲就拒绝。记录直接读取次数和独立搜索次数；后者必须为零。规则 243 验证页可以复用，但其发行端由 Rust 构造的专用连接不应给通用 Actor 预选父组合。[现有核验页](../counterfactual-issuance/overlay.py)

Pending 与已完成引用共用 t@k。子提案可以提前点名已签发实例的某条指令，回执到达后才能取得实际返回。只有所有父引用都可解析、consumer 被调度且所需事实在同一合法源快照可见，才核验并执行。父拒绝、端口失效、重复绑定分别记录。同一 wave 内允许提前签发依赖；这不提前开放同一 Run 的 RHS。复用 Compound 的回执与等待语义，按新核验契约替换普通 route 后缀。[Compound 实现](compound.metal)

## 4. 训练与信用

用随机生成的合法源程序和局部 Cell 交互训练，真实 EggCC workload 留作评估。网络输入为决策时可见的 token 历史、回执和静态模板。事后从完整验证过的证明得到监督，包括每个角色的父实例 t 及该实例的指令序号 k。两级指针共同为整份提案负责。存在多份合法证明时，在完整引用元组上分配信用，逐字段混搭仍须独立成立。加入两类配对反例，分别只改同模板的实例、只改同实例的同类型指令，并确保变更后的结果确实违反绑定。先用正确前缀训练，再让模型消费自己选的前缀和真实回执，测闭环误差。

RL 在生成器签发或停发的动作上实施。对同一合法快照分叉，比较选择大 Cell 与基础 Cell 后，后继是否保全、实际省掉多少独立付费提案。只有经验证的语义变化可以记入签名有效操作，重复或失败提案仍占分母。固定任务且语义完整时优化达到同一结果所需的付费 token；覆盖不足时同时报告缺失绑定和完整性，防止过早 Stop 抬高 EPT。验证器搜索补出的工作不能归功于模型。

## 5. 实施顺序、实验对照和失败后的决策

首个交付是一段含两个独立父、一个组合 Cell 和一个后继的跨 Run 轨迹。两个已提交的实例分别提供 L(7) 和 R(7)，生成器签发 C。在下一个合法 Run，D 通过 C 的第 4 号指令消费实际返回结果。另放一个同模板错父和一条同类型错指令。轨迹先由正确证书重放，再由模型从自己的历史自由生成，最后在 union、版本变化和提前签发三个分叉中重复。两次实验使用同一个具名核验入口。

### M0　给每个引用定义可重放的含义

编译器从同一份模板导出不可变的指令布局，逐项记录原始指令序号、GNN 结果节点、导出类型、实例结果槽以及最早可见边界。筛掉不可读指令后也保留原序号。冻结目录版本，改版的模板产生新版本。每个初始事实实例化一个固定输入模板，使用一个固定指令结果位置；动态输入行号不会成为模板里的指令号。组合 Cell 的独立外部输入和下游需要的所有导出也要进入布局，特别是一个内部结果同时供链外使用的情况。

逐指令验证返回契约。Let 调表、Let 调 primitive、Copy 和 Set 分别检查结果种类。别名沿用已有证据，标量可用于计算，独立表事实需要相应的见证，Set 可能会触发 merge。Union 保留在模板图和有序效果里；其生效可以留下回执、改变已有结果的可用性，单凭执行了 Union 不能签发某个表事实。Hide、失败和空 LHS 各有实际作用。当前 Rust 将见证区分为 Fact 和 Function；计划复用它已经提供的有条件回执转发。[指令和模板定义](../../../engine/cell-runtime/src/program.rs) · [运行时见证与转发](../../../engine/cell-runtime/src/graph.rs)

签发引用已提交结果时，将观察版本与该输入一同封存。Pending 引用在其生产者第一次合法回执上绑定，随后也执行版本检查。核验时以消费快照为准核对被观察版本。测试构造复用、同键有证明的合并、同键覆盖成不同值、无继承者的 Hide、旧物理槽复用。只在证据允许时沿同键转发并重验消费条件。原实例的逻辑引用可保留，换 owner 时核对 Bake 投影的方向和结果序号。对连续两次转发检查终点和无环性，跨快照使用缓存需有版本约束。量过链长再决定是否压缩。已退役的实例可能仍被挂起提案持有，需要保留足以拒绝旧引用的世代信息。

从干净初图重放 teacher 的模板选择和具名输入。磁带只携带签发、必要的观察版本和源边界，执行时生成实际结果。第一步修复已有两 Run 样例的三条 resume 事件差异，定位第一个分歧的源 Run、Cursor 和输出指令。随后加入上述双父例和两条扰动，每次只破坏一个独立输入；该绑定应被拒，独立兄弟应继续。逐 Run 核对规则调度、有序 RHS、有效写入、union、Spine 接续与最终状态。具名核验进程关闭或移除独立搜索入口，离线参考另起进程。对 sum-bits 的已审查终图契约使用 choice_diagnosis.py，严格哈希另列。新 workload 先说明所用契约。[现有具名核验与已知差异](../named-only-verifier/README.md) · [终图验收边界](../../marker-handoff/choice-diagnosis.md)

#### 运行时 repair 事件也进入 token 历史

repair 合并两行可变函数时可能执行一份已编译的 merge 程序。该程序是事件的静态模板。碰撞双方和实际执行的结果指令由运行时确定。第一版以拥有源 Run 的运行时签发该事件，单列事件、结果数、引用数、登记成本与实际图效果的归属。正常提案读取这些结果仍需通过具名核验。

1. 在 teacher 轨迹中导出事件模板、按 old/new 排序的两个来源引用及观察版本、实际可读结果 PC、生产 Run 与最早可消费 Run。训练器在消费快照中重建与部署相同的历史。来自运行时的事件不能作为生成器应当签发的正例。
2. 输入、普通签发和事件使用共享的结构读出。键包含种类、模板 GNN 结构、局部结果位置以及按角色编码的输入结构。可选的行 latent 只给普通 token 提供额外上下文。事件的两个参数保留角色，非交换 merge 能区分交换前后的含义。
3. 训练集继续用随机合法程序生成。配对构造发生碰撞与未发生碰撞的快照；记录自然频率，可在训练中提高含事件引用的样本比例，留出评估保留原始频率。每一类分别报告正确引用数与应引用数，以及整枚 token、完整后继的结果。
4. 除留出程序外，按归一化的 merge 程序结构划分留出家族。同一份程序换表名仍属于同一家族。用未见过的 merge 检验结构读出，同时报告见过的模板在新实例上的结果。
5. 对同一事件同时测试生产 Run 内和下一个合法 Run 的地址读取。前者应失败，后者还要通过版本、类型与 delta 归属。运行时事件不消耗模型输出 lane，事件产生的有效操作和 CPU 时间单列；后续模型选中它并提交独立效果时，只计后续实际完成的工作。

### M1　量出可表达范围和核验时间预算

已有 delta 诊断覆盖 sum-bits 和 dot-product。对 sum-bits 的 7,265 个提交，7,263 个有新鲜表见证，另外两个为空 LHS。当前目录在不限窗口、允许替代 pivot 后可锚定 1,432 个；两输出槽、单绑定提案的逐 Run 上限合计 213。允许新入口的结构分析另发现 5,163 个绑定仍需要额外独立输入。上述集合存在重叠。下一份逐 ruleset 统计要回答的是每份完整绑定的所有独立父能否在当时编码为 t@k，哪些只能由初始化、缺失模板、缺少导出、失效引用或签发预算解释。按规则自身的 watermark 标记新鲜锚点，其他父可读整个快照；两个不同 delta 锚点通向同一绑定时按源归属去重。用 union 后首次成立的旧父组合、多个 Run 未调度的规则和零表输入规则核对 native 边界。delta 的大小和旧父扇出都要实测。[已有逐项计数与预算](delta-coverage.json)

语义对齐之后才做理想提案器计时。对相同输入、目录、设备和提交器，交替测普通精确执行、预载正确 t@k 的具名重放、在线模型签发三种完整执行。第一轮先比较前两种。将离线采集排除在重放时间外，保留遍历磁带、读取回执、检查、去重、RHS、repair 和可见性维护。差值给出当前布局中在线选择器可花的近似时间预算；需单列它替代的磁带读取和新增的上下文维护。若耗时差小于测量波动，先查成本分解。旧地址磁带实测 sum-bits 上理想重放 18.43 ms、vanilla 21.80 ms，Deriche 上分别为 1,661.00 ms、1,578.79 ms。那次使用物理地址、版本及已有点读后缀，今次要量的是新证书经过具名核验的净成本。[历史理想重放的实现和计时](../perfect-receipt-replay/README.md)

### M2　用最小闭环分清选错实例、选错指令和无法分辨

冻结本 Run 的历史。模型读取已签发 token、实例的可见回执、当前 ruleset 及其 watermark。模板的 GNN 指令键只编码一次；动态信息至少能区分同模板实例在同一指令上返回的不同值。对候选相同但正确父不同的成对输入，比较送到网络的全部观测。如果观测相同且合法证明集合不相交，就找出在该时刻实际可见、却未编码的返回字段或失效事件，再改输入契约。未来提交结果只用来打标签。

首个可用头直接支持两个独立输入。对照组在所有合法 (t,k) 上联合打分，实验组先按 t 打分，再在被选实例内选 k。两者在同一冻结历史、同一签发预算下比较。先选错 t 后，第二层再准也无法恢复；同时报告给定正确父和自由选择两种指令命中率。分层约需 T 次父打分加所选模板的 P 次指令打分，另计准备动态父摘要的代价。冻结其他条件开关 RoPE，再比较模板整体读出与逐指令读出。已有旋转寻址实验给定了请求的来源地址，这里由未携带目标地址的消费者角色发起读取。[既有旋转实验的输入契约](../../multi-row-generation/address_ablation/README.md)

验收看两父整枚命中及 D 对模型实际生成的 C 的消费成功率，并分别列出缺失和多提。重命名 token、置换物理存储、固定同模板的错误实例、调换同类型但不等价的指令结果、注入旧世代。真正等价的替代证明允许通过。长历史固定正确父与合法绑定，逐步加入同类型干扰项，测准确率、注意力读取数、缓存准备耗时与峰值内存。模型主动检索可另作消融；若宿主已按共享变量做精确 join 或给出正确父组合，该组单独归因。注意力计算、索引维护和内存作为成本报告，不计作额外签发。

### M3　自由生成、提交顺序和停止

训练数据从随机生成的合法 Cell 交互获得。覆盖空 LHS、多父、同父多用、跨 Run 旧父、构造复用、Set 覆盖与 union 后复活的匹配。按完整合法引用元组做集合监督，让多 lane 可以交换顺序，并保留多种成立的整份证明。随机改名在输入与标签上同步。先用正确前缀定位错误，再用模型自己的 rollout，让离线精确执行为它实际到达的状态补标签。真实 EggCC 仅作评估，分别留出同模板的新实例、新 workload 和整个模板家族。预留至少一个只增加模板长度与无关历史的对照。

从一 wave 两 lane 起，在同一冻结快照上允许多个批次。每 lane 可放弃，整批可停止或耗尽预算。多个提案提交时按源规则与绑定恢复确定顺序，分开验证同绑定不同证明、共享父的不同绑定以及竞争性可变写。Pending 可指向更早签发的实例，接收端在所有必需结果可见后核验。双父只到其一、父拒绝、后续 ruleset 延迟调度各需一个分叉。一个父失效只退休真正依赖它的证明。一个仍有其他合法证明的绑定可以存活。

在无补搜轨迹，Actor 的 Stop 先记为停发。固定 Run 数的 schedule 照源顺序推进；要求饱和的阶段另外核对剩余义务及收敛条件。有独立完备证据时才在线宣告已完成。暂缺证据时将停止标为未证明，离线精确程序报告第一次漏提，不给模型补发。诊断用的有辅助轨迹和真实自由轨迹分开。主要部署对照采用离线 GPU 训练、单线程 CPU 推理和 authoritative Rust 核验；PyTorch、Rust 及 Metal 对照逐 Run 检查离散模板、地址、回执与有序提交，另测浮点误差及平局，不从离散相同推出浮点逐位相同。

### M4　给大 Cell 的实际接管分配信用，然后扩目录

从同一合法快照分叉，一边签发大 RipSat Cell，另一边用基础 Cell 完成同一组源效果。为大 Cell 检查独立侧输入、被其他链消费的导出、所有权转移和未来新版本。再让相同的独立后继自由运行。每对记录保留了哪些义务、删掉哪些独立签发、核验器少读几次，及两边的最终有效操作。模板大或选到了新 owner 本身都不给奖励。先做集合监督；在同一签发预算、初始化和样本下，再比较只对生成器的模板、引用或停发动作做 RL。旧两行实验中集合监督的完整覆盖高于团队和反事实 RL，此次要检验的是接管后的长期收益。[已测的信用分配消融](../../multi-row-generation/credit_ablation/README.md)

按遗漏义务和实际可省的独立动作选下一批模板。由同一套 Bake 导出、核验及训练接口逐步扩至至少 500 个，记录导出目录数、训练遇到数、在线实际签发数和真正接管数。扩大目录时先复用因果小例和已保存导出；实际速度集中在路径稳定后统一对照。新增接口进共享编译器及 runtime 的正常入口，实验开关共用它们；逐规则专用签发器只能作为注明来源的对照。
