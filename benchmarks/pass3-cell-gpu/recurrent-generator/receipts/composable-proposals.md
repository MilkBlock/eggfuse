实验沿用 [AGENTS.md](../../../../AGENTS.md#recursive-neural-cell-generation-and-verification-on-gpu) 中的两个时间单位。生成波决定一批候选何时可被下一次前向读取。源 Run 决定事实何时可见、绑定按什么次序生效。一份证书可以覆盖多次源提交，同一项提交只归因一次。

### 60 · 固定每 Run 最多两份证书，比较单叶与组合

先独立重放已与 CPU 对齐的 GPU 轨迹。每次发布记录唯一发布序号、生产者的全局 RHS 序号、效果位置、物理记录与表。每次搜索之前快照当时可见的发布序号。由包中的获胜锚点回到实际读到的那次发布，即使同一行被重新发布，也能区分两次来源。按编译产物的 joins 顺序重建有序路径，检查每一步的规则、入口、表及准确的父效果位置。每份候选证书的首项必须在当时八个可见候选位置内。后继可以通过父端口到达窗口外。

每条候选链只选一个具体实例，不把同一父的所有后继免费打包。用二元整数规划选择链。每份链在起点源 Run 占一个名额；每个不同的全局 RHS 在目标函数中最多计一次，跨 Run 的重叠也去重。在最大覆盖相同的解中选择证书最少的解。报告以**该冻结轨迹上可识别的获胜来源**为分母，允许事后选到正确分支，假设可在后继原 Run 验完边界。在线策略、补查成本及新的等价推导不在这个量中。

|程序|两个名额只选叶|两个名额允许组合|预算不限制时组合可达的不同 RHS|Pass 3 全部 RHS|
|---|---:|---:|---:|---:|
|sum-bits|181|246|825|7265|
|dot-product|161|207|726|6704|
|gemm-bias-relu|154|222|997|15462|
|stable-argmax|117|166|768|8190|

sum-bits 的一条四步链从 Run 98 的 RHS #404 开始。Run 102 的 #444 读 #404 的效果 1（物理行 603），Run 106 的 #702 读 #444 的效果 1（行 659），Run 110 的 #869 读 #702 的效果 2（行 847）。公开顺序依次保持在 98、102、106、110。将四步写进同一份提案，只说明可以共享其证明前缀，未来的版本、可见性和外部条件仍要在各自边界检查。[覆盖求解与实例](composed-ceilings.json)

图 50 的实际网络还提供了一个更紧的诊断。固定它选到的首个实例，允许事后知道其所有正确后继分支。sum-bits 种子 1703 的 106 个网络提交中，12 个能开始已烘焙的多步链，合计最多还有 27 个未由该模型提交的不同 RHS；dot-product 的 85 个提交中有 4 个可开始，额外 5 个。这里没有给已有网络追加任何提交归因。图 42 的在线对照增加一项训练消融：同一组合动作空间内，把“当前叶会成功”和“由该入口能完成多少个不同后继”分别用作入口监督。未来轨迹仅在训练家族上产生标签。

### 61 · 同一个 Run 内持续生成，直到预算或弃权

固定图 50 的权重和单叶动作空间，改变神经调用次数。每行下一波直接读自己的 GPU token 及前一波两行的验证回执。始终在最后才开始完整精确补查和原序提交。另设上限 16 的双行全弃权停止臂。停止以后将最后产生的 token 带入下一源 Run。设备端跳过剩余前向的计算，固定上限内的空 kernel 提交仍计时。模型在两波上训练，这里测的是同一权重外推到更多波；按波数重新训练是另一个变量。

|程序 / 种子|1 波神经 RHS|2 波|4 波|8 波|16 波|全弃权停止|停止时遗漏的窗口内获胜候选|
|---|---:|---:|---:|---:|---:|---:|---:|
|sum-bits/1703|58|106|126|126|126|126|119|
|sum-bits/1709|59|112|156|158|158|158|109|
|dot-product/1703|49|85|101|101|101|101|135|
|dot-product/1709|47|86|122|126|126|126|128|

开放更多波以后，两种子的 sum-bits 在第 8 波前已经达到本次 16 波的最终覆盖。保留同样的八个候选地址，每 Run 32 个提案槽时，其参考获胜来源上限是 705。缺口可以来自弃权、重复、错地址和动作缺少已关闭任务的长期记忆；仅凭覆盖平台不能区分这几个因素。文件逐波保留两行的不同提交与计时。下一项控制固定 16 波和权重，比较只读上一波回执、只排除上一波已关闭项、排除本 Run 所有已关闭项，检查重复是否转化为新增提交。[逐波在线结果](wave-results.json) · [单叶预算曲线](leaf-budgets.json)

### 62 · 相同网络与组合动作，逐波回执对照先生成后批验（在线结果见下）

以“生成一份可核验的推导”为动作。一个后继引用至少能定位父 token 的 row、位置、输出端口及代数。实例证书携带组合模板 ID 和编译器尚不能唯一推出的边界引用。区分三种父端口状态：已验证且可见、已验证但待原 Run 开放、已生成待验证。CPU 只参与离线 Bake、训练和事后核对。在线匹配、验证和残余补查都留在 GPU。

|条件|子如何产生|验真何时反馈|能回答的问题|
|---|---|---|---|
|逐波回执|网络读上一波生成的 token，引用其父端口|每波后返还真实回执，尚未到源边界的条件继续待查|及时知道父失败能减少多少无效子提案？|
|延迟批验|同一网络读已生成的 pending 父，保留来源地址和 latent|批结束沿依赖拓扑核验，共享父只验一次|允许猜测的额外子工作，是否小于减少的检验和同步？|
|冻结提案的交叉重放|保存实际在线生成的 DAG，交叉送给两种验证器|冻结网络输出和来源，只改变验真安排|从总差异中分离策略改变和验证安排的成本。重放单列诊断。|

固定初始状态、组合库、最大行与每 Run 总槽数、每批上限、边界读权限、证书格式及原 Run 发布规则。主对照用同一组权重，在训练程序上按批随机遮盖尚未返回的回执并提供显式“待验”状态。用 1703、1709 两个种子，sum-bits、dot-product 及两个预先留出的程序家族复核。每个在线臂另跑全弃权、屏蔽父地址、关闭精确补查。设备 verifier 从当前端口证明合法性，不能用参考 RHS 选择子链。失败回执返回给下一波或下一批，未关闭的源义务按期补查。

需要保存每项 raw 提案与父地址、实际复用的父证明、每份证书覆盖的不同 RHS、重复拒绝、待验父子边数、最长待验深度、峰值字节、批次数、残余精确工作、首个自治分叉。两臂都要在配对的完整 Pass 3 下比较有序 RHS、有效写入、Spine、union 和终图。报告同机交错的净耗时与冷启动/常驻边界。图 59 仅把同样的逐波验证合并提交，并未测试 pending 父端口。

为这个对照已导出四个训练家族的 **1,787 条多步路径实例**，以及两个开发家族的 895 条。每条标签保存起点的 Run、叶、候选位置、组合模板及各成员的全局 RHS 序号；同一结论可以出现在多条路径中。sum-bits、dot-product、GEMM-bias-ReLU、stable-argmax 的轨迹均未用于这些标签。后续在线实验已观测到子端口真正供给有序 RHS。sum-bits 的批验子提交为 25／26，逐波为 29／33；dot-product 为 17／16 和 18／18。[图 62 训练、重放与归因](../pending/README.md) [按家族的训练清单](compound-targets.json)

### 63 · 失效的范围由实际依赖决定

从图 62 实际生成的同一批 DAG 出发，比较整批退役、按传递依赖退役、再保留其他独立证明三版。给一个菱形图加独立分支，分别注入父拒绝、父代数过期、union 后源地址不同但同类、另一父提供相同结论。对共享父，验真只收一次成本；对仍有其他证明的结论，区分撤销一份证书与撤销最后一份支持。每次核对被撤销的精确实例集合、错误传播、独立幸存、原 Run 再验证、补查及最终可见性。真实轨迹和注入反例分表。任何非法后继发布直接判该臂失败。

真实冻结神经流中，整批退役额外丢弃了 39 个待验兄弟，其中 28 个在按依赖退役时能进入有序 RHS。独立支持属于构造器事实；原 Spine 引用仍需核对指定发布身份。[图 63 的来源与退役实测](../../proof-retirement/README.md)
