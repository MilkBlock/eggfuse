## 保留的架构

1. **编译器生成共享模板、入口与类型化指令。** 数值、原始事实地址和当前等价类各自有明确含义。冻结的 packed 地址头从打乱的实例库取实例，共享端口头选择输入、结果或缺失位置。GPU 校验地址和端口，并沿实际选择读取。初图无需在 CPU 恢复；图 21 单列了对真实内容和次序的验证。
2. **每个源 Run 在冻结快照上产生 token。** 两个逻辑 row 各有 32 个遍历分片，总计 64 份入口工作。完整键走哈希目录并复核所有有序参数，其余查询枚举被分配的入口，再执行精确联接。按已绑定输入宽度存储 token；同一规则的所有分片共享有界输出区，原子预留后再按源输入顺序提交。工作区溢出会报告失败。
3. **已提交事实向后续 Run 提供 Spine 端口。** 256 个编译器入口各自有完整的后继检查顺序。已登记的生产者返回真实物理行时，设备发布 root、生产者和深度。在该消费者原有的 Run，设备从仍可见且达到水位的行出发，按编译顺序读取其他键并生成真正的绑定。通用匹配只负责未被这条路径接管的绑定。重复提案按输入身份去重，保留较深接续和稳定的见证次序。
4. **提交顺序和闭包由设备执行。** Run 内暂存显式 union；所有 RHS 提交后再处理这批等价事件。repair 按上次已发布的键查找真实幸存行，保留原有 merge 参数方向，并记录有效更新。嵌套 sequence、repeat 和 saturate 都读设备的变更 epoch。主机只提交一个有显式上限的命令预算，设备程序计数器到终点就停止产生工作。

学习型分工使用两个 row 分数决定入口归属。训练输入是单独生成的有关联键的 join 小图，目标是分散匹配工作并让相同键具有局部性。在线时 PyTorch 在 GPU 对有限的特征取值计算共享分数；每个实际发布的入口据自身键和模板特征选择 row，随后该 row 生成完整绑定。精确枚举与容量检查保证覆盖。这里验证的是**学习提案分工加精确推理**，没有用无限制的神经解码器替代任意规则匹配。[学习分工](routing.py) · [设备执行](executor.metal)

## 图 23　等价可见时间和有序 merge 是两个条件

立即 union 会让同一 Run 较后的 RHS 提前看到新类。具体到 `Expr-size`，sum-bits 在 Run 122 少一次写入，dot-product 在 Run 165 少两次。按源边界再做 union 后，若仍选择较早分配的物理行作为碰撞幸存者，sum-bits 的写入数量已经一致，终图的 `Smaller(old,new)` 顺序仍有差异；dot-product 的首次写入数量差移到 Run 896。仅改幸存者、不延迟 union，两例终图均可完全一致，中间的写入数量却仍然错误。两项同时修正后，有序写入和终图都对齐。此四臂先在通用匹配路径上隔离机制。

## 图 24　Spine 是实际执行的入口

通用精确枚举可以给出一样的可见事实，却没有任何 Spine 接续。接入按见证激活的入口后，两种负载的接续记录逐字摘要全部一致。例如 sum-bits 的第一条是 Run 9 的第 5 个 RHS，根 0 从规则 375 接给 281，进入时深度 1。dot-product 从 Run 11 的第 15 个 RHS 开始，375 接给 285。最大进入深度分别是 9 和 11。还测试了在残余 join 遇到已覆盖见证时就剪枝，相比末端去重，输出一致；探索性计时在两个负载上的方向不同。

## 图 25　哪些运算可以浮点化？

按类型签名区分等价类身份比较、整数守卫、布尔值和标量算术。GPU 实现与 Rust 相同的有检查 i64 加、减、乘、除和余数语义；查询中的失败守卫保留失败，RHS 中不合法的计算显式报错。浮点对照只在两个操作数可精确表示、且所需整数结果也可精确表示时走 FP32。超出范围或遇到除余时在设备上走精确整数路径。等价类 ID 始终按整数比较。

4,054 个独立边界测试覆盖实际指令集、符号、零、i64 边界和浮点相邻整数碰撞。精确整数与受保护 FP32 均为零差异，放宽保护有 279 处错误。三个表示在这两个小工作负载上恰好通过相同的输出检查，不能单靠它们发现错误。受保护试验中实际走浮点分支的调用为 76,584/98,317 和 101,255/134,017。保留精确整数为默认。无边界保证的 FP32 仅作诊断。[边界用例与反例](results/typed-scalars.json)

## 图 26–28　迭代、批量与存储各自省了什么？

以下为固定种子与源输入的单次诊断耗时。正式 CLI 中位数另列；每个列入对照的设备结果都核过源轨迹。

| 对照 | sum-bits 推理 | dot-product 推理 | 可归因的变化 |
| --- | ---: | ---: | --- |
| 64 个分片，在表内扫描 | 1.89 s | 3.58 s | 公平基线，保持 token 布局和分片数相同 |
| 完整键只查一次，目录仍为链表 | 1.87 s | 3.67 s | 查找次数减少，单次查找仍需遍历 |
| 完整键使用带碰撞复核的哈希桶 | 1.57 s | 3.42 s | 保留相同的已发布键及 merge 方向 |
| 两个遍历工作项，每个源 Run 独立提交控制／查询／RHS 内核 | 11.62 s | 15.09 s | 低并行度的 Run 批量对照基线 |
| 将 1／4／16 个连续 Run 放入一个线程组 | 26.12／25.79／25.78 s | 34.80／34.49／34.55 s | 设备内保留边界屏障，跨规则的并行度受限 |

在同一 Run 内把每个逻辑 row 的遍历分成 1、4、8 份，普通稠密私有 token 区的时间分别为 11.29→4.07→2.94 s、14.62→6.03→4.72 s。分片真正分开遍历各自的入口链。图中不同源码 Run 的语义先后从未调换。

每行 8 分片时，所有规则按最大绑定宽度预留要 836.6 MiB；按编译期实际输入宽度预留为 220.7 MiB。每行扩至 32 分片后，私有表即使按实际宽度仍需 882.6 MiB；将每分片容量从 256 降到 32 可降至 110.3 MiB，但单个热点分片更容易提前耗尽。最终用每规则共享发布区，在同样的 64 分片配置上降到 **27.6 MiB**，并显式检查全规则容量。这些数字是 token 缓冲区，未用它们推算总 RSS。原子发布的初版在计数器清理阶段超时；改为独立的设备清零操作后重新执行并验收，超时样本不用于计算加速。

## 图 29　同预算一行、两行与学习分工

固定 64 个遍历分片；一行使用 64 份，两行各用 32 份。两种布局的有序 RHS、有效写入、接续、最终图均一致。学习分工的两个训练种子也逐项通过。sum-bits 学习种子 1703／1709 的行间提交分别为 (3,436, 3,829)／(2,940, 4,325)；dot-product 为 (4,004, 2,700)／(3,244, 3,460)。这些是按源身份去重后真正消费的 token。共同提案与独占贡献均在 GPU 排序后、去重前按完整的规则输入统计。

在完整提交之前直接统计原始提案，普通两行的独占绑定为 sum-bits 3,369／3,868，另有 28 个绑定两行都提过；dot-product 为 3,572／3,126，另有 6 个绑定两行都提过。相加分别得到完整的 7,265 与 6,704 项义务。多个可用的 Spine pivot 可以提出同一绑定，去重后的行内份额和生成时的独占份额含义不同。学习头两个种子的独占、重叠和行内重复也都单列。[提交前证据与全新目录复跑](results/release-check.json)

正式时间在通过有序验收后测量。每个计时样本启动独立进程，从加载设备镜像或 CPU 程序，到最终图写入磁盘、进程退出。每负载每配置一次热身、三次交错计时，包含神经权重加载与 GPU 同步，排除离线 Bake、训练及独立审计。GPU 定时不写大型诊断轨迹。五种配置每次都核对导出哈希，CPU 比较对象是同源的独立 Rust Cell CPU，不是原生 egglog 的性能基线。[CLI 原始时间](results/cli.json)

完整 CLI 的主要结论是：这两个工作负载适合 CPU 的低延迟执行。真实多 row 互补绑定已经实现；默认两行与同分片数的一行相近，学习分工没有稳定速度优势。运行目标限定为这里的两个冻结 Pass 3；静态容量、Apple Metal、单 GPU、固定上界的命令提交和有序单线程 RHS 均是此实现的边界。原生选择语义在 sum-bits 上使用仓库认可的 `choice_diagnosis.py`。dot-product 另行核对冻结指纹，要求两个源的类型表、时间线、全部非初始化规则的 query/effects、槽位 sort 与定义相同，再使用相同的窄证明条件核验原生 unmarked、marked 和 GPU 终态。未扩大等价项或表排除范围。[dot-product 的审查入口](native_accept.py)

## 重现验收

在外接盘研究工作树根目录运行。参数是新实验目录和图 03 的冻结权重。驱动程序会重新 Bake 两个注册源，用 GPU 执行普通与学习分工，随后独立运行 CPU 审计、原生语义检查与冷启动计时。设备 CLI 没有匹配回填选项。独立目录测试只提供两个权重、设备清单、二进制指令和导出 schema，并拒绝 Python 读取实验目录，两负载均产生相同的已验收导出。[隔离检查](results/isolated.json)

```sh
base=benchmarks/pass3-cell-gpu
runner=/Volumes/EggFuseWorkspace/bin/run-eggfuse
rotary=/Volumes/EggFuseWorkspace/experiments/rotary-axes-20261119/packed-1703/final.pt
~/.local/bin/eggfuse-job submit --kind compute -- "$runner" env PYTORCH_ENABLE_MPS_FALLBACK=0 python "$base/reproduce.py" /Volumes/EggFuseWorkspace/experiments/NEW-verified-pass3 "$rotary"
```

已有编译产物时，直接运行 `run.py DEVICE.json ADDRESS_WEIGHT OUTPUT --port-weights PORT_WEIGHT --export-only`。默认路径为受检查整数、已发布键哈希、Run 边界 union、启用 Spine、两行各 32 分片、按规则宽度共享 token 区。传入 `--router WEIGHT` 可以测学习的入口分配；`--rows 1 --tiles 64` 给出等遍历预算的一行基线。
