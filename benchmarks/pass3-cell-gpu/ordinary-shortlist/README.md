## 实际省下的操作

- **稀疏签名目录。** 用 1,024 个签名位表示已占用的第一视图 key 桶。将最多 16 个目录字和 query 对应的静态 Hamming 邻域取交集，再按原数值顺序访问实际存在的桶。原计数含大量已占用但不相近的签名头。区间模式保留原来的子掩码顺序。
- **当前表版本内共享已打分的行。** 缓存按表、列、表版本、所有视图的 query 签名及其允许掩码绑定。缓存的是学习分数通过的行位置，尚未检查原始关系等式。它可以同时缓存空列表。水位和其余已绑定列仍按此次发行上下文判断。表版本变化会撤下旧目录；本 Run 模式还在下一 Run 首次使用时清空列表。
- **实际父端口生存期。** 静态标出后续独立指针真正要读的槽，深搜时仅把这些生成的查询签名写入当前栈。每个必要槽由该候选路径的首个提供者赋值。后续指针继续读取它，同时避免为假阳性临时复制完整变量表。封包结束才按原验证契约重建可信绑定。

sum-bits 的 85,087 次缓存命中中，42,967 次复用了更早 Run 建的列表；dot-product 为 46,523／92,678，GEMM 为 146,628／232,388。每 Run 清理的对照中跨 Run 命中为零。sum-bits 峰值为 2,918 个缓存条目和 2,557 个行位置，GEMM 为 6,239 和 5,241。两个峰值分别统计。行位置数不包括容器容量、哈希表与分配器开销，也没有测 RSS。

## 密封批次的行提示

另一组对照把每个定宽的源地址元组紧密排在连续数组里，同时携带其来源表快照中的位置提示。验证器检查表版本、位置边界、位置上的实际稳定依赖身份，再读取该行的可信字段。Rust 图在该源规则的整批匹配和核验期间保持同一读视图。最终唯一键点查和 primitive 仍照常执行。检查前所有完整地址先封包，位置提示不参与选择候选。在 12 次交错配对中，普通栈和该连续格式在 sum-bits 为 56.6 → 55.2 ms，dot-product 为 57.3 → 55.5，GEMM 为 167.3 → 160.2，stable-argmax 为 52.8 → 52.3。实际获胜地址和完整候选序列一致。[独立配对](flat.json)

将每份完整候选的第一个位置提示改成另一行或越界位置，或者给该表送入旧 generation，两种反例都保留原地址流 SHA，但神经贡献降为零。两个负载均由显式剩余搜索恢复原结果。种子 1709 在四程序上也单独重跑连续格式和冻结基线，所有原始候选及获胜 ticket 均对齐。[错位与过期反例](hint-controls.json) · [第二种子](seed1709.json)

## 复现与联合接入

独立补丁通过 overlay.py 的 install(crate) 安装在 ordinary-witness/patch.py 的 install(crate) 之后。已有网络、编译计划和默认实现无需更换。正常三视图模式使用 stackseal3xlearned，连续元组模式为 flatseal3xlearned，均使用半径 2。两者的规则作用域与主生成器相同。这个实验没有改变单见证提供者，也不把其 RHS 计入本模块。

~~~sh
d=benchmarks/pass3-cell-gpu/ordinary-shortlist
w=benchmarks/pass3-cell-gpu/ordinary-witness
python "$w/build.py" "$out/baseline"
python "$d/build.py" "$out/overlay"
python "$d/study.py" "$out/baseline/session" "$out/overlay/session" "$w/weights-1703.json" "$ref" "$families" "$captures" "$out/paired"
python "$d/study.py" "$out/baseline/session" "$out/overlay/session" "$w/weights-1703.json" "$ref" "$families" "$captures" "$out/flat" --flat --repeats 12
~~~
