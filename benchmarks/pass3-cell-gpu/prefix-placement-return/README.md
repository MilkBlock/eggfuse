# The downstream return of one early private placement

The trained old-owner merge gate in the earlier prospective-storage study could observe only pairs which had already been made available. This experiment moves one decision to the first storage admission of a complete, extendable prefix of at most 16 ordinary source members. The compiler catalog must certify a possible successor. All other first admissions retain stock pooling in the matched single-action rollouts. Both arms keep the ordinary native extension behavior: an existing exclusively backed prefix can take on a later member. No artificial splitting, stream of explicit owner merge requests, or policy-selected source matches is involved.

At the selected callback the single-threaded Unix executor forks. The parent pools that prefix and the child stores the whole prefix privately. The two processes inherit the same graph, allocator, previous capacities, source Run and physical member IDs. They perform the remaining full original schedule, compaction, repair and source storage independently. A sham pair pools in both processes. Every pass compares the digest of ordered RHS, effective writes, Spine, committed unions, source schedule and final graph against the previously independently audited full source. The identified original op addresses are read at every subsequent settled Run in both arms. Their canonical fields and epochs must match after the intervention. The physical backing and its occupancy at birth, maximum occupancy, later growth steps and terminal backing are retained for the focused prefix.

An observation contains the component's member, slot and fact counts, the number of members and estimated bytes already awaiting pooled allocation, the number of certified successor transitions, distinct member templates and known parent users. No model receives program or shape identity, absolute Run or action serial, allocator outcomes, future growth or future reader activity. Pooled census states supply a feature-diversity sample; the two actual paired decisions are measured after the fork in one execution. These trials measure the physical allocation decision of the standalone Cell CPU research storage engine. The original source matcher generates the RHS in every arm.

Three labels distinguish the reduction in all completed-owner bytes at the first affected boundary, the reduction in terminal whole-Graph heap on actual destruction, and the sum of reductions in completed-owner retained bytes across all subsequent Run boundaries. The last metric is owner-byte-Runs; it counts Run boundaries equally, includes inactive intervals, and is not a process RSS integral or a full-graph per-Run measure. Whole-Graph drop measures requested live heap bytes released by destroying the graph, with the same compiled input program on each fork. A larger first-stage slab may later avoid allocations; co-admitted sibling packing changes caused by the chosen action are part of its return. The separate lifecycle census measures whole-program placement policies and entire-graph residency.

The three nine-parameter linear return heads use the same eight features, donor-only normalization, closed-form ridge regression and a fixed zero decision threshold. Each head optimizes one of these labels. At deployment a pooled sibling process and the learned process start together at their first eligible state; the latter chooses on all subsequent states it creates. Decisions are checked against the frozen weights. Summing isolated positive returns over the original state sequence gives an offline diagnostic; the native deployment is measured separately.

A multi-member threshold and always-private provide simple deployment controls. The score-pool timer forces a negative score after feature extraction and includes its runtime overhead; stock pooling avoids the scorer. Lean timings use ordinary Rust execution, four rotated measured passes after warmup, and exclude diagnostic forks, per-Run owner-size scans, retrospective action labels and final graph export. The raw end-to-end data are for this physical-storage engine; they cannot establish parity for a learned RHS proposer.

For an additional curve, the first sampled state with width above one and a nonempty pending pool is selected in each held-out program; the first sampled state is used if that criterion has no match. This rule reads no potential returns, future extensions or optimizer outcome. After the action, a private disposable process directly releases the dynamic Graph at every original Run boundary and retains its Program and observer. The main paths continue the original source schedule. The terminal teardown independently checks the last checkpoint and the paired dynamic-Graph byte-Run difference is compared to the corresponding completed-owner byte-Run difference. The graph probe helper is reused from the [native lifetime study](../placement-lifetime/README.md).

## Measured interventions

All 56 paired episodes produced a smaller backing at the focused prefix's birth, and all four sham pairs agreed in terminal bytes, accumulated completed-owner bytes, physical outcome, source graph and old-port read history. Among 32 donor pairs, only five had positive terminal return, 22 tied and five lost. The eight normalized inputs do not include later extension history. All catalogs were frozen before placement scoring. Each workload supplied its own previously baked fragment catalog; the learned gate transfers across programs, while this study does not test catalog discovery on unseen workloads.

For example, at dot-product Run 321 members 3510 and 3511 normally share a 16-member backing. Placing them privately immediately saves 32 B of completed-owner capacity and allows their backing to grow from two to four members. Nevertheless it consumes 64 B more terminal Graph heap and 47,136 more completed-owner byte-Runs. Every entry is measured versus its own sibling with the original stock policy, including later packing and extension choices. The longer-horizon labels reduce harmful admissions substantially in both held-out programs. Stock pooling retains the least memory among these deployed arms. The multi-member control is less costly than the byte-Run gate on GEMM and more costly on gated-state. These outcomes also show why one cannot sum the measured savings of rare individual actions to predict an entire layout. The feature-stratified single-action sample and natural offer distribution have different weights. For the independently selected GEMM pair at Run 190 (members 4240 and 4266), the terminal Graph difference is exactly zero, but retaining the private placement adds **31,232 dynamic Graph byte-Runs** across 1,463 boundaries. The completed-owner-only measure adds 29,952. The gated-state pair at Run 297 (members 3553 and 3554) saves **32 terminal B and 27,744 dynamic Graph byte-Runs** across 867 boundaries. These two exact whole-Graph curves evaluate individual actions; they are independent of the 32 donor training labels. [Paired per-boundary Graph measurements](curves.json)

In the lean timing control GEMM stock / score-pool / terminal / byte-Run gate medians were **94.73 / 89.20 / 89.99 / 91.05 ms**; gated-state was **34.39 / 34.16 / 34.77 / 33.97 ms**. Four rotated samples and noticeable variation even between the two semantically pooled controls limit performance attribution. This experiment establishes a placement-cost training signal and does not establish a robust inference speedup.
