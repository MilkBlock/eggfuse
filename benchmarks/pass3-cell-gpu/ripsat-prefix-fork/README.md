# Counterfactual continuation checks

The native overlay changes one branch in finish_set after the source Set RHS succeeds.
Only the selected root's private publication is withheld. For each workload
study.py takes the first three terminal records in the control and replays from
the same program and inputs once per record. This reproduces the prefix; there
is no memory snapshot clone. The matched history through the middle commit,
ordered RHS inputs and physical parents, writes, resumes, Run schedule and end
state are checked. Internal winner ordinals must differ by exactly the target,
with one extra external proposal. Siblings in the JSON are independently owned
terminals in the same consumer Run. Root serials can shift after intervention.

generator.py separately re-reads the existing seed-1709 frozen Metal replay
which damaged one root address, leaving its sibling intact. It compares both
previous-child tensors at the consumer decision, and re-evaluates the original
PyTorch root on the shared reference candidate capture. It checks emitted
discrete outputs, source Run records, schema-width graph rows, writes, RHS
bindings, unions and Spine. The exposed prior events are available after the
issuing Run; they contain no owner label or future child winner. Candidate
features in the damaged arm were not captured independently. This is an
original-policy readout on frozen trajectories, not a new neural rollout.
A rejected parent and a committed prefix with a withheld terminal are separate
interventions on different execution systems. A target absent from the root
bank gives no continue/stop comparison for that action.

Use the external worktree launcher and shared compute queue. Set
E=/Volumes/EggFuseWorkspace/experiments and O to a fresh directory under E.
Run build.py O with PYTHONPATH=benchmarks/pass3-cell-gpu/joint-witness,
then study.py E O/session O and generator.py E O/generator.json.
