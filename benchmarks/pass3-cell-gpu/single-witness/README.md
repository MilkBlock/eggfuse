# Native recurrent generation from zero or one independent row

Before a rule's first suffix lookup, the CPU network scores the typed physical rows of one input relation and emits a batch of versioned addresses. Both initial program facts and rows created since injection are addressable. The static compiler tries the zero-input closure first, then each relation pivot. An admitted subsequent table must have a completely bound key; a primitive must have all inputs. The verifier binds the one supplied row and executes only that forward plan. There is no residual DFS or alternative-parent enumeration behind a positive token. Its cost includes building the full candidate address bank, scoring every row and checking forged/stale input identity. The ordinary source engine still runs every unsupported rule in the assisted single-witness study.

**Identity and order.** The generator assigns an occurrence ID before verification. Only a verified selected candidate attaches a marker to the real native binding instance with its initial/runtime handle, row epoch, complete physical receipts and checked RHS inputs. The existing entry scheduler reattaches applicable Spine cursors from those exact witnesses. The marker follows the winning binding through source sort/dedup, and is checked again at actual RHS application. Every credited global ordinal is checked against its Run and rule and every required table witness. Birth and function-write events independently identify the creating source for dynamic physical addresses where provided; this audit does not reinterpret a row's latest update as its initial birth. Exact residual rows never acquire the marker. [Native predictor, compiler and verifier](single.rs) · [Source-audited learned outcomes](learned.json)

## Two different ways to keep almost all source work

The general neural head has four recurrent floats. It scores prospective candidate attributes and advances its hidden state with a summary of its own emissions. Four disjoint training program families supply labels. A training-only calibration chooses thresholds requiring a specified recall in each training family. Free-running NumPy post-audits separately reproduce total emissions and valid proposed rows from captured causal observations and actual suffix outcomes. In sum-bits seed 1703, the high-recall policy emitted 61,048 of 70,366 candidates and contributed 2,665 of the 2,677 reachable RHS. In dot-product the same seed contributed 2,897 of 2,899 (per-seed counts are in the table file). The remaining exact engine work includes both abstained keys and source rules needing two or more independent witnesses. A whole-executor no-residual control reports the first divergence when those other rules are unavailable.

The certified architecture retrains the same recurrent head after removing dynamic feature columns except the selected row's freshness. For each rule, the compiler computes a lower score bound across all freshness values consistent with a match and **all** possible recurrent latents in [-1,1]. In a seminaive rule with a single dynamic source relation, a stale witness cannot establish a current match. In rules with more dynamic reads both freshness values remain possible. Bounded weights, monotone tanh, conservative FP32 slack and a fail-closed check protect the threshold. Every potentially valid candidate scores above its compiled threshold without answering any suffix query. This policy emits all possibly valid tuples but can reject provably stale ones. We separately measure a deterministic delta gate to learn how much of this behavior needs a neural network. [Certified outcomes, timings and ordinal lists](certified.json)

The certified network and deterministic delta gate gave identical winners and address counts for both programs. The network required **zero exact fallback for this cohort**, with no safety-guard supplementation. The rest of the program was executed by the ordinary engine in this isolated experiment. Paired resident sum-bits seed 1703 was 45.36 ms with the certified network, 40.72 ms with the deterministic gate and 23.12 ms with the unchanged exact engine. Dot-product was 42.27, 38.27 and 20.63 ms respectively. All three include the original source schedule, writes, rebuilds and Spine. These numbers do not establish an end-to-end speedup. The optional guarded high-recall policy explicitly separates its verified neural proposals from supplemental source addresses admitted to preserve coverage. The general selector's empirical high recall alone does not prove completeness.

## Reproduction

Build the native crate copy using `build.py OUT`. The CPU-only hook is reusable as `patch.install(crate_dir)`, including in the combined ordinary-multi-witness executor. Set `EGGFUSE_SINGLE_POLICY` to a frozen config before running the normal CLI with `--audit-events`. `residual` controls checks of unselected candidates. `complete_unsupported` separately allows the ordinary runtime to handle rules outside the admitted grammar. Only a combined run that covers those rules can claim full autonomous Pass 3. The executable and service use Cargo `precomputed-forest,slot-transfer-audit`. The original GPU binding backend is not used. Project-level evidence runs against the source artifacts named in [training](train.py), [training-only threshold sweep](calibrate.py), [conservative per-rule bucket calibration](bucket_floor.py), [source alignment and timing](study.py) and [certified cohort test](certified_study.py). Frozen CPU weights are supplied for both seeds.
