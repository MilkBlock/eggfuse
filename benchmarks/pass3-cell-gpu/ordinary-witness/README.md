# 多个独立父端口的普通规则绑定

这个 CPU 入口覆盖一组明确的源义务。对某条规则，已知一个关系行以后，即使把所有已知完整键点查及可前向求值的 primitive 都用上，仍不能确定整套 LHS 变量，网络便需要提出至少两个独立的来源。使用与总覆盖表相同的静态函数依赖分析。min-width 为 0 或 1 的规则留给其他提供者，不能从本实验单独推出整轮达到 98%。[共同分母](../coverage-target/addressability.py) · [实际编译计划](plan.py)

| 完整源 Pass 3 | 有序 RHS 总数 | 至少两个独立见证的 RHS | 严格接管后模型实际提交，两个种子 | 1703 先封好再验的完整候选数 |
|---|---:|---:|---:|---:|
| sum-bits | 7,265 | 4,588 | 4,588／4,588 | 21,443 |
| dot-product | 6,704 | 3,805 | 3,805／3,805 | 21,210 |
| GEMM-bias-ReLU | 15,462 | 9,561 | 9,561／9,561 | 78,407 |
| stable-argmax | 8,190 | 4,912 | 4,912／4,912 | 20,607 |

这四个程序在上述规则内全部关闭原精确匹配器。源调度、逐 Run 有序 RHS、有效写入、Spine 接续、union 顺序及字节级最终图均与独立原生记录对齐。宽度 2、3、4、5 分别贡献 sum-bits 的 4,374、186、20、8 个 RHS。两个种子均只从另外四个源家族的已提交相关槽训练。[1703 的封包记录](results/three-view.json) · [1709 的封包记录](results/seed-1709.json)

## 谁提出绑定，谁验真

模型接受编译器选出的端口关系。每个语义值先投影为固定的 16 个符号特征，两套独立训练的线性层分别产生 query 和 key 的 10 个有损符号位。训练使用四个家族、700 次更新以及新编号布局，优化匹配对的区分度。三视图复用同一权重，并对符号编号使用三种固定置换。地址粗筛按第一视图的有损 key 签名分桶，候选须在三个视图中都通过学习分数门槛。枚举这些近似桶、读取图端口和所有假阳性都计成本。模型不读取源 RHS 列表。[训练](train.py) · [Rust 前向及验证](ordinary.rs)

在每个实际调度的规则 occurrence 中，调用方提供当前可见的类型化源行和水位。第一张关系表的可见行是根候选。上一父 token 发布的槽携带学习到的 query 签名，下一次指针选择直接读取这些签名。普通规则涉及独立地址的整批候选全部生成完才开始确切关系检查。地址为物理 Fact(cell,op) 或 Function 标识。封包阶段不检查不同父之间的精确共享变量、字面量、primitive 或后缀关系，候选相互冲突也会发出。验证器随后重新读取提案指向的确切来源，检查类型、可见性、槽等式、确定性键和 primitive。min-width 相同的规则可能需要额外指针，使每次选择能实际消费上一个父 token 的端口。

sum-bits 的 Run 106 中，规则 90 的源 RHS #627 来自两个独立 Fact，分别是 Cell 477 的操作 1 和 Cell 624 的操作 0。规则 538 的最小见证是 Get 与 TupleT，两者的输入地址没有直接关联。编译器把连接它们的 HasType 加入生成端口序列，Run 15 的 RHS #79 最终使用三个已提出的地址。一份通过检查的提案直接产生 native Instance 并保留 ticket，直到原序 apply 才赋予真实全局 RHS 序号。逐项记录规则、原 Run、完整输入和父引用，复核其源序号未落入 Spine 获胜者。按宽度抽样、全部流的 SHA 与二次运行比对见[常驻对照](results/paired.json)，完整外置逐项归因文件的摘要见[清单](results/provenance-manifest.json)。

作用域是一次规则读视图内的递归父端口选择。连续流动的神经状态是每个已选端口的有损学习签名；该模型没有训练跨整个 Pass 持续更新的图级 RNN。封包只在一个源规则 occurrence 内完成，源 Run 之间继续读取依法公开的新图。

## 反事实与性能

sum-bits 主臂的 21,443 份完整候选先封包，445 份在父地址之间的精确校验中被拒绝，20,998 份通过父校验，最终通过后缀和水位并提交 4,588 份。dot-product 对应为 21,210、424、20,786 和 3,805。封包时计算 SHA-256，同一输入重建后全部候选序列和实际获胜序号均复现。

- 屏蔽已生成父端口的神经签名，同时保留离散地址与验证器，sum-bits 种子 1703 只剩 3 个实际获胜绑定。随机丢掉约半数独立指针，仍保留相同的评分网络时剩 2,113 个。这些臂开放原生精确补查。[干预](results/three-view.json)
- 同架构换成未训练的独立权重，同半径下两个锚点分别发出 128、72 份完整候选，实际获胜均为零。[随机权重](results/untrained.json)
- 另外允许枚举整个类型化候选笛卡尔积，每规则 occurrence 同限 4,000 次指针发行。它在两个锚点分别封包 261 万、329 万份，达到上限后得到 4,009、2,912 个 RHS，其发行全部记作确定性枚举。已训练三视图在同预算内没有触及上限。[同预算对照](results/equal-budget-all.json)
- 比较了每个父指针随即验真再生成后继的前缀臂、固定半径的先封包臂、按 query 置信度扩展的臂，以及用学到的 Q/K 滤波器差异证明可忽略签名位的区间臂。区间证明是验证器使用的确定性信息。[前缀消融](results/prefix.json) · [封包和预算上限](results/single-view-wide.json)

同一 native 进程保留编译程序，每次还原初图，十次轮换顺序测完整源调度的推理。sum-bits 的默认 Rust、前缀、三视图封包、三视图区间分别为 24.56、94.64、104.26、76.53 ms；dot-product 分别为 21.02、99.88、118.95、81.98 ms。真实多见证发行解决了这部分覆盖率，当前常驻速度落后于默认 Rust。所有计时样本核对最终图和提交计数，另用审计运行完整核对源事件、原始候选序列及每项获胜来源。

## 联合入口

私有构建入口是 patch.py 的 install(crate_dir)，仅向实验用 native crate 增加模块、Instance 标识与 matches 包装。低宽度路径继续走原匹配函数；与单见证提供者共存时，两边按静态最小见证数互斥准入。每次新图单独 configure。推荐的已测配置如下。

~~~sh
d=benchmarks/pass3-cell-gpu/ordinary-witness
python "$d/plan.py" "$image" "$out/plan.json" --sealed
python "$d/build.py" "$out/native"
python "$d/trial.py" "$out/native/session" "$d/weights-1703.json" "$ref" "$families" "$captures" "$out/strict" --sealed --arms seal3xlearned-2-only --cap 1000000
~~~

加载相同 Program 后调用 ordinary_witness::configure(&program, plan_bytes, model_bytes, "seal3xlearned", 2, false, 1_000_000, true)。以 ordinary_witness::report() 中实际 apply 的序号与另一提供者做不相交检查。严格模式只关闭本模块所接管规则的精确搜索；覆盖整轮的验收还需在同一次运行中对齐其他宽度的来源。
