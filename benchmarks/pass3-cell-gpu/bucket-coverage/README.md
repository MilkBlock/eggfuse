# 完整 Pass 3 的键与范围覆盖证书（图 45）

本实验使用图 50 的双行神经生成器和两波设备回执。一个原 Run 内的四次发行额度、输入图、32 个 Bake 入口与每叶八个候选均固定。网络发出叶块号和物理锚点。原验证器检查来源、调度、水位、Spine 游标和其余 LHS。第二波仍由第一波实际生成的 token 和回执驱动。实验在最后一波和原有精确补查之间加入覆盖检查；所有未关闭义务继续参与原搜索，原 Run 有序提交。

## 对照和证书作用域

三臂在同一批真实提案上分别跑完整键和部分键面板。键和输入列来自编译产物的实际 pivot 表、类型签名和共享查询变量。完整键面板从网络所选锚点读取全部输入列。部分键优先保留在其他 LHS 关系中共享的列和字面量。自由扫描按第一输入列分桶；只有一个输入列且无合适投影时按输出值作逆向分桶。相同的物理键部分可以对应不同的父记录和 RHS。义务只覆盖指定叶块、Run 和键范围；整条规则的其他入口仍由原搜索执行。

| 臂 | 正例来源检查后如何处理这个键 |
|---|---|
| positive | 保留已验证的神经正例。键上的精确枚举照常执行。 |
| unique | 在完整键面板查实际公布键的唯一哈希目录。命中同一物理记录才关闭该源记录。部分键面板继续走 positive。 |
| range | 完整键沿用 unique。部分键以本 Run 的可见表构建目录。神经锚点选中包含自己的四成员页。设备枚举器产生有序物理行见证，验证器核对 Run、union 版本、区间端点及每个成员。只关闭已验的页，未列出的页仍需补查。 |

点查得到的源记录由同一份预先执行的 LHS 验真负责；负例也保留这次已做的工作。部分键桶按需建索引，当前 Run 内共享，下一 Run 的索引按需重建。哈希碰撞要逐列精确比较。附加兄弟记录的 LHS 由目录枚举后精确验证，真正赢得的全局 RHS 序号归给目录补全。网络信用仅计它自己提出并赢得的物理见证。

## 验收与计时

按被检验的源 Run 核对有序 RHS、有效写入、Spine 接续、union、根和最终有类型图。网络原始 token 与回执在正常三臂间逐字段相等。每个有来源归因的 RHS 以唯一全局序号、源 Run、规则和物理父做独立检查。计数运行另用没有读取投影目录的全表遍历核对每个通过的页及其完整端点。常驻计时移除这次审计遍历。positive 和部分键面板上的 unique 也省掉纯诊断用的覆盖 kernel 提交。常驻时间包含神经生成、原正例验真、覆盖检查、目录维护、剩余精确搜索、有序提交和最终同步。

反例分别使模型全部弃权、重复提交相同键声明、遗漏一个同键父或复用 union 以前的 Run/版本。需拒绝的声明在验真失败前不能写入任何已闭合标记。结果按不同键与页去重统计全覆盖与剩余行；额外精确枚举产生的 RHS、版本和目录维护分别计数。针对有实际提案的 Run，另以主机墙钟和两侧 MPS 同步测原正例验证和覆盖检查的提交区段。这些区段包含单次提交和同步，独立于常驻整轮墙钟。

## 实际提交与成本

每格的两个数均按种子 1703／1709 排列，单位 ms。完整键 positive → unique 在 sum-bits 为 1,102 → 1,125／1,100 → 1,120，在 dot-product 为 1,082 → 1,104／1,106 → 1,147。完整键使用已存在的哈希索引。部分键中，unique 没有完整性证据可用，保留全部剩余搜索。

| 部分键 positive → range | sum-bits | dot-product |
|---|---:|---:|
| 常驻整轮推理 | 1,089 → 1,110／1,076 → 1,097 | 1,085 → 1,136／1,134 → 1,180 |
| 已完整关闭的不同键 / 已检查的不同键 | 113/126、137/149 | 81/111、94/121 |
| 未经已验页覆盖的不同成员 | 46／45 | 352／306 |
| 目录重建读取的表行 | 8,571／10,263 | 7,423／8,974 |
| 实际免去的残余入口检查 | 222／262 | 201／210 |
| 模型直接提交的 RHS | 106／112 | 85／86 |
| 目录补全提交的额外 RHS | 16／30 | 24／21 |
| 其余精确搜索提交的 RHS | 7,143／7,123 | 6,595／6,597 |

页上限为四行，sum-bits／dot-product 观测到的最大完整桶分别含 8／36 行。两个负载的部分键提出主要来自源扫描按首输入列切分。按同组 LHS 关系共享变量或常量分桶的声明，在种子 1703 中分别占 32/260、36/238。类型化页可以关闭工作，也能正确保留边界以外的待办；目前每个涉及的源 Run 都重建投影目录，两负载的净墙钟都增加。下一组对照应固定提案及页宽，比较逐 Run 重建和按实际投影键、可见性、union 变化更新目录。[双种子计数与计时](results.json) · [各类声明和同键父实例](examples.json)

在两个种子的完整性检查与六次交错常驻重放中，源调度、有效写入、有序 RHS、Spine 和终图对齐。另对 1703 种子观测最先出现的 24 个活跃神经验真波，全部为两行同时发射。按提案数摊销，正例验真提交区段在 sum-bits／dot-product 的 positive 臂分别为 141／198 μs；部分页验证和目录查询的区段分别为 87／127 μs。此诊断每个区段两侧均做 MPS 同步，含调度开销，不能与整轮墙钟直接相加。

## 一次真实遗漏

sum-bits 的 Run 98 中，规则 65 读 Bop 表。网络选中物理父 174，第一输入列为类 13，对应有序 RHS #379 的实参为 [13, 358, 360, 361]。同一键还有物理父 208，对应 RHS #380 的实参 [13, 392, 394, 395]。遗漏实验从页证书中删掉 208。即使 174 的正例合法，页端点与见证长度仍然不符，验证器拒绝关闭这一页；两个 RHS 保持原序出现。dot-product 的 Run 131 同样检出类 36 下的物理父 235 和 237，其 RHS 序号分别为 710 和 709。遗漏反例共拒绝 134／138 项页声明，其中缺掉的物理父分别有 38／28 次是源执行的真实 RHS 获胜者。union 日志确实发生增长后重用旧版本，分别拒绝 70／62 项声明。
