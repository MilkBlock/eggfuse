# 一次批验能否证明一个饱和片段已经完成？

在实际 eggcc Pass 3 的初始化和第一次属性传播饱和中可以。源程序会依次执行多个 Run。每个提案 token 提供成员身份、父端口、逻辑深度和属性值。整批生成结束后，一次 Metal dispatch 并行检查所有成员，独立审计再与完整 Pass 3 的冻结输出对照。

| 测量 | sum-bits | dot-product |
|---|---:|---:|
| 完整 Pass 3 的 RHS | 7,265 | 6,704 |
| 证书覆盖的连续源 Run，含终止空 Run | 8 | 10 |
| 覆盖片段中的有序 RHS / 有效写入 | 10 / 15 | 14 / 28 |
| 整批检查的成员位置 / 父引用 | 9 / 8 | 13 / 12 |
| 朴素饱和基线的轮数 / 逐边父键探测 | 7 / 56 | 9 / 108 |
| 其后出现的同一传播规则 RHS | 2 | 4 |

两组程序各有两条空 LHS 规则。首次激活后其半朴素水位会阻止重发。上述前缀已覆盖这两条规则在整份程序中的全部 RHS。该前缀没有 Spine 接续。逐条核对了冻结的 CPU 对齐轨迹中的有序 RHS 和有效写入。[构造正反例的测量](results.json)

## 验证器为何能检查覆盖

编译器从类型化规则指令中提取属性递推。一个常量构造器提供基值，一条递归规则沿构造器的一个子端口读取已有属性，加上整型常量后写入当前键。这里识别的是空 LHS 初始化、空列表长度和非空列表长度。初始 ingress、模板参数与初始化效果构成输入。初始化在两个程序中分别有 220 和 411 个效果，得到的成员域分别含 9 个和 13 个键。其余八条 helper 规则都需要一张在该片段内始终为空的输入表，编译器用表存在性的保守不动点排除它们。[准入与成员域](certificate.py)

每个成员有一个由输入确定的目标地址。验证器在该地址检查 token 的身份和活动位。基点必须携带源规则规定的常量。其余成员的父 token 身份必须等于构造器子端口，深度须比父多一，属性值须满足编译器提取的递推式。有界且递增的深度排除了自证循环。每个地址都通过，所有成员便均有一份见证。深度也确定了其结果在原调度中最早何时可见。[GPU 批验证](coverage.metal)

删去最外层的一项后，所有尚在的 token 都保持合法，且没有幸存的子 token 指向被删项。两组测试的逐条合法性错误数都为零，域覆盖检查均准确报一项空缺。相同属性值的错父、重复基点占用他人位置、错误属性值和提前公开均被拒绝。全弃权通过已发 token 的空检查，并缺少全部应有成员。

## 后续 Run 的边界

sum-bits 的 Run 34 和 79 使用初始域内的尾部类 317、342，并给新结果类 620、674 写入长度。dot-product 在 Run 18、18、37、67 使用初始尾部 325、326、325、416，结果类为 724、678、861、974。这六项的完整构造器键均未出现在初始化域中。旧尾部证明仍可复用，覆盖新增构造器需要新的成员义务。

构造正反例的实验是独立的证书验证原型。一次 GPU dispatch 指**整个已准入饱和片段的覆盖检查**。初始化解释、域构造、正例生成、事后逐 Run 核对各自另计。常驻检查延迟含设备同步和读取诊断标志。朴素基线的探测数计每轮扫描全部构造器所读的父键。完整 CLI 和优化引擎耗时需另测。

## 独立学习的父指针和激活

学习对照保留同一份编译器导出的成员域。域只给每一行自己的类和构造器的尾部类，网络需要从全部成员位置中选出父端口。共享双线性指针通过类标识的固定随机向量为每个父候选打分，小门控预测本波是否发射。训练只使用四个训练家族，反复打乱类编码和行布局。每波读取自己的上一波 token，递归模仿训练期间也用模型自己的离散选择更新状态。

推理预设 24 波。所有波运行完之前，网络只能访问输入域、已选择的父位置及上一波自己生成的 token。编译器给出基点常量和属性递推公式，确切的深度和数值从所选父 token 投影。网络产生指针和激活决策。初始域包含离线执行的一个空 LHS 初始化绑定。核验 10／14 个前缀 RHS 时，模型最多负责其中 9／13 个成员 token，其余一个初始化绑定单列。该批核验没有把 token 写入整轮执行器的 RHS bank。独立验证器仅在最后调用一次。冷启动与建立输入域单列，常驻 GPU 前向及检查计入组合延迟。[共享指针与训练、推理](learned_proposal.py)

两个种子在 sum-bits、dot-product、整族留出的 GEMM-bias-ReLU 和 stable-argmax 上均通过一次批验，四个程序分别发出 9、13、16 和 12 个成员 token。八个配对运行的错父、非法和遗漏数都是 0。随机打乱推理行布局，逆置地址后全部 token 与原布局逐字段相等。屏蔽父 token 或轮换所选父地址后，仅剩基点发射，四个程序分别缺 8、12、15 和 11 项。

sum-bits 的常驻“生成整批＋核验”中位数为 5.90／5.11 ms，dot-product 为 5.94／5.09 ms（1703／1709）。每次完整推理有 24 波模型计算与 1 次覆盖核验，随后才读回结果。模型含 1,193 个可训练参数，输入另用 768 KiB 固定符号码表。当前实验给定了成员域和递推结构；它测父位置选择、激活和父 token 历史，尚未测未知成员域发现或一般 Pass 3 饱和。冻结权重的摘要、原始 GPU token、每项检查和耗时都已存档。[开放环推理证据](learned-results.json)

## 同一批 token 的 CPU 与 MPS 执行

固定同一份训练权重、每波的输入、24 波前向和终点覆盖检查。两个后端编译同一段整数验证判据。CPU 用 Clang 原生循环，MPS 每个成员一个线程。每臂预热后轮换执行 20 次。每次完整推理都读回最终判定并与存档的五字段神经 token 逐位比较。两负载、两种子以及各放置方式全部对齐，非法与遗漏均为零。额外的四个反例也给出相同错误类别。

| 完整前向＋检查中位数，ms | sum-bits，1703／1709 | dot-product，1703／1709 |
|---|---:|---:|
| CPU 单线程生成，CPU 检查 | 0.861／0.848 | 0.860／0.868 |
| CPU 四线程生成，CPU 检查 | 1.368／1.375 | 1.360／1.372 |
| MPS 生成，MPS 检查 | 5.236／5.343 | 5.296／5.237 |
| MPS 生成，CPU 检查 | 5.229／5.398 | 5.289／5.283 |
| CPU 单线程生成，MPS 检查 | 1.284／1.292 | 1.301／1.311 |
| CPU 单线程，检测到不动点即停止，CPU 检查 | 0.282／0.276 | 0.346／0.349 |

单列阶段时，CPU 单线程生成耗时 0.837–0.866 ms，同侧覆盖检查与取得判定需 5.2–5.6 μs。MPS 生成耗时 5.328–5.605 ms，同侧覆盖检查与读回判定需 233–238 μs。每个阶段单独同步，表中的整段耗时只有最终同步。前五行都保留 24 波。最后一行利用同一模型、同一输入的确定性递推，当相邻两波完整状态相等则达到不动点，后面所有波的结果均已确定。sum-bits 与 dot-product 分别在第 7、9 波检测到，仍执行最终覆盖检查。

本表只测 9／13 个成员 token 的真实前缀。网络和图已驻留在对应设备，冷启动、源码初始化与事后轨迹审计排除在计时外。混合臂的 token 传输已计入。[对照实现](placement.py) · [全部样本与判定](placement-results.json)

## 复现

在外置工作树中使用配置好的 PyTorch MPS 环境，关闭 MPS fallback。生成权重和运行结果的目录须为新目录。

~~~sh
dir=benchmarks/pass3-cell-gpu/coverage-certificate
ref=/Volumes/EggFuseWorkspace/experiments/pass3-atlas-integration-20261120
families=/Volumes/EggFuseWorkspace/experiments/repair-bake-families-20261120
python "$dir/study.py" "$ref" /tmp/eggfuse-coverage-certificate.json
python "$dir/learned_proposal.py" "$ref" "$families" /tmp/eggfuse-learned-proofs
python "$dir/placement.py" "$ref" /tmp/eggfuse-learned-proofs /tmp/eggfuse-prefix-placement.json
~~~
