# 多 row 分轮生成：真实历史反馈

独立 MLX/Metal 神经原型，不是实际 egglog/eggcc 引擎。目标是检查同图多个 row 能否利用实际生成历史，减少重复与遗漏；压缩不是验收指标。

## 执行和 token 契约

沿用无锚点等值连接任务，8 个输出槽没有预分配的源实例。4×2 布局分两轮、每轮四个 row 各生成一个 token；2×4 布局分四轮、每轮两行。每轮当前查询可以交互，并读取原始输入以及此前已生成的 token。

每个生成 token 是 90 个 float32：64 维连续 latent，加上模型自行预测的六个 one-hot 字段（激活 2、左右指针各 4、key 8、两个 value 各 4）。硬符号在前向由模型自己的 argmax 产生，反向采用明确的 straight-through 估计。它没有每实例稠密关系矩阵，也没有教师中间状态。

后续轮直接读取这些实际 token，使用独立的 row／行内位置旋转坐标。源输入 K/V 每层只准备一次；每个新历史 token 的 K/V 只追加一次。最终仅用固定索引排列恢复 row-major 存放，不做语义排序、去重、匹配修复或 CPU 补齐。空槽不是 EOS，不会截断后续潜在义务。

这些轮次属于**同一个语义阶段的输出过程**，原始源输入始终可见；它不是跨 Run 补全证据。token 引用仍指向 A/B 源实例，历史通过 attention 被消费，没有实现对前一 Run 新实例的完整执行。

## 配对与验收

[PROTOCOL.md](PROTOCOL.md)在拟合前冻结两个种子、4000 步训练预算和新结构族。

- feedback 读取真实生成的 latent 和符号。
- blind 使用同样的历史槽位、模块和参数形状，但历史载荷置零；它单独训练，不能和仅测试时擦除历史混为一谈。
- feedback 模型另做历史擦除、仅同行历史两种事后干预。

两种子分别核对初始权重文件，配对模型初始权重逐字节相同。训练使用与上一轮一致的集合匹配及覆盖/数量损失；没有教师输出进入下一轮。

新验收集是右侧三重度、右侧四重度，各 256 样本，由新生成的左侧多重度输入交换 A/B 后重新计算绑定和字段。A/B 是有类型、有顺序的端口，其有向多重度签名与训练和以前的面板分离。这是有向结构留出，不是全新算子或任意规模泛化。

训练回放、四个旧面板及两个新面板都保留。严格通过要求全部非干预面板完整正确。空图与非空图分开报告；重复少但大量少发 token 不算协调成功。同轮与跨轮重复计数覆盖所有激活绑定，包括非法绑定，和只计合法完整输出的 `duplicates` 指标口径不同。

## 实测结果：消费了历史，但没有稳定收益

所有模型均使用最终第 4000 步，没有根据验收结果挑选 seed 或 checkpoint。表中每项都以 256 图为分母。

| 历史模式／种子 | IID 完整图，4×2 | IID 完整图，2×4 | 右侧三重度完整图，4×2 |
| --- | ---: | ---: | ---: |
| blind / 1703 | 94 | 114 | 25 |
| feedback / 1703 | 34 | 33 | 2 |
| blind / 1709 | 80 | 83 | 18 |
| feedback / 1709 | 43 | 58 | 20 |

剔除空图，4×2 的两个 feedback 模型在 IID 上只有 **4、11 /224**，相应 blind 对照为 **63、50 /224**。新右侧四重度的 170 个非空图，feedback 为 0、1，blind 为 2、2，均没有达到可用程度。另一布局同样失败，详见 `results/*-result.json`。

第一种子的 IID 4×2 有 928 项义务。feedback 只激活 472 个输出，且这些输出并非都合法；blind 激活 846 个。feedback 的同轮/跨轮重复绑定为 62/8，blind 为 62/7。不能把 feedback 较少的合法重复计数（43 对 64）当成协调收益：它同时遗漏更多，字段错误也从 30 增到 112。

在已训练 feedback 模型上擦除历史，IID 完整图从 34→29、43→36；只读同行历史则为 35、44。干预说明模型使用了生成历史，但单独训练的 blind 对照更好。因此“消费了前一步 token”与“历史反馈改善了学习”必须分开判断。

三项专项检查通过；两个配对初始权重哈希一致，24 个干预面板第一轮 token 逐字节相同、后续 token 发生变化。四次独立 CPU 审计复现全部结果。四个模型均严格失败，设施测试通过不能替代模型验收。

## 端到端生成时间

每个布局/面板计时 32 个图，batch=1，按样本轮换模型顺序。输出包含完整 90 维 token 和 latent。

- 4×2、两轮：各组中位数 **3.284–4.272 ms/图**。
- 2×4、四轮：各组中位数 **6.955–7.413 ms/图**。

增加同时生成的 rows 减少了顺序轮数，但完整正确性没有对齐，不能把时间差称为有效推理加速。精确 GPU 对照在各组计时图均 32/32 正确；神经路径没有同正确率的速度收益。原始样本、GPU/CPU 判定和完整图吞吐见 `results/benchmark.json`。本实验没有 native egglog 时间或真实 eggcc 结果。

## 实现检查

三项专项检查覆盖：未来历史不能改变第一轮、屏蔽历史等于同权重 blind 前向、真实历史影响后续 token、token 符号来自自身输出、历史路径有梯度，以及新结构隔离。独立 NumPy 审计不执行模型；它从保存的实际 latent、符号、logits、指针和地址重新检查整套输出。

计时必须保留完整 90 维 token 和 latent，避免编译器删除最后一轮未被消费的 token 构建。包含输入构建、上传、缓存生成、解码和只读 GPU 验证；训练、编译预热及 CPU 事后审计不在计时内。精确 GPU 对照产生精确绑定记录，不产生学习得到的 recurrent latent；它是语义输出对照，不是相同状态表示。

## 后续与真实 Cell 的接口

当前原型仍让神经网络预测 key/value，虽然这些字段在给定绑定后可以由模板确定。这与项目已有的共享模板能力没有充分衔接。

实际引擎的 [Template/Op](../../../engine/cell-runtime/src/program.rs) 表示槽位和 Copy/Let/Set 等操作；[known_results::Plans](../../../engine/cell-runtime/src/known_results.rs) 从带类型的 Cell 定义推导静态别名、已知结果及其 Query/Effect 来源，并核验外部计划。它不是无条件可用的全局结果缓存：来源必须存在，前提必须成立。

下一项应从这种编译产物提取可验证的字段投影，让共享模板承担已证明的结构部分，网络继续决定实例引用与任务认领。投影不能查找正确匹配、代替缺失绑定或隐瞒非法提案。它能消除一类字段错误，但不能自动保证完整覆盖，因此重复、遗漏、逐轮历史和最终状态仍须独立验收。此方向尚未在当前神经原型实现。

另做了只读的冻结绑定诊断，没有改写预测、执行模型或把修正字段送回历史。在 IID 4×2 中，两个 feedback 模型的完整绑定集合分别只有 **38、53 /256**，而完整字段/绑定验收为 34、43；固定这些绑定时，字段投影仅能挽回 **4、10 图**。因此字段投影不是覆盖问题的捷径。改变生成历史之后的真实结果仍必须重新实验，不能把这个上限当作新模型准确率。见 `results/projection-ceiling.json`。

## 复现

通过硬盘环境和共享队列运行，使用新的输出目录，脚本拒绝覆盖最终权重：

```sh
~/.local/bin/eggfuse-job submit --kind compute -- \
  /Volumes/EggFuseWorkspace/bin/run-eggfuse python \
  benchmarks/multi-row-generation/streaming/train.py \
  /Volumes/EggFuseWorkspace/experiments/NEW-stream-feedback-1703 \
  --arm feedback --seed 1703

~/.local/bin/eggfuse-job submit --kind compute -- \
  /Volumes/EggFuseWorkspace/bin/run-eggfuse python \
  benchmarks/multi-row-generation/streaming/audit_saved.py \
  /Volumes/EggFuseWorkspace/experiments/multi-row-streaming-20261118/feedback-1703
```

另跑 blind 及 1709。权重和 NPZ 留在硬盘实验目录；Git 仅记录来源、协议及文本结果。验收失败退出 1，不得当作成功忽略。
