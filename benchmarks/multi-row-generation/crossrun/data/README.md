# Two-Run data and witness audit

`crossrun_data.dataset(split)` returns two source tables, four requests and two unordered target sets. A and B each have four rows with key/value columns. Their row indices are stable source identities. Run 1 forms Pair(i,j,k,x,y) for every equal-key binding. Run 2 consumes a generated Pair and a Request(i,j,t) with the same two source identities, producing Result(i,j,t,x,y). Training targets store active, i, j and three fields. A decoder selecting a generated Pair addresses its physical slot in the generated frontier. The order used to serialize the labels carries no supervised slot ownership.

Training and IID include variable multiplicities, empty obligations and distractors. Within either source side, records that share a key receive distinct values on these panels. Different inputs may therefore match the same key, but each Run 1 binding produces a distinct (k,x,y) payload. The two collision panels deliberately violate that property on one side at a time. `manifest.py` computes cardinality histograms and exact array hashes from the four frozen seeds.

Each collision panel contains 128 pairs of counterfactual request sets. Within a pair, the same A/B tables produce the same two equal-valued candidate parents. One request changes only its target source identity. Its physical request position, tag and all distractors remain identical. Each graph requests between one and three valid results. At least one request is invalid and at least one member of the colliding parent pair is left unrequested. The 256 samples thus share 128 underlying source graphs. These panels hold out the equal-payload/different-parent property. They reuse the training key and value vocabularies.

`crossrun_audit.audit` starts from decoded active bits, pointers and fields for both Runs. It reconstructs source obligations from the input relations. A Run 2 witness must consume an active Run 1 slot with a legal source binding, a valid Request slot and matching parent identities. Full semantic coverage additionally requires both the consumed Pair payload and the Result fields to match the source. The Run 2 score depends only on the consumed lineage. `both_complete_graphs` also charges unrelated failures in the first Run.

- `complete_graphs` counts exact multiset coverage, valid fields and valid ancestry. `nonempty_complete_graphs` uses the same condition on graphs with positive source obligations.
- `binding_complete_graphs` counts exact identity coverage, with no extra illegal bindings. `duplicates` counts repeated legal identities even when fields are wrong. `illegal` counts invalid actual witnesses, including equal-valued wrong-parent swaps.
- `missing` counts identities absent from the legal binding set. `semantic_missing` also counts identities for which every emitted token has a wrong field or a wrong field in its selected parent. `field_errors` and `parent_field_errors` count only identity-valid claims and may overlap.
- `audit_twins` requires identical Run 1 discrete traces for the two counterfactuals. It measures whether the one changed Request receives exactly one correct result on both twins. The other requests have their usual whole-graph coverage checks.

The audit runs entirely in NumPy after generation. It can be invoked on outputs in any physical order as long as Run 2 references the actual positions. Hiding explicit source references at the network input is an intervention on one information channel. Generated latent values and a learned layout can still encode source identity. The twin construction prevents a fixed request-slot/tag shortcut on the changed target.
