# 覆盖监督的配对消融

结论：增加覆盖量与输出数量监督能改善部分模型，但没有稳定解决互补生成。四个新模型仍然全部未通过完整验收，推理成本基本不变。该结果来自独立 MLX/Metal 原型，不是实际 egglog/eggcc 引擎。

## 唯一干预：训练损失

沿用上一轮无锚点集合任务：同图 4 个 A 实例、4 个 B 实例，8 个自由输出槽可生成任意合法绑定或空槽。网络、参数维数、推理代码、数据、初始化种子、4000 步预算、布局与优化器保持一致。四份原模型作为对照，权重没有重训或改变。

原损失用 Hungarian 在训练时对齐无序输出与真值。本轮额外把每个槽的激活概率和两个端口分布组合成软认领量：

```
C[i,j] = Σ_s P_s(active) P_s(left=i) P_s(right=j)
```

训练时要求总认领量接近离线真值集合，激活数量接近义务总数。公式、系数和冻结条件见 [PROTOCOL.md](PROTOCOL.md)。这是合并加入两个辅助项的消融，不能分别归因于某一个辅助项。

临时的 4×4 覆盖矩阵只用于训练损失，不进入 token、latent 或推理状态。推理依然没有正确匹配表、去重、过滤、排序或 CPU 补齐。测试明确保留一个反例：两个半激活的重复提案可以让软覆盖误差为零，却在硬解码后遗漏答案。因此损失下降不是验收通过。

## 严格验收结果

旧 IID 和 A 侧三重度集合只作诊断。训练前冻结两个新结构族，各 256 个新样本，结构签名与原训练及旧检查集不重叠：

- 双侧三重度：两侧都存在一个出现三次的 key，5 种多重度结构；192 个非空图。
- A 侧四重度：四个 A 共用一个 key，B 侧最多两次，7 种结构；170 个非空图。

所有样本均在已有“至多 8 个义务”的任务容量内。双侧同 key 三重度产生 9 个匹配的情况明确不在该容量契约内，不能截断后计为通过。每个结构族的 256 个样本包含编号、布局和数值变化，并非 256 个不同拓扑。

表中都是“原对照 → 覆盖监督”，不挑选种子。

| 模式／种子 | IID 完整图 /256，4×2 | IID 完整图 /256，2×4 | 双侧三重度非空完整图 /192，4×2 | A 四重度非空完整图 /170，4×2 |
| --- | ---: | ---: | ---: | ---: |
| 联合 / 1703 | 63 → 78 | 56 → 86 | 21 → 36 | 0 → 25 |
| 联合 / 1709 | 55 → 156 | 57 → 121 | 17 → 54 | 2 → 3 |
| 行内交互 / 1703 | 84 → 138 | 90 → 134 | 39 → 44 | 1 → 0 |
| 行内交互 / 1709 | 115 → 101 | 105 → 69 | 37 → 60 | 0 → 0 |

2×4 布局的 A 四重度非空通过数，四个新模型依次是 **8、0、0、0 /170**。不能只挑 4×2 的较好数字。两个布局检查相同输入图，不应累加成更多独立样本。

不仅结构留出未通过，4×2 训练回放的完整图也只有 85、155、158、97 /256。现有证据不能把全部失败归因于结构泛化或过拟合；这套训练配方还没有充分解决训练域上的完整输出。

## 数量接近与互补覆盖的差别

联合模型 1703 在 IID 4×2 中，遗漏从 **314 降到 206**，重复却从 **64 增到 155**；软覆盖误差从 0.264 降到 0.229。另一种子 1709 的同组结果则明显改善，遗漏 328→170、重复 162→20，但还没有达到完整正确。

这说明覆盖监督值得作为后续对照保留，同时其效果受训练结果影响很大。不能把软认领总量正确等同于每个离散任务恰好被一个 token 承担。所有逐基数统计、字段错误、软覆盖误差、激活熵和硬数量误差见 `results/*-result.json`。

## 时间和验证

同输入、batch=1、每组 32 个计时图，包含输入构建、上传、神经生成、地址解码和只读 GPU 验证。所有神经模型中位数在 **1.532–1.677 ms**；精确 GPU 对照为 **0.394–0.424 ms**，各组计时样本均 32/32 正确。神经模型正确性不相等，不能据此声称可替换的推理加速。新训练项没有增加推理操作；时差不能解释为网络架构加速。

离线训练、编译预热和独立 CPU 事后审计不在该延迟内。原始样本和有效完整图/秒保留在 `results/benchmark.json`。

验证完成：

- 3 项专项检查通过：新结构隔离、软覆盖反例、关闭新损失后原损失与梯度一致。
- 对照模型权重与原模型逐字节一致，16 份旧面板的输入、指针、字段、地址及 GPU 判定逐项一致。
- 8 个独立 NumPy 审计读取保存的真实输出，验证硬 token 与实际神经 logits 的绑定、字段、地址和整个集合；所有报告一致，模型验收仍为失败。
- 推理网络源码与提交 `c13fd51b` 完全一致；训练源文件及模型哈希已核对。

## 下一步的架构问题

目前一次同时输出所有 row 的所有位置，没有显式消费其他 row 已经发出的认领信息。下一项值得测试的是**多 row 分轮生成**：每轮每行输出一个 token，后一轮直接读取前一轮真实生成的端口引用、激活状态和 latent，再决定继续生成什么。它仍保留多行并行，行内则形成有实际生成历史的序列。

应与相同计算预算的无反馈版本比较，保留当前覆盖损失作对照；不能加入确定性去重来冒充模型学会协调。先验证反馈是否减少重复和遗漏，再比较相同正确性下的完整批延迟。该路径尚未在本目录实现，也不能替代跨阶段接续、union、ownership 和强表示契约的最终验收。
