# Figure 20: template-local alias information

**Primary question.** Does a per-port encoder help a single row retain the
correct source identity while using equality established at a later boundary?
The source of a token and the semantic read endpoint have separate addresses.

Admit a template only if its physical port-to-slot map, precise Eq sort,
source operation and earliest post-effect observation are available, and
execution witnesses the stated nontrivial equality. Keep a third, same-sort
separate control port. Record whether the source is an actual two-leaf catalog
composition or a replayed source rule from the corresponding frozen Pass 3
recipe. Report those sources separately when coverage permits. Local receipt
inputs denote observed rule completion, never a predicted union applied on trust.
Concrete instance handles and multi-instance demand tables are synthetic.

**Four paired models.** Explicit structural ports; singleton class node per port;
direct pairwise edges for the certified equivalence closure; anonymous class
nodes and membership edges for that same closure. Use two physical message
layers, same feature vocabulary, parameter count, initialization and width.
For the path-length diagnostic also compare c/d with the same trained weights,
reducing class-member embeddings and broadcasting the peer mean in a single
logical round; do not label a zero-retraining intervention as a fitted arm.

Freeze seeds 1703 and 1709, final checkpoint only. Train on whole template
families, hold out whole families selected without neural outputs. Per owner
instantiate the pre/post-and-committed view; choose from the four preencoded
entries on GPU. External instance unions only enter as explicit observed event
features, available to every model. The source operand index addresses template
embeddings internally. It never enters the numeric candidate features as a
class label or public certificate endpoint index. Random local handles, row
order, request position, and anonymous-class storage eliminate fixed slot order
as an intended solution.

**One physical row, two boundaries.** A learned producer selects A/B references,
activations and static payload projections. A learned consumer reads exactly the
generated frontier, the supplied Requests and observed controls. The compiler
projection copies only the selected rows. A shared semantic-relation head scores
the two role-specific endpoints carried by a Request. It receives no eclass
ID or truth table, and is supervised on actual semantic equality only during
training. Its score is available as a feature to the decoder. Report its
binary decisions separately from whole-graph coverage so that a broken
producer cannot masquerade as a successful relational decoder. Never replace
a missing parent or output with an oracle.

Use 1,536 Adam updates at 0.001, batch 32, same template/minibatch stream across
arms within each seed, hidden width 32 and eight causal positions per Run.
Train the same unordered active/pointer loss and auxiliary field loss in all
arms, plus unit-weight BCE on the semantic head. No checkpoint selection or
test-driven retries. If source admission or a GPU check fails, record it and
repair the harness before interpreting outcomes.

**Endpoints.** Second-Run nonempty exact graph coverage, missing/duplicate/
invalid witnesses and wrong ancestry, including confusable equal-but-wrong
sources. Measure premature local equality, spurious merge on a noncommitted
owner, and cross-instance contamination separately. Stratify pre, post,
nonmerge and external, on the same source inputs. Record exactness when all
required generated parents exist. Confirm predicted port/handle identities
are preserved after checking equality. Compare batch-one MPS latency for both
Runs with an already compiled/encoded template and from an in-memory static
description with a cold embedding bank. Include raw tensor transfer and
device synchronization; keep offline compilation, training, disk and CPU audit
outside that window. Interpret speed only alongside exact coverage.

Before fitting, 10 real source-rule templates qualified (7 structural families;
7 templates/5 families train; 3 templates/2 families held out). A source table
supplies six publication candidates over two owners. Each Request names the
lookup endpoint and the required origin independently. Handles and physical
table order are randomized. Every tested group consists of four receipt/event
states times two variants changing the requested origin. Each held-out template
has 128 samples (16 correlated groups), 64 generated without reference to its
certificate's choice of endpoints. Same state, both seeds, all arms share the
same raw external event and static addresses of its endpoints. The derived
closure of its effects is used only for supervision and audit. Rule 266, 267,
580 training-family counterexamples have secondary constructor congruence;
the three held-out rules have none of those specific secondary events.
