# Closed-loop value reads with exact parent provenance

Every template in this panel has a CPU-backed same-sort certificate and three co-observable public ports. In two isolated instances the six corresponding pre-event values are initially distinct. A successful producer may equate two ports of its own instance after the verified operation. A third port supplies an independently observed distractor. The archived Rust executions and their visible partitions are listed in `../corpus/`. The neural source tables and consumer requests are synthetic rebindings of these observed interfaces.

## Two Runs

Each graph provides six A records `[owner, instance_handle, raw_object, payload]` and two B publication frames `[owner, tag]`. Candidate positions, raw object labels and instance-local handle codes are shuffled. Payload is shared across all six records so equality of the payload cannot distinguish parents. The first Run joins A and B on owner to publish an observation `[owner, handle, raw_object, payload, publication_tag]`. The two owner frames are unique. These observations refer to existing objects before the union and retain their original identities after it.

In the second Run a Request has `[read_owner, read_handle, required_owner, required_handle, query_tag]`. An active proposal consumes a genuine generated observation from the requested *origin*. The read endpoint and the requested origin must be semantically equal at this point. Projection returns `[origin_owner, origin_handle, query_tag, payload, publication_tag]`. Choosing a different parent in the same e-class fails the provenance requirement even if the ordinary payload agrees. Choosing the specified parent before the applicable equality becomes visible fails the semantic requirement. This is a provenance-constrained consumer task over measured source partitions; observations from unrelated parents are not interchangeable witnesses in its contract.

`dataset('train'|'test', template)` returns `a`, `b`, `requests`, the static port addresses needed only for indexing template embeddings (`a_port`, `request_ports`, `external_ports`), per-owner `phase` and `committed`, and a single instance event `external=[enabled,owner_l,handle_l,owner_r,handle_r]`. When disabled, this event carries no endpoint information. Per-instance states index owners 0/1; unordered A/B table positions are distinct from those owner indices. Raw table fields and runtime event values fit 0–7. Original template port ordinals may be larger. Raw static ordinals address GNN outputs; they are not a source of anonymous class labels.

`target1` and `target2` each contain eight padded rows `[active,left,right,...five projected fields]`. For training `target2.left` names a canonical source witness in `target1`. An actual second-Run prediction must name a physical slot of the **generated** producer tokens. `legal_parents` and `request_legal` record offline source supervision. Model inference also excludes `state`, `variant`, `group_id`, `focal_owner`, `probe_kind`, `blind`, and all CPU closure tables. All arms use the same source samples for both seeds.

## Counterfactual groups and split

A group has four states and two variants, so one group contributes eight correlated graphs. A/B and all raw handles are fixed for the whole group. Between the two variants, one Request's required origin changes to another local handle while its read target, physical position and tag stay fixed. Between states, the query is identical for each variant.

| State | Local visibility | Instance event |
| --- | --- | --- |
| pre | Both instances at stage 0, no commit receipt | none |
| post | Both at stage 1 with source receipts | none |
| nonmerge | Both at stage 1; focal receipt absent, peer successfully committed | none |
| external | Same local state as post | one cross-owner union committed before reading |

A Request can be an always-valid self read, a local nontrivial/never-alias probe, an origin-switch probe, or a cross-owner read. A suppressed receipt on one instance does not invalidate the other instance's receipt. The permanently unrelated local neutral port provides negative tests even when a union is visible. The cross-owner queries include genuine consequences, unrelated endpoints and cases requiring transitive closure. The semantic head can be judged independently from producer undercoverage using `request_legal`.

Half the base groups are blind. The raw owner/handle tables, requests, event endpoints and per-instance flags are generated from the same random stream for all templates in this stratum; their hashes are checked. Probes cycle through public-port positions without reading a certificate. Changing the template can then change valid requests for the same raw input. A different template family can nevertheless have the same partition on its three selected ports. The held-out templates all share their anonymous three-port partition with some training templates. This split tests novel structural families and does not establish generalization to an unseen anonymous partition shape.

Seven training templates from five families supply 7,168 training graphs. Test panels contain 128 graphs per template (16 base groups × 8 variants). Three templates from two held-out families supply 384 nonempty graphs, including 192 blind samples. Source role identities and sample budget were fixed separately from training outcomes. The initial six distinct raw objects are crucial to the negative controls. Ports whose neutral would already alias a global nullary constructor in both instances are excluded by certificate admission.

## Independent source truth

All templates use all nine ordered cross-instance combinations of their three public ports. `runtime.py` rebinds the six source identities to the concrete `equal_groups` from the archived CPU Run. `source.py` creates labels from that observed partition. During audit `check.py` independently reconstructs connectivity from phase-gated local certificates, the raw scoped external edge, and CPU-observed secondary congruence edges, and checks it against the CPU partition before evaluating predicted witnesses.

For some rules, an external union has an additional effect through constructor congruence. This includes the non-injective reverse trap: merging two constructor outputs does not generally justify merging their operands. The audit uses the particular source replay instead of guessing the direction. Secondary edges, replay case names and final semantic class labels are never supplied as neural inputs. Across the entire training split, 148 demanded results depend on these additional edges. The training-template test split has 20; the held-out split has zero and cannot by itself validate extrapolation of those secondary consequences.

`manifest.json` records the four-state counts, SHA-256 of all input/target arrays, CPU evidence and source hashes, CPU replay coverage and blind same-input/template substitution results. Regenerate with `python data/freeze.py data/manifest.json` from the experiment directory. `test_data.py` checks legal but wrong-origin twins, pre/post/suppressed filtering, cross-instance contamination and independent probe versus emission scoring.

## Metrics

`audit(data,first,second)` consumes the actual decoded `active`, `pointers` and full `rows`. It rebuilds original source identities from selected A/B records, not a claimed identity or a teacher slot. Per-graph metrics distinguish wrong origins (and confusable same-eclass alternatives), missing parents, invalid producer selections, duplicates, missed legal obligations, pre-commit/tentative equality, spurious local equality and cross-instance spreading. A proposed result on an inactive request can be both an illegal equality and a wrong-origin decision; the aggregate `illegal` counts invalid proposals only once. `parent_ready_nonempty_*` separately measures consumer success when all required correctly decoded parents already exist. Outstanding legal obligations are counted after the run. A pre-commit request that could become legal following a future successful receipt is recorded as conditional. The current decoder does not publish an explicit deferred-obligation token or prove global saturation.

`paired_controls` counts both ends of each truly changing request: pre→post, suppressed→post, post→external. It reports whether both semantic decisions are right, whether both actual outputs follow the true obligation, and the emission result conditional on correct parents being available. For two post-state variants whose read target stays fixed while switching between two valid same-class origins, both variants must identify their respective real producers. The competing proposals may not be silently filtered or remapped. The independent replay reads the saved tensors and verifies their rows, hard address codes, static port-address scalar and graph verdicts before computing these paired scores.
