# 图 20 原检查点对并行宽度的敏感性

将三个留出规则（134、135、143）的同一批输入交给原 `pairwise` 解码器，保留两个种子的原始权重、八个独立的 `position.weight` 和 `source_position.weight`。每张图仍有八个潜在输出；每个 Run 改用 1×8、2×4 或 4×2 的生成顺序。各行在时间步 `t` 同时发出 token，下一步读取同行在 `t−1` 实际发出的 token；进入 `finish` 时携带全部已生成的 Pair。绝对槽号始终为 `r * L + t`。这些检查点只用单行历史训练，所以这里检验改变历史可见范围后旧权重能否继续工作。

使用与本次宽度实验相同的 `grouped_stage` 跑全部宽度。在 `1×8` 上，六份冻结轨迹中两个 Run 的活跃位、两个指针、投影字段、完整 Pair 张量及关系分类 logits 全部逐位复现。以下为每个种子的 384 张非空图。每个图使用原来的运行时合法性、发布和指定父身份审计。

两种子各有 780 个第二 Run 义务。1703 随宽度增加大量重复发布；1709 主要少发、漏发。两行时，两个种子在所有图里都已备齐正确父，完整率依然显著下降。1703 的 2×4 相对原检查点新增 8 张完整图，同时丢失 40 张；1709 新增 2 张，丢失 65 张。说明校验整个集合和逐图配对很有必要。图 20 的盲测同类换源探针在 post、external 两组均为 0/6，三个宽度一致。

原图 20 的四个状态/来源干预组（32 图）逐规则用于单图计时。每个种子计时 96 张，先预热 3 次，按图轮换三个宽度的执行顺序。含原始输入搬运、两个完整神经 Run、MPS 同步；冻结模板编码已驻留，审计在计时之后。所有计时图的硬预测与对应批量结果相同。
