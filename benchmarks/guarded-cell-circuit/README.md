# 将局部 Cell completion 编译为共享条件电路

这是一个**独立的、有界语义原型和后端设计**，不是 EggFuse runtime 改动，
没有运行 GPU，也不提供加速结论。它验证了一个具体构造：把边界 union
可能触发的局部匹配与 congruence 一起符号化求闭包，再共享其成立条件。
运行时执行闭包的条件函数，不再重演该有限片段的推导历史。

```sh
python3 benchmarks/guarded-cell-circuit/prototype.py
```

只依赖 Python 标准库；输出应与 [results.json](results.json) 一致。
这里的验收是有限模型的全部观测，不是 native egglog 语义验收。
未修改 CPU/compiler，故没有重复运行 Cargo 或 sum-bits/Raytrace 测速。

## 为什么选择这个切口

当前分支的 [Cell normalization](../../engine/cell-runtime/src/cell_completion.rs)
已经共享正构造子结构，但把 RHS union 保留为有序 terminal obligations；
这些 union 不参与该路径的 constructor closure，含 terminal union 的前缀
也不能直接通过 `extension` 证明后继包含关系。这保留了正确的源 Run
时序，但还没有表达“在这些边界等式成立时，后面会完成什么”。

[上次实际完成记录](../ripsat-cell-completion/README.md)中，sum-bits
减少了 330 次普通交接尝试，但新增 2,692 次 plan probe；Raytrace 的
128-Run 前缀没有直接命中，却做了 2,876 次 probe。更多状态及逐状态试探
并不能自动带来收益。本次研究的机会是把多个后继状态的成立条件共同编译，
并消掉已覆盖区域内部的重复传播。

历史 `resident_ridge` 工作已有 GPU 常驻特征和矩阵评分，但仍需要精确
guard；真实 Raytrace 的 resident response 实验保留了 708,814 次 CPU
残余读取，完整推理在一组配对测量中为 14.1441 → 14.2114 秒。其来源是
历史 worktree 的 `experiments/structural_runtime/RESIDENT_RESULTS.md`。
这提示我们必须先把需要执行的精确函数变小，不能仅把预测放到 GPU。

本次相对当前分支的 runtime 工作量和耗时差异：**未测，没有 runtime 接管**。
下面的电路大小是人工片段的结构实验，不是上述应用的性能数据。

## 构造：以条件函数表示完成，而不是逐个保存所有完成图

先限定一个已证明封闭的有限局部项域、正规则集，以及合法观察边界。
令 `e` 是边界相等关系和已成立输入条件的布尔向量。对每个局部结论 `f`
计算函数 `phi_f(e)`，表示它何时成立：

```
初始条件             phi_input = 对应输入位
规则 p AND q -> r    phi_r := phi_r OR (phi_p AND phi_q)
不同路线推出同一 r    共享 phi_r 的 OR，保留各条证明的前提
congruence           与普通规则一样，把参数 Eq 的 AND 接到结果 Eq
```

Bake 在符号布尔域中求最小不动点，运行时执行求好的函数。
原型用固定变量次序的 ROBDD 做离线化简、共享和不动点相等判断；
**编译器没有枚举输入赋值，枚举仅用于独立验证**。
BDD 节点不作为运行时指针追踪结构，随后降为静态 AND/OR 电路。

例如，仅在已有两条同形 F 链、没有额外结果 union 的覆盖区内：

```
Eq(a,b) -> Eq(F(a),F(b)) -> ... -> Eq(F^64(a),F^64(b))
```

所有这些等式具有同一个成立条件。模板里的每个结论指向这个共享 guard，
而不是执行 64 轮 dirty 通知、key 重写或逐层条件传播。
多参数构造子仍要求所有对应参数相等；不能用 digest 代替这个合取。

最重要的补充是，**closure 必须包含 union 新启用的匹配**。只对旧图做
congruence 不够。例如已有 `Pair(a,c)`，规则为：

```
Pair(x,x) -> H(x)
H(x) -> union(x,b)
```

`union(a,c)` 先启用第一条规则，再使 `a=b`，进而影响 F 链。
这部分必须进入符号不动点。原型专门验证了这条反馈链。

有限正 Horn 模型中，布尔赋值与 AND/OR 推导可交换，所以求得的函数
对每个赋值都给出相同的最小闭包。这个论证不覆盖未界定的项生成、删除、
可变函数或跨 Run 的效果重排。实际导入必须证明 grounding 完备，不能
只从一条已观察历史中抽取部分规则后就宣称闭包完整。

## 如何利用 dominate，以及如何归一化

在同一正片段中，增加输入事实或 Eq 假设不会撤销已经成立的结论。
不同输入对应同一份“带 guard 的完成结构”，由当前条件选择其中成立部分。
dominated 到 dominator 的扩展因此可以共享结构、端口布局和 guard 子电路，
不要求为每个边界 partition 复制整份 Cell。

Cell 身份仍需包含规范化的端口、输入契约、操作及阶段边界。
BDD 只归一化**固定输入接口下的布尔函数**，并不解决端口图的同构问题。
两个推导得到相同输出但有不同的额外效果，仍不能合并成可替换实现。
多个图上结论引用同一个 guard，也不表示这些结论的节点身份相同。

已有编译器应先完成端口规范化，再把 guard 作为相应操作/投影的属性。
不建立第二套运行时 fact graph，也不复制 Instance 的绑定。

## 运行时表示与 GPU 降低

设一个模板族有 `B` 个活跃实例、`k` 个边界条件、`g` 个共享 guard。
目标布局是现有实例槽的批量视图加必要条件列，模板保存静态 wiring。
既有构造子的实际返回见证、生命周期和 generation 元数据继续有效。
全局 e-class ID 不编码为浮点坐标；精确身份读取产生布尔条件。

电路可以精确降为矩阵行和阈值算子，`H(t)=1 iff t>0`：

```
AND(x,y) = H(x + y - 1.5)
OR (x,y) = H(x + y - 0.5)

同一层的批量执行：X_next = H(X_available W + b)
```

`X_available` 可以借用较早层的值，静态调度必须计入这些值的存活空间。
权重是编译器生成的 0/1，偏置为 -0.5/-1.5，不需要 ridge 学习语义。
二输入门所有中间量在 binary16 中精确表示，阈值有 0.5 的间隔。
这只证明该门形的数值正确性；实际 GPU 编译及融合仍需设备验证。

**能写成 GEMM，不等于值得运行稠密 GEMM。** 当前电路每个门只有两个
输入，通常应优先尝试按实例位切片：一个机器字的不同位代表不同实例，
一次 AND/OR 同时算一批实例。原型也穷举验证了这一表达，使用 Python
大整数，仅作语义检查。GPU 实现应融合整个模板电路，避免每门启动 kernel。
只有密集算术或足够稠密的块，才有理由使用浮点矩阵单元。

神经网络式效率在这里对应：共享静态程序、大批同形实例、常驻状态、
可预测的连续访问，以及消除内部动态维护。是否能达到类似吞吐，取决于
批量、寄存器压力、边界数据访问和实际电路大小，不由可表示性保证。
Ridge 可用于离线选择值得 Bake 的模板或可选候选排序，精确小电路不应
为使用 ridge 而再增加一轮预测及验证。

## 本次实测的结构结果

4 个边界端口的 6 个独立 union 种子位，加 2 个规则启用位，共 256 种
赋值；其中不同种子集合可能产生相同 partition。包含两条 Pair、可选 H
成员关系、结果 Eq，以及四条不同长度的 F 链。
两条规则启用位仅是模型输入，**不模拟 egglog 的源 Run 调度**。

| F 链深度 | Ground Horn 规则 | 输出投影数 | 不同输出 guard | 阈值门数 | 电路深度 |
|---:|---:|---:|---:|---:|---:|
| 1 | 54 | 23 | 17 | 142 | 9 |
| 8 | 180 | 65 | 17 | 142 | 9 |
| 64 | 1,188 | 401 | 17 | 142 | 9 |

三组共 768 个赋值检查，符号闭包、binary16 阈值网络、位切片网络均与
独立 union-find oracle 一致。oracle 不调用 Horn 推导或 BDD。
每组离线分配 287 个非终结 BDD 节点，其中输出可达 117 个。

输出投影数增加了，不能藏掉这个成本：测试会读出全部输出。
真正的压缩 runtime 必须让查询直接投影共享 guard；如果最终仍要物化
401 个结果或提交大量全局 union，就仍要支付这些输出成本。
142 个门对于很短的 Cell 完全可能比直接判断更贵。表格只证明在这类
重复链上，条件计算规模可以不随内部深度增长，不证明普遍压缩或加速。

## 生产接入所需的证明与顺序

1. 从实际执行的 Cell 定义和必要后继开始，限定有限正片段。编译器必须
   证明所有可能新匹配/生成项都在范围内；溢出则缩小片段或保留原路径。
   已观察执行用于排序候选，不构成完整覆盖证明。
2. 给每个合法源 Run 边界编译状态函数。前一边界的已提交结果才可作为
   下一阶段输入。不能把整个 schedule 的最终闭包提前交给消费者。
   有序 union、可变读写、删除及 primitive 失败继续保持原语义。
3. 在原 Cell 实例中保留必要输入和 guard 结果。Shared Entry 直接投影
   此表示；对覆盖区删除旧重复匹配和内部 repair 维护，避免两套并行存在。
4. 跨 Cell 的构造子判重、新节点分配、实际见证获取、外部 union 以及
   生命周期校验都仍有成本。要免除它们，必须扩大封闭区域或让相关
   查询支持压缩表示；不能用内部逻辑闭包冒充已提交全局效果。
5. 先接入一个真实模板族，核对合法边界的输入、输出和残余匹配。再比较
   **同一电路**的 CPU 位操作、GPU 位操作、GPU 矩阵实现，计入打包、
   dispatch、边界处理和物化；先通过语义检查，再做总耗时配对。

主要成本指标：每个有效完成实例的精确边界读取、唯一 guard 门数、
状态字节、输出/union 数、打包字节、batch 占用、kernel 启动、残余路径
比例与端到端时间。内部闭包深度下降不单独算收益。

## 膨胀边界与文献

BDD 不是免费压缩：变量排序可能极大影响大小，最坏情况会指数膨胀。
一般电路有共享也可能太大。有限 grounding 可用有界不动点展开获得
正确电路，但 grounding 本身、匹配位置数和项生成都可能非常昂贵。
应设 Bake 大小上限，按总成本拒绝不划算的模板，而不是退回实例内
维护第二份动态图。整个任意 egraph 的 GPU 高效执行仍未解决。

- [Colored E-Graph: Equality Reasoning with Conditions](https://arxiv.org/abs/2305.19203)
  说明不同条件下的 congruence 可以共享基础结构。它仍有各颜色的 rebuild，
  不能据此声称已得到无 repair 的 GPU 执行器。
- [Circuits for Datalog Provenance](https://openproceedings.org/2014/conf/icdt/DeutchMRT14.pdf)
  提供递归推导的共享条件电路基础。其有限 Datalog 的复杂度结论不自动
  覆盖任意 egraph 项生成，也不保证 ROBDD 紧凑。
- [A Linear Algebraic Approach to Datalog Evaluation](https://arxiv.org/abs/1608.00139)
  给出特定线性 Datalog 的矩阵语义及实验。它说明矩阵化有严格构造，
  不是 EggFuse 全量 GPU 加速的现成证明。

这里提出的是将这些思路与 Cell 的静态 wiring、实例槽、dominate 和源
Run 边界结合的工程构造；没有声称这些基础概念是新的，也没有证明已
达到神经网络吞吐。
