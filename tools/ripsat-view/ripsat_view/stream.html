常见问题 · FAQ
第一次看，从哪里开始？
选一轮 Run，再点一枚网络请求。按“生成 → 回执 → 发布”阅读右侧记录。带下划线的父请求和消费者可以跳转。
Cell 结构和 Token 执行流分别回答什么？
结构视图解释规则需要哪些输入以及计算如何接线；执行流显示某次运行实际选择的引用和 CPU 回执。规则编号只在对应程序内有意义。
一页有 160 枚 Token，代表 160 次根据回执重新决策吗？
这套采集器在每个 Run 开头从同一上下文生成一页，然后分批签发。每条请求有独立回执；页内较早的回执没有参与后半页的生成。
为什么“已接受”之后还要看发布？
已接受表示 CPU 准许执行。后继读取具名端口，还需要实际发布及适用的版本。工具只展示分片中直接记录到的端口；末轮的最终发布可能不在文件内。
重复、未触发、绑定错误有何区别？
重复是原生执行器对该次请求的判定；未触发表示规则当时没有被触发；绑定错误表示给定父引用没有形成要求的绑定。两个请求看起来相同，仍各自计一次签发。
有效操作为零是否说明请求无用？
“当轮贡献”来自原生分叉的 signed_gain，只统计当时已归属的新增操作。如有终图账本，详情还会显示最终归属。训练数据应保留决策时可见的状态，把随后发布的端口及最终贡献留作监督。
Teacher 和遗漏为什么分开？
Teacher 与随机辅助都实际签发并获得 CPU 回执。遗漏来自同一状态的离线分叉，未计入网络请求数。原有贡献归属发生变化时，遗漏结论保留未知。
如何打开自己的数据？
在“打开轨迹”里选择 credit-scaling 的 buffer 分片。解压和查询均在本机进行。结构跳转需要同一 program.json；仅凭不同文件里相同的规则号无法对齐。
