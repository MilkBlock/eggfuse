\subsection{Current eggcc replay}

The new replay uses the historical corpus of 96 workloads and three pass inputs, fixed common training, and a transferred donor. The standalone Cell implementation is based on revision \texttt{8450e627}; the native version-2.0 timing binary is built from the pristine \texttt{egglog-baseline} tag. Three fresh-process pairs alternate order for each input. Offline compilation/Bake and linking are recorded separately. The host is an Apple M3 Max with 48 GiB RAM; runtime and offline analysis each use one thread.

The campaign completed 288 of 288 attempted pass inputs (288 expected).

As in the historical replay, native uses the default Rust allocator and Cell uses mimalloc. This is another implementation difference included in the aggregate timings. The Cell lane enables sparse storage, view ports and RSS measurement, with result-port repair and shared Entry publication. Repetitions must preserve its endpoint and ordered schedule digests. This proves repeatability, not equivalence to native egglog. The reviewed sum-bits choice contract passes separately; it is not extended to the other workloads. This replay does not execute the production extraction chain, and no suite-wide semantics-preserving acceleration is claimed.
